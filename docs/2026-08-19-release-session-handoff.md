## 3. 확정된 것 (되돌릴 수 없음)

- **npm 조직 `ohmymcp-hsu`** — 조직 이름은 생성 후 변경 불가. 소유자 `storyrago`
- **스코프 `@ohmymcp-hsu`** — 라이브러리 6 개가 이미 그 이름으로 발행됨
- **인증** — GitHub 시크릿 `NPM_TOKEN`(Granular Access Token, **2FA 우회 켜짐**, All packages)
- **provenance** — `release.yml` 에 `id-token: write` + `NPM_CONFIG_PROVENANCE`
- **7 패키지에 `repository.url`** — provenance 검증이 요구한다. 실제 `E422` 는
  `package.json: "repository.url" is ""` 였다. `homepage`·`bugs` 는 #191 이 같이 넣었지만
  provenance 대조 대상이 아니다 — 빼도 발행은 된다

원래 쓰려던 `@ohmymcp` 스코프는 2026-08-05 에 타인(`@ohmymcp/pi-directx`, npm 유저 `ev3lynx`)이
선점해 사용할 수 없다.

## 4. 남은 결정 하나 — CLI 패키지 이름

무스코프 `ohmymcp` 은 **쓸 수 없다.** `oh-my-mcp`(2026-06-17 발행, 주당 391 다운로드)와
정규화 결과가 같아 npm 이 차단한다.

| | 설치 명령 | 라이브러리와의 일관성 | 확실성 |
|---|---|---|---|
| **A** | `npm i -g @ohmymcp-hsu/cli` | 완전 일치 | **확실** — 스코프 안은 유사 검사 없음 |
| **B** | `npm i -g ohmymcp-cli` | 이름은 통함 | 높음 (`ohmymcpcli` ≠ `ohmymcp`) |
| **D** | `npm i -g ohmymcpjs` 등 | 갈림 | **발행해야 안다** |

**세 안 모두 `bin` 은 `ohmymcp` 로 둔다.** 설치 후 실행 명령은 `ohmymcp` 로 동일하고,
차이는 설치 한 줄과 설치 없이 `npx` 로 한 번만 실행할 때뿐이다.

**PR #192 는 A 안으로 준비돼 있고 draft 로 잠가뒀다.** 이름이 정해지면 그 이름으로 고쳐서
draft 를 풀면 된다.

실패해도 **이미 나간 6 개는 되돌아가지 않으므로 B·D 를 시도하고 안 되면 A 로 돌아오는 비용은
워크플로 한 바퀴다.** 다만 동결까지 시도 횟수에 여유가 많지 않다.

⚠️ **`changeset` 은 이미 소모됐다.** `changeset version` 이 `publish` 앞에서 돌면서 changeset
파일을 소비하고 `package.json` 을 갱신하므로, 실패 시점에 `.changeset/` 는 비어 있고 CLI 도
`0.8.0` 인 채로 발행만 실패한 상태다. **재시도할 때 `pnpm version-packages` 를 다시 돌리지
마라** — 소비할 changeset 이 없고 버전만 한 칸 더 올라간다. 이름만 바꿔 현재 버전 그대로
발행한다. 절차 전문은 배포 준비 문서 §7.2 ④.

## 5. 발행에서 막혔던 세 지점과 그 결과

리허설(`pnpm pack` → 빈 디렉터리 설치 → 실행)은 전부 통과했는데 **실제 발행에서 세 번 막혔다.**
공통점은 **레지스트리가 받을 때 판정하는 것**이라 리허설로 재현되지 않는다는 점이다.

| # | 오류 | 원인 | 해소 |
|---|---|---|---|
| 1 | `EOTP` | 토큰에 2FA 우회가 꺼져 있었다 | 토큰 재발급 시 체크 |
| 2 | `E422` | provenance 가 `repository.url` 을 대조한다 | 7 패키지에 필드 추가 (#191) |
| 3 | `E403` | `ohmymcp` 이 유사 이름 차단 | CLI 이름 재검토 중 |
| 결과 | 부분 발행 | 3 번 때문에 6 개만 나감 | 나간 6 개는 그대로 둔다 |

상세와 교훈은 배포 준비 문서 §7 에 있다.

**세 건 모두 사전 판단이 틀린 것이었다.**

- "Granular token 은 2FA 를 우회하도록 설계됐다" → 우회는 **발급 시 체크하는 옵션**
- "provenance 는 환경변수에서 저장소를 뽑으므로 `repository` 가 없어도 된다" → **생성은** 그렇고
  레지스트리가 **대조해 거부**한다
- "registry 가 404 니 이름이 가용하다" → 404 는 그 이름의 패키지가 없다는 뜻일 뿐.
  유사도 검사는 **발행 시점에만** 돌고 미리 조회할 수 없다

**#181 은 이슈 본문의 범위와 다르게 나갔다.** 이슈는 "`required` 와 타입 둘만" 을 전제했으나
`generate` 의 `buildViolationCases` 는 네 축(`required` · `type` · `enum` · `range`)을 조건 없이
만든다. 두 축만 검사하면 가짜 통과가 절반 남으므로 **네 축 전부**로 갔다.

확정된 것 (ADR-0048):

- 네 축 전부, **최상위 필드만**. 중첩 객체·배열 내부는 보지 않는다
- **주입된 응답이 스키마 검사보다 우선한다** — 그래서 검사를 끄는 스위치를 만들지 않았다
- 해석 불가 스키마는 ADR-0015 규칙대로 건너뛰고 기동 시 `stderr` 로 고지
- JSON Schema 평가기 의존 추가 없음, `runner` import 없음 (의존 방향 유지)

**남은 후속:** CLI E2E 에 진짜 위반 케이스를 넣어 `rejectionUnverified` 를 0 으로 만드는 것.
지금 `dist-cli-e2e.mjs` 는 `rejectionUnverified: 1` 을 정상값으로 단언한다.

## 9. 반드시 지킬 것

- **발행 전 changeset 의 패키지명이 매니페스트에 실재하는지 확인한다.** 개명 이후에도 옛
  스코프로 changeset 을 넣는 PR 이 계속 들어왔다 — #173 에서 3 건, 그 뒤 1 건. 존재하지 않는
  패키지를 가리키면 `changeset version` 이 실패한다. 명령은 배포 준비 문서 §3.2 에 있다.
- **버전 PR 은 개명·이름 변경 후 반드시 재생성한다.** 봇이 만든 브랜치는 개명을 따라오지
  않는다. #112 가 개명 6 분 전 상태로 남아 그대로 머지하면 발행이 403 으로 죽을 뻔했다.
- **`.changeset/` 이 비어 있는지는 디렉터리 존재로 판단하지 않는다.** `README.md` 와
  `config.json` 이 항상 남는다.
- **turbo 캐시를 의심한다.** `FULL TURBO` 는 실행되지 않았다는 뜻이다. 개명·리네임 검증에는
  `--force` 를 쓴다. 실제로 이것 때문에 서브패스 참조 누락을 한 번 놓쳤다.
