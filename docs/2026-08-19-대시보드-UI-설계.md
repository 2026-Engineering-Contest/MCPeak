# 대시보드 UI 설계 (2026-08-19)

상위 문서: `docs/2026-08-19-대시보드-설계.md`(아키텍처 확정본). 진행 중인
`docs/plans/2026-08-19-대시보드-구현계획.md`와는 독립인 별도 문서다. 구현계획 반영
여부와 시점은 따로 결정한다. 시각 확정본은 디자인 캔버스에 있다:
https://claude.ai/code/artifact/922c2947-84c2-4eca-a465-8dbcb0fa9cb7 (아트보드 8장).
정적 캡처(1440×900 PNG 8장)는 `docs/mockups/2026-08-19-대시보드/`에 있다.
캔버스와 이 문서가 어긋나면 **이 문서가 우선**한다. 캔버스 이후 확정된 변경 두 가지가
이 문서에만 있다: 사이드바 라벨 영어화, 다크 모드 지원.

## 1. 설계 원칙

1. **터미널 문장이 곧 제품이다.** CLI가 찍는 실패 메시지·제안 문면을 재작성·재정렬·요약하지
   않고 그대로 보여준다. 로그 패널은 이를 위한 전용 영역이다.
2. **명령어를 몰라도 쓸 수 있어야 한다.** 사용자가 CLI 플래그나 셸 명령을 타이핑하는 입력을
   두지 않는다. 옵션은 전부 GUI 컨트롤로 노출하고, 프론트가 argv를 조립한다. 대신 조립된
   CLI 명령을 항상 보여줘서 학습·검증 통로를 남긴다.
3. **레퍼런스 셸, 마케팅 요소 제거.** 사이드바 + 카드 + 테이블 + 상태 뱃지 구조를 쓰되
   히어로 배너·홍보 문구·앱스토어형 카드는 두지 않는다.

## 2. 레이아웃과 내비게이션

- 데스크톱 우선 고정 셸: 좌측 사이드바 248px + 우측(헤더 64px + 콘텐츠). 기준 뷰포트
  1440×900, 최소 지원 폭 1024(그 아래 대응은 비범위).
- 사이드바: 상단 로고 블록(그라데이션 아이콘 + "OhMyMCP" + "MCP Test Dashboard"),
  내비 5항목, 하단에 서버 주소(`localhost:7357`, mono).
- **내비 라벨은 영어만 쓴다**: `Home`, `Runs`, `Generate`, `Cassettes`, `Repair`.
  해시 라우트는 `#/home`, `#/runs`(및 `#/runs/:id`), `#/generate`, `#/cassettes`,
  `#/repair/:id`. 활성 항목은 배경 필 + 굵기로 표시한다.
- 아이콘은 전부 인라인 SVG stroke(16px, stroke-width 2). 이모지 금지.
- 콘텐츠 본문의 문구는 한국어를 유지한다(영어화는 사이드바 라벨만).

## 3. 테마: 라이트·다크 모두 지원

- CSS 커스텀 프로퍼티로 토큰을 정의하고 Tailwind v4 `@theme`에 연결한다.
- 기본은 OS 설정(`prefers-color-scheme`)을 따르고, 헤더 우측 토글로 수동 전환한다.
  수동 선택은 `localStorage`에 저장하며 루트 요소의 `data-theme="light" | "dark"`
  속성으로 적용한다(속성이 없으면 OS 설정).
- **로그 패널은 테마와 무관하게 항상 다크다.** 터미널 재현 영역이라 라이트 변형을 만들지
  않는다. ANSI 색이 두 테마에서 달라지면 같은 실패가 다르게 보이므로 고정한다.

| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--bg` | `#f7f7f8` | `#131318` | 페이지 배경 |
| `--surface` | `#ffffff` | `#1b1b21` | 카드·사이드바·헤더 |
| `--border` | `#e8e8ec` | `#2a2a33` | 카드·구분선 |
| `--border-subtle` | `#f0f0f3` | `#232329` | 행 구분선 |
| `--text` | `#18181b` | `#e4e4e7` | 본문 |
| `--text-muted` | `#71717a` | `#8b8b96` | 보조 문구 |
| `--accent` | `#6d28d9` | `#8b5cf6` | 주 버튼·활성·링크 |
| `--accent-soft` | `#faf8ff` | `#241a35` | 선택 배경 |
| `--accent-border` | `#ddd6fe` | `#4c3575` | 선택 테두리 |

상태 색(뱃지·점). 다크에서는 같은 계열의 밝은 톤을 쓴다.

| 상태 | 라이트 fg / bg | 다크 fg / bg |
|---|---|---|
| `running` | `#2563eb` / `#eff6ff` | `#60a5fa` / `#172036` |
| `waiting-input` | `#d97706` / `#fffbeb` | `#fbbf24` / `#2c2410` |
| `done` | `#16a34a` / `#f0fdf4` | `#4ade80` / `#122618` |
| `failed` | `#dc2626` / `#fef2f2` | `#f87171` / `#2b1518` |

로그 패널 본문(테마 공통 고정): 배경 `#0d0d12`, 헤더 스트립 `#16161c`, 기본 글자
`#d4d4d8`, 보조 `#8b8b96`. `ansi-*` 클래스 색: 31(빨강) `#f87171`, 32(초록) `#4ade80`,
33(노랑) `#facc15`, 36(시안) `#22d3ee`, 90(회색) `#8b8b96`, 1(굵게) `font-weight:700`.
색 정의는 web 전역 CSS가 소유한다(서버 `ansiToHtml`은 클래스만 붙인다. 구현계획 T4).

**다크 모드에서 터미널 구분 장치.** 다크 모드는 UI 전체가 어두워져 로그 패널이 주변 카드와
섞인다. 본문 색은 위 고정값을 유지하고, 구분은 패널의 둘레 장치가 만든다.

- 배경 단차: 패널 본문 `#0d0d12`는 다크 페이지 `#131318`·표면 `#1b1b21`보다 두 단계
  어둡게 고정한다(가장 어두운 면 = 터미널이라는 위계).
- 테두리: 라이트 `#26262f`, 다크 `#34343f`. 다크에서는 주변 `--border`(`#2a2a33`)보다
  밝은 선이 되어 윤곽이 남는다(토큰 `--terminal-border`로 분리).
- 헤더 스트립 `#16161c` + "터미널 출력" 라벨은 양 테마 공통. 카드와 달리 패널임을
  머리에서 먼저 알린다.
- 다크에서만 패널에 `box-shadow: inset 0 1px 0 rgba(255,255,255,0.04)`를 얹어
  표면 카드와 재질을 다르게 한다. 그 외 장식(글로우·그라데이션)은 금지.

타이포: 본문 `system-ui` 스택, 코드·경로·터미널 `ui-monospace` 스택. 웹폰트를 쓰지
않는다(오프라인 로컬 도구, 외부 요청 0).

## 4. 공용 컴포넌트

- **상태 뱃지**: 점 + 라벨 필. 라벨은 `실행 중`, `입력 대기`, `완료 · exit 0`,
  `실패 · exit N`. `RunStatus` 4값과 1:1.
- **flow 칩**: `test`/`generate`/`replay`/`repair`를 mono 소문자 그대로 회색 필에.
- **버튼**: primary(accent 채움), outline(테두리), 위험 동작 없음(삭제도 outline).
- **로그 패널**: 헤더(라벨 + 우측 상태/카운트) + 본문(mono 13px, line-height 1.85,
  stdout/stderr 이벤트 순서 그대로, 줄바꿈·공백 보존).
- **QuestionPanel**: 로그 패널 하단 또는 별도 카드. "질문" 뱃지 + message +
  kind별 컨트롤. `input`은 텍스트박스+제출, `choose`는 선택지 버튼 나열(값 그대로 전송),
  `confirm`은 예(`"y"`)/아니오(`"n"`). 응답 후 패널은 사라지고 스트림이 이어진다.
- **스텝 인디케이터**(Generate 전용): 원형 번호 + 라벨 + 연결선. 완료 단계는 체크,
  현재는 accent 채움, 미래는 테두리만.

## 5. 화면 사양

### 5-1. Home (`#/home`)

2열 카드. 좌측 "테스트 스위트"(`GET /api/suites`): 행마다 경로(mono)·부가 정보·
`실행` 버튼. 실행 클릭 시 실행 옵션(`--command` 입력값)을 물은 뒤
`POST /api/runs {flow:"test"}` 하고 `#/runs/:id`로 이동. 우측 "최근 실행"
(`GET /api/runs`): flow 칩 + 대상 + 상태 뱃지, 행 클릭 시 `#/runs/:id`.

### 5-2. RunView (`#/runs/:id`)

헤더: 뒤로 링크, flow 칩, 대상 경로, 상태 뱃지, 상태가 `failed`면 `repair 시작`
버튼(`POST /api/runs {flow:"repair", ...}`). 본문: 로그 패널 전면.
`pendingQuestion`이 있으면 QuestionPanel 표시. 이벤트는 수신 순서 그대로 렌더한다.

### 5-3. Generate (`#/generate`) : 4단계 마법사

한 화면씩 진행(가운데 카드 800px, 상단 스텝 인디케이터, 하단 이전/다음).
단계 상태는 프론트 메모리에만 있고, 마지막 단계의 `생성 시작`에서 argv를 조립해
`POST /api/runs {flow:"generate"}` 후 RunView와 동일한 스트림 화면으로 전환한다
(dry-run 승인 질문이 이 통로로 온다).

| 단계 | 컨트롤 | CLI 대응 |
|---|---|---|
| 1. 테스트할 서버 | 실행 방법 세그먼트(Node 스크립트/npx 패키지/Python/직접 입력), 서버 스크립트 선택(프로젝트 스캔 후보 + 직접 입력), 서버 인자 칩 목록, "실행될 명령" 확인줄 | `--command`, `--arg`(반복) |
| 2. 만들어질 스위트 | 스위트 ID, 스위트 이름, 저장 위치(스크립트 기준 자동 제안), 덮어쓰기 체크 | `--suite-id`, `--name`, `--out`, `--force` |
| 3. 생성 방식 | "AI가 테스트 케이스 작성" vs "기본 골격만" 라디오 카드, AI 도구 선택(claude/codex), 모델(선택), "저장 전에 시험 실행으로 검증" 토글(기본 켬), "실패한 입력값 자동 교정" 토글(기본 켬) | `--baseline-only`, `--provider`, `--model`, 끄면 `--no-dry-run`, 끄면 `--no-repair` |
| 4. 녹화와 확인 | 카세트 저장 위치(선택, 비우면 녹화 없음), 시험 실행 전 초기화 명령(선택), 재녹화 체크, **선택 요약 + 실행될 CLI 명령 전문**, `생성 시작` | `--cassette`, `--reset-cmd`, `--record` |

폼 검증은 `parseGenerateCommand`의 규칙을 UI 단계에서 선반영한다(서버 검증이 최종).

- 필수 미입력 시 다음/시작 버튼 비활성 + 사유 문구.
- 시험 실행 토글을 끄면 카세트·초기화 명령 입력을 비활성화한다
  (`--no-dry-run`은 `--cassette`·`--reset-cmd`와 함께 쓸 수 없다).
- 시험 실행과 자동 교정을 동시에 끌 수 없다.
- 재녹화 체크는 카세트 경로가 있을 때만 활성(`--record`는 `--cassette` 전제).

### 5-4. Cassettes (`#/cassettes`)

좌측 목록(300px, `GET /api/cassettes`) + 우측 상세. 상세 헤더: 경로 + `삭제`/`저장`/
`replay 실행` 버튼. 본문: 상호작용 타임라인(번호 + method 칩 + 요약 한 줄, 선택 시 하단
JSON textarea로 편집), `PUT` 결과가 `saved:false`면 경고 배너 "다른 곳에서 파일이
바뀌었습니다. 새로고침 후 다시 시도하세요."를 띄우고 덮어쓰지 않는다. replay 버튼은
`POST /api/runs {flow:"replay", argv:[<스위트>, "--cassette", <카세트>]}`.

### 5-5. RepairReview (`#/repair/:id`)

RunView와 같은 스트림 화면의 repair 변형. 로그 패널이 실패 문장과 제안 diff를 stdout
텍스트 그대로 보여주고(±행 배경만 붉게/푸르게, 별도 diff 파서 없음), 하단 QuestionPanel
카드가 승인/거부를 담당한다.

## 6. 비범위

- 모바일·태블릿 레이아웃, 1024px 미만 대응
- 애니메이션·트랜지션(테마 전환 포함), 접근성 심화(스크린리더 최적화)
- 로그 검색·필터, 가상 스크롤(이벤트 수천 개 규모는 상정하지 않음)
- 캔버스 목업의 한국어 사이드바·라이트 전용 상태를 갱신하는 일(목업은 참고용으로 동결)

## 7. 임의 판단 기록

- 다크 모드 적용 방식(`data-theme` + OS 기본 + localStorage)과 토큰 값은 목업 팔레트에서
  파생해 이 문서에서 확정했다. 색상 세부는 구현 중 미세 조정 가능하되 토큰 이름과 매핑
  구조는 유지한다.
- 스텝 상태를 URL에 싣지 않는다(`#/generate` 하나). 새로고침 시 1단계로 돌아가는 것을
  허용한다. 서버 재시작·영속화가 비범위인 도구 성격과 맞춘 단순화다.
- 로그 패널 배경을 목업의 `#16161e`에서 `#0d0d12`로 낮췄다. 다크 모드에서 표면 카드와
  구분되는 단차를 만들기 위해서다(위 "다크 모드에서 터미널 구분 장치"). 캡처 PNG는
  목업 시점 값이라 이 차이가 반영돼 있지 않다.
