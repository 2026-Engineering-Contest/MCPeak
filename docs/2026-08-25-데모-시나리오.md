### A-3. 목으로 실행, 그리고 Claude 에 붙이기

1. 홈 → `packages/cli/tests/fixtures/mock-suite.json` 행 `실행`.
2. 카드 `mcpeak-mock` 선택. 인자 칩이 `packages/mock/dist/stdio.mjs` 로 바뀐다.
3. `인자 하나씩 추가` 에 `packages/cli/tests/fixtures/mock-definition.json` 을 넣고 `추가`.
   칩이 두 개가 된다. **끝에 공백이 붙지 않게** 넣는다. 미리보기에서 인자가 따옴표로 감싸이면
   공백이 딸려 온 것이다(§C).
4. `실행 시작` → `완료 · exit 0`, `4 passed (4 total)`.

이 실행은 `mcpeak test` 한 번이고, 서버 자리에 `mcpeak-mock` 이 온 것이다. 러너가 목을 자식으로
띄우고 끝나면 내린다. 살아 있는 서비스를 세워 두는 게 아니다. 대사는 "목 서버 띄웠다" 가 아니라
"서버 없이 명세를 먼저 검증했다". 넷째 케이스 `unmatched-args-miss` 가 핵심이다. 정의에 없는
`add(9, 9)` 는 도구 오류가 된다. 목이 아무거나 OK 하지 않는다는 증거.

이어서 터미널. Claude Code 에 같은 목이 미리 등록돼 있다(§0).

1. `claude` → `/mcp`. `mcpeak-mock ✔ connected`, 툴 2개.
2. "서울 날씨 알려줘" → `get_weather` 호출, 응답 `{ city: "서울", tempC: 21 }`.
   정의 파일에 적은 값 그대로다.

질문은 정의 범위 안에서만 한다. `get_weather` 는 도시와 무관하게 서울 값이 나오고(`args` 생략
응답), `add` 는 `1+2` 만 성공한다.

5. 와이파이를 다시 켠다.

재생은 localhost 코디네이터를 거친다. 와이파이를 꺼도 loopback 은 살아 있으니 괜찮지만, 방화벽
앱으로 "모든 연결 차단" 하는 연출은 하지 않는다. loopback 이 막히면 `Coordinator에 연결하지
못했습니다` 로 2건이 실패한다. 2026-08-25 확인은 `sandbox-exec` 로 외부 IP 만 막고 돌린 것이다.
같은 조건에서 세션 없이 돌리면 `4 passed, 2 failed` (`fetch failed`) 가 나와 차단은 실제였다.
2회 실행 출력이 바이트 단위로 같았다.

### B-5. Repair

1. 홈 → `packages/cli/tests/fixtures/weather-suite-failing.json` 행 `실행`, 서버는
   `example-weather-server`, `실행 시작`. `실패 · exit 1`.
2. `repair 시작`. 폼에 모델 `sonnet`, `시작`.
3. Repair 화면. `보내시겠습니까?` → `예`.

### B-6. 외부 호출 녹화·재생 (CLI)

서버는 `examples/live-weather-server` (Open-Meteo·Frankfurter 를 `fetch` 로 부른다).

```bash
# 녹화. 실제 API 를 부른다
$MCPEAK test examples/live-weather-server/server.suite.json \
  --command node --arg examples/live-weather-server/server.mjs \

기대 마지막 줄:

```

$MCPEAK test examples/live-weather-server/server.suite.json \

기대 마지막 줄:

```
6 passed  (6 total)
→ 녹화된 외부 호출 5건을 재생했습니다: .mcpeak/live-weather.session.json (2026-08-25 07:25:01 UTC 녹화)
```

대사: 서버는 진짜로 뜨고, 서버가 밖에 부르는 호출만 녹화본에서 답한다. 같은 입력 같은 출력.
네트워크 없이 CI 에서 돈다.

와이파이 끄고 재생하는 장면은 **오늘 확인 안 됨** (녹화·재생은 네트워크 켠 채로 확인). 리허설에서
한 번 본다. 재생은 설계상 네트워크를 안 타지만(ADR-0057·0061) 눈으로 보고 넣는다.

## C. 막혔을 때

| 상황 | 대처 |
|---|---|
| Generate 1단계 첫 후보가 `.claude/worktrees/...` | worktree 가 남아 있다. §0 첫 항목 |
| AI 질문이 안 오고 `입력 대기` 만 | `claude` CLI 로그인 풀림. 백업 Run 으로 |
| `get_forecast` 가 `fetch failed` | 망 문제. 미리 만든 `.mcpeak/live-weather.session.json` 으로 재생만 보여준다 |
| Open-Meteo 가 도시를 못 찾음 | `서울` 은 못 찾는다. `부산`·`Seoul` 만 쓴다 |
| 로그가 안 보임 | 패널 자동 스크롤 없음. 마우스로 내린다 |
| Repair `시작` 이 비활성 | 모델 미입력. `sonnet` |
| 목 실행이 `목 정의 파일을 읽을 수 없습니다 ... .json '` (경로 끝에 공백) | 인자 칩에 공백이 딸려 들어감. 폼이 trim 을 안 한다. 칩 `×` 로 지우고 공백 없이 다시 `추가`. 미리보기의 따옴표가 사라지면 됨 |
| 녹화가 `세션 파일에 이미 녹화가 있습니다` | 이전 테이크 파일. `rm .mcpeak/demo-live.session.json` 뒤 재실행 |
| 재생이 `Coordinator에 연결하지 못했습니다` | loopback 이 막힘. 방화벽 앱을 끈다. 와이파이 끄기는 무관 |
| 재생인데 `fetch failed` | 세션이 안 붙음. 세그먼트가 `녹화본 재생` 인지, 경로가 녹화 때와 같은지 |
| 서버 카드를 눌렀는데 다른 카드가 선택됨 | 라디오 원이 아니라 카드 본문을 누른다 |
| `/mcp` 에 `mcpeak-mock` 이 없음 | §0 등록이 다른 디렉터리에서 됐다(`-s local` 은 프로젝트 단위). 루트에서 다시 `claude mcp add` |
| 통과 Run 끝에 `거절을 기대한 케이스 N건은 거절 근거를 확인하지 못했습니다` | 오류 아님. `isError` 만 보고 통과시켰고 거절 이유는 generate 승인 단계 몫. 질문 오면 그렇게 답한다 |

## D. 이 시나리오에서 말하지 않는 것

- AI 사전보완이 `미채택 2 (baseline 값이 이미 통과)` 라 한 직후 시험 실행에서 그 값이 실패하는
  장면이 B-4 에 있다. 결국 교정돼 저장되므로 흐름은 되지만, 질문이 들어오면 "사전보완은 값 형식
  검사, 시험 실행은 실제 응답 검사" 로 답한다. generate 패키지 몫이라 이번 PR 범위 밖.
- 검토 메뉴 버튼이 영문 그대로인 것, 로그 자동 스크롤이 없는 것, 서버 인자 칩이 앞뒤 공백을
  trim 하지 않는 것은 dashboard 후속 PR 대상이다.
- 대시보드가 목을 **살아 있는 서비스로** 띄워 두고 Claude 가 거기 붙는 그림은 지금 구조로 안
  된다. stdio 목은 클라이언트가 프로세스를 소유한다. 그게 되려면 HTTP 목(`createMockServer`)을
  띄우는 자리가 필요한데 CLI 에도 대시보드에도 없다. 「목 띄우기」 화면(정의 파일 → HTTP 목 기동
  → `claude mcp add --transport http` 한 줄 → 실시간 호출 로그)은 후속 기능이며 `cli` 에
  `mock serve` 명령이 먼저 있어야 한다. 질문이 오면 "지금은 `claude mcp add` 로 붙인다" 로 답한다.
