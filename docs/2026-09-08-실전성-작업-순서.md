# 실전성 이슈 우선순위 (#385 ~ #407)

2026-09-09 개정. 기준 커밋 `6da819f`. 1번 #389 는 PR #423 으로, 2번 #407 은 PR #435 로 끝났다.

**개정 기준이 바뀌었다.** 처음 판은 "잡는 범위를 넓히는 순서" 였다. 남은 기간이 한 주라 이번 판은
**"대형 공개 서버(notion · git · filesystem 류)에 실제로 붙였을 때 화면에서 터지는 것" 을 먼저** 로
바꿨다. 근거는 `docs/adoption.md` §1.4 · §1.6 의 실측이다. 거기서 관측된 데모 위험은 넷이다.

| 관측 | 어디서 | 화면에서 어떻게 보이나 |
|---|---|---|
| `"example"` 자리값이 정상 케이스를 실패시킴 | time 2건, filesystem 8건. 손으로 값 11개 고쳐야 녹색 | 서버는 멀쩡한데 도구가 깨졌다고 한다 |
| 상태 바꾸는 툴이 실제로 실행됨 | `git_commit` · `write_file` | notion 이면 페이지가 생긴다. 두 번 돌리면 결과가 다르다 |
| 서버가 준 이유를 우리가 버림 | server-everything 의 `taskSupport` 거절 | 원인 없는 빨강 4건 |
| 툴 건너뜀 뒤 커버리지 숫자가 어긋남 | desktop-commander 의 배열 `type` | 화면 숫자가 틀림 |

첫째가 가장 크다. 서드파티 서버에는 `.meta({ examples })` 같은 유효값 선언이 없어서 zod-notes-server
처럼 처음부터 통과하지 않는다. 그것을 풀라고 있는 것이 AI 사전보완과 repair 이고, #397 과 #385 가
정확히 그 둘의 결함이다. 그래서 순서가 바뀐다.
