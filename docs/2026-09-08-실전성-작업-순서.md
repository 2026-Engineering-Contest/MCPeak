# 실전성 이슈 우선순위 (#385 ~ #407)

2026-09-08 평가 기준. 위에서부터 순서대로 한다. 기준 커밋 `c0a1934`.

1. **#389** 실제 스키마 키워드(`pattern`·`anyOf`·`$ref`·`additionalProperties`) 지원
   zod·pydantic 서버에서 툴이 통째로 스킵되는 원인. 이게 막히면 나머지가 돌 툴이 없다.
2. **#407** zod 기반 예제 서버 + E2E
   #389 회귀 방지. "아직 미지원" 단언 E2E 는 #389 와 동시에 시작해도 된다.
3. **#397** `--no-dry-run` 에서도 사전보완이 툴을 호출
   데이터 변경 도구에 부작용. 안전 문제라 기능보다 앞.
4. **#387** 범위 위반이 하한만 생성해 상한 누락을 놓침
   한 파일 수정. `BASELINE_POLICY_VERSION` 을 #389 와 같이 올려 재승인 한 번으로.
5. **#406** `outputSchema` 를 명세에 보존해 정상 케이스에 출력 계약 단언
   AI 없이 결정론적으로 잡는 범위를 넓히는 첫 수. core → runner → generate 순.
6. **#386** 정상 케이스에 응답 내용 검증 생성
   계산 오답을 잡는 유일한 길. #406 위에 얹는다. ADR 먼저.
7. **#388** 중첩 객체·배열 원소의 위반 케이스
8. **#385** 미실행 명세를 `specApproved: true` 로 오판해 올바른 명세 수정 제안을 버림
   repair 줄기의 첫 단계. 프롬프트 전제부터 고쳐야 뒤가 의미 있다.
9. **#393** repair 번들에 툴 계약·소스 범위·케이스별 근거
   AI 가 지금은 툴 선언(`tools: []`)도 소스도 못 본다.
10. **#394** 원인 후보를 검토 가능한 패치로
    "고치는 로직" 의 실체. #393 이 소스 범위를 실어야 가능. ADR 먼저.
11. **#405** 툴 건너뛴 뒤 커버리지 재계산 (#391 흡수)
12. **#392** `--json` stdout 에 안내문이 섞여 CI 파싱 실패
13. **#402** 알려진 `format` 이 길이 제약을 무시
14. **#401** enum 두 번째 값·boolean false·선택 필드 분기
15. **#399** 사전보완·최종 재검증을 같은 초기 상태에서 (#398 흡수)
16. **#395** 정상·결함 표본으로 탐지율 기준선 기록
    1단계는 지금 가능. #389·#386 전후 비교용이라 1번 전에 시작해도 됨.
17. **#404** generate README 지원 범위
18. **#403** cli README 전송·문법·repair 안내
19. **#390** 실재 값 픽스처 계약 (선택)

닫음(`not_planned`): #396 상태 기반 시나리오, #400 거절 근거 CI 정책. 6번 뒤에 재검토.
