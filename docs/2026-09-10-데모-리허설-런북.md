`docs/2026-09-08-실전성-작업-순서.md` 의 0번이다. 시연할 서버 셋을 끝까지 돌리고, 명령과 값
교정과 샌드박스 초기화와 기대 출력을 여기에 남긴다.

- 실행일: 2026-09-10
- 기준 커밋: `ca3cce1`
- 빌드: `pnpm build --force` 로 `Cached: 0 cached, 7 total` 확인 후 `packages/cli/dist/cli.mjs` 를 직접 실행
- 정책 버전: `schema-baseline-v3`, repair 번들 형식: 2

아래 명령의 `$R` 은 리허설 작업 디렉터리다. 저장소 밖에 둔다. 샌드박스와 명세가 전부 그 아래
생긴다.

```sh

mkdir -p "$R"
```

## 공통으로 알아야 할 것

### 값을 손으로 고치면 재승인이 필요하고, 안내문대로 하면 교정이 날아간다

실서버 명세는 `"example"` 자리값 때문에 처음부터 통과하지 않는다. 값을 고치면 `test` 가 이렇게
찍는다.

```
명세: 현재 명세와 저장된 approval.fingerprint가 불일치함
  → 승인 331a5017af0d…   현재 b08dfb31582c…
  → 승인받지 않은 현재 명세로 모든 테스트가 통과했습니다.
  → 의도한 변경이면 같은 설정으로 mcpeak generate 를 다시 실행하고 --force 로 재승인하세요.
```

**마지막 줄을 그대로 따르면 안 된다.** `generate --force` 는 출력 파일을 덮어쓰는 옵션이라
(`packages/cli/src/generate-command.ts:84`) 방금 고친 값이 전부 `"example"` 로 돌아간다. 손으로
고친 명세를 재승인하는 CLI 경로는 없다. 리허설에서는 지문을 다시 찍어 넣었다.

```sh
node -e "
import('./packages/runner/dist/index.mjs').then(async (m) => {
  const fs = await import('node:fs');
  const p = process.argv[1];
  const s = JSON.parse(fs.readFileSync(p, 'utf8'));
  delete s.approval;
  s.approval = { fingerprint: m.suiteFingerprint(s) };
  fs.writeFileSync(p, JSON.stringify(s, null, 2));
});
" "$R/<명세>.json"
```

지문이 맞으면 `명세:` 줄 자체가 화면에서 사라진다. 데모 화면에 노란 줄을 남기지 않으려면 이
단계를 거친다. 다만 이렇게 찍은 지문에는 `approval.cases` 가 없으므로, `repair` 는 그 명세를
`승인 지문 일치 · 실행 기록 없음` 으로 본다(ADR-0090). 그것이 맞는 판정이다.

### `--determinism` 과 `--reset-cmd` 를 함께 쓴다

`--determinism` 만 쓰면 "2회 결과가 같았다" 까지고, `--reset-cmd` 를 붙여야 결정론성 판정이
된다. 초기화 스크립트는 셸을 거치지 않으므로 파이프나 `&&` 를 쓸 수 없다. 스크립트 파일로
만들어 경로를 준다.

**초기화 스크립트 자신이 결정론적이어야 한다.** git 샌드박스를 고정 날짜 없이 만들었더니 매
초기화마다 커밋 SHA 가 달라져 차이 3건이 나왔다. 원인은 서버가 아니라 초기화 쪽이었다.

### 서버에 환경변수를 주려면 `env` 로 감싼다

`test` 에는 자식 프로세스 환경변수를 주는 옵션이 없다. `--command env` 로 감싸면 된다.

```sh
--command env --arg "KEY=value" --arg npx --arg -y --arg <패키지>
```

## 1. `@modelcontextprotocol/server-memory`

**로드맵 표의 "상태 없음" 은 틀렸다.** 이 서버는 지식 그래프를 파일에 쓴다. 경로를 지정하지
않으면 `npx` 캐시 안의 패키지 디렉터리에 쓴다.

```
~/.npm/_npx/<해시>/node_modules/@modelcontextprotocol/server-memory/dist/memory.jsonl
```

처음 이 파일을 확인했을 때 이전 데모가 남긴 항목이 들어 있었고, 리허설 실행이 그 파일을 다시
썼다. 25/25 가 안정적으로 나온 이유는 상태가 없어서가 아니라 생성 케이스와 삭제 케이스가 같은
이름(`example`)을 써서 서로 상쇄하고, 조회 케이스의 단언이 `isError` 뿐이라 내용에 둔감하기
때문이다. **`MEMORY_FILE_PATH` 로 샌드박스를 지정한다.**

### 초기화

```sh
cat > "$R/reset-memory.sh" <<EOF

: > "$R/mem-sandbox.jsonl"
EOF
chmod +x "$R/reset-memory.sh"
```

### 생성

```sh
node packages/cli/dist/cli.mjs generate --suite-id memory --name memory \
```

## 2. `mcp-server-git`

12툴 59축이 전부 생성된다. #389(PR #423) 전에 `anyOf` 로 잃던 3툴이 살아 있다.

### 초기화

커밋 날짜를 고정하지 않으면 매번 SHA 가 달라진다.

```sh
cat > "$R/reset-git.sh" <<EOF
#!/bin/sh
set -e
export GIT_AUTHOR_DATE="2026-01-01T00:00:00+0000"
export GIT_COMMITTER_DATE="2026-01-01T00:00:00+0000"
S="$R/git-sandbox"

printf 'second\n' > b.txt

printf 'unstaged\n' >> a.txt

chmod +x "$R/reset-git.sh"
```

### 남는 차이 1건의 원인

`git_show` 가 파이썬 객체의 `repr` 을 그대로 응답에 싣는다.

```python
# mcp_server_git/server.py:234
f"Date: {commit.authored_datetime!r}\n"
```

`repr` 안에 `tzinfo=<git.objects.util.tzoffset object at 0x…>` 가 들어가고, 그 주소는 프로세스마다
다르다. **초기화로 없앨 수 없다.** 데모에서 이 서버에 `--determinism` 을 쓰면 이 1건은 반드시
보인다. 셋 중 하나를 고른다.

1. 화면에 띄우고 원인을 설명한다. 이 진단은 종료 코드를 바꾸지 않으므로 판정은 59/59 그대로다.
2. `git-show-success` 를 뺀 명세로 시연한다.
3. `mcp-server-git` 에는 `--determinism` 을 쓰지 않는다.

**1번을 권한다.** 서버가 단언 기준으로 쓸 수 없는 값을 싣고 있다는 사실을 우리 도구가 찾아낸
장면이고, 그것이 이 기능의 존재 이유다. 다만 아래 §알아 둘 것 의 화면 문제가 먼저 풀려야 한다.

`get_file_info` 가 `created` · `modified` · `accessed` 를 싣는데, 초기화가 파일을 다시 만들기

않다. 게다가 `edit_file` 케이스가 그 앞에서 `a.txt` 를 다시 써서 수정 시각도 실행 시각이 된다.
**초기화 방식으로 없앨 수 없다.** 화면에 원인 문장이 함께 나오므로 그대로 두고 설명한다.

## 알아 둘 것: 리허설에서 새로 나온 문제 넷

로드맵 A 의 남은 항목(#392 · #405 · #402)과 별개로 이번에 관측됐다.

### ① 결정론성 차이 화면이 차이를 보여주지 못한다 (#447 로 등록)

`git_show` 의 차이는 문자열 앞부분이 같고 뒤에서 갈린다. 화면은 값을 앞에서 고정 길이로
자르므로(`packages/runner/src/diagnostics.ts:215`, 상한 200자) 1회차와 2회차가 **글자 하나까지 같아 보인다.**

```
     1회차: "Commit: 'b587de1e…'\nAuthor: …\nDate: datetime.datetime(2026, 1, 1, 0, 0, tzinfo=<git.objects.util.tzoffset object at 0x…(총 233자)
     2회차: "Commit: 'b587de1e…'\nAuthor: …\nDate: datetime.datetime(2026, 1, 1, 0, 0, tzinfo=<git.objects.util.tzoffset object at 0x…(총 233자)
```

같은 두 값을 놓고 다르다고 말하는 화면이다. 심사자 앞에서 도구가 틀린 것처럼 보인다.
`--json` 의 `determinism.differences` 도 같은 잘린 문자열을 실으므로 CI 소비자도 원인을 알 수
없다. **차이가 나는 지점이 보이도록 잘라야 한다.**

### ② 손으로 고친 명세의 재승인 경로가 없고, 안내문은 교정을 지우는 명령을 시킨다 (미등록)

위 §공통 에 적었다. 실서버 적용은 값 교정이 전제이므로 이 경로는 예외가 아니라 기본 경로다.
