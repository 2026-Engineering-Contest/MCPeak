# 범위 밖 호출 관측이 런처 자신의 트래픽을 세는 것을 고친다 (2026-09-12)

관측: 이 문서 §1.2 의 context7 실측.
참조: `docs/2026-09-11-npx-런처-녹화-누락-설계.md` §8.2(예고한 자리),
ADR-0057(어댑터는 global fetch 까지만), ADR-0068(범위 밖 호출을 가로채지 않고 센다),
ADR-0095(설정 소비 시점과 단일 기록자).

기준 커밋 `0164d74`.

## 1. 배경

### 1.1 지금 코드가 하는 일

관측 사이드카는 재생에서만 돈다. `node:http` · `node:https` 로 나간 호출을
`diagnostics_channel` 로 세어 종료 시점에 파일 하나에 쓰고, Coordinator 가 그것을 읽어
요약의 `outOfScope` 로 싣는다(ADR-0068).

보고 경로는 환경변수로 간다. `bootstrap.mjs` 는 그 값을 읽자마자 지운다.

```js
delete process.env[ENV_OBSERVER_PATH];
```

지우는 이유는 보고 파일이 **하나**이기 때문이다. 여러 프로세스가 같은 경로에 쓰면
`writeFileSync` 가 덮어써서 마지막에 끝난 프로세스의 숫자만 남는다.

ADR-0095 는 설정 환경변수의 삭제를 첫 가로챈 호출 시점으로 미뤘지만, **이 관측 경로만은
로드 시점 삭제를 그대로 두었다.** 그 결정은 그 설계의 §3 비범위이자 §8.2 남은 갈래였다.

### 1.2 실측: 예고한 것보다 나쁘다

ADR-0095 를 머지한 뒤 `@upstash/context7-mcp` 로 확인했다. 실측 문서가 "키 불필요 + 외부 API +
전역 `fetch` + Node" 교집합의 유일한 서버로 꼽은 그 서버다.

같은 명세, 같은 녹화본으로 재생만 두 형태로 돌렸다.

| 실행 형태 | 재생 | 범위 밖 경고 |
|---|---|---|
| `npx -y @upstash/context7-mcp` | 2건, 10/10 통과 | **1건** |
| `node <캐시된 index.js>` (런처 없음) | 2건, 10/10 통과 | **없음** |

npx 경유는 2회 반복해도 같다. 그 1건은 서버가 부른 것이 아니라 **`npx` 자신의 레지스트리
트래픽**이다. 관측 사이드카가 런처 프로세스에 설치됐기 때문이다.

화면에는 이렇게 나온다.

```
경고: 범위 밖 호출 1건이 실제 네트워크로 나갔습니다.
→ 이 실행은 재현 가능하지 않습니다. 그 호출의 응답은 녹화본이 아니라 오늘의 것입니다.
→ 서버가 `node:http`·axios 등으로 부른 호출입니다. 재생하려면 `fetch` 로 바꾸거나,
  그 외부 의존을 `mcpeak mock` 으로 대신하세요.
```

### 1.3 왜 지금 고치나

ADR-0095 의 §8.2 는 이것을 "숫자만 틀린 채로 초록이 나온다" 로 적었다. 실제로는 그보다
나쁘다. **재현 가능한 재생에 "재현 가능하지 않습니다" 를 붙인다.** 그리고 그 자리가 하필
공개 서버의 표준 실행 경로다.

사용자가 할 일도 틀리게 지시한다. 화면은 서버 코드에서 `node:http` 나 axios 를 찾아 `fetch` 로
바꾸라고 말하는데, 그 서버는 이미 전역 `fetch` 만 쓴다. 찾을 것이 없다.

ADR-0095 전에는 이 경고를 볼 일이 없었다. 재생 자체가 성립하지 않았기 때문이다. 고치고 나서
비로소 드러난 자리다.

## 2. 목표와 완료 조건

**목표.** 관측이 세는 것을 이 세션의 기록자가 낸 호출로 좁힌다. 그러면서 ADR-0068 의
"부재는 0이 아니라 못 셌음" 을 유지한다.

| # | 완료 조건 | 판정 방법 |
|---|---|---|
| 1 | 런처를 거친 재생에서 런처 자신의 `node:http` 호출이 안 세어진다 | 신규 E2E. 런처가 호출을 내도 `outOfScope` 가 0이다 |
| 2 | 기록자가 낸 범위 밖 호출은 그대로 세어진다 | 신규 E2E. 서버가 `node:http` 로 부르면 그 수가 나온다 |
| 3 | 어댑터를 한 번도 안 쓴 재생에서도 센다 | 신규 E2E. 서버가 `node:http` 만 쓰는 경우 |
| 4 | 훅이 못 뛰면 여전히 "못 셌음" 이다 | 신규 유닛. 파일이 하나도 없으면 `undefined` |
| 5 | 기존 재생·관측 동작이 그대로다 | `pnpm test` 전량, `dist-external-e2e.mjs` |
| 6 | 빌드·테스트·타입체크·린트 | 통합 게이트 |

## 3. 비범위

- **녹화에서의 관측.** 사이드카는 재생 전용이고 그 범위를 넓히지 않는다(ADR-0068).
- **어댑터 범위를 `node:http` 로 넓히는 것.** ADR-0057 이 금지한 것이며 여기서 하는 것은
  가로채기가 아니라 세기다.
- **`outOfScope` 의 CLI 문안.** 숫자가 맞아지면 기존 문장이 그대로 참이 된다. `cli` 를
  건드리지 않는다.
- ADR-0095 가 남긴 다른 갈래(worker_threads, 소비 시점 누락).

## 4. 결정

### 4.1 결정 1: 보고를 프로세스마다 다른 파일로 나눈다

`ENV_OBSERVER_PATH`(파일)를 `ENV_OBSERVER_DIR`(디렉터리)로 바꾸고, **로드 시점에 지우지
않는다.** 자식 Node 프로세스마다 관측이 설치되고, 각자 자기 파일에 쓴다.

파일명은 `${process.pid}-${randomUUID()}.json` 이다. pid 만 쓰면 한 실행 안에서 프로세스가
끝나고 그 번호가 재사용될 때 덮어쓴다. 파일명은 세션에 저장되지 않으므로 난수가 들어가도
결정론성과 무관하다.

이것만으로는 런처 트래픽이 여전히 합계에 들어간다. 결정 2가 그것을 거른다.

### 4.2 결정 2: 기록자가 있으면 기록자의 것만 센다

자식은 자기 보고에 **자기가 이 세션의 기록자였는지**를 함께 적는다.

```json
{ "outOfScope": 3, "claimed": true }
```

`claimed` 는 그 프로세스의 Coordinator 호출이 **`WRITER_CONFLICT` 가 아닌 응답으로 한 번이라도
끝났는가**다. ADR-0095 가 만든 단일 기록자 판정이 인증 바로 뒤, body 파싱 앞에 있으므로,
`REPLAY_MISS` 로 끝난 호출도 기록자 자격의 증거다. 거절당한 쪽만 `false` 로 남는다.

런처는 `globalThis.fetch` 를 쓰지 않아 Coordinator 를 한 번도 부르지 않는다. 그래서 언제나
`claimed: false` 다.

Coordinator 의 집계 규칙은 두 줄이다.

| 상황 | 세는 것 |
|---|---|
| `claimed: true` 인 보고가 하나라도 있다 | **그 보고들만** 합친다 |
| 하나도 없다 | 읽을 수 있는 보고를 **전부** 합친다 |
| 보고 파일이 하나도 없다 | `undefined`. 못 셌음 |

둘째 줄이 이 설계의 요점이다. **어댑터를 한 번도 안 쓴 재생을 버리지 않기 위해서다.** 서버가
`node:http` 만 쓰면 `globalThis.fetch` 를 부르지 않아 아무도 기록자가 되지 않는다. 그런데 그
경우가 바로 ADR-0068 이 이 기능을 만든 이유다. 기록자만 세는 규칙을 무조건 적용하면 이 기능의
본래 용도가 죽는다.

그 갈래에서는 런처 트래픽이 다시 섞인다. 그래도 **오늘보다 나쁘지 않다.** 오늘은 런처 것만
세고 서버 것은 아예 못 센다. 바뀐 뒤에는 둘 다 센다. 정확하지는 않아도 방향이 맞고, 이 갈래는
런처와 `node:http`-전용 서버가 겹칠 때만 나온다.

### 4.3 결정 3: 관측은 여전히 재생에서만 설치한다

ADR-0068 의 범위를 그대로 둔다. 녹화에서는 범위 밖 호출이 실제로 나가는 것이 정상이고, 그
사실은 기존 0건 알림이 말한다.

### 4.4 버린 선택지

**(A) 기록자만 보고한다.** 결정 2에서 둘째 줄(폴백)을 뺀 것이다. 더 단순하다. 기각 이유는
`node:http` 전용 서버의 재생이 늘 "못 셌음" 이 되는 것이다. ADR-0068 이 만들어진 바로 그
경우를 이 기능이 놓치게 된다.

**(B) 런처를 식별해 제외한다.** `process.argv[1]` 을 보고 `npx-cli.js` 류면 관측을 설치하지
않는다. ADR-0095 가 같은 이유로 이미 기각했다. 목록 밖 런처에서 같은 결함이 재현되고 npm 내부
파일명에 의존하게 된다.

**(C) 경고 문구에 단서를 단다.** "런처를 거치면 런처 자신의 호출이 섞일 수 있습니다" 를
붙인다. 기각 이유는 그 문장이 사용자에게 할 일을 주지 못하는 것이다. 지금 화면은 "재현 가능하지
않습니다" 라고 단정하는데, 단서를 붙여도 사용자는 그 1건이 자기 서버 것인지 아닌지 알 방법이
없다.

**(D) 관측 경로도 첫 가로챈 호출에서 소비한다.** ADR-0095 의 설정 소비와 같은 방식이다. 기각
이유는 관측이 **첫 호출보다 앞에서 일어난 것도 세야** 하기 때문이다. 소비 시점까지 기다리면
서버 부팅 중에 나간 `node:http` 호출을 놓친다.

## 5. 계약 (전량)

### 5.1 환경변수 이름

`coordinator.ts` 의 상수 한 줄을 바꾼다. 값이 파일이 아니라 디렉터리가 되므로 이름도 바꾼다.

```ts
const ENV_OBSERVER_DIR = "MCPEAK_EXTERNAL_OBSERVER_DIR";
```

`bootstrap.mjs` 의 `ENV_OBSERVER_PATH` 도 같은 이름·같은 값으로 바꾼다. **두 자리가 같은
문자열이어야 하고, 어긋나면 관측이 조용히 꺼진다.** 그 실패는 테스트가 아니라 실사용에서만
드러나므로 §7.1 이 그것을 단언한다.

### 5.2 `child/out-of-scope-observer.mjs`

`reportPath` 를 `reportDir` 로 바꾸고 `isClaimed` 를 받는다. 세는 부분(`onRequest`,
`subscribe`)은 한 글자도 바꾸지 않는다.

```js
/**
 * @param {{ coordinatorHostHeader: string, reportDir: string, isClaimed: () => boolean }} options
 *   `coordinatorHostHeader` 는 `host:port` 형식이다. **이 필터가 없으면 안 된다** —
 *   어댑터 자신의 Coordinator 클라이언트가 `node:http` 를 쓰므로, 재생할 때마다 우리 왕복이
 *   "범위 밖 호출" 로 잡혀 매 실행이 거짓 경고를 낸다.
 *
 *   `reportDir` 는 **디렉터리**다. 프로세스마다 다른 파일을 쓴다. 예전에는 파일 하나였는데,
 *   중간에 Node 런처(`npx`)가 끼면 여럿이 같은 경로를 덮어써서 마지막에 끝난 프로세스의
 *   숫자만 남았다(ADR-0096).
 *
 *   `isClaimed` 는 **이 프로세스가 이 세션의 기록자였는가**를 묻는다. 종료 시점에 읽는다.
 *   설치 시점에는 아직 아무도 기록자가 아니다.
 */
export function installOutOfScopeObserver(options) {
```

`flush` 를 바꾼다.

```js
  // 파일명에 난수를 섞는다. pid 만 쓰면 한 실행 안에서 먼저 끝난 프로세스의 번호가 재사용될 때
  // 덮어쓴다. 이 이름은 세션에 저장되지 않으므로 난수여도 결정론성과 무관하다.
  const reportPath = join(options.reportDir, `${process.pid}-${randomUUID()}.json`);

  const flush = () => {
    try {
      writeFileSync(reportPath, JSON.stringify({ outOfScope: count, claimed: options.isClaimed() }));
    } catch {
      // 쓰기에 실패해도 서버 종료를 막지 않는다. 부모는 "못 셌음" 으로 읽는다.
    }
  };
```

`join` 은 `node:path`, `randomUUID` 는 `node:crypto` 에서 import 한다.

### 5.3 `child/fetch-adapter.mjs`

기록자 자격을 표시한다. Coordinator 호출이 `WRITER_CONFLICT` 가 아닌 결과로 끝나면 이
프로세스가 임자다.

`installFetchAdapter` 가 `onClaim` 을 받고, 아래 세 자리에서 부른다.

```js
  /**
   * **`WRITER_CONFLICT` 가 아닌 응답이면 임자다.** 단일 기록자 판정은 인증 바로 뒤, body 파싱
   * 앞에 있으므로(ADR-0095), `REPLAY_MISS` 로 끝난 호출도 "이 프로세스가 통과했다" 는 증거다.
   * 성공만 세면 미스가 난 실행의 관측이 통째로 폴백으로 떨어진다.
   */
  let claimed = false;
  const markClaimed = () => {
    if (claimed) return;
    claimed = true;
    options.onClaim();
  };
```

replay 갈래:

```js
    if (options.mode === "replay") {
      try {
        const hit = await client.lookup(normalized);
        markClaimed();
        return restoreHttpOutcome(hit.outcome);
      } catch (error) {
        if (error?.code !== "WRITER_CONFLICT") markClaimed();
        throw error;
      }
    }
```

record 갈래의 `client.begin` try/catch 에서는 성공 뒤와 `WRITER_CONFLICT` 아닌 실패 뒤에
`markClaimed()` 를 부른다. record 는 관측을 안 쓰지만 갈래를 하나만 두는 편이 다음 사람에게
읽힌다.

### 5.4 `child/bootstrap.mjs`

관측 경로를 **지우지 않는다.** 그 줄과 그 위 주석을 통째로 지운다. 설정 소비
(`consumeConfiguration`)에도 넣지 않는다. 결정 4.4(D) 가 이유다.

```js
const observerDir = process.env[ENV_OBSERVER_DIR];
```

설치부를 바꾼다.

```js
    // 관측은 어댑터보다 **먼저** 설치해야 부팅 중에 나간 호출도 센다. 다만 기록자 자격은
    // 어댑터가 정하므로, 둘이 같은 상자를 본다.
    const claim = { won: false };
    if (values.mode === "replay" && observerDir !== undefined) {
      installOutOfScopeObserver({
        coordinatorHostHeader: coordinatorUrl.host,
        reportDir: observerDir,
        isClaimed: () => claim.won,
      });
    }
    installFetchAdapter({
      mode: values.mode,
      url: coordinatorUrl.href,
      token: values.token,
      schemaVersion: 1,
      timeoutMs,
      writerId: randomUUID(),
      onFirstCall: consumeConfiguration,
      onClaim: () => {
        claim.won = true;
      },
    });
```

**설치 순서가 바뀐다.** 지금은 어댑터가 먼저다. 관측을 앞으로 옮기는 것은 어댑터 설치 자체가
`node:http` 를 부르지 않으므로 안전하고, 서버 부팅 중 호출을 놓치지 않게 한다.

### 5.5 `coordinator.ts` 의 사이드카

`ObserverSidecar` 의 `path` 를 `dir` 로 바꾸고 `read()` 를 집계로 바꾼다.

```ts
interface ObserverSidecar {
  readonly dir: string;
  read(): number | undefined;
}

function createObserverSidecar(): ObserverSidecar {
  const dir = mkdtempSync(join(tmpdir(), "mcpeak-external-observer-"));
  return {
    dir,
    read() {
      let names: string[];
      try {
        names = readdirSync(dir);
      } catch {
        return undefined;
      }
      try {
        // **기록자의 보고가 있으면 그것만 센다.** 중간에 낀 Node 런처(`npx`)도 이 디렉터리를
        // 물려받아 자기 `node:http` 트래픽을 보고하는데, 그것은 서버가 한 일이 아니다.
        // 런처는 Coordinator 를 한 번도 부르지 않으므로 언제나 `claimed: false` 다(ADR-0096).
        //
        // **기록자가 없으면 전부 센다.** 서버가 `node:http` 만 쓰면 어댑터를 한 번도 지나지
        // 않아 아무도 임자가 되지 않는데, 그 경우가 바로 이 기능이 만들어진 이유다
        // (ADR-0068). 기록자만 세는 규칙을 무조건 걸면 본래 용도가 죽는다.
        const reports = names.map((name) => readReport(join(dir, name)));
        const usable = reports.filter((one) => one !== undefined);
        if (usable.length === 0) return undefined;
        const claimed = usable.filter((one) => one.claimed);
        const counted = claimed.length > 0 ? claimed : usable;
        return counted.reduce((sum, one) => sum + one.outOfScope, 0);
      } finally {
        rmSync(dir, { recursive: true, force: true });
      }
    },
  };
}
```

보고 하나를 읽는 함수는 따로 둔다. 자식이 쓴 값이라 형식을 믿지 않는다.

```ts
/**
 * 자식이 쓴 보고 하나. 이상하면 **그 파일만** 버린다. 예전에는 파일이 하나라 이상하면 곧바로
 * "못 셌음" 이었는데, 이제 여럿이라 한 파일의 손상이 나머지를 버릴 이유가 되지 않는다.
 */
function readReport(path: string): { outOfScope: number; claimed: boolean } | undefined {
  let raw: string;
  try {
    raw = readFileSync(path, "utf8");
  } catch {
    return undefined;
  }
  try {
    const parsed: unknown = JSON.parse(raw);
    const value = (parsed as { outOfScope?: unknown })?.outOfScope;
    if (typeof value !== "number" || !Number.isSafeInteger(value) || value < 0) return undefined;
    return { outOfScope: value, claimed: (parsed as { claimed?: unknown })?.claimed === true };
  } catch {
    return undefined;
  }
}
```

`childEnvironment` 의 키 이름을 `ENV_OBSERVER_DIR` 로, 값을 `observer.dir` 로 바꾼다.
`readdirSync` 를 `node:fs` import 에 더한다.

`finish()` 의 계약은 그대로다. `observer.read()` 가 `undefined` 면 `outOfScope` 를 싣지 않고,
그것이 "못 셌음" 이다.

**픽스처 변경.** `fetch-mcp-server.mjs` 에 `http_ping` 툴을 더한다. `node:http` 로

| 케이스 | 실행 | 단언 |
|---|---|---|

케이스 1이 이 설계가 고치는 결함이다. 케이스 2와 3이 같은 숫자인 것이 요점이다. 런처가 있든

케이스 4는 폴백 갈래다. 아무도 기록자가 아니므로 런처 것이 섞인다. 그래서 `>= 2` 로 느슨하게
단언한다. **정확한 값을 단언하지 않는 것이 의도다.** 이 갈래는 정확하지 않다고 §4.2 가 적었고,
테스트가 그 부정확을 고정하면 나중에 고칠 때 테스트가 방해한다.

## 8. 위험

### 8.1 폴백 갈래는 여전히 부정확하다

`node:http` 전용 서버를 런처로 띄운 재생에서는 런처 트래픽이 섞인다(§4.2 셋째 줄).
오늘보다 나쁘지는 않다. 오늘은 런처 것만 세고 서버 것은 아예 못 센다.

이 갈래를 정확하게 만들려면 "누가 서버인가" 를 `globalThis.fetch` 사용 말고 다른 신호로
알아야 하는데, 그 신호가 없다. `node:http` 전용 서버는 우리 어댑터를 한 번도 지나지 않으므로
우리에게 보이지 않는다.

### 8.2 종료 순서

런처는 자식보다 늦게 끝난다. 두 프로세스의 `exit` 훅이 각자 자기 파일에 쓰므로 경합이 없다.
Coordinator 의 `read()` 는 `finish()` 안에서 도는데, 그 시점에 자식들은 이미 끝나 있다
(호출자가 실행을 마친 뒤 부른다). 지금 코드의 주석이 그 전제를 이미 적어 뒀고 이 변경이
그것을 바꾸지 않는다.

다만 **런처가 자식보다 먼저 죽는 경우**(자식을 detach 했거나 런처가 죽임을 당한 경우)에는
자식의 파일이 늦게 생길 수 있다. 그때는 그 보고가 빠지고 숫자가 작아진다. 오늘도 같은 성질이라
새 위험은 아니다.

### 8.3 디렉터리 정리

`read()` 는 `finally` 에서 디렉터리를 지운다. `finish()` 를 두 번 부르면 두 번째는 디렉터리가
없어 `undefined` 다. `finish()` 가 `finishPromise` 로 한 번만 도는 구조라 그 일은 없지만,
`read()` 자체는 그 성질을 가진다. §7.3 의 마지막 줄이 그것을 고정한다.
