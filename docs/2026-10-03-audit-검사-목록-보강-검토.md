# audit 검사 목록 보강 검토: 사고 사례·논문 대조 (2026-10-03)

`docs/2026-10-03-analyze-로드맵.md` 단계 1·2 의 검사 목록(A 설명, B 스키마, C 프로토콜, D 표면 드리프트,
E 비밀 카나리, F 행위 관측)이 실제 사고와 연구가 보고한 공격을 얼마나 덮는지 대조했다. 결론은
**"설명문 정규식만으로는 사고의 2할도 못 잡는다. 전 필드 검사, 응답 검사, 실행 명령 검사, 행위 관측이
본체다."** 아래에 근거와 추가·수정 항목을 적는다.

## 1. 사고 사례를 원인별로 나누면

2025-03 부터 2026-04 까지 공개된 사고 50여 건(vulnerablemcp.info, authzed 타임라인)을 원인으로 묶었다.

## 2. 연구가 말하는 정적 검사의 한계

- **CyberArk "Poison Everywhere"(2025-07)**: 설명뿐 아니라 `title`, 파라미터 이름, `enum`, `default`,
  `examples`, `required` 배열, 비표준 추가 필드, 중첩 설명 **모든 문자열 필드**에서 주입이 성공했다.
  우리 A 는 `description` 과 파라미터 설명만 본다.
- **현실적 중독 벤치마크(arXiv 2605.24069)**: 패러프레이즈, 동형 문자(homoglyph), base64, 비영어 문장으로
  바꾸면 키워드 필터를 그대로 통과한다. 일부 스캐너는 도구 **결과**, `title`/`enum`, 중첩 속성, 도구
  **이름**을 전혀 보지 않는다.
- **MCPTox(AAAI 2026)**: 실서버 45개, 353개 도구에 1,312개 중독 사례. 모델의 거절율 최대 2.8%. 모델
  정렬은 방어가 아니다. 공격 세 유형: 명시 트리거 기능 하이재킹(P1), 암묵 트리거 기능 하이재킹(P2),
  암묵 트리거 **파라미터 변조**(P3). P2·P3 는 "ignore previous instructions" 류 문형이 없다.
- **Connor(arXiv 2604.01905)**: 마켓플레이스 1,672개 서버에서 실물 악성 2개. 설명 정적 분석이 놓치는 것은
  여러 구성요소에 분산된 공격, 응답이 다음 호출을 조종하는 연쇄, 특정 인자 조합에서만 나타나는 행위.
  **실행 설정의 셸 명령 분석 + 실행 궤적 추적**으로 F1 94.6%.
- **MCP-38 분류(arXiv 2603.18063)**: 주입(A), 악성 행위(C), 정보 노출(D), DoS(E) 는 **실행 관측으로만**
  탐지된다. 인증·무결성·프로토콜(B·F·G)만 설치 전 메타데이터로 잡힌다. Docker 층을 미루면 안 되는 근거다.
- **SandScope(arXiv 2601.01241)**: 환경변수·파일 내용·입력 바이트가 출력에 나타나는 "출처→싱크 증인" 을
  **원문, 구분자 정규화형, base64·hex·ROT13 디코딩형**으로 대조. 정밀도 1.0, 재현율 0.889. 암호화·요약
  같은 변형은 못 잡는다고 명시. "증인이 없다는 것은 흐름이 없다는 증명이 아니다."
- **과권한 감사(arXiv 2603.21641)**: 선언한 주석·설명과 실제 파일·네트워크 도달 범위가 어긋나는 서버가
  다수. 선언 대 실제 대조가 검사 축이다.

## 3. 추가할 검사

### 3.1 A 설명 검사의 적용 범위와 정규화를 바꾼다 (Docker 불필요)

- **`desc/*` 규칙을 도구 객체의 모든 문자열에 적용한다.** `name`, `title`, `description`, 파라미터 이름,
  파라미터 설명, `enum`, `default`, `examples`, `const`, `required`, 비표준 키의 값, 중첩 전 깊이. 발견
  위치를 JSON 경로로 보고한다. 서버 `instructions`, `prompts/list` 의 설명과 메시지, `resources/list` 의
  이름·설명도 같은 규칙으로 본다.
- **대조 전 정규화 단계를 둔다.** NFKC 정규화, 혼동 문자(confusables)를 ASCII 로 접기, 제로폭 제거,
  구분자(`_`, `-`, 공백 연속) 정규화. 그리고 base64·hex·ROT13 **후보 토큰은 디코딩한 뒤에도 대조**한다.
  정규화 전 원문에서 유니코드 검사를 먼저 해야 한다(mcpward 의 주석과 같은 이유).
- 새 규칙:
  - `desc/encoded-blob`: 설명 안에 길이 40 이상의 base64·hex 블록. 정상 설명에는 거의 없다.
  - `desc/ansi-escape`: ESC 시퀀스. 터미널에서 지시를 숨긴다(2025-04 사례).
  - `desc/non-standard-field`: 스키마 표준 키 밖의 필드에 긴 문자열. CyberArk 가 보인 주입 자리다.
  - `desc/implicit-trigger`: MCPTox P2·P3 문형. "whenever the user", "after every call", "always pass",
    "set the parameter X to" 처럼 **트리거 + 파라미터 지정** 조합. 기존 주입 문형과 별도 규칙이다.
- **회피에 약함을 리포트가 스스로 말한다.** 정적 층 결과 머리에 "패러프레이즈된 지시는 이 검사가 놓칠 수
  있습니다. 행위 관측 결과를 함께 보세요" 를 고정 문장으로 둔다.

### 3.2 새 가족 `launch`: 서버 실행 명령 검사 (Docker 불필요)

TrustFall 과 Connor 의 설정 분석에 대응한다. 대상이 stdio 이면 명령줄 자체를 본다.

- `launch/inline-code`: `node -e`, `python -c`, `bash -c`, `sh -c`, `eval`, 백틱·`$()` 가 인자에 있음.
- `launch/pipe-to-shell`: `curl ... | sh`, `wget ... | bash`.
- `launch/unpinned-package`: `npx -y <pkg>`, `uvx <pkg>` 에 버전이 없음. 다음 실행에서 다른 코드가 돈다.
- `launch/remote-source`: 인자에 URL 이 있고 그것이 코드 출처로 보임(`npx <git url>`, `pip install <url>`).
- `launch/env-passthrough`: 설정이 `env` 로 비밀 이름(`*_TOKEN`, `*_KEY`, `*_SECRET`)을 넘김. 정보성.
  단계 1 의 비밀 카나리(E)가 이 이름들에 토큰을 심는다.

### 3.3 새 가족 `supply`: 패키지 출처 (Docker 불필요, 레지스트리 조회는 선택)

postmark-mcp 류는 블랙박스 행위로 못 잡는다. 할 수 있는 것은 **바뀌었음을 알리는 것**이다.

- `supply/package-baseline`: `npx`/`uvx` 로 실행되는 패키지의 이름·버전·설치 무결성 해시(npm `integrity`,
  PyPI sha256)를 D 의 기준 파일에 함께 기록. 다음 실행에서 다르면 `supply/package-changed`(high).
- `supply/young-version`(선택, 레지스트리 조회 필요): 실행될 버전의 발행 시각이 1,440분(24시간) 이내.
  근거는 이 저장소의 `pnpm-workspace.yaml` 이 같은 값으로 공급망 방어를 하는 것과 같다. 조회는 패키지
  메타데이터 **읽기**만이고 사용자 데이터를 보내지 않는다. 오프라인이면 "확인 안 함" 으로 명시.
- `supply/publisher-changed`(선택): 직전 버전과 발행자가 다름.

### 3.4 새 가족 `flow`: 독성 흐름 가능성 (Docker 불필요, 경고 등급)

GitHub MCP·Supabase·Jira 사고는 서버 결함이 아니라 **(외부 입력을 읽는 도구) + (비공개 데이터에 닿는
도구) + (밖으로 쓰는 도구)** 조합이다. 서버 하나 안에서도 세 역할이 함께 있으면 경고한다.

- 도구를 셋으로 분류: `reads-untrusted`(issue, comment, ticket, email, web, document 등 이름·설명·`openWorldHint`),
  `reads-private`(repository, file, database, record, message 등 + `readOnlyHint` 유무),
  `writes-external`(create, post, send, publish, comment, pull request 등 + `openWorldHint`).
- `flow/toxic-combination`: 세 분류가 한 서버에 모두 있음. 메시지는 "이 서버는 외부 입력을 읽고, 비공개
  데이터에 닿고, 밖으로 쓸 수 있습니다. 외부 입력에 숨은 지시가 있으면 비공개 데이터가 밖으로 나갈 수
  있습니다(GitHub MCP 2025-05 사고와 같은 모양). 결함이 아니라 **권한 조합 경고**입니다."
- 분류는 키워드 표라 결정론적이다. 사용자가 끄거나 분류를 덮어쓸 수 있어야 한다(오탐 성격).

### 3.5 C 프로토콜 검사에 더한다 (Docker 불필요)

- `protocol/oauth-endpoint`: HTTP 대상이 OAuth 메타데이터를 주면 `authorization_endpoint`·`token_endpoint`
  가 `https://` 인지, 셸 메타문자·공백·`file:`·`javascript:` 가 없는지. mcp-remote CVE-2025-6514 대응.
- `protocol/origin-check`: HTTP 대상에 임의 `Origin`·`Host` 헤더로 요청해 수락하면 DNS 리바인딩 취약(SDK
  2025-07 권고). 로컬호스트 대상에서만 의미가 있다.
- `protocol/session-in-url`: 응답이나 리다이렉트 URL 에 세션 식별자.
- `protocol/server-requests`: 접속 중 서버가 보낸 요청(`sampling/createMessage`, `elicitation/create`,
  `roots/list`)을 전부 기록. 요청 본문에 `desc/*` 규칙을 적용해 `protocol/sampling-injection`. 샘플링
  요청 자체는 정보성으로 보고한다(쿼터 탈취 경로).
- `protocol/list-changed-mid-session`: 감사 중 `notifications/tools/list_changed` 가 오고 표면이 바뀜.
  러그풀의 실시간형이다.

### 3.6 응답 검사 (Docker 불필요. 도구를 부르는 모든 층에서)

CyberArk ATPA 와 Universal Output Poisoning 에 대응한다. 정상값 호출 결과, 오류 응답, `isError` 본문,
`structuredContent`, 리소스 읽기 결과에 `desc/*` 규칙을 적용한다.

- `result/injection`: 응답 텍스트에 모델 지시 문형.
- `result/hidden-unicode`, `result/ansi-escape`: 응답의 숨은 문자.
- `result/oversized`: 응답이 `maxMessageBytes` 의 절반을 넘음. 컨텍스트 소진.
- `result/secret-echo`: E 의 카나리 토큰이 응답에 있음(기존 `secret/env-leak` 과 같은 것을 응답 쪽에서 본다).

### 3.7 F 행위 관측에 더한다 (Docker 필요)

- `behavior/annotation-violation`: `readOnlyHint=true` 인 도구가 파일 쓰기·`execve`·`connect` 를 시도.
  `destructiveHint=false` 인데 삭제·덮어쓰기. 과권한 논문의 "선언 대 실제" 를 그대로 검사한다. 정적 B 의
  `annotation-mismatch` 보다 훨씬 강한 증거다.
- `behavior/argument-injection`: 페이로드 목록에 `--output=/tmp/x`, `-o`, `--exec`, `--upload-pack` 같은
  **옵션 주입**을 추가. Git MCP CVE-2025-68144 가 이 형이다. 경로 순회·명령 주입과 별도 규칙.
- `behavior/write-outside-sandbox`: 임시 작업 디렉터리 밖 쓰기 시도(읽기 전용이라 실패하지만 기록).
- `behavior/hang`: 호출이 타임아웃. mcp-harness 원칙대로 **fail closed**. 조용한 통과가 아니라 발견이다.
- `behavior/decoded-witness`: SandScope 방식. 카나리 토큰과 환경변수 값을 원문 외에 base64·hex·ROT13
  디코딩형으로도 응답에서 찾는다.
- 보고 문장에 한계를 고정한다: "관측되지 않았다는 것은 없다는 증명이 아닙니다. 암호화·요약된 유출과
  인증이 필요한 경로는 이 검사가 보지 못합니다."

## 4. 수정할 것

- **B `schema/exfil-channel` 의 조건을 더 좁힌다.** 필드명 + "항상 포함" 문형 외에, 그 필드가 도구의
  선언 목적과 무관한 자유 문자열일 때만. MCPTox 의 P3(파라미터 변조)와 CyberArk 의 "파라미터로 민감
  컨텍스트를 채우게 하는" 사례가 이것인데, 정상 서버의 `note` 필드가 흔해 오탐이 크다.
- **D 드리프트의 정규화 범위를 명시한다.** 해시에 들어가는 것: 이름, 설명(공백 정규화 후), inputSchema,
  outputSchema, annotations, `title`. 들어가지 않는 것: 순서. 공백만 바뀐 설명은 변경이 아니다.
  주석이 **완화**되는 방향(`readOnlyHint` true→false, `destructiveHint` false→true)은 high 다.
- **E 비밀 카나리는 이름을 하나 더 심는다.** 사용자가 `--env` 를 하나도 안 줘도, 흔한 이름
  (`GITHUB_TOKEN`, `OPENAI_API_KEY`, `AWS_SECRET_ACCESS_KEY`, `SLACK_TOKEN` 등 고정 목록 10개)에 토큰을
  채워 띄운다. 자기 것이 아닌 비밀을 읽어 내보내는 서버를 잡기 위해서다(Amp 사고의 환경변수 유출형).
- **A 의 `desc/sensitive-path` 는 등급을 낮춘다.** 파일 서버의 설명에 `.env` 가 나오는 것은 정상이다.
  단독으로는 info, 지시 문형과 결합될 때만 high.

## 5. "충분한가" 에 대한 답과 측정 방법

충분하다고 **말할 수 없고, 측정해야 한다.** 측정 기준 두 가지를 단계 1 완료 조건에 넣는다.

- **재현율**: MCPTox 의 1,312 사례(공개)를 `fixtures/` 가 아닌 외부 벤치마크로 두고 정적 층의 탐지율을
  낸다. 첫 실측 전에는 목표 수치를 적지 않는다. 실측 뒤 그 값을 CI 하한으로 고정하고 회귀를 막는다.
  arXiv 2605.24069 의 회피 변형(패러프레이즈·동형문자·base64·비영어)도 같은 방식으로 따로 센다.
  패러프레이즈 재현율은 낮게 나올 것이고, 그것이 행위 층의 존재 이유라고 리포트와 문서에 적는다.
- **정밀도**: `examples/` 전부와 공개 정상 서버 20개(ADR-0102 실험에 쓴 35개 중 고름)에서 발견 0.
  Cisco `prompt_defense` 류의 "방어 문구 없음" 검사를 뺀 이유가 이 기준이다.

행위 층은 `examples/` 의 취약 예제 서버(경로 순회, 인자 주입, SSRF, 자식 프로세스, 주석 위반, 응답 주입
각 1개)에서 각 규칙이 정확히 한 번, 정상 예제에서 0 이면 통과다. 실물 CVE 재현(Git MCP 68144 의
`--output` 주입, Fetch SSRF 의 사설 IP)을 그 예제에 그대로 옮긴다.

## 6. 단계 배치 변경 제안

| 단계 | 추가 |

| 1 | 3.1 전 필드·정규화·디코딩, 3.2 `launch`, 3.5 중 `oauth-endpoint`·`server-requests`·`list-changed`, 3.6 응답 검사, 3.4 `flow`(경고 등급), §4 수정 전부, §5 MCPTox 측정 |
| 2 | 3.7 전부, 3.3 `supply`(기준 파일은 1 에서 만들고 비교·레지스트리 조회는 2 에서) |

규칙이라 패키지 구조는 바뀌지 않는다. 구현 계획에서 규칙 가족별로 태스크를 나누면 병렬이 된다.
