## 1. 적용 이력

### 1.1 `examples/weather-server` — 자체 제작, CI 상시

우리가 만든 예제 서버다. **§10 이 말하는 "적용 저장소" 에는 넣지 않는다.** 우리 도구가 다루기
가장 쉽도록 설계돼 있어(고정 데이터 · 인증 불필요 · 저수준 `Server` 사용) 외부 서버의 난이도를
대표하지 못한다. 그럼에도 회귀를 막는 최저선이라 기록한다.

CI(`.github/workflows/ci.yml`)가 매 실행 두 경로로 돈다.

| 경로 | 무엇을 지키나 |
|---|---|
| `pnpm --filter ohmymcp test:e2e` | 빌드 산출물 `dist/cli.mjs` 가 실제로 도는지. 번들링·exports·shebang 결함은 소스 테스트로는 안 잡힌다 |
| `--junit junit-dogfood.xml` → `dorny/test-reporter` | 우리가 내보낸 XML 을 실제 CI 리포터가 읽는지 |

### 1.2 외부 공개 MCP 서버 — **아직 없다**

§10 은 공개된 외부 MCP 서버 3~5개를 요구한다. **한 건도 시작하지 않았다.**

예상되는 실패 지점은 조사돼 있으나 실측되지 않았다.

| 실제 서버의 특성 | 지금 어떻게 될 것으로 보나 | 근거 |
|---|---|---|
| 스키마에 `$ref` · `anyOf` 포함 | `generate` 가 거절 | ADR-0004 가 명시적 비지원 |
| Streamable HTTP 전송 | 연결됨 (2026-08-14 해소) | 이슈 #16 · ADR-0020 |
| stdout 에 로그를 섞어 뱉음 | `TRANSPORT_FAILED` 로 추정. **겪어 본 적 없음** | — |
| 툴 20~50개 | 순차 실행 + 케이스당 10초 기본 타임아웃. **실사용 시간 미측정** | — |

이 표의 3·4행은 **가정이다.** 실제로 붙여 보기 전에는 결함 수에 세지 않는다.

| 발견 도구 | `ohmymcp repair` |
| 무엇을 했나 | `repair` 가 원인으로 정규화 불일치를 지목했고, 사람이 해당 줄을 손으로 고쳐 재실행해 초록을 확인했다 |
| 결과 | 수정됨 |

> **채우지 못한 칸:** 대상 서버가 어디였는지 저장소에 기록이 없다. 이슈 #122 본문이 유일한 흔적이고
> 거기에도 서버 이름이 없다. **이 파일이 없어서 실적이 이슈 본문에 흩어진 사례 자체다.**
> 돌린 사람이 서버명과 나머지 발견 사항을 채워 주면 좋겠다.

## 3. 우리 산출물을 외부 도구로 검증한 것

### 3.1 JUnit XML → `dorny/test-reporter` — 2026-08-16 (PR #124)

ADR-0016 이 **"검증되지 않은 가정"** 으로 남겨 둔 항목(`time="0"` 과 속성 생략 중 어느 쪽이 실제
CI 파서와 맞는가)을 실측해 닫았다.

- 파서가 거부하지 않았고 경고도 없었다. 케이스 3건이 렌더됐고 한글 이름도 안 깨졌다.
- `time="0"` 은 `0ms` 로 표시된다.
- 결론: A안(`0` 으로 고정) 유지. 속성 생략이 오히려 파서를 깨뜨린다.
- **관측된 대가:** 화면에는 "시간 정보 없음" 이 아니라 "0ms 만에 끝났다" 로 읽힌다. 파서가 이
  구분을 표현할 방법이 없다. **실제 오독 사례가 보고된 적은 없다** — 다만 오독할 여지가 있다는
  것 자체는 추정이 아니라 화면으로 확인됐다 (ADR-0016 「결과」).

결함은 아니지만 **우리 출력이 남의 도구에서 도는지**를 배포 전에 확인한 건이라 여기 남긴다.
