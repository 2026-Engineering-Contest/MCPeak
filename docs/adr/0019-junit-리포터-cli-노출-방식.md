# ADR-0019: JUnit 리포터를 `--junit <path>` 로 노출한다

- 상태: 제안
- 날짜: 2026-08-14
- 작성자: @endl24 (runner 파트)
- 관련 결정: [ADR-0016](./0016-junit-time-속성-고정.md) — `renderJUnit` 이 생긴 결정
- 관련 결정: [ADR-0012](./0012-cli-기본-출력-전환.md) — `--json` 의 의미를 정한 결정

## 배경

ADR-0016 이 `renderJUnit(report, options?)` 을 만들었고 `@ohmymcp/runner` 가 이를 공개 API 로
내보낸다. 그런데 **사용자는 이 기능을 쓸 수 없다.** `ohmymcp test` 에 리포터를 고르는 수단이
없기 때문이다. 라이브러리로 직접 import 하지 않는 한 도달할 방법이 없고, 이 도구의 사용자는
대부분 CLI 로 온다.

CI 도구가 테스트 결과를 화면에 렌더하려면 JUnit XML 파일이 필요하다. 만든 것이 아무에게도
닿지 않는 상태를 끝내는 것이 이 결정의 목적이다.

동시에 정해야 할 것이 세 가지였고, 서로 얽혀 있었다.

1. **플래그 형태.** `--reporter junit` 인가 `--junit <path>` 인가.
2. **출력 대상.** stdout 인가 파일인가.
3. **`--json` 과의 관계.** 동시 지정을 허용할 것인가 오류로 막을 것인가.

## 선택지

### A. `--junit <path>`

XML 을 지정한 경로에 파일로 쓴다. stdout 은 건드리지 않으므로 `--json` 과 병용할 수 있다.

- 장점
  - CI 도구가 요구하는 파일 경로를 그대로 받는다.
  - 사람용 보고서와 XML 이 한 스트림에서 섞이지 않는다.
  - ADR-0012 가 정한 `--json` 의 의미를 건드리지 않는다.
  - `pytest --junit-xml`, `vitest --outputFile` 과 같은 관행이라 학습 비용이 없다.
- 단점
  - 리포터가 늘어나면 `--tap` 처럼 플래그가 하나씩 는다.

### B. `--reporter junit`

stdout 형식을 리포터 이름으로 고른다. 파일 저장은 쉘 리다이렉트에 맡긴다.

- 장점
  - 리포터 추가가 값 하나 추가로 끝난다.
- 단점
  - **stdout 형식 선택 수단이 `--json` 과 `--reporter` 둘로 갈린다.** `--reporter json` 을
    받지 않으면 일관성이 없고, 받으면 `--json` 과 의미가 겹친다.
  - XML 이 stdout 을 차지하므로 진단 보고서를 함께 볼 수 없다. `--json` 과 동시 지정은 오류로
    막을 수밖에 없다.
  - CI 액션은 대개 파일 경로를 요구한다. 사용자가 매번 리다이렉트를 붙여야 하고, 그 경로에는
    쉘이 만든 빈 파일이 실패 시에도 남는다.

### C. `--reporter junit --output <path>`

확장성과 파일 출력을 모두 가진다.

- 장점
  - 리포터가 늘어나도 플래그 수가 늘지 않고, 파일 경로도 받는다.
- 단점
  - **정해야 할 조합이 늘어난다.** `--output` 만 준 경우, `--reporter` 만 준 경우,
    `--reporter pretty|json` 도 받아야 하는지, `--json` 과 `--reporter json` 의 중복을
    어떻게 할지가 전부 새 결정이 된다.
  - 리포터가 둘(사람용·JSON)뿐인 지금 플래그를 셋으로 늘린다.

## 결정

**A안을 채택한다.**

1. `ohmymcp test` 에 `--junit <path>` 를 더한다. `--junit=<path>` 형태도 받는다. 값 검사 규칙은
   `--command` 와 같다 — 중복 지정, 값 없음, 빈 값, `--` 로 시작하는 값을 거절한다.
2. XML 은 **파일로만** 쓴다. stdout 으로 내는 경로를 두지 않는다.
3. **`--json` 과 병용을 허용한다.** 둘은 경쟁하지 않는다. `--json` 은 stdout 형식을,
   `--junit` 은 별도 산출물을 정한다.
4. XML 파일을 stdout 보다 **먼저** 쓴다.
5. 쓰기에 실패하면 모든 테스트가 통과했더라도 `JUNIT_WRITE_FAILED` 와 함께 종료 코드 1 을 낸다.
6. `renderJUnit` 과 파일 쓰기 함수는 `TestCommandDependencies` 로 주입한다. `runCli` 는
   `node:fs` 를 import 하지 않는다.

## 이유

**세 결정이 A 하나로 전부 풀린다.** 플래그가 경로를 받으므로 "출력 대상" 이 플래그 형태에서
따라 나오고, stdout 을 차지하지 않으므로 "`--json` 과의 관계" 도 따라 나온다. B 와 C 는 세
질문에 각각 답해야 하고, 그 답들이 서로를 제약한다.

**B 는 `--json` 과 싸운다.** ADR-0012 는 stdout 기본값을 사람용으로 정하고 기계용을 `--json`
으로 옮긴 결정이다. 이제 와서 `--reporter` 라는 두 번째 stdout 형식 선택 수단을 들이면, 같은
것을 고르는 방법이 두 개가 된다. 그 상태를 정리하려면 `--json` 을 `--reporter json` 의 별칭으로
만들어야 하는데, 이는 방금 배포한 출력 계약을 다시 흔드는 일이다. 지금 그 값을 치를 이유가 없다.

**C 는 지금 규모에 비해 비싸다.** 리포터가 다섯 개쯤 되면 C 가 옳다. 둘일 때 도입하면 조합
검증과 문서가 기능보다 커진다. **A 에서 C 로 가는 길은 열려 있다** — `--reporter` 를 나중에
더하면서 `--junit` 을 그 별칭으로 남기면 기존 사용자를 깨뜨리지 않는다. 반대로 B 로 시작하면
stdout 계약이 이미 갈라진 뒤라 되돌리기가 비싸다. ADR-0016 과 같은 원칙이다 — **되돌리기 싼
쪽으로 시작한다.**

**쓰기 실패에 0 을 내지 않는 이유.** CI 는 종료 코드로 판정한다. 파일을 못 썼는데 0 을 내면
빌드는 초록이고 리포트만 조용히 사라진다. 사용자는 리포트가 필요한 순간에야 없다는 것을 안다.
`--junit` 을 준 것은 그 파일을 요구한 것이므로, 요구가 충족되지 않으면 실패다.

**stdout 보다 파일을 먼저 쓰는 이유.** `ohmymcp test ... --junit r.xml | head` 처럼 stdout 이
EPIPE 로 깨지는 경우가 있다. 그때 사용자가 명시적으로 요청한 산출물까지 함께 잃을 이유가 없다.
`--junit` 을 주지 않으면 이 분기를 통째로 건너뛰므로 기존 출력 순서는 변하지 않는다.

**무엇을 포기했는지 분명히 한다.** A 의 대가는 리포터가 늘 때 플래그가 함께 느는 것이다.
`--tap`, `--allure` 가 생기면 `test` 의 플래그 표가 길어진다. 그 시점에 C 로 옮기는 비용을
치르기로 하고, 지금은 사용자가 오늘 쓸 수 있는 최소 표면을 택한다.

## 결과

- `renderJUnit` 이 사용자에게 도달한다. ADR-0016 이 만든 기능이 CLI 로 쓰인다.
- `ohmymcp test` 의 기존 출력 바이트가 변하지 않는다. `--junit` 없이 실행하면 이 변경 전과
  같은 stdout, 같은 종료 코드, 같은 stderr 를 낸다.
- **[이행됨 · 2026-08-16] ADR-0016 의 미검증 항목을 실측할 수 있게 됐다.** `time="0"` 이 실제
  CI 파서와 맞는지를 이 플래그로 만든 파일로 확인하기로 했고, PR #124 가 CI 에
  `--junit` → `dorny/test-reporter` 경로를 붙여 실측했다. **파서는 이 XML 을 거부하지 않았고
  `time="0"` 을 `0ms` 로 표시했다.** 결과와 그때 새로 드러난 오독 위험은
  [ADR-0016](./0016-junit-time-속성-고정.md) 의 결과 항목에 적었다.
- `runCli` 는 여전히 `process` 와 `node:fs` 를 읽지 않는다. 파일 쓰기는 주입된 의존성이고,
  실제 `node:fs/promises` 결선은 `packages/cli/src/index.ts` 한 곳에서만 한다.
- 새 의존성을 추가하지 않았다. 파일 쓰기는 Node 표준 모듈이다.
- 리포터가 셋 이상이 되면 `--reporter` 도입을 재검토한다. 그때 `--junit` 은 별칭으로 남긴다.
- `packages/core/src/types.ts` 의 동결 타입과 의존 방향(`cli → runner → core`)에 영향이 없다.
  이 변경은 `cli` 한 패키지 안에서 끝난다.

### 승인 상태

- 상태: **미승인.**
- 확정 방법: [ADR-0002](./0002-matcher-strategy.md) 가 세운 절차를 따른다. 머지만으로 승인
  처리하지 않으며, 파트 ① 밖 오너 최소 1명의 명시적 승인(§5-2)을 확인한 뒤 상태를 `승인` 으로
  바꾸고 승인일과 승인한 오너를 적는다.

**이 결정은 승인보다 먼저 사용자에게 나갔다.** `--junit` 은 이 ADR 이 `제안` 인 상태로 머지되어
`ohmymcp test` 의 공개 플래그가 되었다. 즉 아래 두 가지가 지금 사실이다.

1. **플래그 이름과 동작은 이미 공개 계약이다.** 사용자가 CI 설정에 `--junit` 을 적기 시작하면
   바꾸는 비용이 오른다. 이 ADR 이 나중에 뒤집히면 그 비용은 우리가 아니라 사용자가 낸다.
2. **그럼에도 팀은 이 설계를 공식적으로 합의한 적이 없다.** `승인` 이 아닌 것을 `승인` 인 척
   하지 않기 위해 이 절을 남긴다.

되돌릴 여지는 남겨 두었다 — 「이유」 절이 적었듯 A(`--junit`)에서 C(`--reporter` + `--output`)로
가는 길은 `--junit` 을 별칭으로 남기면 열린다. 승인 과정에서 B 나 C 가 옳다고 판정되면 그 경로로
간다. **다만 사용자가 생긴 뒤에는 같은 변경이 훨씬 비싸므로, 승인은 미룰수록 손해다.**
