# ADR-0035: `callTool` 인자의 배열 허용 범위

- 상태: 채택
- 날짜: 2026-08-16
- 작성자: @endl24 (① MCP 서버 테스트 파트 · `core`)
- 승인: 승인 (2026-08-17, @endl24 · 파트 ① 오너)
- 관련: [ADR-0003](./0003-cassette-matching-key.md) · [ADR-0029](./0029-목-매칭-키-정규화-경계.md) · #113

## 배경

`core.callTool(name, args)` 는 SDK 에 넘기기 전에 `assertToolArguments` 로 인자를 검증한다.
이 검증이 **배열이 들어 있는 인자를 전부 거부하고 있었다.** 빈 배열도 마찬가지다(#113).

```
✓ { a: 1, b: 2 }
✗ { items: [1, 2, 3] }   → callTool 인자가 JSON object가 아닙니다.
✗ { items: [] }          → 같음
```

원인은 검사가 두 군데에 있고 그중 하나가 자리를 잘못 잡은 것이다.

```ts
// 최상위 인자 — 맞다. MCP 의 arguments 는 객체여야 한다.
if (… || Array.isArray(args) || typeof args !== "object") throw invalidArguments(diagnostics);

// 순회 루프 안 — 버그. 같은 검사가 중첩된 모든 값에 걸린다.
if (… || Array.isArray(value) || typeof value !== "object" || …) throw invalidArguments(diagnostics);
```

JSON Schema 의 `type: "array"` 를 쓰는 MCP 서버는 흔하다. 그런 서버는 이 도구로 테스트할 수
없었다.

**배열을 열면 새로 답해야 하는 질문이 생긴다.** 지금까지는 배열 자체를 막아서 물어볼 일이
없었던 것이다 — **희소 배열(`[1, , 3]`)을 어떻게 할 것인가.** 빈 자리는 `JSON.stringify` 를
거치면 `null` 이 되어 실제 `null` 원소와 구분되지 않는다. 사용자가 넘긴 값과 서버가 받는 값이
달라지는 유일한 배열 형태다.

## 선택지

- **A안: 배열을 열되 희소 배열은 거부한다.** 거부 집합을 `record`(ADR-0003) ·
  `mock`(ADR-0029)과 같게 맞춘다 — 순환 참조 · 희소 배열 · `NaN`/`Infinity` · JSON 이 아닌 값.
- **B안: 배열을 전부 연다.** 희소 배열도 통과시키고 `JSON.stringify` 가 `null` 로 바꾸는 것을
  그대로 둔다. 검증은 "JSON 으로 직렬화 가능한가" 만 본다.
- **C안: 희소 배열을 조용히 메운다.** 빈 자리를 `null` 로 채워 넘긴다. 사용자가 의도한 대로
  동작하게 만든다.

## 결정

**A안을 택한다.** 배열을 중첩 값으로 허용하되 희소 배열은 거부한다. 최상위 `args` 가 객체여야
한다는 제약은 그대로 둔다.

배열은 객체와 **같은 컨테이너로** 순회한다. 깊이(`MAX_JSON_DEPTH`)와 순환 참조 검사가 똑같이
걸리고, 공유 참조(같은 배열을 두 곳에서 참조)는 순환이 아니므로 허용한다 — 객체에 이미 적용
중인 규칙과 같다.

## 이유

**C안은 조용히 값을 바꾼다.** 이 프로젝트의 도구는 "서버가 무엇을 받았는가" 를 검증하는 데
쓰인다. 검증기가 인자를 손대면 테스트가 통과했을 때 무엇이 통과한 것인지 알 수 없다. 사용자가
넘긴 값과 서버가 받은 값이 다른데 아무도 그 사실을 모르는 상태가 최악이다.

**B안은 세 패키지의 판정을 갈라놓는다.** `record` 는 ADR-0003 으로, `mock` 은 ADR-0029 로 이미
희소 배열을 거부하기로 정했다. `core` 만 통과시키면 같은 값이 `core.callTool()` 에서는 되고
`mock.on()` 에서는 안 되는 상태가 된다. 사용자는 어느 층에서 막힌 건지 알 수 없고, "우리 도구로
우리를 검증한다" 는 E2E 도 층마다 다른 답을 받는다. **일관성이 이 결정의 실질적 근거다.**

**다만 ADR-0029 의 논거를 그대로 가져오지는 않는다.** 그 ADR 은 "이 값들은 MCP 호출로는 절대
나타나지 않는다 — JSON-RPC 를 건너온 `arguments` 는 JSON 파서를 거치기 때문" 을 근거로 든다.
`core.callTool()` 도 사용자가 코드로 직접 부르는 공개 API 라 같은 상황이고, 여기까지는 같다.

그런데 `core` 에는 한 가지가 더 있다. **`core` 는 이 값을 SDK 에 넘기는 마지막 지점이다.**
`mock` 은 주입 시점에 거부하면 그만이지만, `core` 가 통과시킨 값은 그대로 직렬화되어 서버로
나간다. 즉 `core` 에서의 통과는 "키가 안정적이다" 가 아니라 **"사용자가 넘긴 것이 서버에
도착한다"** 를 뜻한다. 희소 배열은 그 약속을 깨는 유일한 배열 형태이므로, 같은 결론이지만
더 강한 이유로 거부한다.

**최상위 배열은 계속 거부한다.** MCP 의 `arguments` 는 객체다. 이건 우리 판단이 아니라 규약이라
선택지에 넣지 않았다.

**무엇을 포기했는지 분명히 한다.** 희소 배열을 쓰는 사용자는 이 도구를 쓸 수 없다. 실무에서
희소 배열을 의도적으로 만드는 경우는 드물고, 대개 `delete arr[i]` 같은 실수의 결과다. 그 경우
거부가 오히려 맞다고 본다. 그러나 이것은 관측이 아니라 판단이며, 반례가 나오면 재검토한다.

## 결과

- JSON Schema 의 `type: "array"` 를 쓰는 MCP 서버를 이 도구로 테스트할 수 있게 된다. #113 이
  보고한 막힘이 풀린다.
- **거부 집합이 세 패키지에서 같아진다** — `core`(이 ADR) · `record`(ADR-0003) ·
  `mock`(ADR-0029). 한 곳이 바뀌면 나머지 둘도 함께 봐야 한다.
- 배열도 깊이 비용을 갖는다. `[[[…]]]` 로 `MAX_JSON_DEPTH`(100)를 넘기면 거부된다. 객체로
  넘기는 것과 동일하다.
- 검증은 값을 변형하지 않는다. SDK 가 받는 것은 사용자가 넘긴 배열 그대로다.
- 공개 API 표면이 바뀌지 않는다. `assertToolArguments` 의 시그니처와 `McpClient` 인터페이스는
  그대로다. `packages/core/src/types.ts` 의 동결 타입에 영향이 없다.
- **진단 메시지는 이 ADR 의 범위 밖이다.** 지금은 어느 필드가 왜 거부됐는지 나오지 않는다.

  ```
  callTool 인자가 JSON object가 아닙니다.
  ```

  희소 배열이 `items` 안에 있어도 이 문장이 나온다. CLAUDE.md 가 금지한 형태이고 고쳐야 하지만,
  `McpClientError` 의 메시지가 `MCP_CLIENT_ERROR_DETAILS` 에 코드별로 고정돼 있어 에러 타입
  표면을 건드려야 한다. 범위와 리뷰 단위가 달라 후속 PR 로 분리한다.
- **배열의 인덱스가 아닌 속성(`arr.foo = 1`)도 거부된다.** `JSON.stringify` 가 그것을 통째로
  버리므로 희소 배열과 같은 종류의 손실이다. 판정을 own 키 수와 `length` 의 비교로 구현하면서
  같이 걸리게 됐고, 이 ADR 이 세운 기준("넘긴 것이 서버에 도착한다")에 비추면 거부가 맞다.
- **판정은 `length` 가 아니라 own 키 수에 비례한다.** `Object.keys(value).length !== value.length`
  하나로 본다. 처음에는 `0..length` 를 돌며 `index in value` 로 구멍을 찾았는데 두 가지가
  틀렸다.
  - `in` 은 프로토타입 체인을 탄다. `Array.prototype[1]` 이 채워져 있으면 구멍이 있는데도
    있는 것으로 판정된다. `Object.keys` 는 own 프로퍼티만 본다.
  - 길이에 비례해 도는 것은 `arr.length = 2 ** 32 - 1` 같은 값에 40억 회 순회가 된다.
    슬롯 없이 `length` 만 부풀린 값이나 같은 `length` 를 보고하는 `Proxy` 가 그렇다. own 키
    수로 보면 상수 시간에 끝난다.

  `Object.keys` 자체가 던지는 입력(`ownKeys` 트랩이 `length` 를 빠뜨리는 `Proxy`)은 순회를
  감싼 `try`/`catch` 가 받아 `INVALID_TOOL_ARGUMENTS` 로 바꾼다.
