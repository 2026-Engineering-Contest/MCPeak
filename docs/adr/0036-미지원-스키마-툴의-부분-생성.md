# ADR-0036: 미지원 스키마 툴은 건너뛰고 나머지를 생성한다

- 상태: 제안
- 날짜: 2026-08-17
- 담당: generate
- 작성자: @seodduu
- 참조: ADR-0004(생성 테스트의 자동화 범위), `docs/adoption.md` §1.3, 이슈 #135

## 배경

ADR-0004 는 지원하지 않는 JSON Schema 키워드를 만나면 파일 쓰기 전에 실패하기로 정했다.
그때 단위는 사실상 서버 전체였다. `createBaselineSuite` 가 첫 미지원 키워드에서 던지므로,
툴 하나의 키워드 하나가 나머지 툴 전부의 생성을 막는다.

도그푸딩(2026-08-17)에서 이 단위가 실제 병목으로 관측됐다. 공개 MCP 서버 8개에 붙인 결과
5개가 툴 한 개의 `maximum` · `minItems` · `exclusiveMaximum` · `anyOf` 에서 전체 거절됐다.
`server-everything` 은 13개 툴 중 12개가 지원 범위 안인데 `tools[3]` 의 `count.maximum`
하나로 0개가 생성됐다. CONTRIBUTING §10 의 "외부 서버 3~5개 적용" 을 막는 1순위 원인이었다.

## 선택지

- A안: 지금처럼 전체 거절을 유지한다. 안전하지만 위 병목이 그대로 남는다.
- B안: 미지원 키워드가 있는 **툴만** 건너뛰고 나머지를 생성하며, 건너뛴 툴을 결과와 화면에
  고지한다.
- C안: 미지원 키워드를 **무시하고** 그 툴도 생성한다. `maximum` 을 모른 채 값을 합성하면
  잘못된 입력이 정상 케이스로 저장된다. ADR-0004 가 막은 "조용히 잘못된 입력" 이 그대로
  되살아난다.

## 결정

B안. 격리 단위는 툴이고, 격리 대상은 `UNSUPPORTED_SCHEMA` 하나다.

- 다른 오류 코드(`INVALID_TOOL`, `INVALID_OPTIONS` 등)는 입력 자체의 결함이므로 종전대로
  전체를 멈춘다.
- 건너뛴 툴은 `BaselineGenerationResult.skippedTools` 에 이름·경로·원인 문장으로 실리고,
  `cli` 가 커버리지 화면과 같은 자리에서 고지한다. 고지 없는 건너뜀은 "이 서버를 전부
  검증했다" 로 읽히므로 허용하지 않는다.
- 커버리지 분모에서도 뺀다. 케이스가 있을 수 없는 툴을 분모에 넣으면 매 실행 거짓
  "미검증" 이 쌓인다.
- 모든 툴이 건너뛰어지면 저장할 것이 없으므로 종전대로 `UNSUPPORTED_SCHEMA` 를 던진다.
- `skippedTools` 는 suite 밖에 실린다. 전 툴 지원 서버의 출력 바이트와 지문은 변하지
  않으므로 `BASELINE_POLICY_VERSION` 은 v2 를 유지한다. v3 로 올리면 기존 승인 지문이
  전부 무효가 되는데(#88), 이 변경은 기존에 생성되던 산출물을 한 바이트도 바꾸지 않는다.

## 이유

- ADR-0004 의 원칙(모르는 제약으로 값을 합성하지 않는다)은 그대로 지킨다. 바뀌는 것은
  실패의 **반경**이다. 키워드 하나의 무지가 서버 전체의 무지가 될 이유가 없다.
- 부분 결과가 부분임을 아는 한 안전하다. ADR-0004 가 경계했던 것은 "부분 결과를 전체로
  오해하는 것" 이고, 그래서 고지를 결정의 일부로 못 박는다.
- 실측 근거가 있다. 이 결정 하나로 공개 서버 후보 5개가 전부 적용 가능 범위로 돌아온다.

## 결과

- `server-everything` 류 혼합 서버에서 지원 툴만으로 명세가 생성된다. 화면에는
  `건너뜀 N tools` 블록이 커버리지 아래 붙는다.
- 미탐이 하나 생긴다. 건너뛴 툴은 어떤 검증도 받지 않으며, 그 사실은 고지 한 블록이
  전부다. 사용자가 그 툴의 케이스를 손으로 쓰는 것이 후속 조치다.
- 키워드 지원을 넓히는 일(ADR-0004 의 "후속 결정")과는 독립이다. 지원이 넓어질수록
  건너뛰는 툴이 줄어들 뿐, 이 격리 규칙 자체는 유지된다.
