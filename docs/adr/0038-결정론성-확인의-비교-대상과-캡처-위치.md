# ADR-0038: 결정론성 확인은 케이스별 구조화 비교로 하고, 응답 캡처는 CLI 래퍼가 한다

- 상태: 제안
- 날짜: 2026-08-18
- 담당: runner · cli
- 작성자: @seodduu
- 참조: `docs/superpowers/specs/2026-08-18-determinism-check-design.md`,
  `docs/adoption.md` §1.4.3(수동 실측), ADR-0018(비차단 진단의 지위), ADR-0023(초기화 명령),
  ADR-0027(응답 본문을 읽는 조건), `CLAUDE.md`("실패 메시지가 곧 제품이다", "결정론성이 핵심 가치다")

## 배경

이 도구의 전제는 "명세가 옳고 실패는 서버 결함" 이다. 명세가 시간·랜덤·상태에 의존하면 그
전제가 무너진다. 서버를 안 고쳐도 내일 빨간불이 나고, 팀은 빨간불을 무시하기 시작한다.

2026-08-17 수동 실측(`docs/adoption.md` §1.4.3)이 요구를 구체화했다.

- `server-filesystem`: 매 실행 전 샌드박스를 복원하고 2회 실행해 54/54 · 54/54.
  **같은 초기 상태에서 같은 결과**라고 말할 수 있었다.
- `mcp-server-git`: 복원 없이 2회 실행해 40/40 · 40/40. 1회차가 만든 커밋 위에서 2회차가
  돌았으므로 **"두 실행 모두 40/40" 까지만** 말할 수 있었다. 결정론성 판정이 아니다.

이 구분을 사람이 손으로 했다. 샌드박스를 만들고, 두 번 돌리고, 눈으로 diff 했다. 로드맵
단계 7 은 이것을 자동화한다. 착수 시점에 판단이 필요한 지점이 셋이었다.

## 선택지

**1. 무엇을 비교하나.**

- A안(로드맵 원문): 보고서 전체 바이트. 구현이 가장 짧다. 대신 화면이 "다릅니다" 까지만
  말하고 어디가 다른지는 사람이 직접 diff 해야 한다.
- B안: 케이스 판정(`status`)만 비교. 단언이 안 걸린 필드의 비결정을 통째로 놓친다. 오늘
  단언이 없는 필드가 내일 단언 대상이 되므로, 놓치는 것이 정확히 미래의 빨간불이다.
- C안: 케이스별 구조화 비교. 응답을 정규화해 대조하고 첫 차이 지점의 경로와 양쪽 값을 짚는다.

**2. 응답을 어디서 캡처하나.**

- D안: `RunnerEvent` 를 확장해 응답을 실어 보낸다. runner 안에서 끝나고 CLI 는 받기만 한다.
  대신 `RunnerReport`·executor·이벤트 계약이 바뀌고, 그것은 5인 병렬 작업의 공유 기준점이다.
- E안: CLI 가 `McpClient` 를 감싸는 래퍼로 캡처한다. `cassetteClient` 가 이미 쓰는 패턴이라
  runner 를 한 줄도 안 고친다.

**3. 상태 복원이 없는 실행을 어떻게 다루나.**

- F안: `--reset-cmd` 를 필수로 한다. 읽기 전용 서버(날씨·시계) 사용자에게 불필요한 문턱이다.
- G안: 복원 없이도 돌리되 결론 문장의 강도를 낮춘다.

## 결정

C안 · E안 · G안.

- **비교는 케이스별 구조화 비교다.** `status` → 단언 status 배열 → 응답 순으로 대조하고,
  앞 단계가 다르면 뒤는 보지 않는다. 응답은 `canonicalJson` 으로 정규화해 문자열이 다를 때만
  첫 차이 지점을 찾아 경로(`content[0].text`)와 양쪽 값을 싣는다. 정규화가 흡수하는 것은
  객체 키 순서뿐이고 **배열 순서 차이는 차이로 본다.**
- **캡처는 CLI 의 클라이언트 래퍼가 한다.** `packages/cli/src/determinism-capture.ts` 가
  `McpClient` 를 감싸 호출 시점의 케이스에 응답을 귀속시킨다. `RunnerReport` 에 새 필드를
  넣지 않고, 결과는 CLI 가 보고서 뒤 별도 블록으로 렌더한다.
- **복원은 선택이고 결론 강도가 갈린다.** 차이 0 + 복원 있음은 `deterministic`,
  차이 0 + 복원 없음은 `consistentWithoutReset`, 차이 1건 이상은 복원 유무와 무관하게
  `nondeterministic` 이다. 판정·종료 코드·`RunnerReport` 는 어느 경우에도 바뀌지 않는다
  (ADR-0018 의 비차단 진단과 같은 지위).

## 이유

- **비교 대상.** 이 저장소는 실패 메시지를 제품으로 본다. "2회 실행 결과가 다릅니다" 만 찍고
  마는 화면은 `expected true, got false` 와 같은 등급이다. 실측에서 사람이 실제로 한 일이
  "어느 필드가 달라졌는지 찾기" 였으므로, 자동화가 대신해야 할 일도 그것이다. 판정만 비교하는
  B안을 버린 이유는 비결정 필드가 단언에 안 걸려 있을 때 침묵한다는 것 하나로 충분하다.
  응답 안의 text 블록을 JSON 으로 파싱해 더 깊이 들어가지 않는 것도 같은 원칙이다. 파싱하면
  공백·키 순서 차이가 흡수돼 바이트 수준 비결정을 놓친다.
- **캡처 위치.** `McpClient` 와 `RunnerReport` 는 5인이 병렬로 기대는 계약이다. 진단 하나를
  얹으려고 그것을 흔드는 것은 비용이 수확보다 크다. 래퍼는 기존 `cassetteClient` 와 같은
  모양이라 새 개념을 만들지도 않는다. `--determinism` 없이는 래퍼를 아예 만들지 않으므로
  기존 경로의 비용은 0 이고 출력은 바이트 단위로 불변이다.
- **결론 강도.** 복원을 필수로 하면 읽기 전용 서버 사용자가 이 기능을 못 쓴다. 반대로 복원
  없는 실행에 "결정론성을 확인했습니다" 라고 쓰면 §1.4.3 의 `mcp-server-git` 사례처럼 거짓말이
  된다. 실측에서 사람이 두 사례를 다르게 말한 그 구분을 그대로 제품 문장으로 옮겼다. 도구가
  아는 만큼만 말하게 하는 것이 이 저장소에서 침묵과 과장을 모두 피하는 방법이다.

## 결과

- 비결정 필드를 만나면 화면이 경로·양쪽 값·원인 추정(시간 의존·식별자·측정값 변동)을 함께
  준다. 힌트는 결정론적 휴리스틱 셋이고 **양쪽 값이 모두** 패턴에 맞을 때만 단다. 틀린 추정을
  확신조로 말하는 것이 추정 없음보다 나쁘기 때문이다.
- `RunnerReport` JSON 과 JUnit XML 의 바이트가 그대로다. 기존 소비자와 CI 배선이 안 깨진다.
  `--json` 에는 `--determinism` 을 줬고 비교까지 갔을 때만 `determinism` 키가 생긴다.
- **대가가 하나 있다. 종료 절차의 client 동일성 계약을 CLI 가 손으로 지켜야 한다.**
  `finalizeRunnerExecution` 은 `runSuite` 에 바인딩된 client 와 `shutdown.client` 가 같은
  객체일 것을 요구한다(`runner/src/shutdown.ts` 의 `boundClient`). 러너에는 래퍼를 넘기면서
  shutdown 에는 원본을 넘기면 종료 절차가 통째로 건너뛰어지고 서버 프로세스가 좀비로 남는다.
  **이 결함은 실제로 났다.** 단계 7 구현 중 1회차 배선에서 발생해 CLI 가 오류를 찍고도 끝나지
  않았고(exit 124), 유닛 1879개는 전부 녹색이었다. 가짜 `finalize` 로는 이 계약이 안 돌기
  때문이다. D안(이벤트 확장)이었다면 애초에 이 지점이 없었다. 즉 이 선택의 비용은 "runner 를
  안 건드리는 대신 CLI 가 계약을 손으로 지킨다" 이고, 그 방어선은 지금 두 겹이다.
  `test-command.test.ts` 가 두 회차의 client 객체 동일성을 `toBe` 로 단언하고,
  `determinism-e2e.test.ts` 가 실서버로 프로세스 잔존을 본다.
- 래퍼가 캡처하는 값은 `JSON.parse(JSON.stringify(...))` 로 한 번 평문화한 사본이다.
  `canonicalJson` 이 undefined 필드·비평문 인스턴스·순환 참조를 거절하므로 비교 단계에서
  터지지 않게 앞에서 막는다. 평문화가 실패하면 그 케이스의 캡처만 버린다. **호출자에게
  돌려주는 값은 언제나 원본이다.** executor 가 그 값으로 단언을 평가하므로 여기서 바꾸면
  판정이 달라진다.
- 비결정 필드의 무시 목록("이 필드는 비교에서 빼라")은 이번에 만들지 않았다. `record` 파트의
  카세트 매칭 키 책임과 겹치는 영역이라 필요해지면 이슈로 협의한다.
- 차이의 원인을 AI 로 진단하는 것은 별도 이슈로 미뤘다. 결정론성 검사가 비결정 도구에 기대는
  자기모순을 피한다.
