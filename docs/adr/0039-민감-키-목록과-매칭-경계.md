# ADR-0039: 민감 키 목록에 `cookie` 를 넣고 매칭을 단어 경계로 좁힌다 (ADR-0003 개정)

## 배경

ADR-0003 이 정한 기본 마스킹 목록은 일곱 개다 — `authorization`, `apikey`, `accesstoken`,
`refreshtoken`, `token`, `secret`, `password`. 이 목록이 두 방향으로 어긋나 있다.

**빠진 것.** `cookie` 와 `set-cookie` 가 없다. `authorization` 은 목록에 있는데, 세션
식별자를 나른다는 점에서 같은 급인 `Cookie` 가 없는 것은 일관성 결함이다. HTTP 응답 헤더를
그대로 돌려주는 툴이라면 세션 값이 카세트 파일과 경고 출력에 원문으로 남는다.
`normalizeKey` 가 `-` 와 `_` 를 제거하므로 `Set-Cookie` → `setcookie` 가 되어, 항목 하나로
둘 다 덮인다.

**과하게 잡는 것.** `sensitiveKey` 가 `includes` 부분일치라 `tokenCount` · `secretariat` ·
`passwordPolicy` 가 전부 마스킹된다. ADR-0003 이 "비밀값 마스킹은 정확성보다 안전을
우선한다"며 **명시적으로 감수한** 트레이드오프다.

두 문제가 서로 얽혀 있다. 부분일치를 유지한 채 `cookie` 만 추가하면 `cookieCount` ·
`cookiePolicy` · `cookieConsent` 가 새로 걸려 오탐이 곱해진다.

## 선택지

1. **`cookie` 만 추가한다.** 매칭 방식은 그대로 둔다.
2. **매칭만 좁힌다.** `cookie` 는 넣지 않는다.
3. **둘 다 한다.** 항목을 추가하고 매칭을 단어 경계 기준으로 좁힌다.
4. **사용자 정의 목록을 연다.** 기본값 논쟁을 사용자에게 넘긴다.

## 결정

**선택지 3 을 고른다.**

- 목록에 `cookie` · `setcookie` 를 추가한다.
- 매칭을 `includes` 부분일치에서 **단어 경계 기준**으로 좁힌다. `tokenCount` 는 걸리지 않고
  `accessToken` 은 걸린다.
- 사용자 정의 마스킹 규칙은 여전히 제공하지 않는다. ADR-0003 의 이 부분은 유지한다.

세 개정 중 **가장 먼저** 구현한다.

## 이유

**`Cookie` 는 `Authorization` 과 같은 급이다.** 둘 다 요청자의 신원을 증명하는 값을 나른다.
하나만 가리는 목록은 근거가 없다.

**항목을 늘리면서 매칭을 그대로 두면 손해가 커진다.** 부분일치는 항목 수에 비례해 오탐을
만든다. 지금도 `tokenCount` 가 걸리는데 여기에 `cookie` 를 얹으면 웹 콘텐츠를 다루는 툴에서
오탐이 눈에 띄게 늘어난다. 이 레포의 E2E 가 쓰는 `mcp-server-fetch` 가 정확히 그런 서버다.

**과잉 마스킹의 비용이 곧 바뀐다.** ADR-0003 이 과잉을 감수한 것은 비용이 "카세트 파일이 좀
지저분하다"였기 때문이다. 그 판단은 그때 타당했다. 그런데 ADR-0041 이 마스킹을 **테스트가
보는 값**에까지 닿게 하면 비용이 "테스트가 그 필드를 영영 못 본다"로 바뀐다. 같은
트레이드오프가 아니므로 판단도 같을 이유가 없다. 이 ADR 이 0041 보다 먼저 가는 이유가
그것이다 — 먼저 좁혀 두면 0041 의 폭발 반경이 작아진다.

**선택지 4 를 버린 이유.** 기본값이 틀린 채로 옵션을 열면 대부분의 사용자는 틀린 기본값을
쓴다. ADR-0003 이 첫 버전에서 사용자 정의 규칙을 배제한 판단을 유지한다.

## 결과

- ADR-0003 의 기본 마스킹 목록 문단과 "정확성보다 안전 우선" 문단을 개정한다.
- **카세트 파일 내용이 바뀐다.** `cookie` 계열이 새로 가려지고 `tokenCount` 계열은 안
  가려진다. 포맷과 `CASSETTE_VERSION` 은 바뀌지 않으므로 기존 카세트는 그대로 로드되지만,
  재녹화 전까지 옛 마스킹 결과를 갖는다.
- `packages/record/tests/index.test.ts` 의 `tokenCount: "[redacted]"` 기대값이 바뀐다. 이
  단언은 ADR-0003 이 승인한 동작을 고정한 것이므로, 수정은 정리가 아니라 결정을 바꾸는 행위다.
- 단어 경계의 정확한 정의(구분자 · 카멜케이스 경계 처리)는 구현 PR 에서 테스트로 고정한다.
