# ADR-0041: 마스킹은 경계에서 적용하고 런타임 내부는 원문을 유지한다 (ADR-0003 개정)

## 배경

`record` 실행과 `replay` 실행이 같은 요청에 다른 값을 돌려준다.

```
서버 응답: { tokenCount: 42, sessionToken: "abc", city: "Seoul" }

record run : {"tokenCount":42, "sessionToken":"abc", "city":"Seoul"}
replay run : {"city":"Seoul", "sessionToken":"[redacted]", "tokenCount":"[redacted]"}
```

`toInteraction` 은 `args` 만 즉시 마스킹하고 응답은 원문으로 둔다. 응답 마스킹은
`prepareCassetteForWrite`, 즉 **파일에 쓰는 시점에만** 걸린다. "인메모리는 원문"이 한
프로세스 안에서만 참이라, 파일을 거쳐 다음 실행으로 가면 무너진다.

**타입까지 바뀐다.** `{tokenCount: 128}` → `"[redacted]"` (number → string).
`raw.passwordPolicy.minLength` 를 보는 테스트는 1회차 통과, 2회차 `TypeError` 다.

이건 실수가 아니라 ADR-0003 이 승인한 설계의 결과다. 그 ADR 은 "응답 `content`/`raw` 와
`tools` 는 런타임 내부 카세트에서 원문을 유지하되, `onFlush` 에는 마스킹된 저장용 카세트만
넘긴다"고 명시했다. 현재 완화책은 `cli` 의 `replay-command` 가 마스킹된 경로를 stderr 로
고지하는 것뿐이고, 그 근거인 ADR-0028 은 아직 제안 상태다.

같은 문제의 표시 쪽 절반은 이미 닫았다. 중복 응답 경고가 비밀값 원문을 출력하던 문제를 PR
#169 가 "판정은 원문, 표시 직전에만 마스킹"으로 막았다. 이 ADR 은 그 방식을 나머지 경계로
일반화한다.

## 선택지

1. **현행 + 고지.** ADR-0028 의 경고를 유지하고 값 불일치는 남긴다.
2. **마스킹 대상이 있으면 `replay` 를 거절한다.**
3. **경계에서만 마스킹하고 내부는 원문을 유지한다.** `callTool` 반환값도 저장될 값과 같게
   만든다.
4. **마스킹을 메타데이터로 만든다.** 무엇이 마스킹됐는지 경로 목록을 카세트에 기록하고,
   재생 중 그 경로를 실제로 건드릴 때만 실패시킨다. 카세트 포맷 변경(v2)이 따른다.

## 결정

**선택지 3 을 고른다.** 마스킹은 값이 프로세스 밖으로 나가는 네 경계에서만 적용한다.

| 경계 | 무엇이 나가나 | 상태 |
|---|---|---|
| `onFlush` | 카세트 파일 | 이미 있음 (`prepareCassetteForWrite`) |
| `callTool` 반환 | 테스트가 보는 응답 | **이번에 추가** |
| `listTools` 반환 | 호출자가 보는 툴 선언 | **이번에 추가** |
| 사용자 표시 | 경고 · 실패 메시지 | PR #169 로 적용됨 |

**`listTools` 도 같은 경계다.** `replay` 모드는 카세트의 `tools` 를 돌려주고 `record`
모드는 실서버가 준 원문을 돌려준다. `callTool` 과 정확히 같은 비대칭이 툴 선언에도 있다.
여기에 적용되는 마스킹 규칙은 데이터가 아니라 스키마용이므로 **ADR-0040 을 따른다** — 두
ADR 이 만나는 자리다.

ADR-0003 의 "런타임 내부 카세트는 원문을 유지한다"는 **유지한다.** 바꾸는 것은 `callTool` 이
무엇을 반환하는가 하나다.

ADR-0039 · ADR-0040 다음, 마지막에 구현한다.

## 이유

**"비밀값 보호"와 "재생 결정론성"은 양립 불가로 보였지만, 실제로는 *언제 가리는가* 를 안
정해서 생긴 문제였다.** 경계를 정하면 둘이 동시에 선다. 안에서는 원문이라 비교와 판정이
정확하고, 밖으로 나갈 때만 가리므로 유출도 막힌다.

**PR #169 가 이걸 좁은 범위에서 먼저 실증했다.** 중복 응답 경고에서 마스킹한 값으로
비교했다면 서로 다른 두 비밀값이 같아져 "같은 요청에 다른 응답" 경고 자체가 사라졌을 것이고,
ADR-0003 이 그 경고에 기대한 효용("같은 요청에 다른 응답이 오는 서버는 비결정 서버로
드러난다")이 죽었을 것이다. 판정을 원문으로 두는 것이 기능을 살린다.

**선택지 2 를 버린 이유.** 사용자에게 빠져나갈 길이 없다. 비밀값 하나가 섞였다고 카세트
전체를 못 쓰게 되고, 재녹화해도 같은 자리에서 또 막힌다.

**선택지 4 는 지금이 아니다.** 손실을 기록하는 쪽이 더 근본적이지만 카세트 포맷 변경이 따르고,
ADR-0039 · ADR-0040 이 규칙을 정리하기 전에 하면 "무엇이 왜 마스킹됐는지"가 정해지지 않은 채
기록만 남는다. 규칙을 먼저 세우고 다음 단계로 미룬다.

**순서가 마지막인 이유.** 이 변경은 마스킹을 테스트가 보는 값에까지 닿게 한다. ADR-0039 로
과잉 마스킹을 먼저 좁혀 두지 않으면 `tokenCount` 같은 무해한 필드에서 대량으로 터진다.

## 결과

- ADR-0003 의 마스킹 시점 문단을 개정한다. "런타임 내부 원문 유지"는 살아남고, `callTool`
  반환값에 대한 규정이 새로 들어간다.
- **`--record` 실행이 새로 실패할 수 있다.** 마스킹된 필드를 보는 테스트는 지금 2회차에
  깨지는데 앞으로는 1회차부터 깨진다. 실패가 원인 가까이로 이동하는 것이므로 개선이지만,
  "어제까지 통과하던 것이 깨졌다"로 보이므로 릴리스 노트가 필요하다.
- 카세트 파일에 쓰이는 내용은 **이 ADR 만으로는 바뀌지 않는다.** 마스킹이 멱등이라 미리 걸어도
  결과가 같다. 다만 ADR-0039 · ADR-0040 이 값과 구조를 바꾸므로, 세 개정을 함께 적용한 뒤의
  카세트는 이전과 다르다. 호환성 계약은 ADR-0039 의 「카세트 호환성 계약」 절에 있다.
- `packages/record/tests/index.test.ts` 의 `.toBe(result)` 단언 — record 실행이 실서버 응답
  객체를 동일 참조로 돌려준다는 기대 — 가 바뀐다. ADR-0003 이 승인한 동작을 고정한 자리다.
- ADR-0028 의 stderr 고지는 **안전망으로 남긴다.** 1차 방어선이 아니라 이중 확인이 된다.
- **남는 문제.** 타입 변화(number → string)는 해결되지 않는다. 양쪽이 같아질 뿐 손실이
  없어지는 것은 아니다. 타입 보존 마스킹은 선택지 4 와 함께 별도로 다룬다.
