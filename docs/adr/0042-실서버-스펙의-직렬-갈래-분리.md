# ADR-0042: 실서버 스펙은 파일명 규약으로 갈라 러너가 직렬로 돌린다

- 상태: 제안
- 날짜: 2026-08-18
- 담당: 루트 러너 설정 (전 패키지 공유)
- 참조: 이슈 #119, #93(stdio-integration 의 PID 대기 예산), `docs/core-stdio-integration-flaky.md`,
  `CLAUDE.md`("결정론성이 핵심 가치다")

## 배경

실제 서버·자식 프로세스를 띄우는 스펙과 인메모리 스펙이 같은 러너 설정 안에 섞여 있었다.
수집 규칙은 `packages/*/tests/**/*.test.ts` 하나였고, "실서버 E2E 는 직렬로 돌린다" 는 규칙은
사람의 실행 순서에만 있었다.

vitest 는 파일을 병렬로 돌린다. `describe.sequential` 은 파일 안만 직렬화하고 파일 사이는
막지 못한다. 그래서 실프로세스 스펙끼리 서로의 타이밍 예산을 잠식해 **단독 실행은 녹색인데
전체 실행에서 간헐 실패**하는 일이 실제로 났다. 관측 셋.

1. 다른 세션이 동시에 `pnpm test` 를 돌리던 시점에 1건 실패, 단독 재실행은 초록.
2. 단독 실행 4회 중 1회 `stdio-integration` 의 handshake timeout 정리 검사 실패(#93).
3. 결정론성 E2E(단계 7)에서 프로세스 잔존을 프로세스 수로 판정하는 단언이 전체 실행에서
   **남의 파일이 띄운 같은 서버**를 내 좀비로 셌다.

이슈 등록 시점에 실프로세스 스펙은 5개였고 지금은 7개다. 스펙이 늘수록 재발했다.

## 선택지

**1. 갈래를 어떻게 가르나.**

- A안: 파일명 규약. `*-e2e.test.ts` 면 e2e 갈래. 이미 3개 파일(`repair-e2e` ·
  `fetch-server-e2e` · `determinism-e2e`)이 이 접미를 쓰고 있어 관례를 규약으로 승격하는
  것이고, 리네임 4개로 끝난다.
- B안: 디렉터리 분리(`tests/e2e/`). 이동 규모가 크고 상대 경로 import 가 전부 깨진다.
- C안: 지금처럼 사람이 지킨다. 새 기여자가 규칙을 모르면 그대로 깨지고, 실제로 두 번 깨졌다.

**2. e2e 갈래를 어떻게 직렬화하나.**

- D안: vitest `projects` 2개. e2e 갈래에만 `fileParallelism: false`. 인메모리 갈래는 그대로
  병렬이다.
- E안: 전역 `fileParallelism: false`. 인메모리 스펙까지 느려진다. 빠른 판정 루프가 죽는다.
- F안: 개별 스펙의 타임아웃·대기 예산 확대(#93 방향). 스펙이 늘수록 예산 경쟁이 다시
  일어난다. 증상 완화지 원인 제거가 아니다.

## 결정

A안 + D안. 파일명 규약 `*-e2e.test.ts` 로 갈래를 가르고, vitest `projects` 로 e2e 갈래만
파일 간 직렬로 돌린다.

```
unit: packages/*/tests/**/*.test.ts (단, *-e2e.test.ts 제외) — 병렬 유지
e2e:  packages/*/tests/**/*-e2e.test.ts — fileParallelism: false
```

`pnpm test` 하나로 두 갈래가 다 돈다. 판정 명령은 바뀌지 않는다.

## 이유

- **갈래 판정을 러너가 한다.** 사람이 기억할 것은 "프로세스를 띄우면 파일명에 `-e2e` 를
  붙인다" 하나로 줄었고, 그것을 잊어도 리뷰에서 파일명으로 보인다. 실행 순서라는 보이지 않는
  규칙보다 어기기 어렵다.
- **관례의 승격이라 이행 비용이 최소다.** 7개 중 3개는 이미 규약대로였고, 4개는 `git mv`
  뿐이다. 내용 수정 0바이트.
- **인메모리 갈래의 속도를 지킨다.** 직렬화는 프로세스를 띄우는 7개 파일에만 걸린다.
- 결정론성이 핵심 가치인 저장소에서 실행 순서에 따라 판정이 흔들리는 배치는 자기모순이다.

## 결과

- 전체 82개 파일이 unit 75 + e2e 7 로 갈렸다. 수집 누락 0, 갈래 누출 0을 실측으로 확인했다.
- e2e 갈래는 파일끼리도 직렬이므로, 프로세스 잔존을 프로세스 수로 판정하는 단언이 같은
  갈래 안에서는 남의 프로세스를 셀 일이 없다. 단 unit 갈래와는 여전히 동시에 돌므로, 그런
  단언은 **그 테스트 파일 전용 실행 파일**에만 걸어야 한다는 원칙은 그대로 유효하다.
- 실프로세스 스펙을 새로 쓸 때 파일명이 `*-e2e.test.ts` 가 아니면 병렬 갈래로 들어가
  간헐 실패로 나타난다. 이 사고가 나면 이 ADR 이 원인 문서다.
- `--project unit` / `--project e2e` 로 갈래 단독 실행이 가능해졌다. 인메모리만 빠르게
  돌리는 루프에 쓸 수 있다.
- #93(대기 예산)은 이 분리로 없어지는 문제가 아니다. 같은 갈래 안 직렬 실행에서도 기계가
  느리면 나는 실패라 별개로 남는다. 다만 병렬 잠식이 사라져 재현 빈도는 낮아질 것이다.
