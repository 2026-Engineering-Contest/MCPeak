# ADR-0043: npm `@ohmymcp` 스코프 선점에 따른 패키지 개명

- 상태: 제안 (스코프 확보 완료 — 개명 실행은 오너 전원 승인 대기)
- 날짜: 2026-08-17
- 작성자: @storyrago (③ mock server 파트 · 릴리스 담당)

## 배경

첫 알파 배포(#71) 준비 중 **`@ohmymcp` 스코프를 쓸 수 없다**는 것이 확인됐다.

```
@ohmymcp/pi-directx@0.1.0
  발행자: ev3lynx <evelyn.ofdrive1@gmail.com>
  발행일: 2026-08-05
  내용:   Pi 용 MCP 브리지 — OhMyMCP 와 무관한 프로젝트
```

npm 에서 스코프는 **동명의 조직 또는 사용자 계정**이 소유한다. 제3의 경로가 없고,
이미 패키지가 발행된 스코프는 조직 생성이 거부된다("This name is unavailable").
되찾을 방법이 없다.

이 문제가 지금까지 드러나지 않은 이유는, 저장소 안에서는 `@ohmymcp/*` 가 레지스트리를
타지 않기 때문이다. `workspace:*` 라 pnpm 이 로컬 폴더를 심볼릭 링크한다. **개발·테스트·CI
전 구간이 정상 동작하고 배포하는 순간에만 막힌다.**

리허설에서 확인한 가용 상태 (2026-08-17):

| 이름 | 상태 |
|---|---|
| `ohmymcp` (무스코프, CLI) | **가용** — 사용자가 실제로 치는 이름은 무사하다 |
| `@ohmymcp/*` (라이브러리 5개) | **불가** — 스코프 선점됨 |
| `ohmymcp-core`, `-runner`, `-generate`, `-record`, `-mock` | 전부 가용 |

개명 영향 범위(origin/main 기준 2026-08-18): **180 파일 / 551 참조** (`.ts` 87, `.md` 86, `.json` 7).
`packages/` 103, `docs/` 58, `.changeset/` 15, 그 외 루트 설정 4.

## 선택지

- **A안: 새 스코프로 옮긴다.** `@<새이름>/core` 형태를 유지한다. npm 조직을 만들어야 하고,
  가용 여부는 조직 생성 UI 에서 시도해야만 알 수 있다 (레지스트리 API 로 스코프 가용을
  조회하는 공개 엔드포인트가 없다).
- **B안: 무스코프로 평탄화한다.** `ohmymcp-core`, `ohmymcp-runner` … 조직이 필요 없고
  다섯 이름 모두 가용이 **확인됐다.**
- **C안: 개명하지 않고 CLI 하나만 배포한다.** 라이브러리 다섯을 `ohmymcp` 의 `dist` 로
  번들해 런타임 의존을 없앤다. 개명 0 파일, 조직 불필요.

## 결정

**A안을 택한다. 새 스코프는 `@ohmymcp-dev` 다.**

2026-08-17 npm 조직 `ohmymcp-dev` 를 생성해 스코프를 확보했다(소유자 `storyrago`, Free 플랜).
라이브러리 다섯의 이름은 다음과 같이 바뀐다.

| 현재 | 변경 후 |
|---|---|
| `@ohmymcp/core` | `@ohmymcp-dev/core` |
| `@ohmymcp/runner` | `@ohmymcp-dev/runner` |
| `@ohmymcp/generate` | `@ohmymcp-dev/generate` |
| `@ohmymcp/record` | `@ohmymcp-dev/record` |
| `@ohmymcp/mock` | `@ohmymcp-dev/mock` |

**CLI 의 이름 `ohmymcp` 은 바뀌지 않는다.** 무스코프라 조직과 무관하고 현재 가용이다.
사용자가 치는 `npm install ohmymcp` 는 그대로다.

개명 **실행**은 6 패키지 전부를 건드리므로 오너 전원의 승인이 필요하다. 이 ADR 은 이름을
확정했을 뿐 실행 승인을 대신하지 않는다.

## 이유

**A 와 B 의 개명 비용이 같기 때문이다.** 둘 다 180 파일을 건드린다. 비용이 같다면
스코프 쪽이 낫다 — 조직을 소유하면 그 네임스페이스 전체가 잠기므로 이번 같은 선점 사고가
다시 나지 않는다. B 는 이름 다섯 개를 각각 노출한 채로 둔다.

**C 를 권고에서 뺀 이유.** diff 가 0 이라 가장 싸지만, `@ohmymcp/runner` 를 라이브러리로
설치해 쓰는 사용 형태를 제품에서 빼는 결정이다. 그건 배포 방식이 아니라 **제품 범위**의
문제라 릴리스 담당이 단독으로 정할 수 없다. 또한 `cli` 를 얇게 유지한다는 구조 원칙
(CLAUDE.md)과 발행 산출물 수준에서 어긋난다. 팀이 "알파는 CLI 만"으로 합의하면 C 가
가장 합리적인 선택이 된다.

**지금 해야 하는 이유.** README 에 아직 `npm install` 예시가 없다(`pnpm install` 개발
셋업만 있다). 즉 **깨질 사용자 문서가 아직 없다.** 한 번이라도 발행한 뒤에 바꾸면 죽은
이름이 레지스트리에 영구히 남는다. 코드 동결이 2026-08-24 다.

## 결과

**공통으로 얻는 것**

- 사용자 진입점 `npm install ohmymcp` 는 어느 안을 택하든 바뀌지 않는다. 무스코프
  이름이라 조직과 무관하고 현재 가용이다.

**받아들이는 비용 (A·B)**

- 180 파일 / 551 참조의 기계적 치환. 6 패키지 전부를 건드리므로 **오너 전원의 합의와
  협조**가 필요하다 (CLAUDE.md "다른 오너의 패키지를 수정하지 마라").
- `docs/adr/` 의 기존 ADR 56 개가 옛 이름을 참조한다. 기록물이므로 그대로 두면 이름이
  어긋나고, 고치면 과거 기록을 사후 편집하는 셈이 된다. 이 ADR 이 대응표 역할을 한다.
- `.changeset/*.md` 15 개가 `"@ohmymcp/mock": minor` 형태로 패키지명을 담고 있다.
  개명 시 함께 바꿔야 changesets 가 깨지지 않는다.

**순서 제약**

개명은 **PR #112(Version Packages) 머지 이후**에 해야 한다. #112 는 `.changeset/*.md`
21 개와 `packages/*/package.json` 6 개, `CHANGELOG.md` 6 개를 건드리는데, 개명이 정확히
같은 파일들을 건드려 정면 충돌한다. #112 를 먼저 머지하면 changeset 이 소비되어 사라지고
충돌면이 `package.json` 6 개로 줄어든다.

**후속 과제**

- 스코프 이름이 정해지면 이 ADR 의 상태를 `채택` 으로 올리고 결정 항목을 채운다.
- 개명 실행 절차는 `docs/2026-08-17-npm-알파-배포-준비.md` 에 있다.
