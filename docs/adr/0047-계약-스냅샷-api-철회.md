# ADR-0047: 계약 스냅샷 API(`snapshotContract`)를 철회한다

- 상태: 채택
- 날짜: 2026-08-19
- 작성자: @ddxng5 (② replay/record 파트)
- 승인: 승인 (2026-08-19, @ddxng5 · ② replay/record 파트 오너 — 작성자 본인)
- 개정 대상: [ADR-0003](./0003-cassette-matching-key.md) 「결정」의 계약 스냅샷 문단

## 배경

ADR-0003 은 `snapshotContract(result)` 를 결정 항목으로 넣었다. `ToolResult.raw` 를 깊게
순회해 `id` · `requestId` · `sessionId` · `timestamp` · `createdAt` · `updatedAt` ·
`expiresAt` 을 제거한 뒤 비밀값을 마스킹하는 함수다. 전제는 "실행마다 달라지는 값이 계약
스냅샷에 남으면 실제 동작은 같아도 테스트가 실패한다" 였다.

구현하고 배포한 지금(0.1.1), 실제 상태는 이렇다.

- `cli` · `runner` · `generate` · `mock` · `core` 중 **어느 패키지도 이 함수를 부르지
  않는다.** 소비자가 0 이다.
- 카세트 저장 경로(`prepareCassetteForWrite`)도 `redact` 만 부른다. 즉 카세트에
  `timestamp` 가 있으면 그대로 저장되고 그대로 재생된다. 녹화·재생·매칭 어느 경로에도
  이 함수가 끼어들지 않는다.
- 이 함수만 쓰는 코드는 `NONDETERMINISTIC_KEYS` · `normalizeKey` · `transformJson` 의
  옵션 두 개로 약 18 줄이다. 나머지 순회 로직은 `redact` 와 공유한다.

그 사이 [ADR-0038](./0038-결정론성-확인의-비교-대상과-캡처-위치.md) 이 같은 문제에
**반대 방향의** 답을 냈고 그쪽이 실제로 배선됐다. `runner/src/determinism.ts` 는 같은
시험을 두 번 돌려 응답을 바이트로 비교하고, 차이가 나면 지우는 대신 경로와 값을 보고하며
`timestamp` · `randomId` · `numericDrift` 힌트를 붙인다. 그 파일의 주석이 이유를 직접
적고 있다 — "파싱하면 공백·키 순서 차이가 흡수돼 바이트 비결정을 놓친다."

record 자신도 이미 같은 철학으로 동작한다. 같은 키에 다른 응답이 오면 첫 응답을 유지하고
경고하며, 그 문장은 "이 툴은 오라클로 쓸 수 없습니다" 로 끝난다. ADR-0003 이 그렇게
정했다. 비결정 필드를 조용히 지우는 `snapshotContract` 는 같은 ADR 안에서 반대 방향을
보고 있다.

## 선택지

- A안: 그대로 둔다.
  - 언젠가 계약 판정이 필요해지면 쓸 수 있다.
  - 그때까지 `package.json` description · README · ADR-0003 세 곳이 "제공한다" 고
    말하는데 실제로는 아무 경로에도 없다. 공개 API 는 부르는 사람이 없어도 계약이라,
    바꾸거나 지울 때 비용을 낸다. 배포된 패키지라 더 그렇다.
- B안: export 만 떼고 내부에 남긴다.
  - 아무도 못 부르는 코드가 18 줄 남는다. 죽은 코드에는 테스트를 유지할 근거도, 지울
    근거도 안 생긴다. 가장 나쁜 쪽이다.
- C안: 함수와 전용 코드를 함께 지우고, 문서에서 이 기능을 제공하지 않는다고 명시한다.
  - 공개 API 축소라 배포된 패키지에는 breaking 이다.
  - 다만 npm 상의 소비자가 우리 자신뿐이고(모노레포 내 참조 0), 0.x 다.

## 결정

C안. `snapshotContract` 를 공개 API 에서 제거하고, 이 함수만 쓰던
`NONDETERMINISTIC_KEYS` · `normalizeKey` · `transformJson` 의 옵션 분기까지 함께
걷어낸다. `transformJson` 은 옵션이 사라지면 `redact` 와 같은 함수가 되므로 `redact` 가
본체를 흡수하고, 짝 헬퍼는 `redactJsonString` 으로 개명한다.

`redact` 의 동작은 바뀌지 않는다. 마스킹 경계 세 곳(`callTool` 반환 · `listTools` 반환 ·
`onFlush`)도 그대로다.

record 는 비결정 필드를 **제거하지 않는다.** 실행 간 차이를 판정하는 일은 ADR-0038 의
결정론성 확인이 맡는다. README 「제외 범위」에 이것을 명시한다.

## 이유

지우는 근거는 "안 쓰니까" 가 아니다. 안 쓰이는 이유가 더 중요하다. 이 함수의 전제를
프로젝트가 이미 뒤집었다. CLAUDE.md 가 「결정론성이 핵심 가치다」로 적은 것은 "비결정
값을 무해하게 만든다" 가 아니라 "같은 입력에 항상 같은 결과가 나오게 한다" 이고, 그
기준에서 비결정 필드를 조용히 지우는 것은 문제를 고치는 게 아니라 증거를 지우는 것이다.
ADR-0038 이 그 판단을 내렸고 `runner` 가 그대로 구현했다.

A안을 고르면 문서가 계속 거짓말을 한다. 남겨 두는 비용이 코드 18 줄이 아니라 "우리가
제공한다고 적어 둔 것과 실제로 동작하는 것이 다르다" 는 상태의 유지 비용이다. 실패
메시지가 제품인 도구에서 문서와 구현의 불일치는 그냥 버그다.

breaking 을 감수하는 근거는 소비자가 우리뿐이라는 점이다. 모노레포 안에서 이 심볼을
import 하는 곳은 0 이고, 0.x 라 외부에서 고정해 쓰고 있다고 보기 어렵다. 나중에 계약
판정이 정말 필요해지면 그때 필요한 형태는 지금 이 시그니처가 아닐 가능성이 크다 —
ADR-0038 이 정한 비교 대상은 `raw` 하나가 아니라 `status` · `assertionStatuses` ·
`response` 셋이다.

## 결과

- `@ohmymcp-hsu/record` 의 공개 API 가 하나 줄어든다. minor 로 올린다(0.x breaking).
- src 약 76 줄이 줄고, 테스트 2 개가 없어진다. 남은 47 개는 통과한다.
  `cookieCount` 를 마스킹하지 않는다는 고정은 「이름에 민감 단어가 들어 있어도 머리가
  아니면 마스킹하지 않는다」 케이스가 이미 갖고 있다.
- `package.json` description 이 "녹화 · 재생 · 계약 스냅샷" 에서 "녹화 · 재생" 이 된다.
- ADR-0003 「결정」의 계약 스냅샷 문단은 이 ADR 로 철회된다. `redact` 의 마스킹 목록과
  판정 규칙은 그대로 유효하다.
- 계약 판정이 다시 필요해지면 ADR-0038 의 비교 대상을 출발점으로 새 ADR 을 쓴다. 이
  ADR 은 그 문을 닫지 않는다.
