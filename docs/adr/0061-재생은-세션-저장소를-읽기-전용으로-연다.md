# ADR-0061: 재생은 세션 저장소를 읽기 전용으로 연다

- 상태: 채택
- 날짜: 2026-08-23
- 담당: record (배선은 cli)
- 작성자: @ddxng5 (② replay/record 파트)
- 승인: 승인 (2026-08-23, @ddxng5 · ② replay/record 파트 오너가 검토하고 결정)
- 선행 결정: [ADR-0052](./0052-coordinator가-engine과-session-store를-소유한다.md)
- 참조: [#291](https://github.com/2026-Engineering-Contest/MCPeak/issues/291)

## 배경

`createSqliteSessionStore` 는 모드를 구분하는 인자를 받지 않고, 열 때마다 스키마 DDL 과
`meta` INSERT 를 **무조건** 실행했다. 녹화에는 맞는 동작이지만 재생(`--session`)은 읽기다.

그 어긋남이 결함 둘로 나타났다(#291).

1. **읽기 전용(chmod 444) 세션은 재생이 불가능하다.** 케이스가 한 건도 실행되지 않고
   `attempt to write a readonly database` 로 끝난다. 저장소에 커밋한 세션 · CI 아티팩트
   캐시 · 읽기 전용 마운트에서 재생을 쓸 수 없다.
2. **0바이트 파일을 넘기면 실패한 실행이 그 파일을 빈 세션 DB(36,864바이트)로 덮어쓴다.**
   재생은 실패하는데 사용자 파일은 바뀐다. 사용자는 바뀐 줄 모른다.

**CLI 층은 이미 "재생은 읽기" 를 전제로 적혀 있었다.** `external-wiring.ts` 와
`test-command.ts` 주석 둘이 그렇게 말한다. 저장소 층만 그 전제를 지키지 않았다.

같은 파일의 `loadSession` 은 이미 `readOnly: true` 로 열며, 그 주석이 이유를 적어 두었다 —
"기본 모드로 열면 없는 경로에 빈 DB 를 만들고 스키마까지 심는다."

## 선택지

- **A안**: `createSqliteSessionStore` 에 `readOnly` 옵션을 더한다. 호출자가 모드에 맞춰 켠다.
- **B안**: 첫 호출로 모드를 추론한다. 첫 연산이 읽기면 읽기 전용으로, 쓰기면 읽기·쓰기로 연다.
- **C안**: `createReplaySessionStore` 를 별도 팩토리로 낸다.
- **D안**: 저장소 생성을 Coordinator 안으로 옮긴다. Coordinator 는 이미 mode 를 안다.

## 결정

**A안 — `readOnly` 옵션.** 기본값은 `false` 라 녹화 경로는 무변경이다.

켜면 DB 를 읽기 전용으로 열고 DDL·`meta` INSERT 를 돌리지 않는다. 더해 **우리가 만들지 않은
파일을 받는 자리**이므로 판정과 거부를 여기서 한다.

| 대상 | 결과 |
|---|---|
| 없는 경로 | `SESSION_NOT_FOUND` · 파일을 만들지 않는다 |
| 0바이트 · 세션 아닌 SQLite | `SESSION_NOT_FOUND` · 파일 불변 |
| `meta.store_version` 불일치 | `SCHEMA_VERSION_UNSUPPORTED` |
| `meta` 만 있고 세션 테이블이 없음 | `SESSION_NOT_FOUND` · 핸들을 닫는다 |
| 정상 세션 | 읽기 정상 · 녹화 계열 호출은 우리 문장으로 거부 |

`ExternalErrorCode` 는 늘리지 않는다. 공개 union 이라 항목을 더하면 소비자의 exhaustive
switch 가 깨진다.

## 이유

**B안(첫 호출로 추론)을 버린 이유는 호출 순서가 계약이 되기 때문이다.** cli 수정 없이 지금
당장 고쳐진다는 이점이 실제로 있었다 — 녹화는 `createSession`, 재생은 `read` 로 시작하므로
오늘은 성립한다. 그러나 발행되는 라이브러리에서 그것은 **문서에 적히지 않는 계약**이고,
"읽고 나서 쓰는" 소비자가 하나 생기면 조용히 깨진다. 조용히 깨지는 것이 이 결함의 성질과
같다는 점이 결정적이었다 — #291 자체가 "실패가 조용히 파일을 바꾼다" 는 문제다.

**C안(별도 팩토리)을 버린 이유는 표면만 넓어지기 때문이다.** `SessionStore` 계약이 쓰기
메서드를 요구하므로 결국 던지는 구현이 되고, 호출자 수정도 A안과 똑같이 필요하다.

**D안(Coordinator 소유)을 버린 이유는 이 결함에 비해 변경이 크기 때문이다.** store 수명
(`close()`)을 호출자가 쥐는 현재 계약(ADR-0052)을 바꿔야 한다. 그 계약을 바꿀 이유가
따로 생기면 그때 별도 ADR 로 다룬다.

**판정을 `loadSession` 과 같은 방식으로 한 이유는 한 파일 안에서 답이 갈리면 안 되기
때문이다.** 다만 **답의 형태는 다르다.** `loadSession` 은 프로젝트를 훑는 판별기라 아닌
파일이 정상 입력이고 그래서 `null` 이다. 여기는 사용자가 **이 파일로 재생하겠다고 지목한**
자리라 왜 안 되는지를 말해야 한다.

**세션이 없는 파일과 version 이 다른 파일을 가르는 이유는 사용자가 할 일이 정반대여서다** —
앞은 경로를 고치는 것이고 뒤는 다시 녹화하는 것이다.

## 결과

- **이 결정만으로는 사용자에게 결함이 사라지지 않는다.** 운영 호출자는
  `packages/cli/src/external-wiring.ts` 하나이고, 거기서 `readOnly` 를 넘겨야 한다.
  패키지 경계 규칙(`CLAUDE.md`)상 **별도 PR** 이다. 그전까지 #291 은 열려 있다.
- **세션 파일 경로는 저장소의 문장에 싣지 않는다.** 사용자가 아는 식별자는 경로이고 그것은
  호출자만 안다. 경로를 붙이는 것은 cli 의 몫이며 [#290](https://github.com/2026-Engineering-Contest/MCPeak/issues/290)
  이 그 이슈다.
- **읽기 전용 파일 테스트는 Windows 에서 건너뛴다.** `chmod` 로 소유자의 쓰기를 막지 못한다.
  결함이 보고된 환경은 POSIX 이고 CI 의 verify 잡은 ubuntu 라 거기서 실측된다.
- 재생 경로가 파일을 만들지 않게 되면서, 재생 실패 안내에서 **'쓰기 권한' 이라는 말을 뺄 수
  있다.** `test-command.ts` 주석이 이미 그 전제를 적어 두었고, 그 정리는 cli PR 에서 한다.
- 이 결정이 뒤집히려면 "재생 중에 세션 파일을 써야 하는" 요구가 실측돼야 한다. 지금
  replay 엔진은 `read` 와 `lookup` 만 부르고 `finish()` 도 순수 인메모리다.
