# ADR-0067: 결정론성 힌트는 패턴 존재가 아니라 값 변화로 판정한다

- 상태: 초안
- 날짜: 2026-08-23
- 담당: runner
- 작성자: @endl24 (① MCP 서버 테스트 파트)
- 선행 결정: [ADR-0038](./0038-결정론성-확인의-비교-대상과-캡처-위치.md)
- 참조: [#293](https://github.com/2026-Engineering-Contest/MCPeak/issues/293)

## 배경

결정론성 진단은 차이 지점마다 원인 추정 한 줄을 붙인다. 문장은 셋이다 — `timestamp` ·
`randomId` · `numericDrift`. #293 이 관측한 것은 **그중 둘이 실서버에서 한 번도 안 나온다**는
것이다.

실서버는 결과를 JSON 으로 만들어 text content 블록에 문자열로 감싸 보내는 것이 기본이다. 그러면
비교 지점이 `content[0].text` 가 되고 그 값은 `{"user":"example","token":"a29017…"}` 같은 JSON
전문 한 덩어리다. `UUID_PATTERN` 은 `^…$` 앵커라 블록 전체가 UUID 하나일 때만 걸리고,
`numericDrift` 는 `typeof === "number"` 분기에만 있는데 text content 는 언제나 string 이라 도달
자체가 안 된다. 앵커가 없던 `TIMESTAMP_PATTERN` 하나만 살아 있었다.

비교 대상을 파싱하지 않는 것은 ADR-0038 이 정한 것이고 바꿀 이유가 없다 — 파싱하면 공백·키
순서 차이가 흡수돼 바이트 비결정을 놓친다. 그러니 고칠 자리는 힌트 판정 한 곳이다.

## 선택지

- **A안**: 앵커만 뗀다. `UUID_PATTERN` 의 `^…$` 를 지우고 `numericDrift` 에 숫자 패턴을 더한다.
- **B안**: 힌트 판정용으로만 text 를 JSON 파싱해 값 단위로 본다. 비교는 원본 그대로 둔다.
- **C안**: 앵커를 떼되 판정을 `test()` 에서 **뽑은 자리 값의 변화**로 바꾼다. 우선순위대로 훑으며
  앞 패턴이 집은 자리를 마스킹하고, 마스킹 후에도 두 문자열이 다르면 힌트를 달지 않는다.

## 결정

**C안을 채택한다.**

패턴은 앵커 없이 부분 일치로 찾는다. 다만 "패턴이 있다" 가 아니라 **양쪽에서 뽑은 자리 값이
실제로 달라졌는가** 로 판정한다. 우선순위는 `timestamp` → `randomId` → `numericDrift` 이고,
앞 패턴이 집은 자리는 다음 패턴이 보기 전에 마스킹한다.

패턴을 모두 가린 뒤에도 두 문자열이 다르면 **힌트를 달지 않는다.** 패턴 밖 무언가가 함께 변한
경우이고, 그때 원인을 단정하면 사용자가 짚어준 값을 고쳐도 여전히 다르다.

`typeof === "number"` 분기는 남긴다. `structuredContent` 와 `listTools` 에서는 여전히 도달한다.

## 이유

**A안은 `numericDrift` 를 만능 힌트로 만든다.** 부분 일치로 `test()` 만 하면 숫자를 품은 모든
JSON 이 걸린다. `{"city":"서울","code":200}` 처럼 숫자가 그대로인 응답에도 "측정값 변동으로
보입니다" 가 붙는다. 안 나오는 문장을 나오게 하려다 **틀린 문장이 늘 나오게** 된다.

**A안은 이미 있는 오귀속도 그대로 둔다.** `TIMESTAMP_PATTERN` 은 앵커가 없어서, 시간은 그대로고
옆자리가 변한 응답에도 "시간 의존으로 보입니다" 를 붙여 왔다. 뽑은 값을 대조하면 이 갈래가 같이
사라진다.

**B안은 ADR-0038 이 비교에서 막은 것을 판정으로 들여온다.** 비교와 판정에서 서로 다른 값을 보게
되면, 화면이 짚은 지점(`content[0].text`)과 힌트가 말하는 근거가 다른 층이 된다. 파싱 실패
갈래(JSON 이 아닌 text)도 새로 생긴다. 얻는 정확도는 C안이 파싱 없이 이미 준다.

**마스킹 순서가 있어야 하는 이유는 숫자다.** 타임스탬프와 UUID 는 그 자체가 숫자를 품고 있어서,
가리지 않으면 숫자 패턴이 같은 자리를 다시 집는다. 그러면 시간이 변한 응답이 `numericDrift` 로
분류될 수 있다.

**침묵을 택한 것은 이 저장소에서 실패 메시지가 제품이기 때문이다.** 힌트는 "보입니다" 로 끝나는
추정이지만, 추정도 틀리면 사용자를 엉뚱한 곳으로 보낸다. 근거를 댈 수 있을 때만 말한다.

## 결과

- 공개 API 는 그대로다. `DeterminismHint` · `DeterminismDifference` · `checkDeterminism` ·
  `describeDeterminismDifference` 와 힌트 문장 셋 모두 변경 없다. 바뀐 것은 `detectHint` 내부뿐이다.
- 실서버 기본 형태에서 힌트 셋이 모두 나온다. 이슈의 재현 서버로 확인했다 — `now` → timestamp,
  `issue_token` → randomId, `measure` → numericDrift, 결정론적인 `echo` 는 차이 없음.
- **오귀속 하나가 사라진다.** 타임스탬프가 같고 옆자리만 변한 응답은 이제 시간 탓을 하지 않는다.
- **힌트가 사라지는 갈래가 하나 생긴다.** 패턴 밖 차이가 섞이면(예: UUID 도 도시 이름도 함께
  변함) 이전에도 힌트가 없었지만, 이제는 타임스탬프가 섞인 경우까지 침묵한다. 의도한 교환이다.
- `numericDrift` 문장은 카운터·순번 변화에도 붙는다. `{"seq":1}` → `{"seq":2}` 가 "측정값
  변동으로 보입니다" 로 읽힌다. #293 은 판정 버그만 다루므로 문구 재검토는 별건으로 남긴다.
- 마스크는 비문자 U+FFFF 로 시작하되, 치환 전에 **양쪽 본문에 없는 토큰이 될 때까지 늘린다.**
  고정값이면 그 토큰이 실제로 실린 응답에서 마스킹한 두 문자열이 우연히 같아져 없는 원인을
  지목한다 — UUID 와 그 토큰의 자리가 맞바뀐 두 응답이 그렇다. 회귀 테스트로 고정했다.
