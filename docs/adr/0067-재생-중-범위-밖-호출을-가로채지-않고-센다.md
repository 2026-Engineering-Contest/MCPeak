# ADR-0067: 재생 중 범위 밖 호출을 가로채지 않고 센다

## 배경

ADR-0057 이 어댑터 범위를 `globalThis.fetch` 로 그었고, 범위를 벗어나면 경고한다고 정했다.
그 경고는 **"녹화 0건"** 을 트리거로 삼는다. 그래서 서버가 전부 범위 밖일 때만 뜬다.

**실제 서버는 섞어 쓴다.** 한 툴 호출 안에서 `fetch` 로 한 번, `node:http`(또는 axios·got)로
한 번 나가는 서버를 만들어 재현했다.

| | 녹화 실행 | 재생 실행 |
|---|---|---|
| 서버가 실제로 낸 호출 | fetch 1 + http 1 | fetch 1 + http 1 |
| origin 이 받은 호출 | 2건 | **1건 — http 쪽이 라이브로 나갔다** |
| 세션에 남은 것 | 1건 | — |
| 화면에 나온 경고 | **없음** | **없음** |

`interactionCount = 1 > 0`, `consumedCount = 1 > 0`, `unusedCount = 0`. **경고 네 갈래가 전부
이 상황을 비켜간다.** 사용자가 보는 것은 초록과 "1건을 재생했습니다" 뿐이고, 그 실행의 절반은
오늘의 라이브 응답이다.

**결정론성을 핵심 가치로 내건 도구에서 가장 아프게 틀리는 자리다.** 재생의 값은 "외부가 변해도
같은 결과" 인데, 부분 커버리지에서는 그 보장이 절반만 성립하면서 화면은 전부 성립한 것처럼
보인다. ADR-0066 이 붙인 결과 문장은 이 오독을 **강화**했다 — 침묵하던 자리에 "재생했습니다"
라는 단정이 들어갔기 때문이다.

## 선택지

**A안: 조건절로 끝낸다.** "범위 밖 호출은 재생 중에도 실제 네트워크로 나갑니다" 를 항상 붙인다.
ADR-0066 이 지금 하고 있는 것이다.

**B안: 어댑터 범위를 넓힌다.** `node:http`·`node:https` 도 가로채 재생 대상으로 만든다.
ADR-0057 을 뒤집는다.

**C안: 가로채지 않고 센다.** 범위 밖 호출이 몇 건 실제로 나갔는지 관측해 사실로 알린다.

**D안: 재생에서 범위 밖 호출을 막는다.** 나가려 하면 실패시킨다.

## 결정

**C안 — `diagnostics_channel` 로 관측한다.** 함께 고정한 것 넷.

1. **채널은 `http.client.request.created`.** 원숭이 패치를 쓰지 않는다. 요청 객체를 읽지도
   바꾸지도 않고 개수만 올린다.
2. **Coordinator 왕복은 제외한다.** 어댑터의 클라이언트가 `node:http` 를 쓰므로
   (`child/coordinator-client.mjs`), 필터가 없으면 재생마다 거짓 경고가 난다.
3. **개수는 자식 종료 시 동기로 파일에 쓴다.** 부모가 자식 종료 후 읽고 지운다.
4. **`undefined` 는 0 이 아니라 "못 셌음" 이다.** 세 갈래를 끝까지 구분한다.

| 실측 | 화면 |
|---|---|
| `N > 0` | `경고: 범위 밖 호출 N건이 실제 네트워크로 나갔습니다` + 재현 불가 + 대안 |
| `0` | 깨끗한 성공 문장. ADR-0066 의 조건절을 **뗀다** |
| `undefined` | 조건절 유지 |

## 이유

**A안으로 끝낼 수 없는 이유는 조건절이 사실이 아니기 때문이다.** "나갈 수 있습니다" 는 나간
실행과 안 나간 실행에 똑같이 붙는다. 그러면 두 가지가 동시에 나빠진다 — 실제로 샌 실행에서
경고의 무게가 없고, 안 샌 실행에서는 읽히지 않는 소음이 된다. 이 저장소가 `expected true, got
false` 를 금지하는 것과 같은 이유로, **개수를 말할 수 있으면 말해야 한다.**

**B안을 버린 이유는 ADR-0057 이 이미 그 값을 매겼기 때문이다.** 그리고 범위를 넓히는 것은 끝이
없다 — `node:http` 다음은 네이티브 애드온이고, 그다음은 다른 런타임이다. 범위를 긋는 결정 자체는
유효하고, 이 ADR 이 고치는 것은 **범위 밖에서 무슨 일이 일어났는지 모른다는 것**이지 범위가
좁다는 것이 아니다.

**그래서 관측과 대체를 가르는 것이 이 결정의 핵심이다.** ADR-0057 이 금지한 것은 그 호출을
*대체*하는 일이다. *관측*은 다른 일이다 — 서버의 동작이 한 바이트도 안 바뀐다. 그 구분이 말로만
남지 않게 `diagnostics_channel` 을 골랐다. 원숭이 패치로도 셀 수 있지만, 패치는 "지금은 통과만
시킨다" 가 "다음에 조금 손댄다" 로 미끄러지는 자리다. Node 가 관측 전용으로 내놓은 통로를 쓰면
그 미끄러짐이 구조적으로 막힌다.

**D안(막기)을 버린 이유는 그것이 재생의 계약을 바꾸기 때문이다.** 지금 재생은 "서버는 실제로
실행한다" 가 전제다(ADR-0051). 범위 밖 호출을 실패시키면 그 서버는 재생 자체가 불가능해지고,
사용자는 아무 진단도 없이 깨진 서버를 본다. 먼저 **알리는** 것이 맞고, 막을지는 알린 뒤에 사용자가
정할 문제다.

**전달 방식으로 종료 시 파일 쓰기를 고른 것은 경합 때문이다.** 세 가지를 놓고 쟀다.

- **기존 요청에 얹기** — 재생 lookup 에 카운터를 붙인다. **마지막 in-scope 호출 이후에 나간
  것을 놓친다.** 재현 픽스처가 정확히 그 모양(`fetch` 다음에 `node:http`)이라 잡으려는 케이스를
  못 잡는다. 그래서 픽스처의 호출 순서는 회귀 방어이고, 주석에 "바꾸지 마라" 를 적었다.
- **호출마다 비콘** — 정확하지만 마지막 비콘이 종료와 경합한다. 잃는 자리가 하필 위와 같다.
- **종료 시 동기 쓰기** — `exit` 훅에서는 동기 IO 만 가능하므로 파일에 쓴다. 꼬리 호출까지
  정확하고 경합이 없다.

종료 사다리가 **stdin close → SIGTERM → SIGKILL**(`core/src/lifecycle.ts`)이라 정상 경로는
자식의 자연 종료이고, `exit` 훅은 Windows 에서도 뛴다. 강제 종료된 서버에서만 못 센다.

**"못 셌음" 과 0 을 가르는 것이 이 설계에서 가장 중요한 한 줄이다.** ADR-0062 의 `bodyUrls` 는
"자식이 안 보내면 셀 대상이 없다" 로 다뤘는데 여기서는 정반대다 — 부재는 "샜을 수도 있는데 못
봤다" 는 뜻이다. 없음을 0 으로 접으면 이 ADR 이 없애려는 거짓 안심을 그 자리에서 다시 만든다.

## 결과

- **재생이 재현 가능했는지를 화면이 사실로 말한다.** 0 을 확인한 실행에서는 ADR-0066 이 붙인
  조건절이 사라진다 — 관측을 붙인 값이 정상 실행의 화면에서도 나타난다.
- **`ReplaySessionSummary.outOfScope` 가 새 필드다.** 선택 필드이며 Store 는 채우지 않는다.
  Coordinator 가 자식의 보고를 읽어 요약에 얹는다. 세션 파일 포맷은 안 바뀌므로 기존 세션도
  그대로 읽힌다.
- **덮는 범위는 Node 의 `node:http`·`node:https` 와 그 위의 라이브러리다**(axios·got).
  `fetch` 는 undici 채널이라 안 잡힌다 — 어댑터가 이미 처리하므로 잡히면 이중 계산이다.
- **안 덮는 것.** Python·Go 서버는 다른 런타임이라 닿지 않는다(그쪽은 녹화 0건이라 기존 경고가
  잡는다). **네이티브 애드온이 소켓을 직접 여는 Node 서버는 여전히 못 본다** — 실측된 사례가
  아니라 여기 한계로만 적는다.
- **관측 가능 여부 자체를 테스트가 지킨다.** `subscribe` 는 없는 채널 이름에도 조용히 성공하므로,
  채널이 없는 런타임에서는 개수가 늘 0 이 되고 아무 테스트도 빨개지지 않는다. 그래서 채널의
  발행을 직접 단언한다 — 지원 하한(Node 22.18)에서 성립하지 않으면 CI 가 알려 준다.
- **부분 커버리지 픽스처가 생겼다**(`external-mixed-server.mjs`). 전부 범위 안·전부 범위 밖
  픽스처 사이에 빠져 있던 자리다. 이것이 사라지면 이 ADR 의 근거도 사라진다.
- 재검토 조건: 네이티브 애드온이나 다른 런타임에서 유출이 실측 보고되면 관측 수단을 다시 본다.
  그리고 "막을 것인가"(D안)는 이 알림이 실제로 쓰인 뒤에 다시 꺼낸다 — 사용자가 이 경고를 보고
  무엇을 하는지가 그 판단의 재료다.
