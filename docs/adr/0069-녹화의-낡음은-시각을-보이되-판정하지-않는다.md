# ADR-0069: 녹화의 낡음은 시각을 보이되 판정하지 않는다

## 배경

**녹화본은 낡는다.** 석 달 전에 녹화한 세션도 원본 API 가 그 사이 바뀐 뒤 그대로 재생되고,
테스트는 초록으로 통과한다. 그 초록은 "이 서버가 지금도 그렇게 동작한다" 가 아니라 "녹화 시점의
외부 응답에 대해서는 그랬다" 만 증명한다.

ADR-0059 가 이것을 명시적으로 남겨 두었다.

> External 세션의 드리프트 재검증 수단이 없다. `verify` 가 카세트에 대해 하던 일의 External
> 판이 없으며, 이 ADR 도 그것을 만들지 않는다. 녹화가 낡는 문제는 그대로 남는다 — **별도 ADR
> 대상이다.**

구현 계획서 A-2 도 선택지를 셋으로 적어 두었다 — (a) 재검증 명령을 뒤로 미룬다, (b) 세션에 녹화
시각·나이를 남기고 Replay 종료 시 경고한다, (c) 아무것도 하지 않되 "이 도구는 외부 API 드리프트를
감지하지 않는다" 를 문서에 못 박는다.

**이 결정을 지금 하는 이유는 앞선 두 결정이 그 자리를 비워 놓았기 때문이다.** ADR-0066 이
"성공한 재생도 무엇을 했는지 말한다" 를, ADR-0068 이 "재생이 재현 가능했는지 말한다" 를 넣었다.
그 두 문장을 읽은 사용자가 다음으로 묻는 것이 **"그 녹화본은 언제 것인가"** 다. 답할 자리를
만들어 놓고 비워 두면 사용자는 그 답이 없다는 사실조차 모른다.

### 데이터는 이미 있다

`interactions.recorded_at` 이 interaction 마다 저장돼 있다(`session-store-sqlite.ts`). 지금까지
어떤 요약에도, 어떤 화면에도 나오지 않았을 뿐이다.

## 선택지

**A안: 나이를 계산해 보여준다.** `12일 전에 녹화됨`.

**B안: 임계값을 넘으면 경고한다.** `30일 넘은 녹화입니다`. 계획서의 (b) 다.

**C안: 시각만 보여준다.** `2026-05-01 09:12:33 UTC 녹화`. 판정은 사람이 한다.

**D안: 아무것도 하지 않고 문서에만 적는다.** 계획서의 (c) 다.

**E안: 실제로 재검증한다.** 원본 API 를 다시 불러 녹화본과 비교한다. 제거된 `verify` 의
External 판이다.

## 결정

**C안 — 시각만 보여준다.** 함께 고정한 것 넷.

1. **`ReplaySessionSummary.recordedAt`** 은 원본에서 **가장 먼저** 녹화된 시각이다. 세션이
   언제 시작됐는지가 낡음의 기준이므로 마지막이 아니라 첫 번째다.
2. **나이도 임계값도 계산하지 않는다.** 그러려면 지금 시각을 읽어야 한다.
3. **`toLocale*` 를 쓰지 않는다.** ISO 를 문자열로 잘라 `UTC` 를 명시한다.
4. **원본이 비었으면 없다.** 없는 것을 지금 시각이나 빈 문자열로 채우지 않는다.

```
→ 녹화된 외부 호출 1건을 재생했습니다: tmp/weather.db (2026-08-23 13:41:40 UTC 녹화)
```

## 이유

**A안·B안을 버린 이유는 결정론이다.** 나이나 임계값 경고는 지금 시각을 읽으므로, **같은 세션의
같은 재생이 날마다 다른 바이트를 낸다.** 이 저장소는 결정론을 핵심 가치로 걸었고
(`CLAUDE.md`), 대시보드 e2e 는 같은 실행의 SSE 이벤트가 바이트까지 같은지 단언한다
(`dashboard-e2e.test.ts`). 임계값은 특히 나쁘다 — 어제 초록이던 실행이 오늘 아무 변경 없이
경고를 낸다. "같은 입력에 항상 같은 결과" 를 정면으로 어긴다.

**시각은 저장된 값이라 언제 읽어도 같다.** 그래서 같은 성질을 잃지 않고 사용자가 필요한 정보를
얻는다. 판정에 필요한 나머지 절반 — "이 API 는 얼마나 자주 바뀌는가" — 은 애초에 도구가 알 수
없고 사용자만 안다. **모르는 쪽이 판정하지 않는 것이 맞다.**

**이것은 ADR-0062 가 이미 그은 선이다.** 그쪽도 URL 개수만 말하고 "위험하다" 고 판정하지 않았다.
사실을 주고 판단을 남기는 편이, 틀릴 수 있는 판정을 얹는 것보다 낫다.

**`toLocale*` 를 금지하는 것은 같은 이유의 연장이다.** 로캘·타임존은 기계의 성질이라, 같은
세션이 CI 와 개발자 기계에서 다른 문자열을 낸다. 결정론이 프로세스 안에서만 성립하고 기계를
넘으면 깨지는 것은 반쪽이다. `UTC` 표기를 붙이는 것은 그 대가다 — 안 붙이면 KST 사용자가 자기
시간으로 읽어 9시간을 착각한다. 밀리초는 낡음을 판단하는 데 쓸모가 없어 뺀다.

**D안(문서만)을 버린 이유는 데이터가 이미 있기 때문이다.** 저장돼 있는 값을 안 보여 주면서
"감지하지 않습니다" 라고만 적는 것은, 할 수 있는 것을 안 하는 쪽에 가깝다. 다만 D안이 요구한
문서화 — "이 도구는 외부 API 드리프트를 감지하지 않는다" — 는 **여전히 유효하고 아래 「결과」에
남긴다.** 시각을 보여주는 것은 감지가 아니다.

**E안(재검증)이 진짜 답이지만 이 결정의 범위가 아니다.** 원본 재호출, 비교 규칙("어디까지
달라지면 드리프트인가" — 응답 본문의 시각·순번은 원래 달라진다), 새 서브커맨드 표면이 전부
필요하다. 코드 동결(2026-08-24)을 하루 앞두고 시작할 크기가 아니다. **미루는 것을 명시적으로
결정한다** — 계획서 A-2 의 (a) 다.

## 결과

- **재생 결과 문장이 원본의 녹화 시각을 함께 낸다.** 녹화 실행에는 붙지 않는다 — 그 시각은
  "지금" 이라 쓸모가 없고, 출력에 지금 시각을 넣는 순간 결정론이 깨진다.
- **`ReplaySessionSummary.recordedAt` 이 새 선택 필드다.** Store 는 이미 값을 갖고 있었고
  Engine 이 요약에 옮긴다. **세션 파일 포맷은 안 바뀌므로 기존 세션도 그대로 읽힌다** — 구
  버전 파일이라 모양이 다르면 파싱하지 않고 원문 그대로 보여준다(정보를 버리지 않는다).
- **이 도구는 외부 API 드리프트를 감지하지 않는다.** 시각을 보여주는 것은 "언제 찍었는지" 를
  알려 주는 것이지 "그 사이 바뀌었는지" 를 아는 것이 아니다. 낡은 녹화로 통과한 초록은 여전히
  초록이다. 이 문장은 D안이 요구한 못 박기이며, E안이 들어오기 전까지 유효하다.
- **후속: External 재검증(E안).** 동결 이후 또는 다음 사이클의 일이다. 그때 정해야 하는 것은
  기능 유무가 아니라 **비교 규칙**이다 — 응답의 어떤 차이가 드리프트이고 어떤 차이가 정상인지.
  ADR-0053 의 정규화 규칙이 그 출발점이 된다.
- 재검토 조건: 사용자가 시각만 보고는 판단하지 못한다는 보고가 오면 A안·B안이 아니라 E안으로
  간다. 나이 계산은 그때도 답이 아니다 — 결정론을 깨는 값이라는 성질은 변하지 않는다.
