# ADR-0070: 원격 서버의 인증 헤더는 값이 아니라 환경변수 이름으로 받는다

- 상태: 제안
- 날짜: 2026-08-23
- 담당: cli
- 작성자: @endl24 (① MCP 서버 테스트 파트)
- 선행 결정: [ADR-0020](./0020-streamable-http-transport.md), [ADR-0013](./0013-렌더러-배치와-진단-무분기.md)
- 참조: [#137](https://github.com/2026-Engineering-Contest/MCPeak/issues/137)

> **번호 주의**: 0069 로 열었다가 0070 으로 옮겼다. 이 브랜치가 리뷰를 기다리는 사이
> [ADR-0069](./0069-녹화의-낡음은-시각을-보이되-판정하지-않는다.md)(record)가 같은 번호를 집은 채
> main 에 먼저 들어왔다. [#233](https://github.com/2026-Engineering-Contest/MCPeak/issues/233) 이
> 세고 있는 재배정의 **16회차**이며, 앞선 15회와 원인이 같다 — 번호를 브랜치에서 배정한다.

## 배경

ADR-0020 이 `core` 에 Streamable HTTP 를 추가했고 `connectHttp` 는 2026-08-14 부터 동작한다
(#16 CLOSED). 그런데 CLI 에는 그 경로가 배선되지 않아 **라이브러리로는 되고 도구로는 안 되는**
상태가 두 주 넘게 이어졌다. `docs/adoption.md` §1.2 가 그 사실을 적고 있고, §10 도그푸딩
대상에서 원격 서버가 통째로 빠져 있었다.

배선하면서 정해야 할 것이 하나 있었다. **원격 MCP 서버는 대부분 인증을 요구한다.** 헤더를
어떻게 받을지가 이 ADR 이 다루는 결정이다.

`curl -H 'Authorization: Bearer …'` 관례를 그대로 따르면 토큰이 argv 에 실린다. argv 는
`ps` 목록에 그대로 노출되고 셸 히스토리 파일에도 남는다. 우리가 만든 노출이다.

이 저장소는 이미 같은 종류의 판단을 여러 번 했다. ADR-0033(stderr 외부 전송 경계),
ADR-0040·0041(마스킹 규칙과 적용 경계), ADR-0062(세션 본문의 URL 은 지우지 않고 알린다)가
모두 "비밀이 새는 경로를 좁힌다" 쪽이었다. #183 은 반대 방향의 사례다 — 설계 문서가 redaction
을 약속했는데 배선이 따라오지 않아 **"막은 척"** 이 됐고, 그 자체가 결함으로 열려 있다.

## 선택지

### A. `--header 'Name: value'` — curl 관례 그대로

- 장점: 설명이 필요 없다. 스크립트에서 값을 바로 넘긴다.
- 단점: 토큰이 `ps` 와 셸 히스토리에 남는다. **가장 흔한 사용례가 가장 위험한 경로가 된다.**

### B. `--header` 와 `--header-env` 를 둘 다 준다

- 장점: 편의와 안전을 사용자가 고른다.
- 단점: 둘 다 있으면 짧은 쪽이 기본이 된다. 문서에 경고를 달아도 복사·붙여넣기하는 사람은
  경고를 안 읽는다. 안전한 길을 만들어 놓고 위험한 길을 나란히 두면 우리는 아무것도 안 막았다.

### C. `--header-env <헤더이름>=<환경변수이름>` 만 준다

값은 환경변수에서 읽고 argv 에는 **이름만** 싣는다.

- 장점: 노출 경로가 구조적으로 없다. 우회하려면 사용자가 의도적으로 해야 한다.
- 단점: curl 과 달라 처음 보면 낯설다. 옵션 이름이 길다.

### D. 헤더를 이번 범위에서 빼고 인증 없는 엔드포인트만 지원한다

- 장점: 결정을 미룬다.
- 단점: 원격 MCP 의 대부분이 인증을 쓴다. 배선해 놓고 실제로 못 붙이는 상태가 된다.

## 결정

**C안을 채택한다.** `--header-env <헤더이름>=<환경변수이름>` 만 두고 평문 `--header` 는 두지
않는다. 함께 정한 것이 셋 더 있다.

1. **`--url` 에 자격증명을 넣으면 거절한다.** `https://user:token@host` 는 C안을 우회해 토큰을
   argv 에 싣는 가장 쉬운 길이다. 막지 않으면 이 결정의 근거가 그대로 무너진다.
2. **환경변수 이름 자리에 값을 넣으면 거절한다.** `--header-env Authorization=Bearer abc` 는
   POSIX 환경변수 이름 문자셋(`^[A-Za-z_][A-Za-z0-9_]*$`)에서 걸린다. 이 정규식이 편의가 아니라
   안전 근거다.
3. **실패 문장에 값을 싣지 않는다.** 환경변수가 비었을 때 이름만 말한다. 값이 비었다는 사실을
   알리려다 값을 화면에 찍으면 이 옵션이 존재하는 이유가 없어진다.

## 이유

**B안을 고르지 않은 것이 이 결정의 실질이다.** 안전한 경로를 추가하는 일은 위험한 경로를 남겨
두면 아무것도 바꾸지 않는다. 짧고 익숙한 쪽이 기본이 되고, 문서의 경고는 복사·붙여넣기를
막지 못한다.

낯섦은 화면으로 갚는다. `--help` 가 이 옵션이 값을 안 받는 **이유**를 말한다 — "명령줄에 쓴
토큰이 `ps` 목록과 셸 히스토리에 그대로 남기 때문입니다". 이유를 모르면 이 옵션은 번거로운
`--header` 로 보이고, 사용자는 우회로를 찾다가 우리가 막으려던 노출을 스스로 만든다.

거절 문장도 같은 원칙을 따른다. 값을 직접 넣은 사용자에게 형식만 말하지 않고 왜 이렇게
받는지와 올바른 예시(`MCP_TOKEN='Bearer …' mcpeak … --header-env Authorization=MCP_TOKEN`)를
함께 준다. **실패 메시지가 곧 제품이다**(CLAUDE.md).

환경변수를 읽는 일은 `readEnv` 주입점으로 뺐다. CLI 코드가 `process` 를 직접 읽지 않는
ADR-0013 의 경계를 그대로 유지한다.

## 결과

- 인증이 필요한 원격 MCP 서버를 `mcpeak test` · `mcpeak generate` 로 검사할 수 있다. §10
  도그푸딩 대상에 원격 서버가 들어온다.
- **스크립트에서 값을 바로 못 넘긴다.** 환경변수를 거쳐야 한다. CI 는 대부분 시크릿을 이미
  환경변수로 주므로 오히려 자연스럽지만, 손으로 한 번 돌려 보는 경우엔 한 단계가 는다.
- `--header-env` 는 `--url` 과 함께만 쓸 수 있다. stdio 서버와는 헤더를 주고받지 않는다.
- 나중에 `--header` 를 추가하려면 이 ADR 을 뒤집어야 한다. 그때 필요한 것은 "편해서" 가
  아니라 A안의 단점이 해소됐다는 근거다.
- 이 결정은 헤더 값이 **프로세스 환경에 있다**는 것까지만 보장한다. 환경변수 자체가 프로세스
  덤프나 자식 프로세스로 새는 경로는 그대로 남는다. argv 노출보다 좁을 뿐 0 은 아니다.

## 곁가지 — 함께 정한 것

같은 배선에서 나온 판단 넷을 여기 남긴다. 각각은 ADR 을 따로 쓸 만큼 크지 않다.

| | 결정 | 이유 |
|---|---|---|
| 플래그 이름 | `--url` (`--http` 아님) | `--http` 는 값 없는 스위치로 읽힌다. `core` 의 `HttpConnectOptions.url` 과 이름이 같다 |
| `--stderr-lines` | **명시하면** 거절, 기본값이면 무시 | 기본값까지 거절하면 `--url` 사용자가 전원 막힌다. 명시했는데 조용히 무시하면 #183 이 말한 "막은 척" 이 된다 |
| External 세션 옵션 | `--url` 과 함께 거절 | External 배선은 자식 프로세스 환경변수로 주입한다. 원격 서버에는 그 자식이 없어 주입 지점이 없다 |
| HTTP 진단 | 렌더러를 새로 만든다 | ADR-0020 이 만든 `url`·`status`·`statusText`·`sessionId` 를 CLI 가 받는 자리가 없었다. stdio 가드가 HTTP 진단을 걸러내므로, 배선만 하면 원격 실패가 **진단 없이** 끝난다 |

마지막 항목에 딸린 세부 판단 둘:

- **연결 실패 경로는 내용 판정을 걸지 않는다.** 상태 코드가 없어도(DNS 실패, 연결 거부) 어느
  엔드포인트에 붙으려다 실패했는지가 정보다. 실행이 끝난 뒤의 경로에서만 `status !== null` 을
  본다 — core 는 상태 코드를 실패 경로에서만 채우므로, 판정 없이 그리면 초록불 뒤에 매번 빈
  블록이 붙는다.
- **상태 코드가 없을 때 `(없음)` 이라고 쓰지 않는다.** stdio 의 `종료 코드: 없음` 은 "아직 안
  죽었다" 지만 HTTP 에서는 "응답에 닿지 못했다" 로 뜻이 정반대다. 같은 문구를 쓰면 읽는
  사람이 200 을 받았다고 읽는다.
