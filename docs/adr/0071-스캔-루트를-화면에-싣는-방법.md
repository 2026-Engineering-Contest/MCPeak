# ADR-0071: 스캔 루트는 `GET /api/meta` 로 나르고, 절대 경로를 그대로 보여준다

- 상태: 제안
- 날짜: 2026-08-23
- 담당: dashboard (공동)
- 작성자: @storyrago
- 승인: 미승인
- 참조: `docs/adr/0046-대시보드를-로컬-웹서버로-만든다.md`,
  `CONTRIBUTING.md` §4-7 (커밋 문서의 로컬 절대 경로 금지),
  `packages/dashboard/src/server/routes.ts`,
  `packages/dashboard/tests/scaffold.test.ts`,
  이슈 #296

## 배경

대시보드는 서버를 띄운 디렉터리(`process.cwd()`) 아래에서 스위트를 찾는다. 다른 곳에서 띄우면
첫 화면이 통째로 빈다. 원인은 거의 언제나 그 경로 하나인데, 지금까지 화면은 "스위트가
없습니다." 한 줄만 말했다. 사용자는 **도구가 고장 난 것**과 **폴더를 잘못 고른 것**을 구분할 수
없었다.

서버는 그 값을 이미 안다 — `startDashboardServer({ root })` 로 받는다. 문제는 브라우저가 그것을
알 방법이 없다는 것이다. 라우트 표(`routes.ts:44-79`) 어디에도 root 를 내보내는 경로가 없고,
`listSuites` 는 `toRelative` 로 상대경로만 담는다.

앞선 커밋에서 **터미널 기동 줄**에는 이미 실었다(#296 의 절반). 남은 것은 화면이다.

## 선택지

**경로 — root 를 브라우저까지 어떻게 나르나**

| | 방법 | 판정 |
|---|---|---|
| A | `GET /api/suites` 응답을 `{ root, suites }` 로 바꾼다 | 기각 — `apiGet<FileEntry[]>` 가 깨지는 breaking |
| B | `FileEntry` 에 `root` 필드를 더한다 | 기각 — **목록이 0건이면 값이 안 온다.** 필요한 그 순간에 비어 있다 |
| C | `GET /api/health` 를 `{ ok: true, root }` 로 확장한다 | 기각 — 아래 |
| D | `index.html` 에 `window.__MCPEAK_ROOT__` 로 주입한다 | 기각 — 정적 서빙 한복판에 치환·길이 재계산 갈래가 생기고 타입 없는 전역이 는다 |
| E | 응답 헤더 `X-Mcpeak-Root` | 기각 — `apiGet` 이 파싱된 JSON 만 준다. 타입 계약 밖의 값이 된다 |
| F | **새 라우트 `GET /api/meta` → `{ root }`** | **채택** |
| G | **아예 안 나르고, 화면이 터미널의 `스위트 탐색 루트` 줄을 가리킨다** | 기각 — 아래 |

**표시 — 절대 경로를 그대로 띄우나**

1. 그대로 띄운다.
2. 홈 디렉터리를 `~` 로 접는다.
3. 마지막 두 단계만 보여준다.

## 결정

**경로는 F, 표시는 1번.**

`api-types.ts` 에 `ServerMeta { root: string }` 을 추가하고, `routes.ts` 의 `/api/health` 분기
바로 뒤에 `/api/meta` 를 둔다. `Home.tsx` 가 마운트 시 한 번 읽고, 실패는 삼켜 `null` 로 둔다.

빈 목록 문안은 세 줄이다.

```
이 디렉터리 아래에서 스위트를 찾지 못했습니다: <절대경로>
→ 스위트가 있는 디렉터리에서 mcpeak-dashboard 를 다시 띄우거나, 왼쪽 Generate 로 새로 만드세요.
목록에는 스위트 형식을 통과한 .json 만 담습니다. node_modules · .git · dist 아래는 보지 않습니다.
```

## 이유

**C(health 확장)를 버린 이유.** 크기는 F 와 거의 같다. 갈린 지점은 **이름이 사실과 맞는가**
하나다. `tests/scaffold.test.ts:10` 이 `toEqual({ ok: true })` 로 그 응답을 **완전 일치**로
잠가 뒀다 — 확장하면 즉시 깨진다. 그리고 `Home` 이 "health" 를 불러 설정값을 얻는 코드는 읽는
사람에게 거짓말이다. 헬스 프로브는 살아 있는지만 답해야 한다.

**G(안 나른다)를 버린 이유.** 8줄이면 되고 공개 타입도 안 는다 — 가장 싼 안이다. 그런데 이슈
제목이 "**스캔 루트를 어디에도 안 보여준다**" 이고, G 는 여전히 안 보여주고 다른 데를 가리킨다.
터미널이 늘 보이는 것도 아니다 — 스크립트로 띄웠거나, 창을 닫았거나, 스크롤이 지나갔으면
헛말이 된다. `CLAUDE.md` 의 "어떻게 고치는지가 보여야 한다" 를 한 단계 우회로 만드는 값이
62줄보다 크다고 봤다.

**절대 경로를 그대로 띄우는 이유.** 이 서버는 `127.0.0.1` 에만 바인드한다(`index.ts:82`).
페이지를 받는 브라우저는 그 경로의 주인과 같은 사람, 같은 기계다. 값이 기계 밖으로 나가지
않는다. `CONTRIBUTING.md` §4-7 은 "**저장소에 커밋하는 문서에** 로컬 절대 경로를 쓰지 않는다"
로 범위가 명시돼 있고, 런타임 화면 렌더는 그 대상이 아니다.

**`~` 로 접지 않는 이유.** 같은 값을 터미널 기동 줄이 이미 절대 경로로 찍는다. 두 자리의 표기가
갈리면 "터미널과 화면을 대조한다" 는 용도 자체가 사라진다.

## 결과

- **공개 타입이 하나 늘었다.** `ServerMeta` 는 major 없이 못 지운다. 순수 추가라 기존 소비자는
  안 깨지지만, 되돌릴 수 없다는 사실은 그대로다.
- `/api/meta` 응답은 **기계마다 다르다.** 스냅샷·바이트 동일성 비교에 절대 넣지 않는다.
- 화면 테스트는 `/api/meta` 갈래를 **반드시** 스텁해야 한다. catch-all 이 `[]` 를 주면
  `meta.root` 가 `undefined` 가 되어 안내가 조용히 경로 없는 갈래로 샌다. `home.test.tsx` 의
  `stubFetch` 가 그 실패를 일부러 만들 수 있게 `meta` 인자를 받는다.
- 화면 조건은 `root === null` 이 아니라 **진리값**(`root ? … : …`)으로 쓴다. 위 사고를 한 겹 더
  막는다.
- 나중에 "공유용 표시 모드" 가 생긴다면 터미널 줄과 화면을 **같이** 바꾼다. 한쪽만 접으면
  대조가 깨진다.
