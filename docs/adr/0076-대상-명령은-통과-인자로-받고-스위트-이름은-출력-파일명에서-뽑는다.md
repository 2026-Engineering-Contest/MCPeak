# ADR-0076: 대상 명령은 `--` 통과로 받고, 스위트 이름은 `--out` 파일명에서 뽑는다

- 상태: 채택
- 날짜: 2026-08-24
- 담당: cli (공동)
- 작성자: @storyrago
- 승인: 승인 (2026-08-24, @storyrago · 릴리스·문서 관점에서 검토하고 결정)
  이 승인이 닫는 것은 **설계 판단**뿐이다. `cli` 는 공동 소유이므로(`CONTRIBUTING.md` §2.1)
  이 결정을 실행하는 PR 의 머지는 §5-2 가 요구하는 타 파트 오너 리뷰를 따로 받는다.
- 참조: `packages/runner/src/fingerprint.ts` (`suiteFingerprint`),
  `docs/adr/0017-승인-지문-계산-범위.md`,
  `README.md` §30초 예제, 이슈 #242

## 배경

발행본 가이드를 쓰다가 첫 명령이 세 줄이 됐다.

```bash
mcpeak generate --suite-id weather --name "날씨 서버 계약" \
  --out contract.suite.json \
  --command mcpeak-mock --arg weather.mock.json --baseline-only
```

**플래그 여섯 중 정보를 담은 것은 `--out` 과 `--baseline-only` 둘뿐이다.**

비싼 것은 타이핑이 아니다. 가이드는 복사·붙여넣기고 실사용자는 서버당 한 번 친다. 비싼 것은
**읽기 비용**이다 — README 의 "30초 예제" 자리에 플래그 벽이 서 있으면 도구가 무거워 보인다.
처음 여는 사람이 보는 첫 화면이 그것이다.

## 선택지

**대상 명령을 어떻게 받나**

1. 지금대로 `--command` · `--arg`.
2. **`--` 뒤를 통과 인자로 받는다.** `--command` 는 그대로 둔다.
3. `--` 로 바꾸고 `--command` 를 없앤다.

**스위트 id · name**

1. 지금대로 둘 다 필수.
2. **`--out` 파일명에서 뽑는다.** 명시하면 그쪽이 이긴다.
3. 고정 기본값(`suite`)을 쓴다.

## 결정

**둘 다 2번.**

```bash
mcpeak generate --out weather.suite.json -- node ./server.js
```

`--` 뒤 첫 토큰이 실행 파일, 나머지가 그 인자다. **`--command` 와도 `--arg` 와도 함께 쓸 수
없다** — `test` · `generate` 두 커맨드 모두 같다.

| 조합 | 결과 |
|---|---|
| `--command x -- y` | 사용 오류. 대상이 둘이 되면 어느 쪽을 띄울지 화면이 말할 수 없다 |
| `--arg x -- y` | 사용 오류. `--arg` 값이 통과 인자 **앞에** 끼어들어 사용자가 적지 않은 순서로 서버가 뜬다 |
| `--` 뒤가 빔 | 사용 오류 |
`contract.suite.json` → id·name 모두 `contract`. `.json` 을 떼고 `.suite` 가 남으면 그것도 뗀다.
뽑을 이름이 없으면(`.suite.json`) 조용히 빈 값을 만들지 않고 직접 지정하라고 한다.

## 이유

**`--` 는 설명이 필요 없다.** npm · cargo · docker · npx 가 전부 쓴다. 그리고 **뒤에 오는 것을
우리가 해석하지 않는다** — `--arg` 가 값 검사에 두던 특수분기(`option !== "--arg" && value.startsWith("--")`)
가 이 경로에는 필요 없다. `--port 0` 같은 값을 그대로 넘길 수 있다.

**파괴적 변경이 아니다.** 두 서브커맨드 모두 지금 `--` 를 `지원하지 않는 옵션` 으로 거절한다.
그 자리를 쓰고 있는 사용법이 없으므로 그대로 가져다 쓴다. `--command` 를 없애지 않은 것은
(3번 기각) 기존 스크립트와 문서가 그대로 돌아야 하기 때문이다.

**고정 기본값(id 축 3번)을 버린 이유.** 스위트가 둘 이상인 저장소에서 전부 `suite` 가 되면
id 가 식별자 노릇을 못 한다. 파일명은 사용자가 이미 구분해서 지은 값이다.

## 결과

- **출력 파일명이 승인 지문에 들어간다.** `suiteFingerprint` 는 `approval` 만 빼고 전부
  해시한다(ADR-0017). id·name 을 파일명에서 뽑았다면 **파일명을 바꿔 다시 생성할 때 지문이
  달라져 재승인이 뜬다.** 그 사실을 `--out` 도움말이 말한다. 고정하려면 `--suite-id` 와
  `--name` 을 직접 지정한다.
- 이 결합은 **명시값이 없을 때만** 생긴다. 기존처럼 둘을 주는 사용자는 파일명을 바꿔도
  지문이 그대로다.
- 사용법 한 줄이 길어졌다 — 세 갈래(`--`, `--command`, `--url`)를 다 적기 때문이다.
  README 는 `--` 하나만 보여주고 나머지는 아래 문단에서 말한다.
- **오류 문안이 셋 늘었다** — `--command` 병용, `--arg` 병용, `--` 뒤 빔. 셋 다 조용히
  하나를 고르지 않는다. 특히 `--arg` 병용은 조용히 통과시키면 **사용자가 적지 않은 순서로**
  서버가 뜨므로 가장 나쁘다.
- `--out` 의 확장자 제거는 **대소문자를 구분하지 않는다.** `--out` 검사 자체가 `.json` 을
  비구분으로 받으므로, 한쪽만 구분하면 `contract.SUITE.JSON` 이 통과한 뒤 id 로 파일명
  전체가 들어간다.
