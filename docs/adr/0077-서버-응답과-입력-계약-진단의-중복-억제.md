# ADR-0077: 서버 응답과 입력 계약 진단은 확실히 같은 타입 위반일 때만 한 번 표시한다

- 상태: 제안
- 날짜: 2026-08-25
- 담당: cli (공동)
- 작성자: @sunghoon0303
- 참조: 이슈 #350, ADR-0027,
  `packages/cli/src/test-command.ts` (`responseRepeatsTypeMismatch`)

## 배경

`mcpeak test` 는 실패한 `isError` 단언 아래에 서버 응답 본문을 그대로 옮긴다(ADR-0027).
그와 별도로 CLI 는 테스트 명세의 입력과 서버의 `inputSchema` 를 대조해 입력 계약 finding 을
보고서 뒤 `참고:` 블록에 표시한다.

인자 타입이 서버 선언과 다른 경우에는 두 출처가 같은 사실을 말할 수 있다.

```text
→ 툴 'get_weather' 의 'city' 은(는) string 이어야 합니다. 받은 값: 12345 (number)

참고: city-number 의 입력이 서버 선언과 다릅니다
  → input.city 의 타입이 다릅니다. 서버 선언: 'string', 명세: 'number'
```

서버 본문은 서버가 실제로 답한 내용이고, 입력 계약 finding 은 서버가 아무 설명을 하지 않을 때도
나오는 독립 진단이다. 둘 중 하나를 항상 없애면 다른 실행에서 필요한 정보를 잃는다. 반대로 둘을
항상 유지하면 한 실패 원인이 두 문제처럼 읽힌다. 따라서 **어떤 서버 문장을 같은 사실로 볼지**가
별도 정책이 된다.

## 선택지

- **A. 두 출력을 항상 유지한다.** 출처를 전부 보존하지만 같은 사실이 반복된다.
- **B. 서버 응답 본문을 숨긴다.** 중복은 없어지지만 서버가 실제로 무엇이라고 답했는지 잃고
  ADR-0027과 충돌한다.
- **C. 입력 계약 finding 을 항상 숨긴다.** 서버가 조용히 실패하거나 모호한 문장만 반환하면
  타입 위반을 설명하는 유일한 단서가 사라진다.
- **D. 서버 문장을 자연어·유사도로 해석해 겹치는 finding 을 숨긴다.** 표현 차이는 넓게 잡지만
  비슷한 단어를 쓴 다른 사실까지 같은 말로 오인할 수 있다.
- **E. 구조적으로 확인되는 표식이 모두 같은 `TYPE_MISMATCH`만 텍스트에서 숨긴다.** 확실하지
  않은 경우에는 기존 finding 을 유지한다.

## 결정

**E안.** 서버 응답의 한 줄에 다음 표식이 모두 있을 때만 그 케이스의 `TYPE_MISMATCH` finding 을
사람이 읽는 `참고:` 블록에서 제외한다.

1. 입력 필드명
2. 서버가 기대한 타입
3. 실제 타입 또는 실제 입력값

표식은 단어 경계로 비교한다. `id` 가 `invalid` 안에 들어 있다는 이유로 같은 값이라고 보지 않는다.
세 표식은 **같은 응답 줄**에 있어야 한다. 서로 무관한 여러 줄의 단어를 조합해 하나의 설명으로
판정하지 않는다.

억제는 텍스트 출력 단계에만 적용한다. `RunnerReport`의 서버 응답 `notes`와 `--json`의
`spec.findings`는 원문과 구조를 그대로 보존한다. 한 케이스에 다른 입력 계약 finding 이 함께
있으면 겹치는 `TYPE_MISMATCH` 한 건만 제외하고 나머지는 표시한다.

`REQUIRED_MISSING`, `UNDECLARED_FIELD`, `ENUM_MISMATCH`, `RANGE_MISMATCH` 등은 이 정책의 억제
대상이 아니다. 현재 자료만으로는 같은 사실을 오탐 없이 판별할 공통 표식이 충분하지 않다.

## 이유

- **정보 손실보다 일부 중복을 택한다.** 실패 진단을 잘못 숨기면 사용자는 원인을 찾을 수 없지만,
  애매한 중복 한 줄이 남는 것은 원인을 찾는 일을 막지 않는다.
- **서버 원문을 보존한다.** 서버 본문은 관측값이고 입력 계약 finding 은 우리 판정이다. 관측값을
  지우지 않고 우리 표시만 접어 ADR-0027의 경계를 유지한다.
- **자연어 해석을 정책으로 만들지 않는다.** 언어와 문체가 다른 서버를 키워드나 유사도로
  판정하면 오탐 규칙이 계속 늘어난다. 구현이 이미 가진 구조화 값만 사용한다.
- **기계 출력은 안정적으로 유지한다.** 자동화 소비자는 문장 중복이 아니라 finding code로
  분기하므로 `--json`에서 값을 빼지 않는다.
- **한 건씩 억제한다.** 같은 블록의 다른 위반까지 함께 숨기면 서버가 말하지 않은 사실도
  사라진다.

## 결과

- 이슈 #350의 재현에서는 서버 응답 본문이 한 번만 보이고, 뒤의 중복 타입 참고는 나오지 않는다.
- 서버 응답이 `city 값을 처리할 수 없습니다.`처럼 필드만 말하면 타입 설명이 충분하지 않으므로
  기존 참고가 남는다.
- 타입 위반과 미선언 필드가 함께 있으면 타입 finding 만 숨고 미선언 필드는 계속 보인다.
- `--json`에는 억제된 `TYPE_MISMATCH`도 그대로 들어간다. 공개 API와 타입, `schemaVersion`은
  바뀌지 않는다.
- 같은 사실을 여러 줄에 나눠 쓴 서버나 타입을 자연어로만 표현한 서버에서는 중복이 남을 수 있다.
  이는 유일한 단서를 잘못 숨기지 않기 위해 받아들이는 미탐이다.
- 다른 finding 종류의 중복 사례가 생기면 이 ADR을 개정해 그 종류에 필요한 구조적 표식을 별도로
  정한다. 타입 규칙을 일반화해 추측하지 않는다.

## 승인

- `cli`는 공동 소유 영역이므로 이 제안은 PR 리뷰에서 다른 파트 오너의 승인을 받아야 한다.
- 되돌리는 조건: 실제 서버 응답에서 서로 다른 사실을 같은 타입 위반으로 오인해 필요한 finding 이
  사라지는 사례가 확인되면 억제를 제거하거나 표식 조건을 더 좁힌다.
