# ADR-0079: Claude provider는 `--safe-mode` 없이 공통 지원 인자로 실행한다

- 상태: 제안
- 날짜: 2026-08-25
- 담당: generate
- 작성자: @sunghoon0303
- 선행 결정: [ADR-0006](./0006-ai-assisted-test-authoring.md),
  [ADR-0007](./0007-provider-전송-스키마-분리.md),
  [ADR-0065](./0065-옵션-이름은-stderr-가-아니라-우리-args-에서-고른다.md)
- 참조: 이슈 #285, `packages/generate/src/providers.ts` (`claudeSpec`)

## 배경

Claude provider는 모든 호출에 `--safe-mode`를 붙였다. Claude Code 2.1.148은 이 옵션을 몰라
인자를 해석하는 단계에서 종료한다. `generate`의 authoring과 `repair`의 진단이 같은 adapter를
사용하므로 두 경로 모두 요청을 API에 보내기 전에 실패한다.

Claude Code 2.1.235에는 이 옵션이 있지만 정확한 도입 버전은 알 수 없다. 따라서 현재 인자 목록은
최신 버전에서는 동작하고 구버전에서는 항상 실패하는 버전 의존 계약이다.

PR #322와 ADR-0065는 옵션 거절을 정확히 진단하도록 고쳤지만 호출 자체는 복구하지 않았다. 화면이
원인을 알게 된 것과 provider가 동작하는 것은 다른 문제다.

## 선택지

- **A. 최신 Claude Code만 지원한다고 문서화한다.** 구현은 유지되지만 2.1.148 사용자의 두 provider
  경로는 계속 동작하지 않는다. 정확한 최소 버전도 알 수 없다.
- **B. 호출 전에 `claude --help`를 실행해 `--safe-mode` 지원 여부에 따라 인자를 가른다.** 격리
  기능은 가능한 버전에서 유지하지만 호출마다 프로세스와 새 실패 지점이 하나 늘어난다.
- **C. `--safe-mode`를 제거하고 나머지 격리 인자를 유지한다.** 한 인자 목록이 두 버전에서 모두
  동작한다.
- **D. 먼저 `--safe-mode`로 실행하고 `unknownOption`일 때만 빼서 재시도한다.** 최신 버전에서는
  격리를 유지하지만 provider 자동 재시도라는 새 상태와 실행 경로가 생긴다.

## 결정

**C안.** Claude 호출 인자에서 `--safe-mode`를 제거한다. authoring과 진단은 같은 `claudeSpec`을
사용하므로 두 경로에 함께 적용한다.

다음 격리 장치는 그대로 유지한다.

- `--tools ""`: Claude 도구를 비운다.
- `--strict-mcp-config --mcp-config '{"mcpServers":{}}'`: MCP 서버를 비운다.
- `--no-session-persistence`: provider 세션을 남기지 않는다.
- 빈 임시 작업 디렉터리와 환경변수 allowlist: 대상 저장소와 불필요한 자격증명을 넘기지 않는다.
- 고정 프롬프트: 도구·shell·subagent·MCP·파일 접근을 사용하지 말라고 명시한다.

## 이유

- **문제를 일으키는 인자가 기능의 필수 조건은 아니다.** 파일과 외부 도구 접근을 막는 직접 장치는
  `--tools ""`와 빈 MCP 설정이며, 둘 다 2.1.148에서 지원된다.
- **B안은 이미 제거한 사전 검사와 같은 모양이다.** ADR-0007의 `hasRequiredCapabilities`는 help
  출력과 실제 하위 명령의 기능 차이 때문에 provider가 한 번도 실행되지 않는 새 장애를 만들었다.
- **D안은 ADR-0006의 자동 재시도 없음 계약을 넓힌다.** 첫 실행이 인자 파싱에서만 실패했는지와
  두 번째 실행의 승인·timeout·취소를 새로 정의해야 한다. 한 인자를 제거하는 문제보다 범위가 크다.
- **A안은 지원 범위를 말할 근거가 없다.** 도입 버전을 모르는 상태에서 최소 버전을 쓰면 검증하지
  않은 숫자가 새 계약이 된다.

## 결과

- Claude Code 2.1.148에서 `--safe-mode` 옵션 거절 없이 CLI가 기동해 API 요청 단계까지 간다.
- 최신 Claude Code에서도 나머지 인자는 그대로 지원되므로 같은 authoring·진단 경로를 쓴다.
- 공개 API와 타입, 출력 스키마는 바뀌지 않는다.
- `unknownOption` 분류는 다른 provider 옵션의 버전 차이를 진단하기 위해 그대로 유지한다.
- **사용자 수준 Claude 커스터마이징을 한꺼번에 끄는 보장은 약해진다.** `HOME`은 CLI 인증을 위해
  전달하므로 전역 CLAUDE.md·skills·plugins·hooks가 설치된 환경에서는 Claude가 그것을 읽을 수 있다.
  도구와 MCP는 인자로 비워 두지만 커스터마이징 로딩 자체를 차단하지는 않는다. 향후 구버전에서도
  인증을 보존하며 설정 소스만 끄는 공통 옵션이 확인되면 이 결정을 대체한다.

## 승인

- `generate` 오너 리뷰가 필요하다.
- 되돌리는 조건: `--safe-mode` 제거 후 사용자 커스터마이징이 provider 출력이나 외부 동작에 영향을
  주는 재현 사례가 나오면, 지원 버전을 명시하거나 검증된 공통 설정 차단 수단으로 교체한다.
