# ADR-0079: 대시보드의 서버 후보는 서버를 실행하지 않고 설정 파일에서만 읽는다

- 상태: 제안
- 날짜: 2026-08-25
- 담당: dashboard (공용)
- 작성자: @seodduu
- 참조: `docs/2026-08-25-대시보드-홈-실행-폼-설계.md`,
  `packages/dashboard/src/server/files.ts` (`listSuites`),
  `packages/dashboard/web/src/generate/steps/StepServer.tsx`, 이슈 #223, #296

## 배경

홈의 실행 폼은 서버 실행 명령을 스위트마다 손으로 받는다. `StepServer` 의 힌트는
"프로젝트 스캔 API 없음" 이라 적어 두고 최근 사용값만 제공한다. 사용자가 서버를 고르게
하려면 대시보드가 "이 프로젝트에 어떤 서버가 있고 어떻게 띄우는가" 를 어디선가 알아야
한다. 그 출처를 정해야 했다.

## 선택지

1. **설정 파일만 읽는다.** 루트 아래 `.mcp.json` 의 `mcpServers`(MCP 클라이언트가 서버를
   띄우는 바로 그 명령과 인자)와 `package.json` 의 `bin`(패키지의 실행 진입점). 파일을 읽어
   후보를 만들고 아무것도 실행하지 않는다.
2. **서버를 `--help` 로 한 번 띄워 출력을 파싱한다.** 선언 파일이 없어도 인자 목록까지
   얻는다.
3. **대시보드 전용 선언 파일을 새로 정의한다.** 옵션마다 이름·종류·기본값을 적게 하고
   폼을 자동 생성한다.
4. **스위트 JSON 에 서버 명령을 넣는다.** 스위트를 고르면 서버가 따라온다.

## 결정

1번. 후보는 `.mcp.json` 과 `package.json` `bin` 에서만 읽는다. 목록을 만들기 위해 사용자
코드를 실행하지 않는다. 출처가 둘 다 없으면 화면이 탐색 루트와 해결 방법을 말하고 직접
입력으로 내려간다.

`package.json` 의 `scripts.start` 는 출처에 넣지 않는다. 셸 문자열이라 공백으로 쪼개야
하는데, 그 분해가 #223 이 없앤 문제(공백 든 경로가 깨짐)를 되살린다.

## 이유

- **결정론.** 같은 파일이면 같은 목록이다. 서버를 띄워 얻는 출력은 버전·환경·시각에 따라
  달라지고, 파싱 형식도 서버마다 다르다. 목록을 만드는 단계가 흔들리면 그 위의 실행도
  같은 입력에 같은 결과를 못 낸다.
- **안전.** 대시보드는 파일 열람용 로컬 서버다. 목록을 그리려고 프로젝트 안의 임의 스크립트를
  실행하는 것은 `GET` 한 번의 부작용치고 크다. 실행은 사용자가 `실행 시작` 을 눌렀을 때만
  한다.
- **추가 작성 0.** `.mcp.json` 은 MCP 서버를 만드는 사람이 이미 갖고 있을 확률이 높다.
  3번은 우리만의 형식을 하나 더 배우게 한다. 인자 선택 폼이 정말 필요해지면 그때 3번을
  다시 꺼낸다(지금은 필요가 확인되지 않았다).
- **오너 경계.** 4번은 `runner` 의 스위트 스키마 변경이라 다른 오너 패키지다. 대시보드
  편의 때문에 스위트 형식을 바꾸는 것은 꼬리가 몸통을 흔드는 일이다.

## 결과

- `GET /api/servers` 가 생긴다. 스캔 규칙은 `GET /api/suites` 와 같다(제외 디렉터리, 루트
  밖 차단, 실패 항목 조용히 제외).
- `.mcp.json` 항목의 `env` 는 읽되 넘기지 못한다. 대시보드에 자식 프로세스 환경변수 주입
  통로가 없다. 후보 행에 그 사실을 적는다.
- `examples/weather-server` 에는 `.mcp.json` 이 없다. 도그푸딩을 위해 하나 두는 후속
  작업이 필요하며, 그 전까지는 그 예제에서 `package.json` `bin` 후보만 보인다.
- 인자 목록을 고르게 하는 폼(선택지 3번의 영역)은 이 결정으로 닫히지 않는다. 필요가
  생기면 `.mcp.json` 항목 위에 얹는 선언으로 다시 논의한다.
