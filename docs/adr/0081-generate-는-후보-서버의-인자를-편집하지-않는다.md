# ADR-0081: Generate 는 후보 서버의 인자를 편집하지 않는다

- 상태: 제안
- 날짜: 2026-08-25
- 담당: dashboard (공용)
- 작성자: @seodduu
- 참조: `docs/2026-08-25-대시보드-generate-서버-선택-설계.md` §3, §8,
  `docs/2026-08-25-대시보드-홈-실행-폼-설계.md` §5-3, ADR-0079,
  `packages/dashboard/web/src/components/ServerPicker.tsx`

## 배경

홈 실행 폼은 `GET /api/servers` 후보를 고른 뒤에도 서버 인자를 칩으로 빼거나 더할 수
있다(홈 설계 §5-3). Generate 마법사 1단계에 같은 `ServerPicker` 를 얹으면서 인자 편집을
홈과 같게 둘지 정해야 했다. 후보는 `package.json` 의 `bin` 이나 `.mcp.json` 의 항목이고,
대시보드는 그것을 실행 없이 읽기만 한다(ADR-0079).

## 선택지

1. **홈과 같게 편집 허용.** 후보를 골라도 인자 칩이 열린다. 컴포넌트 재사용이 가장 쉽다.
2. **후보 갈래는 읽기 전용, 편집은 직접 입력에서만.** 후보 카드의 부제(명령 전문)로만
   보이고, 인자를 바꾸려면 `직접 입력` 을 고른다.
3. **편집은 허용하되 바꾸면 선택을 `직접 입력` 으로 전환.** 결과는 2 와 같지만 사용자가
   전환을 눈치채기 어렵다.

## 결정

2 를 택한다. Generate 의 후보 갈래는 선언된 명령·인자를 그대로 쓴다. 인자를 고쳐야 하면
`직접 입력` 갈래에서 `StepServer` 의 칩으로 한다.

## 이유

- 홈과 Generate 는 후보를 고르는 이유가 다르다. 홈은 "이 서버를 어떻게든 띄워서 스위트를
  돌린다" 이므로 인자 조정이 잦다. Generate 는 "이 선언에서 명세를 뽑는다" 이다. 선언과
  다른 인자로 뽑은 명세는 나중에 홈에서 같은 후보를 골라 돌릴 때 어긋나고, 그 어긋남은
  스위트 파일에 남지 않아 찾기 어렵다.
- 후보를 고른 채 인자를 바꾸면 화면은 여전히 `package.json` 배지를 달고 있다. 배지가
  가리키는 파일과 실제 실행 명령이 다른 상태를 만들지 않는다.
- 직접 입력 갈래가 이미 있어 기능을 잃지 않는다. 한 번 더 클릭할 뿐이다.

## 결과

- `ServerPicker` 는 바꾸지 않는다. 후보 갈래의 인자 표시는 카드 부제가 담당한다.
- Generate 1단계는 `choice.kind === "manual"` 일 때만 `StepServer` 를 그린다.
- 홈의 인자 편집은 그대로다. 두 화면의 차이는 설계 §8 에 적혀 있고, 이 ADR 이 그 근거다.
- 나중에 "후보 인자를 살짝 바꿔 생성" 이 자주 필요하다고 드러나면 선택지 3 을 다시 본다.
  그때는 전환을 화면에 분명히 알리는 문안이 함께 필요하다.
