# ADR-0085: 세션은 자기를 재생할 명령을 담는다

- 상태: 채택
- 날짜: 2026-08-26
- 담당: record, cli, dashboard
- 작성자: @ddxng5 (② replay/record 파트)
- 선행 결정:
  [ADR-0052](./0052-external-세션-저장소는-갈아-끼울-수-있는-계약이다.md),
  [ADR-0069](./0069-녹화의-낡음은-시각을-보이되-판정하지-않는다.md)
- 참조: `CLAUDE.md` (결정론성이 핵심 가치다), 대시보드 Replay 탭

## 배경

**재생에 필요한 재료는 셋인데 세션 파일이 담은 것은 하나뿐이었다.** 재생은 서버를 실제로
띄우고 스위트를 실제로 돌리며 외부 호출 자리만 녹화본으로 대신한다. 그래서
`mcpeak test <스위트> --command <서버> --session <녹화본>` — 스위트와 서버 명령이 필요한데,
그 둘은 녹화하는 순간 CLI 가 알고 있다가 **버려졌다.** 재생하려는 사용자는 매번 "이 녹화본을
어느 서버, 어느 스위트로 떴더라" 를 기억에서 복원해야 했다.

대시보드 Replay 탭이 이 비용을 표면화했다. 목록에서 녹화본을 골라 한 번에 재생하려면
서버·스위트가 채워져야 하는데, 세션에 없으니 브라우저 `localStorage` 에 적어 두는 임시
방편을 썼다. 그 방식은 다른 브라우저·다른 기계·CLI 녹화본에서 무너진다 — 정보가 세션 밖에
있는 한 구조적으로 못 고친다.

## 선택지

**A안: 세션 파일에 출처(origin)를 저장한다.** 녹화 시작 시 서버 명령·인자·스위트 경로를
`sessions` 테이블에 함께 쓴다. 스키마 버전이 오른다.

**B안: 대시보드 `localStorage` 로 유지한다.** 포맷은 안 바뀌지만 브라우저 밖에서는 원클릭이
안 된다.

**C안: 세션 파일 옆에 별도 메타 파일(`.meta.json`)을 둔다.** 포맷은 안 바뀌지만 파일이 두
개가 되고, 하나만 옮기면 조용히 어긋난다.

**D안: 스위트 내용 해시까지 저장해 재생 때 검증한다.** 출처가 정확한지 판정까지 해 준다.

## 결정

**A안.** 함께 고정한 것 넷.

1. **`SessionOrigin` 은 `command`(실행 파일 하나) · `args`(순서 있는 배열) · `suitePath`
   셋이다.** CLI argv 계약(`--command` / `--arg`)과 1:1 로 대응한다.
2. **`SQLITE_STORE_VERSION` 을 2 로 올리되, 읽기는 1·2 를 모두 받는다.** v1 세션은
   `origin` 만 없이 그대로 재생·조회된다. 버전을 올렸다고 기존 녹화가 "우리 세션이 아니다" 가
   되면 사용자는 아무 잘못 없이 재녹화를 강요당한다 — 재녹화는 실제 네트워크를 다시 부르는
   일이고, 외부 API 가 그 사이 바뀌었다면 같은 녹화를 다시 뜰 수도 없다.
3. **여는 것만으로는 v1 파일을 올리지 않는다.** 마이그레이션(ALTER + version 갱신)은 실제로
   세션을 만드는 순간(`createSession`)에만 한다. 녹화를 거절하는 경로(#290,
   `SESSION_ALREADY_EXISTS`)가 사용자 파일을 바꾸면, 실패한 실행이 파일을 바꾼 것이다.
4. **`origin` 은 선택 필드고, 없으면 없다고 말한다.** 셋 중 하나라도 온전하지 않으면
   (`NULL`·빈 문자열·깨진 `args_json`) `undefined` 다 — 절반짜리 출처로 재생을 시작하면
   엉뚱한 서버를 띄운다. `outOfScope` 의 "undefined 는 0 이 아니라 못 셌음" 과 같은 정책이다.

## 이유

**B안을 버린 이유는 정보가 사는 자리가 틀렸기 때문이다.** 출처는 녹화본의 속성이지 브라우저의
속성이 아니다. 녹화본이 이동하면 따라가야 하고, 그러려면 같은 파일 안에 있어야 한다.
`localStorage` 구현은 A안이 배포될 때까지의 과도기 폴백으로만 남는다(세션의 값이 우선).

**C안을 버린 이유는 파일 두 개가 한 사실을 나눠 갖기 때문이다.** 세션만 복사하고 메타를
빠뜨리면 출처가 사라지고, 메타만 남으면 출처가 거짓이 된다. 어긋남을 감지할 방법도 없다.

**D안(해시 검증)은 이 결정의 범위 밖으로 미룬다.** "출처가 아직 유효한가" 는 External
재검증(ADR-0069 의 E안)과 같은 계열의 문제다. 지금 필요한 것은 판정이 아니라 **기억**이고,
스위트가 바뀌었어도 그 경로로 재생하는 것 자체는 정당한 사용례다(기대값만 고친 스위트).

**출처를 요약(`SessionSummary`)이 아니라 스냅샷(`SessionSnapshot`)에 싣는 것**은 소비자가
대시보드 목록(`loadSession`)과 저장소 조회(`read`)이기 때문이다. 재생 종료 문장에는 필요
없다 — 그 실행은 이미 출처를 알고 시작했다.

## 결과

- **`sessions` 테이블에 `command`·`args_json`·`suite_path` 칼럼이 생긴다(전부 NULL 허용).**
  `SQLITE_STORE_VERSION = 2`. 읽기 경로(`loadSession`·읽기 전용 열기)는 1·2 를 받는다.
- **CLI 는 `--record-session` 실행에서 스위트·서버 명령·인자를 세션에 싣는다.** 재생 쪽
  CLI 표면은 안 바뀐다.
- **대시보드 Replay 는 세션의 `origin` 을 우선 쓰고, 없을 때만 `localStorage` 폴백을 본다.**
  이로써 CLI 녹화본·다른 브라우저에서도 원클릭 재생이 된다.
- **v1 세션은 계속 재생된다.** 목록에는 출처 없이 나오고, 그 녹화본만 원클릭 대신 입력 폼이
  열린다.
- 재검토 조건: protocol 어댑터가 늘어 출처의 모양이 protocol 별로 갈리면, 이 칼럼들을
  ADR-0052 의 불투명 JSON 방식으로 옮기는 것을 검토한다.
