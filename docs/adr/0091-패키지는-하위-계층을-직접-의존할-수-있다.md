# ADR-0091: 패키지는 하위 계층을 직접 의존할 수 있다

- 상태: 제안
- 날짜: 2026-09-10
- 담당: dashboard, 전체 패키지 경계
- 작성자: @sunghoon0303
- 관련: #421, ADR-0046, ADR-0059

## 배경

저장소는 `dashboard` → `cli` → `runner`/`generate`/`record`/`mock` → `core`라는 단방향을
문서화했지만, 이것이 "인접 계층만 의존한다"는 뜻인지 "아래 방향이면 직접 의존해도 된다"는
뜻인지 명시하지 않았다. 실제 dashboard는 `@mcpeak/cli/commands`의 흐름을 재사용하면서 그
커맨드에 주입할 `core`·`runner`·`generate`를 직접 불러 조립하고, 녹화본을 읽을 때는
`@mcpeak/record/external`을 동적으로 불러온다. 반면 `@mcpeak/mock`은 선언만 있고 쓰이지 않았다.

규칙이 문서에만 있어 `core`가 `runner`를 의존하는 식의 역참조나 순환을 CI가 막지 못하는 문제도
있었다.

## 선택지

- **A안: 인접 계층만 의존한다.** dashboard의 모든 기능을 CLI 공개 면으로 올리고 dashboard는
  `@mcpeak/cli/commands`만 불러온다.
- **B안: 아래 방향의 직접 의존을 허용한다.** 패키지가 자기보다 아래 계층을 조립할 수 있게 하되,
  역참조·순환과 쓰지 않는 선언을 테스트로 막는다.
- **C안: 현재 선언을 기준선으로만 고정한다.** 새 의존 추가만 막고 기존의 죽은 선언과 문서 모순은
  남긴다.

## 결정

**B안을 택한다.** 의존 방향의 계약은 "인접 계층만"이 아니라 "항상 아래로만"이다. dashboard는
CLI 커맨드가 요구하는 하위 패키지를 직접 조립할 수 있지만, 사용자 흐름과 판정 로직은 계속
`@mcpeak/cli/commands`를 재사용한다.

7개 패키지의 `package.json`을 읽는 테스트가 각 내부 의존이 허용된 아래 방향인지 검사한다.
dashboard에 대해서는 TypeScript 구문 트리에서 정적 import, 동적 `import()`, 타입 import를 모두
찾아 런타임 의존 선언과 정확히 일치하는지도 검사한다.

## 이유

인접 계층만 강제하면 dashboard의 조립에 필요한 타입과 로더까지 CLI 공개 API로 올려야 한다.
그것은 판정 로직 재사용과 별개로 CLI의 공개 계약만 넓힌다. 현재 코드가 지키는 실질적인 경계는
하위 패키지를 조립할 수 있되 상위 패키지를 역참조하지 않는 것이다.

문자열 검색 대신 TypeScript 구문 트리를 쓰는 이유는 `@mcpeak/record/external` 같은 동적 import를
놓치지 않고, 주석이나 오류 문장에 적힌 패키지명은 사용으로 잘못 세지 않기 위해서다.

## 결과

- dashboard의 사용하지 않는 `@mcpeak/mock` 의존을 제거한다.
- `@mcpeak/record`는 `packages/dashboard/src/server/files.ts`의 동적 import가 사용하므로 유지한다.
- 내부 의존이 역방향으로 추가되면 테스트가 실패한다.
- dashboard에서 내부 패키지를 선언만 하거나 선언 없이 import해도 테스트가 실패한다.
- 다른 패키지의 선언-사용 일치 검사는 각 패키지 오너의 범위이므로 이번 결정에서 강제하지 않는다.
