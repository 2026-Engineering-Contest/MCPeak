# ADR-0093: 대시보드 시각 층을 토큰과 공용 프리미티브로 정리한다

- 상태: 제안
- 날짜: 2026-09-10
- 작성자: endl24
- 관련: ADR-0046(대시보드를 로컬 웹서버로 만든다) · 이슈 #450

## 배경

대시보드 화면(Test · Runs · Generate · Replay · Run 상세)을 실제로 띄워 보고 `web/src` 의
클래스 사용 빈도를 셌다. 색 토큰(`--ink` · `--surface` · `--accent` · `--status-*`)은 이미
`theme.css` 한 곳에 모여 있고 라이트·다크가 모두 정의돼 있다. **색은 문제가 아니다.**

문제는 그 위층이다. 화면의 모든 요소가 같은 무게로 보인다.

| 관찰 | 수치 (`packages/dashboard/web/src/**/*.tsx`) |
|---|---|
| 타입 스케일 | `text-sm` 73 · `text-xs` 63 vs `text-xl` 6 · `text-lg` 1 |
| 그림자 | 0 |
| 트랜지션 | 0 |
| 포커스 링(`focus-visible:` · `ring-*`) | 0 |
| 프라이머리 버튼 | 8곳 · 크기 3종(`px-4 py-2` / `px-3 py-1.5` / `px-3 py-1`) · hover 상태 없음 |
| 모서리 반경 | 버튼 `rounded`(4px) vs 카드 `rounded-lg`(8px) 혼재 |

결과적으로 (1) 화면이 사실상 14px·12px 두 크기의 회색 벽이라 훑어볼 위계가 없고,
(2) 카드와 페이지 배경이 같은 평면에 있어 무엇이 조작 대상인지 형태로 구분되지 않으며,
(3) 기본 CTA 가 hover 에 반응하지 않고 포커스 링이 없어 **키보드로 쓰는 개발자 도구인데
지금 어디에 있는지가 브라우저 기본 아웃라인에만 의존한다.**

부수적으로 `theme.css` 는 다크 팔레트를 두 블록(`[data-theme="dark"]`,
`prefers-color-scheme` 위임)에 **똑같이 복제**하고 있고, 파일 머리 주석이 "반드시 함께
고쳐라" 라고 경고한다. 토큰을 늘리는 작업은 이 복제를 그대로 두면 늘어난 만큼 더 위험해진다.

## 선택지

- **A안 — 손대지 않는다.** 기능이 아니라 외양이고, 마감이 가깝다.
- **B안 — 화면별로 그때그때 다듬는다.** 눈에 걸리는 화면부터 클래스를 고친다.
- **C안 — 토큰 층만 넓힌다.** `theme.css` 에 타입 스케일 · elevation · radius · motion
  토큰을 추가하고 컴포넌트는 건드리지 않는다.
- **D안 — 토큰 층 + 공용 프리미티브.** C안에 더해 `Button` · `Card` · `Field` 를 만들어
  흩어진 버튼 8곳을 모으고 hover · active · `focus-visible` 을 한 번만 정의한다.

## 결정

**C안을 먼저 하고, 이어서 D안을 별도 PR 로 한다.** 두 PR 로 쪼갠다.

- PR 1 (C안): `theme.css` 한 파일. 타입 스케일 4단, elevation 토큰, radius 3단,
  motion 토큰과 `prefers-reduced-motion`.
  같은 PR 에서 `color-scheme` + `light-dark()` 로 중복된 다크 블록 3벌을 한 벌로 줄인다.
- PR 2 (D안): `components/Button.tsx` · `Card.tsx` · `Field.tsx` 를 만들고 호출부를 옮긴다.

**색이 아닌 값은 모양을 고정하고 색만 가른다.** 초안은 elevation 을 "라이트는 그림자,
다크는 테두리+inset" 으로 적었으나, 구현하면서 `light-dark()` 가 **색만 받는다**는 것을
확인했다(PR #455). 그림자 값을 통째로 가르려면 분기 블록이 되살아난다. 대신 그림자의
*모양*은 한 벌로 두고 *색*만 토큰으로 가른다 — 라이트에서 투명색이면 아무것도 그려지지
않으므로 결과가 같고, 선언은 여전히 한 곳이다.

```css
--terminal-inset-color: light-dark(transparent, rgb(255 255 255 / 0.04));
--terminal-inset: inset 0 1px 0 var(--terminal-inset-color);
```

터미널 영역(`--terminal-*`)은 **범위 밖이다.** UI 설계 §3 이 정한 대로 테마와 무관하게
항상 다크이며, ANSI 색과 스크롤바를 포함해 고정 팔레트다. 여기에 토큰 분기를 들이지 않는다.

## 이유

A안을 버린 이유는 이 프로젝트에서 화면이 곧 제품 설명이기 때문이다. 심사와 발표에서 처음
보이는 것이 이 화면이고, "실패 메시지가 곧 제품이다" 와 같은 이유로 **읽을 수 있는 위계가
없는 화면은 도구가 무엇을 하는지 설명하지 못한다.**

B안을 버린 이유는 지금 상태가 이미 B안의 결과이기 때문이다. 버튼 크기 3종과 반경 혼재는
누가 잘못해서 생긴 것이 아니라 화면마다 필요한 만큼 유틸리티를 적어 넣은 자연스러운 결과다.
같은 방식을 반복하면 종류가 더 늘어난다.

C안을 D안보다 먼저 두는 이유는 **회귀 위험의 크기가 다르기** 때문이다. C안은 컴포넌트
DOM 을 바꾸지 않아 기존 컴포넌트 테스트가 그대로 통과한다. D안은 버튼 DOM 을 옮기므로
`web/tests/*.test.tsx` 가 버튼을 어떤 선택자로 잡는지 먼저 확인해야 한다.
둘을 한 PR 에 합치면 CONTRIBUTING §5-4(400줄)도 넘는다.

**다만 C안이 화면을 안 바꾸는 것은 아니다.** 초안은 C안을 "순수 추가" 로 적었는데, radius
토큰 이름을 정하면서 그 전제가 깨졌다. Tailwind 가 이미 `--radius-sm/md/lg` 를 4/6/8px 로
쓰고 있고 코드에 `rounded-md` 15곳·`rounded-lg` 10곳이 있다. 새 이름을 만들면 같은 뜻의
반경이 두 벌로 남으므로 **기본값을 덮어 6/8/12px 로 통일하기로 했다.** 테스트는 DOM 을 보고
반경을 보지 않으므로 그대로 통과하지만, 버튼과 카드는 이전보다 둥글어진다.

`light-dark()` 를 고른 이유는 그것만이 **복제를 실제로 없애면서** `theme.ts` 가 전제하는
"미선택이면 OS 를 따라간다" 를 그대로 보존하기 때문이다. `:root` 에 `color-scheme: light dark`
를 두면 미선택 상태가 OS 를 따라가고, `[data-theme]` 이 붙으면 그 값이 `color-scheme` 을
고정해 명시 선택이 이긴다. 토큰 선언은 한 벌만 남는다.

포기하는 것: `light-dark()` 는 2024년 중반에 널리 쓸 수 있게 된 기능이라, 그보다 오래된
브라우저에서는 미선택 상태가 라이트로 보인다. 로컬 개발 도구이고 명시 선택은 그대로 동작하므로
받아들인다.

## 결과

- `theme.css` 가 시각 계약의 단일 지점이 된다. 이후 화면 작업은 토큰 이름을 쓰고 원시값을
  적지 않는다. 지금 남아 있는 예외는 `Sidebar` 로고의 하드코딩 그라디언트 하나이며,
  PR 1 에서 토큰으로 옮긴다.
- 프리미티브 도입 후에는 버튼·카드를 유틸리티로 새로 조립하지 않는다. 크기가 더 필요하면
  `Button` 에 variant 를 더한다.
- **새 토큰 블록은 `@theme static` 으로 둔다.** Tailwind 4 는 *쓰인* 토큰만 CSS 로 내보낸다.
  그냥 `@theme` 으로 두면 아직 아무 컴포넌트도 쓰지 않는 `--text-body` · `--shadow-card` 가
  실리지 않아 `var(--text-body)` 가 **조용히 빈 값**이 된다(PR #455 에서 실측). 토큰을 먼저
  놓고 나중에 쓰는 이 ADR 의 순서 자체가 그 함정을 만든다.
- 화면 리듬(헤더 제목 중복, 리스트 밀도, 빈 상태)은 **이 ADR 의 결정 대상이 아니다.**
  토큰과 프리미티브가 자리잡은 뒤 별도 이슈로 다룬다.
- 이 ADR 은 번호를 **두 번** 옮겼다. 초안이 잡은 0091 은 머지된 0091(패키지는 하위 계층을
  직접 의존할 수 있다)과 부딪혔고, 옮겨 간 0092 는 **리뷰를 기다리는 동안** 0092(실패 요약 절)가
  main 에 먼저 들어오며 다시 부딪혔다. `docs/adr/README.md` 하단이 세는 재배정에 두 건을
  더한다 — 한 ADR 이 두 번 밀린 것은 그 목록에서도 처음이다.
  머지 직전에 0093 이 여전히 비어 있는지 다시 확인한다.
