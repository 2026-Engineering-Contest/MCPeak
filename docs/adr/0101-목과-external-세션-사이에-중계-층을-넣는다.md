# ADR-0101: 목과 External 세션 사이에 중계 층을 넣는다

- 상태: 제안
- 날짜: 2026-09-18
- 담당: mock
- 작성자: @storyrago
- 참조: `docs/superpowers/specs/2026-09-16-mock-to-relay-design.md`,
  [ADR-0005](./0005-mock-data-strategy.md),
  [ADR-0007](./0007-mock-stdio-transport.md),
  [ADR-0048](./0048-목이-inputSchema-를-실제로-검사한다.md),
  [ADR-0057](./0057-external-어댑터는-global-fetch-까지만-가로챈다.md),
  [ADR-0059](./0059-tool-카세트를-제거한다.md)

## 배경

테스트 판정 화면은 서버가 실제로 무엇을 돌려줬는지 보여주지 않는다. 리포터가 그리는 것은
툴 이름 · 단언 이름 · 통과 · 실패 · 진단 문장뿐이고, 실물 응답은 화면에도 `--json` 보고서에도
남지 않는다. 사용자가 자기 서버의 답을 볼 자리가 없다.

그 자리를 목으로 메울 수 없다는 것이 조사 결과다.

- **스위트 명세만으로는 목을 세울 수 없다.** 저장소 전체 단언 134 건(`isError` 114 ·
  `bodyMatchesSchema` 8 · `structuredContentMatchesSchema` 6 · `toolExists` 6)이 전부 모양을
  보는 단언이고, 값을 보는 단언(`bodyEquals` · `equals` · `contains`)은 0 건이다. 스위트에는
  툴의 `inputSchema` 도 없는데 목 정의는 그것을 요구한다.
- **응답을 녹화해 오는 경로도 없다.** 카세트가
  [ADR-0059](./0059-tool-카세트를-제거한다.md) 로 제거되면서 그 자리가 비었다.
- **stdio 서버는 관찰할 수 없다.** 진짜 서버가 stdio 면 AI 클라이언트가 자기 자식 프로세스로
  띄우므로 대시보드가 오가는 호출을 볼 방법이 없다. 앞에 HTTP 를 한 겹 세워야 보인다.

AI 를 대시보드가 자동으로 부르기로 하면서 이 마지막 이유는 더 강해졌다. 사람이 눈으로 보는
창조차 없으므로 중계기의 기록이 유일한 관찰 채널이다.

## 선택지

1. 목을 그대로 두고 빈 스키마로 때운다
2. 응답을 녹화해 재생한다
3. 진짜 서버를 뒤에 두고 중계한다 — SDK `Server` + `Client` 브리지
4. 진짜 서버를 뒤에 두고 중계한다 — 트랜스포트 직결

## 결정

**4 를 고른다.** 앞이 Streamable HTTP, 뒤가 stdio 인 중계기를 두고, 두 트랜스포트의
`onmessage` / `send` 를 SDK 의 `Server` · `Client` 없이 직접 잇는다.

- 목 패키지를 중계기로 **전환**한다. 병행이 아니다.
- 패키지 이름 `@mcpeak/mock` 은 유지하고 `bin` 에 `mcpeak-relay` 를 더한다. 디렉터리가 그대로라
  의존 경계 테스트 · 오너 표 · 커밋 scope 가 그대로다.
- **bin 전용이다.** `exports` 를 내지 않는다. 공개 타입 계약이 없으면 major 없이 못 바꾸는
  면이 안 생긴다.
- **테스트 스위트는 중계기를 지나지 않는다.** 스위트는 지금처럼 `--command` 로 서버에 직접
  붙는다.
- **중계기당 자식 1 개를 띄워 모든 세션이 공유한다.** 대시보드가 질문마다 새 프로세스를
  띄우므로, 세션당 자식이면 상태를 가진 서버의 상태가 질문 사이에 날아간다.

## 이유

**1 은 알려진 결함을 재현한다.** 빈 스키마로 때우면 입력 검사가 조용히 꺼진 채 초록불이 뜨는
문제(H-5)가 그대로 나온다. 거절 케이스는 더 나쁘다 — 주입이 없으면 미스 진단문이 `isError`
로 나가고 거절 단언이 그걸 보고 통과한다. H-4 가 잡은 가짜 초록과 같은 구조다.

**2 는 경로가 없다.** 카세트가 사라진 자리를 다시 만드는 일이 된다.

**3 은 "진짜 서버가 답한다" 를 깬다.** SDK `Client` 는 `structuredContent` 를 `outputSchema`
로 검증한다. 중계기가 `Client` 를 쓰면 진짜 서버의 잘못된 응답을 중계기가 대신 받아서 던지고,
사용자는 서버의 답이 아니라 중계기가 만든 오류를 본다.

**4 는 해석하는 지점이 없다.** "값을 만들지도 바꾸지도 않는다" 가 규율이 아니라 구조로
보장된다. `initialize` 도 그대로 지나간다 — 능력 협상은 클라이언트와 진짜 서버가 직접 한다.
중계기가 능력을 대신 선언하면 그 순간 진짜 서버가 답하는 것이 아니게 된다.

## 결과

- **무효가 되는 ADR 네 건**: [0005](./0005-mock-data-strategy.md) 목 데이터 전략,
  [0007](./0007-mock-stdio-transport.md) 목 stdio 진입점,
  [0048](./0048-목이-inputSchema-를-실제로-검사한다.md) 목이 `inputSchema` 를 검사한다,
  [0057](./0057-external-어댑터는-global-fetch-까지만-가로챈다.md) 목과 External 세션의 경계.
- **봉투의 `id` 는 중계기가 재작성한다.** 자식이 하나인데 세션이 여럿이라 클라이언트 id 를
  그대로 쓰면 응답이 섞인다. `params` · `result` 는 손대지 않는다.
- **오류는 진짜 서버가 준 코드와 메시지를 그대로 쓴다.** 중계기가 문장을 고쳐 쓰면 사용자가
  보는 것이 진짜 원인이 아니게 된다. 자식이 먼저 죽었을 때도 오류를 지어내지 않고 HTTP
  연결만 끊는다.
- **기록은 stderr 한 줄씩이고 stdout 은 쓰지 않는다.** 인자는 줄이지 않고 그대로 싣는다.
  시간은 `ms` 한 곳에만 둔다 — 결정론성 규칙에 걸리는 유일한 필드다.
- **중계기를 지나는 응답은 결정론적이지 않다.** 그래서 테스트 경로에서 뺐다. 이 구분이
  흐려지면 결정론성이 무너진다.
- 걷어내는 층: 매칭 키 생성, 응답 레지스트리, 중복 주입 거절, 미스 진단문, `inputSchema`
  검사 네 축, 키 위반 검사, stdio 목 진입점. 구현 1,123 줄 중 100 줄 남짓만 살아남는다.
- **2 단계에서 목 소비자를 옮긴다** — `packages/cli/tests/http-remote-e2e.test.ts` ·
  `examples/mock-server` · 문서. 공동 영역이라 이슈를 열고 오너에게 알린다.
