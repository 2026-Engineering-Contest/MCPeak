# ADR-0102: 도구 정의 압축은 tools/list 만 바꾸고 호출은 원본으로 전달한다

- 상태: 제안
- 날짜: 2026-09-28
- 담당: optimize
- 작성자: @seodduu
- 관련: `docs/2026-09-27-mcp-도구-정의-압축-조사-실험.md`, `docs/plans/2026-09-28-optimize-안전-프로필-구현계획.md`, ADR-0091

## 배경

MCP 클라이언트는 서버의 `tools/list` 응답(이름, 설명, `inputSchema`)을 모델 컨텍스트에 싣는다.
도구가 많은 서버는 이것만으로 수천에서 만 단위 토큰을 쓴다. 지연 로딩과 검색은 클라이언트의 권한이라
서버 쪽이 쥘 수 있는 손잡이는 `tools/list` 의 내용뿐이다(실험 문서 §1.1).

문헌이 보고하는 절감(설명 압축 70~97%, OpenAPI 기준 무손실 47~64%)은 기능 유지를 실측하지 않았거나
MCP 실물에서 재현되지 않았다. 우리 실험은 공개 서버 35개, 모델 선택 테스트 210건, 스키마 동치 표본
약 72,000개로 무엇을 지워도 되는지를 먼저 쟀다.

## 선택지

- **A. 서버 코드를 고친다.** 설명과 스키마를 서버 저장소에서 직접 줄인다.
- **B. 파라미터 설명을 지운다.** 스키마 안 `description` 을 일괄 제거한다(실험의 3단계).
- **C. 사용 빈도로 도구를 뺀다.** 적게 쓰이는 도구를 목록에서 제외한다.
- **D. 공유 문장을 서버 instructions 로 승격한다.** 여러 도구에 반복된 설명 문장을 한 번만 둔다.
- **E. 안전 프로필만 쓴다.** 무손실 정규화, 잡음 제거, 공통 파라미터 승격 세 변환을 오버레이 파일로
  내고, 프록시가 `tools/list` 만 오버레이로 답하며 `tools/call` 은 원본 이름과 인자로 서버에 전달한다.

## 결정

**E 를 택한다.** 산출물은 `mcpeak optimize --out` 이 쓰는 오버레이 파일과 `mcpeak-optimize-proxy`
하나다. 변환 결과는 게이트 A(원본과 같은 입력 집합을 받는지)를 통과해야만 파일로 나간다. 프록시는
인자를 검증하지 않고 상류 결과를 그대로 돌려주며, 상류 도구 목록이 오버레이와 다르면 서비스하지
않고 끝난다.

## 이유

- **A 기각.** 이 도구는 남의 서버에 붙는다. 서버 코드를 고칠 권한이 없는 사용자가 대부분이고,
  고친다 해도 서버가 갱신될 때마다 다시 해야 한다. 오버레이는 서버를 건드리지 않고 같은 효과를 낸다.
- **B 기각.** 절감은 20~75%로 가장 크지만 기능이 실제로 깨졌다. chrome-devtools 에서 `navigate_page`
  대신 `new_page` 를 골랐고(6건 중 5건만 같은 도구), notion 에서 조회 filter 인자를 만들지 못했다
  (실험 문서 §5.2). desktop-commander 는 `default` 가 사라지자 기본값을 매번 명시해 출력 토큰이 늘었다.
- **C 기각.** "안 쓰이는 도구" 는 사용자마다 다르다. 배포 전 정의만 보는 도구가 판정할 수 없고,
  도구를 빼면 호출 계약이 바뀐다. 실제 세션을 관측하는 MCPLens 의 영역이다(실험 문서 §2, §6).
- **D 기각(이번 범위).** 3차 실험(20개 서버, 120건)에서 압축이 만든 퇴행 3건(2.5%)이 **전부** 이
  단계에서 나왔다. circleci 는 개조식 설명에서 빈 항목만 남았고, browserstack 은 몇 개 도구에만
  붙어 있던 조건부 지침이 전역이 되어 엉뚱한 도구를 골랐다. 이 단계를 빼도 감소는 15.9% 에서
  13.9% 로 2%p 줄 뿐이다(실험 문서 §5.6). 두 결함을 고친 뒤 별도 결정으로 되살린다.
- **E 채택.** 세 변환은 게이트 A 표본 약 72,000개에서 불일치 0, 1·2차 90건에서 도구 선택 불일치
  0건이었고, 3차의 퇴행 3건에 하나도 관여하지 않았다. 감소는 35개 서버 합계 13.9%, 서버별 중앙값
  12.2%, 범위 0.9~37.5% 다. 절감률은 서버가 정하고 우리가 보장하는 것은 기능 유지다.
- 호출을 원본으로 그대로 넘기는 이유는 "기능 유지" 를 프록시가 거짓으로 만들지 않기 위해서다.
  프록시가 인자를 검증하거나 결과를 다시 조립하면 원본과 다른 오류 문장이나 빠진 필드가 생긴다.

## 결과

- 새 패키지 `@mcpeak/optimize` 는 `core` 에만 의존하고 `cli` 가 그것을 의존한다. 의존은 계속 아래로만
  흐른다(ADR-0091).
- 공통 파라미터 설명은 서버 `instructions` 로 옮겨진다. instructions 를 모델에 보여 주지 않는
  클라이언트에서는 그 설명이 모델에 닿지 않는다. 그런 클라이언트에서는 감소율이 무손실 정규화 수준
  (4~9%)으로 내려간다고 보고 써야 한다(실험 문서 §7).
- 프록시는 tools 만 중계한다. 원본이 resources·prompts 를 광고하면 리포트가 경고한다.
- 서버가 바뀌면 오버레이가 낡는다. 프록시는 시작할 때 도구 이름 목록을 대조해 다르면 종료 코드 1 로
  끝나고, 같은 `mcpeak optimize` 명령으로 다시 만들라고 안내한다.
- 모델 선택 동치(게이트 B)와 검색 오염(게이트 C)은 이번에 넣지 않는다. B 는 모델 호출이 필요해
  결정론 원칙과 충돌하고, C 는 안전 프로필에서 값이 거의 움직이지 않았다.
