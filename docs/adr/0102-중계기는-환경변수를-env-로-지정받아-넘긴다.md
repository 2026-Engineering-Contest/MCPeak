# ADR-0102: 중계기는 환경변수를 `--env` 로 지정받아 넘긴다

- 상태: 제안
- 날짜: 2026-09-20
- 담당: mock
- 작성자: @storyrago
- 참조: [ADR-0070](./0070-원격-서버의-인증-헤더는-값이-아니라-환경변수-이름으로-받는다.md),
  [ADR-0091](./0091-패키지는-하위-계층을-직접-의존할-수-있다.md),
  [ADR-0097](./0097-비밀값은-argv-가-아니라-환경변수로-넘기고-출처-인자는-가린다.md),
  [ADR-0101](./0101-목과-external-세션-사이에-중계-층을-넣는다.md)

## 배경

1 단계에서 만든 중계기(`packages/mock/src/relay-server.ts:60`)는 진짜 서버를 자식으로 띄울 때
`StdioClientTransport` 에 `env` 를 넘기지 않는다.

```ts
const child = new StdioClientTransport({ command, args: [...args], stderr: "inherit" });
```

`env` 가 없으면 SDK 의 `getDefaultEnvironment()` 가 적용된다. 자식이 받는 것은
`HOME` · `LOGNAME` · `PATH` · `SHELL` · `TERM` · `USER` 여섯 개뿐이다. `WEATHER_API_KEY` 같은
것을 읽는 서버는 중계기 뒤에서 조용히 실패하고, 화면 어디에도 **중계기 때문이라는 단서가 없다.**
사용자가 보는 것은 자기 서버가 낸 인증 오류이고, 그 서버는 중계기 없이 띄우면 잘 돈다.

지금 저장소 안에서는 이것이 깨지지 않는다. 예제 서버 넷(`examples/live-weather-server` ·
`mock-server` · `weather-server` · `zod-notes-server`) 중 `process.env` 를 읽는 것이 하나도 없어서
(`grep -rn "process\.env" examples/` → 0 건) E2E 가 초록이다. **결함이 아니라 예제의 성질이
CI 를 초록으로 만들고 있다.**

### 이 저장소에는 같은 결정이 이미 두 번 있다. 둘이 다르다

이 대비가 이 ADR 의 핵심이다.

**AI CLI 를 띄울 때는 우리가 이름을 안다.** `packages/generate/src/providers.ts:25-51` 의
`CLAUDE_ENV_ALLOWLIST` · `CODEX_ENV_ALLOWLIST` 는 하드코딩돼 있다. 사용자가 아무것도 지정하지
않아도 되는 이유는 우리가 `ANTHROPIC_API_KEY` · `OPENAI_API_KEY` 가 무엇인지 알기 때문이다.
provider 별로 쪼갠 이유도 주석에 적혀 있다 — "codex 자식이 Anthropic 자격증명을, claude 자식이
OpenAI 자격증명을 받을 이유가 없다."

**사용자 서버를 띄울 때는 우리가 이름을 모른다.** `packages/core/src/controlled-stdio.ts:80` 은
`{ ...getDefaultEnvironment(), ...this.options.env }` 를 쓰고, 그 `env` 는 CLI 가 `--env <이름>`
으로 받아 채운다(`packages/cli/src/test-command.ts:375`, `packages/cli/src/connect-target.ts:254`).
사용자 서버가 무슨 변수를 읽는지 우리는 알 수 없으므로 사용자가 지정한다. 값이 아니라 **이름**만
받는 이유는 [ADR-0097](./0097-비밀값은-argv-가-아니라-환경변수로-넘기고-출처-인자는-가린다.md) 이다 —
값을 명령줄에 쓰면 `ps` 목록과 셸 히스토리와 녹화 출처에 그대로 남는다.

## 선택지

1. **전부 넘긴다** — `{ ...process.env }`.
2. **중계기용 allowlist 를 둔다** — provider 방식을 중계기에 그대로 옮긴다.
3. **`mcpeak test` 의 `--env` 규약을 그대로 쓴다** — 이름만 받아 `getDefaultEnvironment()` 위에 얹는다.

## 결정

**③ 을 쓴다.** `mcpeak-relay` 는 `--env <이름>` 을 받고, 자식 환경은
`{ ...getDefaultEnvironment(), ...지정된_이름의_값 }` 으로 만든다. 값은 argv 가 아니라 부모
환경에서 읽는다.

## 이유

중계기가 띄우는 것은 **사용자 서버**다. 위 두 갈래 중 아래쪽이고, 그쪽에는 이미 답이 있다.

같은 일에 두 가지 규약을 두면 사용자는 `mcpeak test` 에서 되던 것이 `mcpeak-relay` 에서 안 되는
이유를 알 수 없다. 두 명령은 같은 서버를 같은 방식으로 띄우는데 환경변수만 다르게 취급하는 것은
설명할 수 없는 차이다.

①은 중계기를 띄운 셸의 **모든 비밀**이 자식에게 간다. 사용자 서버는 우리가 감사하지 않은 코드이고,
중계기는 그것을 띄우는 쪽이다. 기본값이 "전부" 인 것은 되돌릴 수 없는 종류의 기본값이다.

②는 애초에 성립하지 않는다. allowlist 가 성립하려면 우리가 변수 **이름을 알아야** 하는데,
사용자 서버의 변수 이름은 사용자만 안다. provider 쪽에서 이것이 통한 이유가 여기서는 없다.

## 결과

### `mcpeak test` 의 `--env` 와 한 곳이 다르다

cli 쪽 `parseEnvForwardOption`(`packages/cli/src/connect-target.ts:265-274`)은 두 이름을 거절한다.

- `NODE_OPTIONS` — "부모의 `NODE_OPTIONS` 는 녹화·재생 배선이 자식에게 이미 이어 붙입니다."
- `MCPEAK_*` — "녹화·재생 배선이 자식 환경에 직접 씁니다. 사용자 값이 그것을 덮으면 녹화가 조용히 꺼집니다."

**중계기는 이 둘을 거절하지 않는다.** 두 거절의 이유가 전부 "녹화·재생 배선이 자식 환경에 직접
쓴다" 인데, 중계기에는 그 배선이 없기 때문이다. 이유가 거짓인 거절 문안을 다는 것이 —
문안이 곧 제품인 저장소에서 — 규약이 한 곳 어긋나는 것보다 나쁘다고 판단했다. 사용자가 그 문장을
읽고 찾으러 갈 배선이 존재하지 않는다.

**나중에 중계기에 녹화가 얹히면 이 판단을 다시 봐야 한다.** 그때는 이유가 참이 되므로, 거절을
추가하는 쪽이 맞다. 이 문단이 그 시점의 근거다.

### 문안이 두 곳에 산다

cli 의 `parseEnvForwardOption` 을 재사용하지 않고 mock 안에 따로 둔다. 의존 방향이
`cli → mock` 이라 반대로 가면 순환이다([ADR-0091](./0091-패키지는-하위-계층을-직접-의존할-수-있다.md) 은
하위 계층을 직접 의존하는 것을 허용하지만, 이것은 상위 계층을 의존하는 것이라 해당하지 않는다).

대가는 이름 형식 검사와 거절 문안이 두 곳에 사는 것이다. **한쪽을 고치면 다른 쪽이 조용히 낡는다.**
위의 의도된 차이(`NODE_OPTIONS` · `MCPEAK_*`)와 의도치 않은 표류를 구별할 방법이 지금은 없다.

### 빈 값

지정한 이름의 값이 비어 있을 때는 **이름만 말한다.** 값이 비었다는 사실을 알리려다 값을 화면에
찍으면 이 옵션이 존재하는 이유가 없어진다([ADR-0070](./0070-원격-서버의-인증-헤더는-값이-아니라-환경변수-이름으로-받는다.md) §3).
