# ADR-0105: 사전 점검의 호출은 읽기 전용 도구만 기본으로 하고 비밀은 카나리로 대체한다

- 상태: 제안
- 날짜: 2026-10-03
- 담당: audit
- 작성자: @seodduu
- 참조: ADR-0104, `docs/plans/2026-10-03-audit-핵심-검사-구현계획.md` §3.5·§3.7·§10,
  `docs/2026-10-03-mcp-보안-테스트-도구-시장조사.md`

## 배경

설명문만 읽어서는 응답에 숨은 지시(ATPA)나 환경변수를 밖으로 내는 서버를 잡지 못한다. 도구를 실제로
불러 응답을 봐야 한다. 그런데 도구 호출은 파일 삭제·메시지 전송처럼 사용자 환경을 바꿀 수 있고,
서버를 띄울 때 사용자의 진짜 토큰을 넘기면 점검 도구가 비밀을 의심스러운 서버에 건넨다. 단계 1 에는
Docker 격리가 없다.

## 선택지

1. **기본 `--probe readonly`(readOnlyHint 가 true 인 도구만 호출), 서버 env 에는 흔한 비밀 이름마다
   무작위 카나리 값을 넣는다. `--env` 로 명시한 이름만 실제 값을 넘긴다.** (채택)
2. mcpward 방식. 모든 도구를 호출하고(`tools/call` 까지) 호스트 env 를 그대로 상속한다. 기각. 상태를
   바꾸는 도구가 사용자 환경에서 실제로 돈다. 호스트 비밀이 검사 대상에 넘어간다.
3. snyk/agent-scan·mcp-shield 방식. 호출은 하지 않고 tools/list 만 보며, 서버는 설정의 env(또는
   `process.env` 전체)로 띄운다. 기각. 호출이 없어 응답 검사가 비고, env 를 넘기는 점은 2 와 같다.
4. jjaram16/mcp-harness 방식. Docker `--network none` 안에서 모든 도구를 부르고 카나리 파일을 심는다.
   보류. 동적 층의 모범이지만 Docker 가 전제라 단계 2(`--sandbox`)로 미룬다.

## 결정

- `--probe` 는 `readonly`(기본), `none`, `all` 셋이다. `all` 은 리포트 머리에 "상태를 바꾸는 도구도
  호출했습니다" 를 적는다. 호출할 도구가 없으면 그 사실을 "검사하지 않은 것" 에 적는다.
- stdio 서버 env 는 `{ ...카나리, ...--env 로 넘긴 실제 값 }` 이다. 카나리 값은 `MCPEAK_CANARY_` 와
  16자 hex 이고 이름마다 다르다. 응답에 카나리가 나오면 `secret/env-leak`, 실제 값이 나오면
  `secret/env-echo` 다. 어느 값도 출력에 쓰지 않고 `<canary:NAME>`·`<redacted:NAME>` 자리표만 쓴다.
- 서버가 보내는 sampling·elicitation·roots 요청을 보려고 세 능력을 광고하되, 요청에는 언제나
  MethodNotFound 로 답한다. 모델 응답을 대신 만들어 주지 않는다.

## 이유

readOnlyHint 는 서버의 자기 신고라 거짓일 수 있지만, 그 거짓이 곧 `schema/annotation-mismatch` 의
대상이다. 신고를 믿고 부른 결과로 사고가 나면 그 서버는 어차피 등록하면 안 되는 서버다. 카나리는
진짜 비밀을 주지 않으면서 "env 를 읽어 밖으로 내는가" 를 결정론적으로 판정한다(값은 무작위여도 출력에
나오지 않으므로 `--json` 바이트는 같다).

## 결과

- 주석을 쓰지 않는 서버는 호출이 0건이라 `result`·`secret/env-leak` 의 응답 부분이 빈다. 리포트가
  그 사실을 이유와 함께 적는다. `examples/` 네 서버가 모두 이 경우다.
- `examples/audit-target-server` 의 `echo_env` 가 카나리 경로를 E2E 로 고정한다.
- HTTP 대상은 띄울 프로세스가 없어 카나리를 심을 수 없다. env 경로 검사는 stdio 전용이다.
