# ADR-0107: 격리 안 네트워크는 차단이 아니라 가로채기로 관측하고 호출 기본값을 all 로 바꾼다

- 상태: 제안
- 날짜: 2026-10-03
- 담당: audit
- 작성자: @seodduu
- 참조: ADR-0104, ADR-0105, `docs/plans/2026-10-03-audit-샌드박스-행위-관측-구현계획.md` §3.0·§3.1·§3.7·§9.4·§10,
  `docs/reports/2026-10-03-sandbox-T1.md` 의 "재생 모드 실측"
- 번호: 계획서와 T1 보고서는 이 결정을 ADR-0106 으로 부른다. 그 번호를 대시보드 ADR 이 먼저 써서 0107 로
  옮겼다. 같은 계획서의 ADR-0107 은 ADR-0108 이다.

## 배경

`mcpeak audit --sandbox` 는 서버를 버려지는 Docker 컨테이너 안에서 띄우고 도구를 불러 행위를 본다. 정할 것이
둘이다. 하나는 컨테이너의 네트워크다. 끊으면 안전하지만 날씨 API 를 부르는 정상 서버가 전부 실패하고, 실패한
서버는 자격 증명을 어디로 보내려 했는지도 보여 주지 않는다. 다른 하나는 호출 범위다. ADR-0105 는 격리가
없다는 이유로 기본을 `readonly` 로 두었고, 격리가 생기면 `all` 로 바꾼다고 예고했다. 주석을 쓰지 않는 서버는
`readonly` 에서 호출이 0건이라 볼 행위가 없다.

## 선택지

1. **컨테이너를 `--internal` 네트워크에만 붙이고, 같은 네트워크의 게이트웨이 컨테이너가 이름 풀이(DNS)에
   자기 주소로 답해 80·443 을 받아 상류로 전달하며 요청을 기록한다. TLS 는 실행마다 만든 CA 로 종단한다.
   격리가 실제로 켜진 실행의 호출 기본값은 `all` 이다.** (채택)
2. `--network none`. 기각. 정상 서버가 동작하지 않아 "정상 서버에서 발견 0" 을 확인할 수 없고, 나가려던
   요청의 목적지와 본문을 보지 못한다. 유출은 요청이 나가야 보인다.
3. 프록시 환경변수(`HTTPS_PROXY`)로 프록시를 거치게 한다. 기각. Node 의 `fetch`(undici)는 그 변수를 기본으로
   읽지 않고 런타임마다 설정법이 다르다. 변수를 무시하는 코드는 프록시를 그냥 지나친다. 관측을 서버의 협조에
   맡기는 셈이다.
4. 격리 안에서도 기본을 `readonly` 로 둔다. 기각. `examples/` 의 정상 서버 대부분이 호출 0건이 되어 격리를
   켠 의미가 없다.

## 결정

- target 컨테이너는 어느 모드에서도 `--internal` 네트워크에만 붙는다. 이름을 물으면 게이트웨이 주소를 받고,
  IP 를 직접 쓰는 접속은 어디에도 닿지 않고 `connect()` 기록에만 남는다.
- 게이트웨이는 `--internal` 과 기본 `bridge` 둘에 붙는다. **재생에서도 그렇다.** 계획 초안은 재생이면
  `bridge` 를 붙이지 않는다고 했지만, Docker 29.2.1 실측에서 `--internal` 에만 붙은 컨테이너는 `-p` 를 줘도
  포트가 publish 되지 않아(`Ports` 가 `{"7000/tcp":[]}`) 호스트가 제어 포트에 닿지 못했다. masquerade 를 끈
  브리지도 Docker Desktop 에서는 외부로 나갔다. 그래서 재생에서 상류에 접속하지 않는 것은 네트워크 구성이
  아니라 게이트웨이 코드(`MCPEAK_GATEWAY_MODE=replay`)가 보장하고, 루프백 스펙이 상류 접속 수 0 과 이름
  조회 0 을 단언한다. 리포트의 `재생(네트워크 없음)` 은 서버 쪽에서 본 사실이다.
- 호출 정책은 둘로 나눈다. 격리가 실제로 켜지면 `all`, 켜지지 않으면(Docker 없음, 지원하지 않는 명령 등)
  `readonly` 다. 사용자가 `--probe` 를 직접 주면 어느 쪽에서도 그 값이다.
- 도구 설명·README·`package.json`·`--allow-host` 에서 읽은 호스트는 선언된 목적지다. 그리로 가는 접속은
  `info` 로만 남는다. 카나리가 실린 요청은 목적지가 선언됐어도 `high` 다.

## 이유

런타임과 무관하게 통하는 것은 "이름을 물으면 게이트웨이 주소를 준다" 와 "신뢰 CA 에 우리 CA 를 더한다"
둘뿐이다. 이 방식이면 정상 서버는 평소대로 응답하고, 악의적인 서버가 보내는 요청은 본문까지 기록된다. 녹화한
세션으로 재생하면 외부 응답이 고정돼 `--json` 이 바이트 단위로 같아지고, 녹화에 없는 요청은 그 자체가 발견이
된다. `all` 은 컨테이너의 홈이 미끼 자격 증명뿐이고 루트가 읽기 전용이라 잃을 것이 없을 때만 켜진다.
격리가 안 켜졌는데 `all` 로 도는 일은 없다.

## 결과

- live-weather 는 격리 안에서 정상 응답을 받고, 접속은 `network/declared-destination` 으로만 남는다. E2E
  (`packages/cli/tests/audit-sandbox-e2e.test.ts`)가 녹화와 재생의 `--json` 이 `sandbox.network` 한 줄만
  다른 것을 고정한다.
- 게이트웨이가 `bridge` 에 붙어 있으므로 서버가 게이트웨이를 발판으로 호스트나 메타데이터 주소에 닿지 못하게,
  내부 주소로 풀리는 이름과 IP 꼴 `Host` 는 전달하지 않는다.
- 인증서 고정을 쓰는 접속은 목적지만 기록되고 내용은 보지 못한다. HTTP 가 아닌 프로토콜도 같다. 리포트가
  그 사실을 적는다.
- 선언은 서버가 스스로 쓸 수 있다. 그래서 선언은 목적지 판정만 누그러뜨리고, 리포트가 선언 목록을 보인다.
- `--probe` 를 주지 않은 `--sandbox` 실행은 상태를 바꾸는 도구도 부른다. 리포트의 호출 정책 줄이 그 사실과
  호출 횟수를 적는다.
