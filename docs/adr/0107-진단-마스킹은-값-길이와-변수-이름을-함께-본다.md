# ADR-0107: 진단 마스킹은 값 길이와 변수 이름을 함께 본다

- 상태: 제안
- 날짜: 2026-09-22
- 담당: dashboard
- 작성자: @storyrago
- 참조: [ADR-0097](./0097-비밀값은-argv-가-아니라-환경변수로-넘기고-출처-인자는-가린다.md),
  [ADR-0105](./0105-대시보드가-케이스-꼬리표를-매기고-중계-통로를-run-과-나눈다.md)

## 배경

중계기가 기동 줄을 내지 못하면 대시보드는 그 stderr 를 기동 실패 진단에 붙여 `POST
/api/relay` 의 HTTP 400 본문으로 돌려준다. 자식이 자기 환경을 되찍는 경우가 흔해, 거기
찍힌 환경변수 값을 문자열 치환으로 가린다.

가릴 대상을 **값의 길이**로만 골랐다(`MIN_MASK_VALUE_LENGTH = 20`, ADR-0097 의
`origin-redaction.ts` 와 같은 문턱). 그래서 20 자 미만인 비밀값은 그물을 그냥 빠져나간다 —
12 자짜리 API 키를 쓰는 서버가 그 값을 stderr 에 되찍으면 원문이 그대로 응답에 실린다.
CWE-532.

## 선택지

1. 길이 문턱을 없애고 모든 환경변수 값을 가린다.
2. 값 길이에 더해 **변수 이름**이 비밀처럼 보이면 가린다.
3. 기동 실패 진단에서 stderr 를 아예 빼고 "터미널에서 직접 확인하라"고만 안내한다.

## 결정

**2 번.** 값이 20 자 이상이거나, 이름이 `KEY`·`TOKEN`·`SECRET`·`PASSWORD`·`CREDENTIAL` 중
하나를 포함하면서 값이 8 자 이상이면 가린다.

## 이유

- **1 번은 진단을 스스로 지운다.** 치환은 `line.split(value).join("***")` 이라 값이 `1` ·
  `true` · 포트 번호면 무관한 글자까지 전부 `***` 가 된다. 「실패 메시지가 곧 제품이다」를
  지키려고 만든 꼬리가 그 원칙을 깨는 꼴이다.
- **3 번은 이 꼬리를 붙인 이유 자체를 버린다.** 중계기가 이미 말해 준 것(`spawn nosuchbinary
  ENOENT` 같은 원인 줄)을 버리고 사용자에게 다시 해보라고만 하게 된다.
- 이름 기반에도 **길이 바닥 8 을 남긴 것**이 이 결정의 요점이다. 이름만 보고 무조건 가리면
  `AUTH=1` 같은 플래그가 1 번과 같은 손해를 낸다. 실제 비밀이 8 자 미만인 경우는 드물다.

## 결과

- 짧은 비밀값이 HTTP 400 본문으로 새는 경로가 닫힌다.
- 이름이 비밀처럼 보이지 않으면서 20 자 미만인 비밀값은 **여전히 샌다.** 값만 보고 비밀 여부를
  판정할 방법이 없어 남긴 한계이고, 더 좁히려면 3 번(원문을 아예 안 싣기)으로 가야 한다.
- `record` 의 `origin-redaction.ts` 는 이 변경을 따라가지 않았다. 그쪽은 "이 값이 비밀처럼
  생겼나"를 접두사 모양으로 재는 다른 판정이고, 여기는 "이미 아는 값을 가릴지"를 잰다.
