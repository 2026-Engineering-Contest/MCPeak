# ADR-0111: 대시보드를 개발자와 사용자 모드로 나누고 사전 점검은 비밀값을 넘기지 않는다

  `docs/2026-10-03-analyze-로드맵.md` §0

## 배경

로드맵 §0 은 대시보드 메뉴를 "`Analyze` 하나에 보안 탭과 토큰 탭" 으로 정했다. 그 보안 탭은 서버 개발자가
자기 프로젝트의 서버를 점검하는 화면이다. MCP 서버를 쓰기만 하는 사람이 **등록하기 전에** 남의 서버를
점검하는 화면은 없다. 이 결정은 로드맵 §0 의 "대시보드 메뉴" 줄을 고친다. `Analyze` 의 두 탭은 그대로 두고,
대시보드를 개발자와 사용자 두 모드로 나눠 사용자 모드에 사전 점검 화면을 따로 둔다.

모드를 나누면 정할 것이 다섯이다. 지금 화면이 어느 모드인지를 무엇이 정하는가, 고른 모드를 언제
기억하는가, 모드를 묻는 화면을 언제 띄우는가, 붙여 넣은 설정의 환경변수와 헤더 값을 서버에 넘기는가,
"등록해도 되는가" 의 결론 문장을 누가 만드는가.

뒤의 둘은 대상이 다르다는 데서 나온다. 개발자용 보안 탭의 대상은 자기 서버이고, 사전 점검의 대상은 믿지
않는 서버다.

## 선택지

| 항목 | 채택 | 버린 것 |
|---|---|---|
| 모드의 진실 | 해시가 먼저, 저장값이 다음이다. 지금 화면의 모드는 `modeOfHash(hash) ?? 저장값 ?? "developer"` 다. 개발자 주소는 그대로 두고 사용자 쪽만 `#/user/` 접두사를 쓴다 | 저장값만 보는 것 |
| 저장 시점 | 도착할 때 저장한다. App 이 받아들인 해시의 모드가 저장값과 다르면 쓴다. 저장값은 "마지막으로 머문 모드" 다 | 전환 링크를 누를 때 저장하는 것 |
| 선택 화면 | 저장값이 없고 갈 곳이 없는 주소(빈 해시, 모르는 해시)일 때만 `#/welcome` 을 띄운다 | 저장값이 없으면 항상 띄우는 것 |
| env·헤더 값 | 보내지 않는다. 이름만 화면에 보인다 | `--env <이름>`, `--header-env` 로 넘기는 것 |
| 판정 문장 | 결론을 만들지 않는다. 발견마다 `fix` 대신 "왜 위험한가" 한 줄을 보인다. 그 문장은 대시보드가 규칙 id 마다 하나씩 갖는다 | 대시보드가 "등록하지 마세요" 같은 결론을 만드는 것. 기존 `fix` 문장을 그대로 보이는 것(처음 결정. 아래 "고친 이력") |

## 결정

- 모드는 `developer` 와 `user` 둘이고 **보기 필터**다. 접근을 막지 않는다. 주소를 직접 치면 반대 모드의
  화면이 열린다.
- 지금 화면의 모드는 해시가 정한다. `#/user/...` 는 사용자, 기존 일곱 화면의 주소는 개발자다. `#/settings`
  와 `#/welcome` 처럼 해시가 말하지 않는 화면에서만 저장값을 보고, 저장값도 없으면 개발자로 그린다.
- 저장값(`localStorage` 의 `mcpeak-mode`)은 App 이 해시를 받아들일 때 쓴다. 리다이렉트될 해시
  (`#/user/unknown`)는 화면에 도착하지 않았으므로 쓰지 않는다.
- 모드 전환은 반대 모드의 첫 화면을 가리키는 링크(`<a href>`)다. 사이드바 아래쪽 `Settings` 바로 위에 둔다.
- 선택 화면은 저장값이 없는 브라우저가 빈 해시나 모르는 해시로 들어올 때만 뜬다. 저장값이 없어도
  `#/runs/abc` 같은 깊은 링크는 그 화면이 바로 열린다.
- 사전 점검은 붙여 넣은 설정의 환경변수와 헤더의 값을 어디에도 보내지 않는다. 요청에 `--env` 와
  `--header-env` 를 싣지 않고, 화면에는 이름만 보인다.
- 실행 파일 앞에 붙은 환경변수 전달(`KEY=value 명령`, `env KEY=value 명령`)은 이름만 남기고 걷어 낸다.
  JSON 설정의 `command` 한 칸에 그런 셸 줄을 통째로 적었으면 입력을 거절한다. 받아들이면 그 값이 대상 줄과
  요청에 실린다. 거절 문장에는 값을 싣지 않는다. 실행 파일 뒤의 인자는 그대로 넘긴다. 인자에 직접 적은
  비밀값(`--api-key sk-...`)은 이 결정이 막지 못한다.
- 사전 점검은 결론 문장을 만들지 않는다. 결과 화면은 개발자용 보안 탭과 같은 컴포넌트이되, 발견마다
  "해결" 줄 대신 "왜 위험한가" 줄을 보인다. `fix` 문장과 CLI 리포트 원문(해결 줄이 들어 있다)은 사용자
  모드에서 보이지 않는다. 위험 설명 문장은 `web/src/analyze/risk-text.ts` 가 규칙 id 마다 하나씩 갖고,
  무엇을 하라는 명령문을 쓰지 않는다. 심각도와 발견 여부는 리포트 그대로다.

## 이유

- 저장값만 보면 같은 주소가 브라우저마다 다른 화면을 연다. 공유한 주소, 새로 고침, 뒤로 가기가 저장값에 따라
  달라진다. 해시가 먼저면 주소 하나가 화면 하나다. 개발자 주소에 `#/dev/` 접두사를 붙이지 않은 것은 기존
  링크와 저장된 주소, 테스트가 전부 움직이기 때문이다.
- 링크를 누를 때 저장하면 이탈 확인(`leave-guard`)이 이동을 막았을 때 이동은 안 했는데 저장만 바뀐다. 이탈
  확인은 `hashchange` 에 걸려 있어서, 전환이 링크이고 저장이 도착 시점이면 확인을 다시 짤 것이 없다.
- 저장값이 없을 때 항상 선택 화면을 띄우면 깊은 링크로 들어온 사람을 막는다. 그 사람은 이미 갈 곳을 골랐다.
- `--env <이름>` 은 값이 아니라 이름을 넘기는 옵션이다. 값은 대시보드 프로세스의 같은 이름 환경변수에서
  읽는다(`audit-command.ts` 의 `forwardedEnv`). 사전 점검이 이름을 넘기면 대시보드를 띄운 사람의 **실제
  값**이 믿지 않는 서버에 간다. 가짜 값으로 바꿔 넘기려면 `cli` 와 `audit` 을 고쳐야 하고, 그것은 이 결정의
  범위 밖이다.
- 판정은 `@mcpeak/audit` 가 한다(ADR-0110). 대시보드가 결론을 새로 쓰면 CLI 리포트와 화면이 다른 말을 하게
  되고, 판정이 규칙이 아니라 화면 코드에 생긴다. 위험 설명은 판정이 아니라 규칙의 설명이라 이 원칙을 깨지
  않는다. 무엇이 발견됐는지(`message`), 심각도, 근거는 여전히 `audit` 의 것이다.
- `fix` 는 "주석을 false 로 고치세요" 처럼 MCP 를 만든 사람에게 하는 말이 섞여 있다. 사전 점검을 쓰는 사람은
  MCP 를 고치지 않는다. 그 문장을 보이면 사용자가 무언가를 고쳐야 하는 것처럼 읽힌다.

## 결과

- 얻는 것: 주소 하나가 화면 하나다. 개발자 모드의 사이드바와 주소는 전환 링크 한 줄 말고는 그대로다. 사전
  점검이 서버 면과 `audit`, `cli` 를 한 줄도 바꾸지 않는다.
- 치르는 것: 저장값은 마지막으로 머문 모드다. 사용자 모드인 사람이 개발자 주소 링크를 열면 그 뒤로는
  개발자 모드로 기억된다. 전환 링크를 눌렀을 때만 바뀌게 하려면 이탈 확인과의 순서를 따로 짜야 한다.
- 치르는 것: API 키가 있어야 뜨는 서버는 사전 점검이 연결 실패로 끝날 수 있다. 화면은 CLI 의 실패 문장을
  그대로 보인다. 가짜 값을 대신 넘기는 것은 후속 후보다.
- 치르는 것: 사전 점검은 "등록해도 된다" 를 말하지 않는다. 심각·주의 발견이 없으면 요약 카드가 없을 뿐이다.
- 모드는 권한이 아니다. 사용자 모드로 띄운 대시보드에서도 개발자 화면의 주소는 열린다.
- 치르는 것: 위험 설명 문장이 `audit` 가 아니라 대시보드에 있다. 규칙이 늘면 문장도 더해야 한다. 빠뜨리면
  `risk-text.test.ts` 가 `audit` 의 규칙 목록과 대조해 빨개지고, 화면은 그 사이 규칙 가족 단위 문장을 보인다.
  문장을 `audit` 의 규칙 설명(`RuleInfo`)으로 옮기는 것은 후속 후보다.

## 고친 이력

- 2026-10-04: "판정 문장" 을 고쳤다. 처음에는 결과 위에 심각·주의 발견의 `fix` 문장을 모은 "먼저 할 일" 카드를
  두고 발견마다 "해결" 줄을 그대로 보였다. 실제로 써 보니 사용자가 MCP 를 고쳐야 하는 것처럼 읽혔다. 카드를
  없애고 "해결" 줄을 "왜 위험한가" 줄로 바꿨다.
