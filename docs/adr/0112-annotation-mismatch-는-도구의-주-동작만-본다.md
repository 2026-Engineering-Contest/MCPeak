# ADR-0112: annotation-mismatch 는 도구의 주 동작만 본다

- 상태: 제안
- 날짜: 2026-10-04
- 담당: audit
- 작성자: @seodduu
- 참조: ADR-0104, `docs/plans/2026-10-04-audit-오탐과-재생-비대칭-수정-구현계획.md` §2·§3,
  `docs/plans/2026-10-03-audit-핵심-검사-구현계획.md` §3·§6

## 배경

`schema/annotation-mismatch`(high)는 `readOnlyHint: true` 인 도구가 실제로는 쓰기·삭제를 한다고 말할 때
잡는 규칙이다. 지금까지는 도구 이름에 읽기 동사가 없으면 이름·제목·설명 **전체**에서 파괴적 낱말을
찾았다. 공개 MCP 서버 39개(도구 676개)의 `tools/list` 에 돌려 보니 high 가 8건 나왔고 전부 정상
도구였다. `git_log` 의 "View commit history"(명사), netlify 의 "get-deploy"(리소스 이름), postman 의
"POST"(HTTP 메서드), notion 의 "read/update capability"(에러 설명) 같은 것들이다. high 는 종료 코드를
바꾸므로, 이 오탐은 정상 서버의 CI 를 빨갛게 만든다.

같은 측정에서 `desc/implicit-trigger`(medium) 13건 중 9건이 파라미터(`inputSchema` 속성) 설명에서
나왔다. "이 도메인을 빼려면 exclude_domains 를 채워라" 꼴의 인자 채우기 안내다.

## 선택지

| 항목 | 채택 | 버린 것 |
|---|---|---|
| annotation-mismatch 가 설명을 보는 범위 | 이름의 첫 토큰, 그리고 설명·제목의 **맨 앞 동사**만 본다 | (가) 설명 전체 훑기 유지. 오탐 8건이 그대로다. (나) 설명을 아예 안 보고 이름만. "Overwrite the remote copy." 로 시작하는 `sync_items` 같은 진짜 불일치를 놓친다 |
| implicit-trigger 가 도는 자리 | 파라미터 설명에서는 돌지 않는다. 도구 설명에서는 그대로 돈다 | 파라미터 설명에서도 유지. 도구 설명 안의 교차 호출 안내까지 좁히기(재현율을 건드린다) |
| 활용형("Deletes …") | 잡지 않는다. 기존 정규식의 단어 경계 그대로다 | 선두 동사에 한해 활용형까지 넓히기. 규칙 의미가 바뀐다 |

## 결정

- `annotation-mismatch` 는 이름에 읽기 동사가 없을 때 이름 첫 토큰, 설명의 맨 앞 낱말,
  `annotations.title` 과 `title` 의 맨 앞 낱말만 `DESTRUCTIVE_VERB` 에 댄다. 이름에 읽기 동사가 있는
  도구는 전과 같이 이름 첫 토큰만 본다.
- `implicit-trigger` 는 위치가 `inputSchema` 로 시작하는 문자열에서 돌지 않는다. 그 문자열에 대한 다른
  규칙(injection, shadowing, covert, sensitive-path)은 그대로 돈다.
- 규칙 id, 심각도, 메시지, fix 문안은 바꾸지 않는다. 발견이 나는 조건만 좁힌다.

## 이유

- 도구 설명은 제 동작 동사로 시작하는 것이 보통이다. 맨 앞 동사는 주 동작이고, 중간의 낱말은 대개
  대상이나 부가 설명이다. 이 구분 하나로 오탐 8건이 전부 사라지고 기존 단언(진짜 불일치)은 전부 남는다.
- high 오탐은 사용자가 규칙 전체를 끄게 만든다. 덜 잡더라도 잡은 것이 맞아야 종료 코드를 믿을 수 있다.
- 파라미터 설명은 모델이 인자를 채울 때 읽는 자리다. 거기 적힌 조건문은 호출을 유발하는 지시가 아니라
  값 선택 안내인 경우가 대부분이다. 숨은 지시를 심는 공격은 injection·covert 규칙이 같은 자리에서
  계속 잡는다.
- MCPTox 측정 하네스는 사례를 속성 없는 스키마로 만들기 때문에 이 변경은 재현율에 닿지 않는다.

## 결과

- 실서버 수집본(39개 서버, 도구 676개): `annotation-mismatch` high 8건 → 0건, 파라미터 설명의
  `implicit-trigger` 9건 → 0건. 도구 설명의 `implicit-trigger` 4건은 남는다.
- MCPTox 재현율은 73.9%(970/1312) 그대로이고, 같은 입력 2회 출력이 바이트까지 같다.
- 한계 1. 설명이 활용형("Deletes …", "Creates …")으로 시작하고 이름 첫 토큰이 파괴적이지 않은 도구는
  잡지 못한다. 수정 전에도 활용형은 못 잡았지만, 설명 중간의 원형 낱말로 우연히 잡히던 경우가 이제
  사라진다. 테스트가 이 동작을 알려진 한계로 고정한다. 선두 동사에 한해 활용형을 받는 것이 후속
  후보이고, 실서버 표본과 MCPTox 재측정을 함께 해야 한다.
- 한계 2. 제목이 "Notion: Delete page" 처럼 접두어로 시작하면 맨 앞 낱말이 동사가 아니라 놓친다.
- 한계 3. 도구 설명 안의 선의의 교차 호출 안내("If the user asks X, call Y")는 여전히 medium 으로
  잡힌다. 선의의 라우팅과 악성 재지정을 정적으로 가르는 것은 ADR-0104 가 적은 정적 층의 한계다.
