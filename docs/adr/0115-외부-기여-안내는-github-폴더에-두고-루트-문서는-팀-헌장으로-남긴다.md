# ADR-0115: 외부 기여 안내는 .github 폴더에 두고 루트 문서는 팀 헌장으로 남긴다

- 상태: 제안
- 날짜: 2026-10-09
- 담당: adr (저장소 공통)
- 작성자: @endl24
- 참조: #511, `.github/CONTRIBUTING.md`, `CONTRIBUTING.md`

## 배경

루트 `CONTRIBUTING.md`는 5인 팀이 대회 마감까지 쓰려고 만든 팀 헌장입니다. 마감일, 코드 동결,
개인 기여 체크리스트 같은 내부 규칙이 대부분입니다. 외부 기여자가 이 문서를 읽으면 자기에게 해당하는
규칙을 찾기 어렵습니다. 예를 들어 "다른 오너의 패키지를 고치지 않는다"를 외부 기여자도 지켜야 하는
규칙으로 읽을 수 있습니다.

그래서 외부용 안내와 팀 내부 규칙을 나누기로 했습니다. 문제는 이 문서를 가리키는 곳이 많다는 점입니다.
저장소 전체에서 `CONTRIBUTING §2.1`, `§6`처럼 절 번호로 이 문서를 가리키는 줄이 121개입니다.
그중에는 각 패키지의 코드 주석, 지난 ADR 24개, `.coderabbit.yaml`, `CLAUDE.md`, 워크플로 주석이 있습니다.

## 선택지

- **A안: 외부용을 `.github/CONTRIBUTING.md`에 새로 쓴다.** 루트 문서는 그대로 두고 맨 위에 안내 한 줄만 넣는다.
- **B안: 루트 문서를 외부용으로 다시 쓰고, 지금 내용은 `docs/team-charter.md`로 옮긴다.**
- **C안: 루트 문서 맨 앞에 외부 기여자용 절을 하나 더 넣는다.**

## 결정

A안을 고릅니다.

## 이유

GitHub은 CONTRIBUTING 파일이 여러 개 있으면 `.github` 폴더, 저장소 루트, `docs` 폴더 순서로 찾아서
처음 찾은 파일을 이슈·PR 화면의 링크에 씁니다
([GitHub 문서](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/setting-guidelines-for-repository-contributors)).
그래서 A안이면 외부 사람은 GitHub이 안내하는 대로 외부용 문서를 보게 되고, 기존 참조 121줄은
그대로 맞습니다.

B안은 파일 이름이 가장 깔끔합니다. 하지만 121줄이 엉뚱한 문서를 가리키게 됩니다. 이 참조를 고치려면
여러 오너의 패키지 코드와 지난 ADR을 한꺼번에 고쳐야 합니다. 패키지 단위 소유 규칙(CONTRIBUTING §2.2)과
맞지 않고, 지난 ADR은 당시 기록이라 고치지 않는 편이 맞습니다.

C안은 가장 간단합니다. 하지만 외부 사람이 470줄짜리 팀 헌장을 계속 받게 됩니다. 새 절을 앞에 넣으면
기존 절 번호가 밀리는 문제도 있습니다.

포기한 것: 이름이 같은 파일이 두 개 생깁니다. 저장소를 처음 보는 사람은 헷갈릴 수 있어서, 루트 문서
맨 위와 README에 외부용 문서 링크를 둡니다.

## 결과

- 외부 기여자 규칙은 `.github/CONTRIBUTING.md`에서만 고칩니다. 루트 문서에 같은 규칙을 복사하지 않습니다.
- 팀 규칙이 바뀌어 외부 기여자에게도 영향이 있으면 두 문서를 함께 고칩니다. 예: 커밋 형식, 의존성 정책.
- `.github/CONTRIBUTING.md`도 전원 리뷰 대상으로 CODEOWNERS에 넣었습니다.
- 남은 일: PR 템플릿(`.github/pull_request_template.md`)은 외부 기여자에게도 보이는데, "면접 답변" 같은
  내부용 문구가 있습니다. 외부용으로 다듬을지는 따로 정합니다.
