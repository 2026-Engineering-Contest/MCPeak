# ADR-0116: Analyze 는 탭이 아니라 축 카드와 상세이고, 축은 한 번에 시작하되 상태는 독립이다

- 상태: 제안. ADR-0117 이 두 단계 흐름을 더한다.
- 날짜: 2026-10-18
- 담당: dashboard
- 작성자: @seodduu
- 참조: ADR-0110, ADR-0111, `docs/2026-10-18-analyze-통합-대시보드-설계.md` §12·§13,
  `docs/plans/2026-10-18-analyze-통합-대시보드-구현계획.md`, `docs/2026-10-03-analyze-로드맵.md` §0

## 배경

로드맵 §0 과 ADR-0111 은 개발자 모드 Analyze 를 "보안 탭과 토큰 탭" 둘로 정했다. 탭은 한 번에 한 축만
보이고, 점검 시작도 축마다 따로 눌러야 한다. 그래서 "이 서버가 지금 어떤 상태인지" 를 한눈에 볼 수 없다.
세 번째 축(성능 효율성)이 들어올 자리도 탭 하나를 더하는 것 말고는 정해져 있지 않았다.

## 선택지

- **(a) 탭 유지 + 탭 라벨에 배지.** 탭마다 판정 배지를 붙인다.
- **(b) 축 카드 + 상세.** 축마다 카드(판정과 핵심 숫자)를 늘어놓고, 고른 축의 상세를 그 아래에 연다.
- **(c) 서버 엔드포인트 하나로 두 결과를 한 run 으로 묶고, 단일 리포트 화면을 둔다.**

## 결정

(b) 를 고른다. 서버는 그대로 두고 브라우저가 보안 점검과 토큰 분석 두 요청을 동시에 보낸다("한 번에
분석"). 두 축의 상태는 서로 독립이다. 한쪽이 실패하거나 늦어도 다른 쪽 카드는 제 상태로 끝난다.

## 이유

(a) 는 배지가 생겨도 한 번에 한 축의 내용만 보여서 한눈에 보기가 안 된다. 시작도 여전히 축마다 따로다.

(c) 는 서버 변경과 리포트 포맷 합의가 필요하다. 게다가 보안은 run(SSE)이고 토큰은 동기 요청이라 수명이
달라, 한 run 으로 묶으면 토큰 결과가 보안 끝날 때까지 기다린다. 토큰 분석은 금방 끝나는데 격리 점검이
길면 그만큼 빈 화면을 보게 된다.

(b) 는 서버 API(`src/api-types.ts`)를 바꾸지 않고 `web/` 안에서 끝난다. 판정 문장은 지금처럼 CLI 가
만들고, 카드는 그 결과를 요약만 한다.

## 결과

- 세 번째 축은 카드·훅·상세 세 파일과 `parseRoute` 한 줄로 끼운다. 성능 효율성은 지금 카드 자리만 있고
  연결되지 않았다.
- 판정은 계속 CLI 의 것이다. 대시보드는 판정을 새로 만들지 않는다.
- 주소는 `#/analyze`(개요), `#/analyze/tokens`, `#/analyze/security` 다. 라우트 세그먼트 `tokens` 는 그대로
  두고 라벨만 "비용 최적화" 로 바꿨다.
- 보안 SSE 구독은 상세가 아니라 훅에 둔다. 상세에 두면 상세를 닫은 동안 카드가 점검이 끝난 것을 모른다.
- 보안의 첫 시작 실패는 카드 `failed` 다. 앞 결과가 있을 때만 `startError` 로 그 결과 옆에 보이고,
  다시 시작하면 그 시점에 `startError` 를 비운다.
- 구현 중 정한 것: 카드 칩의 숫자는 `<b>` 대신 `<strong>` 으로 감싼다(기존 "HTML 로 해석하지 않는다"
  테스트를 보존하기 위해서다). 카드 배치의 반응형 경계는 Tailwind `md`(768px)다.
- 포기한 것: "← 서버 다시 고르기" 로 도는 run 을 화면에서 버리고 새 점검을 시작하던 길이 사라진다.
  run 이 도는 동안 "한 번에 분석" 이 비활성이라 끝날 때까지 기다려야 한다. 격리 점검이 길어 불편하면
  취소 API 와 함께 다시 정한다.
