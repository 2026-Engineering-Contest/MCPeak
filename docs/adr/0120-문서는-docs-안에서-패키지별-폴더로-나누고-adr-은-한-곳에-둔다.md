# ADR-0120: 문서는 `docs/` 안에서 패키지별 폴더로 나누고, ADR 은 한 곳에 둔다

- 상태: 제안
- 날짜: 2026-10-24
- 담당: 전체 (문서 배치)

## 배경

`docs/` 바로 아래에 날짜가 붙은 설계 문서 40여 건이 쌓였고, `docs/plans/` 와 `docs/reports/`,
`docs/superpowers/` 에는 패키지를 가리지 않고 계획과 보고서 500건 가까이가 한 폴더에 섞여 있었습니다.
어느 패키지의 문서인지는 파일명을 읽어야 알 수 있었고, 오너가 자기 패키지의 문서를 모아 보거나
기여 이력을 뽑을 때 매번 손으로 골라야 했습니다.

## 선택지

1. **`docs/<패키지>/` 로 나눈다.** `docs/` 안에 패키지 이름의 폴더를 만들고 설계·계획·보고서를 그 아래로
   옮깁니다. ADR 은 `docs/adr/` 에 그대로 둡니다.
2. **`packages/<패키지>/docs/` 로 옮긴다.** 각 패키지 소스 폴더 안에 문서를 둡니다.
3. **ADR 까지 패키지 폴더로 옮긴다.** 1번에 더해 `docs/<패키지>/adr/` 로 ADR 을 나눕니다.

## 결정

1번을 택합니다. `docs/` 안에 `core` `runner` `generate` `record` `mock` `cli` `dashboard` `optimize`
`audit` `perf` 폴더와, 배포 문서를 두는 `release`, 어느 패키지에도 속하지 않는 문서를 두는 `common`
폴더를 만듭니다. 패키지 폴더 안은 날짜 붙은 설계 문서를 바로 아래에 두고 `specs/` `plans/` `reports/`
`benchmark/` `mockups/` 로 나눕니다. 폴더마다 `README.md` 를 두어 그 패키지 담당 ADR 표와 문서
목록을 싣습니다. `architecture.md` 와 `adoption.md`, `task-integration-ledger.tsv` 는 저장소 전체에
걸치므로 `docs/` 바로 아래에 남깁니다.

## 이유

- 2번은 모든 오너의 패키지 폴더를 한 커밋이 건드리게 됩니다. 패키지 폴더는 오너 한 사람이 소유한다는
  규칙(CONTRIBUTING)과 충돌합니다. `docs/` 안에서만 나누면 소스 폴더의 소유 경계는 그대로입니다.
- 3번은 ADR 번호가 전역이라는 전제를 깨뜨립니다. ADR 번호 충돌 이력(색인 하단)이 보여 주듯 번호를
  인용하는 곳이 많아, 경로까지 바뀌면 인용 수백 곳을 다시 써야 합니다. 색인의 「담당」 열이 이미
  패키지 구분을 주고 있으므로, 패키지 폴더의 README 가 그 열을 골라 보여 주는 것으로 충분합니다.
- `docs/adr/**` 를 코드로 취급하는 CI 판정(`ci.yml` 의 changes 잡)과 ADR 을 읽는 테스트
  (`dependency-boundary.test.ts`)가 경로 변화 없이 그대로 동작합니다.

## 결과

- 파일 536 개가 옮겨지고, 저장소 안의 경로 참조 338 개 파일이 새 경로로 고쳐졌습니다. 패키지 소스의
  주석과 README 에 있던 `docs/...` 문자열도 함께 고쳤습니다. 코드 동작은 바뀌지 않습니다.
- `biome.json` 의 제외 규칙과 `ci.yml` 의 문서 전용 변경 판정은 `docs/*/mockups/**`,
  `docs/*/benchmark/**` 로 바뀝니다.
- 벤치마크 스크립트 가운데 저장소 루트를 상대 경로로 찾던 두 곳은 한 단계 깊어진 만큼 고쳤습니다.
- 새 문서는 해당 패키지 폴더에 둡니다. 두 패키지에 걸치면 주 패키지에 두고, 어디에도 속하지 않으면
  `common/` 에 둡니다. 색인에 없는 ADR 네 건(0079 서버 후보, 0080, 0084, 0085)은 파일 내용으로
  담당을 정해 패키지 README 에 넣었고, 색인 등재는 별도 작업으로 남깁니다.
