## 임의로 판단한 부분

1. **`pnpm-lock.yaml` 갱신 (Files 밖).** 새 워크스페이스 패키지가 lockfile 에 없으면 CI 의 `pnpm install --frozen-lockfile` 이 실패하는 것을 실제로 확인했다. `pnpm install` 로 `packages/audit` importer 9줄만 더해졌다(`@mcpeak/core: link:../core`, SDK `1.30.0`). 외부 패키지 추가·버전 변경은 없다. 받아들이지 않으면 이 파일만 되돌리면 되지만 그 경우 CI 가 깨진다.
2. **`createServerSurface(sdk, diagnostics?)` 에 선택 인자 추가.** 계획서 시그니처는 `(sdk)` 하나다. `listToolsRaw` 가 `listTools` 와 같은 `McpClientError(PAGINATION_CURSOR_REPEATED)` 를 내려면 진단이 필요해, 두 번째 인자를 선택으로 두고 connect 계열은 실제 진단을 넘긴다. 생략하면 빈 stdio 진단을 쓴다(인메모리 테스트용). `(sdk)` 호출은 그대로 된다.
3. **`clientCapabilities(advertise)` 를 `server-surface.ts` 에 두고 export (core 공개 API 는 아님).** `index.ts` 안의 비공개 함수로 두면 "advertise 가 없으면 sampling 을 광고하지 않는다" 를 인메모리로 단언할 수 없어서다.
4. **prompts/resources 페이지네이션.** 계획서는 tools 만 커서 규칙을 말한다. prompts·resources 도 `collectPages` 로 끝까지 따라가고, cursor 반복 시 일반 `Error`(`prompts/list 의 cursor 가 반복되었습니다. ...`)를 던진다. core 오류 코드 `PAGINATION_CURSOR_REPEATED` 의 문장이 "tools/list cursor" 로 고정돼 있고 `errors.ts` 는 Files 밖이라 새 코드를 만들지 않았다.
5. **`listToolsRaw` 의 SDK 오류는 감싸지 않는다.** `listTools` 는 `OPERATION_FAILED`·`PROCESS_EXITED` 등으로 감싸지만, 그 분류 함수(`operationFailureKind`)는 어댑터 내부라 표면에서 쓰지 않았다. 오류는 SDK 원본으로 올라온다. T6 가 연결 실패를 분류해야 하면 보완이 필요하다.
6. **`observeServerMessages` 의 fallback 처리기는 첫 호출 때 설치되고 해제 후에도 남는다.** 리스너가 없어도 요청에는 `MethodNotFound`(`mcpeak does not serve <method>`)로 답하므로 SDK 기본 동작과 같은 오류 코드다.
7. **§5.2 에 없는 `audit`·`AuditDependencies`·`renderReport` 시그니처를 정했다.** `renderReport(report: AuditReport): string`, `audit(options: AuditOptions, deps: AuditDependencies): Promise<AuditReport>`. `AuditDependencies` 는 계획서 §12.7 의 목록(`connect(target, env, advertise)`·`readFile`·`writeFile`·`fetch`·`random`, now 없음)대로 만들었고, 연결 꼴은 `AuditConnection = McpServerInfo & McpServerSurface & { client; close() }` (audit.ts 안, 공개 안 함). **`generatorVersion`(리포트 `generator.version`)과 전달 env 의 실제 값(secret 규칙의 `forwarded`)을 받을 자리가 아직 없다.** T6 이 `audit.ts` 안에서 필드를 더하면 된다(`index.ts` 는 이름만 re-export 하므로 안 바뀐다).
8. **`types.ts`·`index.ts` 의 글자.** 계획서 코드 블록을 그대로 넣은 뒤 `pnpm lint`(biome) 가 긴 줄 줄바꿈과 export 순서 정렬을 요구해 `biome check --write` 를 적용했다. 토큰은 같고 공백·순서만 다르다. `RawTool` 은 `types.ts` 끝에 더했다.
9. **스텁의 매개변수 이름에 `_` 접두.** 미사용 매개변수 경고를 피하려고 붙였다. 각 담당 태스크가 구현하면서 뗀다.
10. `packages/audit/README.md` 는 "구현 중" 세 줄만 두었다. 본문은 T7 몫이다.
