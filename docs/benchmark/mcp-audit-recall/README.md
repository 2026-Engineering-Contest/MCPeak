# MCPTox 재현율 측정: audit 의 desc 가족

`mcpeak audit` 의 정적 층(설명문 규칙, `desc/*`)이 공개 중독 도구 벤치마크를 얼마나 잡는지 잰다.
검토 문서(`docs/2026-10-03-audit-검사-목록-보강-검토.md` §5)의 "충분하다고 말할 수 없고 측정해야
한다" 에 대한 첫 실측이다. 이 값은 계획의 통과 조건이 아니라 **기록**이다. CI 에 넣지 않는다.

## 데이터

[MCPTox](https://github.com/zhiqiangwang4/MCPTox-Benchmark)(AAAI-26). 실제 MCP 서버 45개에 중독 도구를
심은 사례 집합이다. 저장소에 라이선스가 없어 **이 저장소에는 사례를 한 건도 넣지 않는다.** 측정할 때마다
`fetch.mjs` 가 임시 디렉터리에 받는다.

사례 단위는 `response_all.json` 의 `malicious_instance` 중 `wrong_data` 가 0 인 것이다. 논문이 집계한
1,312 사례가 이 집합이다. 각 사례의 `poisoned_tool`("Tool: <이름>\nDescription: <설명>")을 **그 서버의
정상 도구 목록에 더해 서버 하나로 만든다.** 정상 도구 목록은 같은 서버의 `clean_system_promot` 에서
읽는다. 서버 이름은 사례의 `server_name` 이다.

규칙은 두 갈래로 돌린다. 문형 규칙(`collectStrings` → `runDescRules`)은 중독 도구의 문자열에 돌린다.
점수 규칙(`runSteeringRules`, `desc/steering`)은 다른 도구 이름과 견줘야 해서 서버 전체 도구 목록에
돌리고, 중독 도구에 붙은 발견만 센다.

## 실행

```
pnpm build
node docs/benchmark/mcp-audit-recall/fetch.mjs            # 마지막 줄이 받은 경로
node docs/benchmark/mcp-audit-recall/measure.mjs <경로>    # 표. --json 이면 JSON
```

`measure.mjs` 는 빌드된 `packages/audit/dist` 를 읽는다. 규칙을 고친 뒤에는 다시 빌드한다.

## 판정

- **탐지**: 문형 규칙이든 점수 규칙이든 심각도가 medium 이상인 발견이 하나라도 있는 사례. 종료 코드를
  2 로 만드는 기준과 같다.
- **언급**: info 를 포함해 발견이 하나라도 있는 사례. `desc/sensitive-path` 단독과
  `desc/cross-origin` 단독은 info 라 탐지로 세지 않는다.

변형 표의 네 열은 이렇다.

- **문형 규칙(medium 이상)**: `runDescRules` 가 medium 이상 발견을 낸 사례 수.
- **점수 규칙 medium**: `desc/steering` 이 medium 발견을 낸 사례 수.
- **점수 규칙 low 이상**: `desc/steering` 이 심각도와 무관하게 발견을 하나라도 낸 사례 수.
- **탐지(문형 또는 점수 medium)**: 문형 규칙 열과 점수 규칙 medium 열 중 하나라도 해당하는 사례 수.
  재현율은 이 값을 전체 사례 수로 나눈 것이다.

**정상 정의** 줄은 오탐을 본다. MCPTox 가 싣고 있는 서버 45개의 정상 도구 정의(`clean_system_promot`)에
같은 판정을 돌려, 문형 규칙 medium 이상, 점수 규칙 medium, 점수 규칙 low 가 각각 몇 건인지 낸다. 마지막
줄은 점수 규칙이 잡은 정상 도구의 `서버/도구` 이름이다. 정밀도 기준(정상 서버 20개에서 발견 0)은
여기가 아니라 `packages/audit/tests/fixtures/benign/` 과 E2E 가 맡는다.

같은 MCPTox 커밋과 같은 규칙이면 출력이 바이트까지 같다. 결과는 `RESULTS.md` 에 커밋 SHA 와 함께 적는다.

## 변형

`variants.mjs` 가 사례를 여덟 가지로 바꿔 쓴 뒤 같은 판정을 돌린다.

| 변형 | 하는 일 |
|---|---|
| 원본 | 바꾸지 않는다. |
| 말투 완화 | 태그, 무시·은폐 동사, 의무 표현, 도구 이름의 따옴표를 바꾼다. |
| 말투 전부 + 길이 늘림 | 완화에 더해 조건·순서 낱말과 사용자·파라미터를 가리키는 낱말까지 바꾸고, 끝에 무해한 문장을 열두 번 붙인다. |
| 기존 도구에 심음 | 가짜 도구를 따로 두지 않고, 원문이 처음 언급한 정상 도구의 설명 끝에 원문을 붙인다. 그 도구의 이름은 "this tool" 로 바꾼다. |
| 기존 도구에 심음 + 말투 전부 | 위 심음에 말투 전부를 더한다. |
| 이름 풀어 씀 | 다른 도구의 이름을 그 도구의 정상 설명 첫 문장으로 풀어 쓰고, 가짜 도구에 인자를 하나 단다. |
| 이름 풀어 씀 + 말투 전부 + 길이 늘림 | 이름 풀어 씀에 말투 전부와 길이 늘림을 더한다. |
| 심음 + 이름 풀어 씀 + 말투 전부 | 세 가지를 함께 적용한다. |

전부 기계적 치환이다. 새 문장을 짓지 않으므로 같은 입력이면 같은 출력이 나온다. 그래서 이 표는 회피의
하한을 보여 줄 뿐이다. 사람이나 LLM 이 통째로 다시 쓴 설명은 재지 않는다. 검토 문서가 함께 재라고 한
회피 변형(arXiv 2605.24069) 가운데 동형문자·base64·비영어 변형도 여전히 없다.

변형의 치환 규칙은 `desc/steering` 의 점수표를 구할 때 쓴 것과 같다. 고치면 `RESULTS.md` 의 수치와 견줄 수
없게 되므로, 새 변형은 더하고 기존 것은 그대로 둔다.
