## 방법

MCPeak 으로 검증한다. MCP 클라이언트를 직접 작성하지 마라. `npx -y @mcpeak/cli@latest` 로 실행하며
별도 설치는 필요 없다.

### 1. 승인된 명세가 이미 있다

`server.suite.json` 은 이 서버의 요구사항을 검증하는 명세로, 이미 검토·승인된 것이다. 도구마다
정상 케이스와, 요구사항의 축(필수 누락, 타입, enum, 범위)을 하나씩 어기는 거절 케이스가 들어 있다.
**명세를 수정하지 마라.** 케이스를 추가하거나 빼지도 마라.

### 2. 명세를 서버에 돌린다

```bash
npx -y @mcpeak/cli@latest test server.suite.json -- node ./server.mjs
```

케이스별 통과·실패와 실패 이유가 터미널에 찍힌다. 거절 케이스가 실패했다는 것은 서버가
거절해야 할 입력에 성공 응답을 냈다는 뜻이다. 그것이 결함이다. 정상 케이스가 실패했다면 서버가
허용해야 할 입력을 거절한 것이고, 그것도 결함이다. `isError` 단언은 `-32602` 같은 JSON-RPC
오류도 거절로 본다.

### 3. 결과를 판정 규칙에 대조해 보고서를 쓴다

`test` 출력을 읽고 보고 형식대로 `report.md` 를 채운다. 케이스 표는 명세의 케이스를 그대로
옮기고, 실패한 케이스를 결함 표로 정리한다. 명세 파일 경로를 보고서에 적는다.
