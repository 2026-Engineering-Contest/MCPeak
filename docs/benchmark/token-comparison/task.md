# 과제: 이 디렉터리의 MCP 서버를 검증하라

이 디렉터리에는 stdio 트랜스포트로 동작하는 MCP 서버 `server.mjs` 가 있다. 실행 명령은
`node ./server.mjs` 이고 의존성은 설치돼 있다. 네가 할 일은 이 서버가 제공하는 **모든 도구**를
검증하고 결함을 `report.md` 에 보고하는 것이다. 서버 코드를 고치지 마라. 검증이 목적이다.

## 완료 기준

도구마다 다음을 만족해야 완료다.

1. 정상 입력으로 한 번 이상 호출해 성공 응답을 확인했다.
2. 잘못된 입력을 한 번 이상 보내 서버가 거절하는지 확인했다. 잘못된 입력이란 다음 중
   해당하는 축이다: 필수 필드 누락, 타입 불일치, enum 밖의 값, 범위(길이·크기·개수) 밖의 값.
3. 서버가 거절해야 하는데 성공 응답을 낸 경우를 결함으로 기록했다.

`requirements.md` 가 있으면 그 문서가 요구사항이다. 없으면 서버가 `tools/list` 로 선언하는
`inputSchema` 가 요구사항이다.

## 판정 규칙

- 거절이란 JSON-RPC 오류(`-32602` 등) 또는 `isError: true` 응답이다.
- 성공이란 `isError` 가 없거나 `false` 인 응답이다.
- 요구사항이 금지하는 입력에 성공 응답이 오면 결함이다.
- 요구사항이 허용하는 입력에 거절이 오면 결함이다.

## 보고 형식

`report.md` 를 다음 형식으로 쓴다. 표의 열은 바꾸지 않는다.

```markdown
# 검증 보고

## 케이스

| 도구 | 케이스 | 입력 | 기대 | 실제 | 판정 |
|---|---|---|---|---|---|

## 결함

| # | 도구 | 위반 축 | 재현 입력 | 설명 |
|---|---|---|---|---|

## 검증하지 못한 것
```

결함이 없으면 결함 표를 비워 두고 그렇게 적는다. 추측으로 채우지 마라.

## 하지 말 것

- 서버 코드를 수정하지 마라.
- 결함이라고 단정하기 전에 실제로 호출해 응답을 확인하라.
- 보고서 외의 파일은 작업 후 남겨도 되지만 보고서에 경로를 적어라.
