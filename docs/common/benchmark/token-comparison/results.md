상속된 상태라 참고용이다. 유효 비교는 격리 회차끼리만 한다.

## 결론

1. 사람용 CLI 흐름(`generate` 확인 → 픽스처 → `test`)을 에이전트에게 단계별로 시키면 토큰은
   줄지 않는다. 도구 2·3·6개 서버 모두에서 A 보다 10~40% 더 썼다(B). 원인은 단계마다 턴이 생기고
   턴마다 컨텍스트가 다시 읽히기 때문이다. 턴 하나가 케이스 수백 개 분량이다.
2. 판단을 도구 안의 좁은 LLM 호출로 옮기고 왕복을 명령 하나로 줄이면, 전 과정에서도 비용이 절반
   가까이 준다(C). 검출률은 같다. 절감 폭은 케이스 수가 늘수록 커질 구조다(A 는 케이스마다 쓰고
   읽고, C 는 상수).
3. 명세를 미리 승인해 둔 재사용 구도(B')의 24~41% 절감은 "재사용 대 매번 작성" 을 잰 것이라 도구의
   효과로 인용하지 않는다. A 에 스크립트를 미리 주면 같아질 것이다.
4. 한계: 모델 sonnet 하나, 서버 셋(도구 2·3·6개), 조건당 3~5회, 결함이 스키마·출력 계약 위반에
   한정. 요구사항 문서에만 있는 제약(S2)은 C 의 범위 밖이다.
