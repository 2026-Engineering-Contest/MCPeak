## 설계에서 옮기며 줄인 부분과 그 판단

- **배경(설계 §1).** §1.1 의 `childEnvironment` 코드 블록과 `bootstrap.mjs` 삭제 코드 블록은
  뺐다. ADR 이 필요한 것은 "설정 환경변수와 `--import` 를 함께 주고, bootstrap 이 로드 즉시
  환경변수를 지운다" 는 사실과 그 이유(단일 기록자, `occurrence` 결정론성)이지 코드 자체가
  아니라고 봤다. 대신 §1.2 의 재현 출력은 그대로 인용했다. 지시대로 이것이 근거이고, 문장으로
  바꾸면 "NODE_OPTIONS 는 가는데 설정만 사라진다" 는 핵심이 약해진다.
- **§1.4(화면이 틀린 원인을 말한다).** 0건 알림 전문과 `test-command.ts:1992` 는 빼고 배경
  마지막 두 문장으로 줄였다. 사용자에게 무엇이 잘못 보이는지만 남기면 충분하고, 문안 자체는
  결정 4의 영역인데 그 결정은 이 ADR 의 범위 지시에 없었다.
- **선택지(설계 §4.5).** 버린 넷에 채택안을 더해 다섯으로 적었다. 채택안을 1번에 두고 나머지를
  설계의 A·B·C·D 순서로 두되 라벨을 괄호로 남겨 설계 문서와 대조할 수 있게 했다. 기각 사유는
  각각 한두 줄로 줄였다.
- **결정(설계 §4.1 · §4.2 · §4.3).** 세 표(프로세스별 소비 시점, 모드별 거절 처리)는 그대로
  옮겼다. 표를 산문으로 풀면 조건 조합이 뭉개진다. 식별자가 세션에 저장되지 않는다는 것과
  record · replay 의 처리가 다르다는 것은 지시대로 별도 문단·표로 명시했다. §4.3 의
  `bodyUrls` 선택 필드 선례는 구현 세부라 뺐다.
- **§4.4(0건 알림 문구)는 결정 절에 넣지 않았다.** 대신 결과 절의 §8.1 갈래에서 "기록자 경합
  갈래가 숫자를 적는다" 로만 언급했다. 지시가 결정 절을 §4.1~§4.3 으로 한정했기 때문이다.
- **이유.** 설계 §4.2 의 두 문단을 옮기고, 환경변수 기반 보증이 왜 약한지 한 문장을 더했다.
  설계에 흩어져 있던 근거를 이유 절에 모은 것이고 새 주장은 아니다.
- **결과(설계 §8.1 · §8.2).** 두 위험을 결과 항목 둘로 옮겼다. §8.1 의 확인 방법은 "캐시가 있는
  상태와 없는 상태 두 번" 이라는 핵심만 남기고 `npm cache clean --force` 와 구체 패키지명은 뺐다.
  구현계획에 이미 있고 ADR 한 페이지에는 과하다. §8.3(worker_threads) · §8.4(소비 시점을 놓치는
  경로)는 넣지 않았다. 지시 범위 밖이고, 둘 다 "결정 2가 덮는다" 로 끝나 결정 자체를 바꾸지 않는다.
