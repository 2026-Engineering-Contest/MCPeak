### 원인: 설계 §5.1 의 "후보 중 가장 앞선 호출" 배정

설계 §5.1 은 요청 `e` 의 후보 호출을 `c.t0 − 2 ≤ e.t0 ≤ c.t1 + 2` 로 잡고, 후보 중 측정 순서가 가장 앞선
호출에 배정한다. `intervalMs` 0(설계 §8.4 의 기본값)에서는 다음 호출이 앞 호출 `t1` 의 0.1ms 안에 시작하고,
서버가 호출 시작 직후 내는 첫 요청은 앞 호출의 `t1 + 2` 안에 든다. 그러면 그 요청은 **자기 호출이 아니라 앞
호출**에 배정되고, 앞 호출에서는 `e.t0 > c.t1` 이라 `afterResponse` 로 빠진다.

dist 로 `http` 를 3회 잰 타임라인(첫 호출 t0 기준, ms):

```
call 0  0.00 → 106.55     start /a 1.91    end 105.50
call 1  106.68 → 209.37   start /a 107.07  end 208.79
call 2  209.40 → 311.43   start /a 209.89  end 310.72
```

호출 1 의 요청(107.07)은 호출 1 창 안에 있지만 호출 0 의 `t1 + 2 = 108.55` 안에도 있어 호출 0 으로 간다.
호출 2 의 요청도 같다. 그래서 첫 반복만 external ≈ 103, 나머지는 0 이고 p50 이 0 이 된다. 다른 실패도 같은
밀림이다. 케이스 첫 반복의 첫 요청이 앞 케이스 마지막 반복으로 가서 `/first` 가 parallel 에, `/config` 가 retry 에
배정되고 거짓 (b) 가 생긴다. retry 는 다음 반복의 첫 `/flaky`(429) 가 앞 반복으로 와서 그 반복 안에서 200 뒤
같은 키가 다시 보이므로 (a) 가 난다. dependent 는 `/first` 가 앞 반복으로 가서 의존 쌍이 끊긴다.

임계 실측 값도 이 밀림에 오염돼 있다. serial 의 `/a` 가 앞 반복으로 가서 inside 에 약 100ms 의 외부 대기가
들어 있다(정상이면 수 ms). 따라서 `초과=false` 는 기본 게이트의 타당성 근거가 되지 못한다. 배정 규칙을 고친
뒤 다시 재야 한다.

픽스처 쪽 원인이 아니라고 본 이유: 서버가 호출을 받자마자 요청을 내는 것은 실제 서버의 흔한 모양이고, CLI 기본
`--interval-ms 0` 에서 그대로 재현된다. 픽스처에 지연을 넣어 피하면 결함을 가린다.

### 1회차의 제안 (이 태스크는 적용하지 않았고, 6ac3a119·43235ab7 이 반영했다)

후보 중 `c.t0 ≤ e.t0 ≤ c.t1` 을 만족하는 호출이 있으면 그 호출에 배정하고, 없을 때만 ±2ms 여유 창의 가장
앞선 호출을 쓴다. 위 타임라인에서는 모든 요청이 자기 호출로 간다. 설계 §5.1 과 `decompose.ts`(T2 범위),
`decompose.test.ts` 의 경계 케이스를 함께 바꿔야 하므로 사람과 오케스트레이터가 정한다.

## 임의로 판단한 부분

- `/flaky` 응답의 `n` 은 설계 표의 "그 밖" 행이 정의한 전체 요청 카운터를 썼다. `/flaky` 전용 카운터로 읽을 여지가 있다.
- `fails` 케이스의 단언은 `bodyMatchesSchema` `{ "type": "array" }` 다. 명세 검증이 단언 하나 이상과 빈 스키마
  금지를 요구하고, `isError: true` 단언은 계획이 금지한다.
- `MCPEAK_PERF_FIXTURE_ORIGIN` 이 없을 때도 지연 변수와 같이 stderr 와 종료 코드 1 로 끝낸다(계획은 지연만 적었다).
- 도구 `content` 는 받은 응답들의 `{status, body}` 배열을 JSON 텍스트 하나로 낸다. 설계가 결과 모양을 정하지 않았다.
- "관측 없음" 은 반복 1회로 돌린다. 판정 대상이 observation·findings·분해 필드의 유무라 반복 수와 무관하다.
- 프리로드 유무 비교는 프리로드를 실은 실행의 추적에 `hello` 가 있는지 함께 단언한다. 프리로드가 안 실리면
  비교가 공허하게 녹색이 되기 때문이다.
- 진단 (a)·(b) 구분은 `caseIds` 길이(1 이면 (a), 2 이상이면 (b))로 한다. `rules.ts` 의 출력 구조가 그렇다.
- 일회성 확인 스크립트는 scratchpad(`probe.mjs`)에만 두었다. 저장소에는 남기지 않았다.
