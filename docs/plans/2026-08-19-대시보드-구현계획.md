# 대시보드 구현계획 (2026-08-19)

참조 문서: `docs/2026-08-19-대시보드-설계.md` (승인된 설계 확정본)

> **실행 방식:** 이 계획은 서브에이전트 실행 모델을 따른다. 각 터미널의 세션은
> 오케스트레이터이며, 태스크마다 서브에이전트를 스폰해 구현시키고 사이사이 리뷰한다.
> 체크박스(`- [ ]`)로 진행을 추적한다.

## 1. 배경과 근거

CLI를 사용하지 않는 사용자를 위해 로컬 웹 대시보드를 만든다. 형태와 범위는 설계 문서에서
확정했다: 로컬 웹서버, 4개 플로우(테스트 실행, generate, 카세트/replay, repair) 전부,
대화형 승인까지 GUI로.

계획 조사에서 확정한 사실 두 개가 설계를 보정한다.

1. **cli의 공개 면이 좁다.** `packages/cli/src/index.ts`가 export하는 것은 `run`,
   `Command`, `COMMANDS`, `nodeRepairDependencies` 넷뿐이고 `package.json` `exports`도
   `"."` 하나다. `runGenerateCommand` 등 커맨드 함수와 의존성 타입은 모듈 안에 있지만
   패키지 밖으로 나오지 않는다. 재export 서브패스 `ohmymcp/commands`를 추가한다.
   로직 이동은 없다. cli 수정에 해당하지만 **2026-08-19 사용자가 협의 없이 진행을 승인했다.**
2. **`record` 서브커맨드는 미구현이다** (`COMMAND_NOT_IMPLEMENTED`,
   `packages/cli/src/test-command.ts:528`). 녹화는 `generate`의 `--record`/`--cassette`
   경유가 유일한 경로다. 대시보드도 같은 경로를 쓰고 단독 녹화 엔드포인트는 두지 않는다.

### 4-5. `packages/dashboard/src/server/review-bridge.ts` 핵심 로직 (전량)

대화형 승인의 동시성이 이 계획에서 판단이 갈리는 유일한 지점이다. 그대로 구현한다.

```ts
import type { ReviewIO } from "ohmymcp/commands";
import type { PendingQuestion, RunEvent } from "../api-types.js";

/**
 * ReviewIO의 웹 구현. CLI 오케스트레이션은 질문마다 await하므로
 * pending 질문은 항상 0개 또는 1개다. 큐가 아니라 단일 슬롯으로 둔다.
 */
export class WebReviewIO implements ReviewIO {
  readonly interactive = true;
  private pending: {
    readonly question: PendingQuestion;
    readonly resolve: (value: string) => void;
  } | null = null;
  private counter = 0;

  constructor(private readonly emit: (event: RunEvent) => void) {}

  write(text: string): void {
    this.emit({ kind: "stdout", html: ansiToHtml(text) });
  }

  input(message: string): Promise<string> {
    return this.ask({ id: this.nextId(), kind: "input", message });
  }

  async choose(message: string, choices: readonly string[]): Promise<string> {
    const answer = await this.ask({
      id: this.nextId(),
      kind: "choose",
      message,
      choices: [...choices],
    });
    // CLI의 choose는 선택지 문자열을 그대로 돌려받는 계약이다. 검증은 서버가 한다:
    // 목록에 없는 값이면 다시 묻지 않고 그 값 그대로 넘긴다. CLI 쪽 검증 루프가
    // 잘못된 입력을 이미 처리하므로 여기서 이중 검증하지 않는다.
    return answer;
  }

  async confirm(message: string): Promise<boolean> {
    const answer = await this.ask({ id: this.nextId(), kind: "confirm", message });
    return answer === "y";
  }

  /** POST /answer 처리기가 호출한다. id 불일치·pending 없음이면 false. */
  answer(questionId: string, value: string): boolean {
    if (this.pending === null || this.pending.question.id !== questionId) return false;
    const { resolve } = this.pending;
    this.pending = null; // resolve 전에 비운다. resolve가 동기 후속 질문을 던질 수 있다.
    resolve(value);
    return true;
  }

  get pendingQuestion(): PendingQuestion | null {
    return this.pending?.question ?? null;
  }

  private ask(question: PendingQuestion): Promise<string> {
    if (this.pending !== null)
      throw new Error("이미 대기 중인 질문이 있습니다. CLI 플로우 계약 위반입니다.");
    this.emit({ kind: "question", question });
    return new Promise<string>((resolve) => {
      this.pending = { question, resolve };
    });
  }

  private nextId(): string {
    this.counter += 1;
    return `q${this.counter}`; // run 안에서만 유일하면 된다. 난수 불필요(결정론성).
  }
}
```

`ansiToHtml`은 T1이 `packages/dashboard/src/server/ansi.ts`에 구현한다. 계약:
SGR 색·굵기 코드(30–37, 90–97, 1, 0)를 `<span class="ansi-...">`로 변환하고, 그 외
이스케이프는 제거하며, HTML 특수문자(`&`, `<`, `>`)는 항상 이스케이프한다. 같은 입력에
같은 출력(결정론). 이 계약을 그대로 단언하는 테스트가 통과 조건이다.

### 4-6. `packages/dashboard/src/server/paths.ts` 경로 가드 (전량)

```ts
import { resolve, sep } from "node:path";

/**
 * 프로젝트 루트 밖 접근 차단. 절대경로·`..` 탈출 전부 거부.
 * 반환값은 절대경로, 거부는 null이다. 예외를 던지지 않는 이유는 호출부가
 * 404가 아니라 400으로 구분 응답해야 하기 때문이다.
 */
export function resolveProjectPath(root: string, relative: string): string | null {
  if (relative.startsWith("/") || relative.includes("\0")) return null;
  const absolute = resolve(root, relative);
  const rootAbs = resolve(root);
  if (absolute !== rootAbs && !absolute.startsWith(rootAbs + sep)) return null;
  return absolute;
}
```

**Interfaces consumes:** §4-4, §4-5, §4-6. **produces:**
`RunRegistry`(아래 시그니처), `WebReviewIO`, `ansiToHtml(text: string): string`.

```ts
export interface RunHandle {
  readonly runId: string;
  readonly summary: RunSummary;
  /** 지금까지의 전체 이벤트. SSE 늦은 구독자 재전송용. */
  readonly events: readonly RunEvent[];
  subscribe(listener: (event: RunEvent) => void): () => void;
  readonly reviewIO: WebReviewIO;
}
export class RunRegistry {
  start(flow: StartRunRequest["flow"], execute: (io: RunIo) => Promise<number>): RunHandle;
  get(runId: string): RunHandle | undefined;
  list(): readonly RunSummary[];
}
/** execute에 주입되는 IO 묶음 */
export interface RunIo {
  readonly writeStdout: (text: string) => void; // ansiToHtml 거쳐 stdout 이벤트
  readonly writeStderr: (text: string) => void;
  readonly reviewIO: WebReviewIO;
}
```

사양: `start`는 즉시 `RunHandle`을 반환하고 `execute`를 백그라운드로 돌린다. `execute`가
resolve하면 `done` 이벤트(exitCode)와 status 갱신(`0`이면 `done`, 아니면 `failed`).
reject하면 stderr 이벤트로 메시지 출력 후 exitCode 1의 `done`. 질문 pending 중엔 status
`waiting-input`. runId는 `crypto.randomUUID()` — UI 식별 전용, 산출물에 안 들어간다.
이벤트는 배열에 전부 누적한다(늦은 구독자 재전송, 비범위인 영속화와 무관).

테스트 케이스 (전량):

  - `모르는 이스케이프는 제거된다`: `"[2J지움"` → `지움`
