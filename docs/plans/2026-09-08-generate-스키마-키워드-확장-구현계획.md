# generate 스키마 키워드 확장 구현계획 (2026-09-08)

참조 문서: `docs/2026-09-08-generate-스키마-키워드-확장-설계.md`(이하 "설계"), 이슈 #389,
ADR-0004 · ADR-0015 · ADR-0036, `docs/superpowers/specs/2026-08-17-schema-constraint-support-design.md`.

> **실행 방식:** 터미널 세션은 오케스트레이터이며 태스크마다 서브에이전트를 스폰해 구현시키고
> 사이사이 리뷰한다(테스트 통과 + 파일 소유권 준수 + 설계 §5·§6 계약 일치). 직접 구현하지
> 않는다. 규약은 `.claude/conventions/plan.md` 와 `.claude/conventions/execution.md` 다.

## 전역 제약

프로젝트 지침과 설계에서 그대로 옮긴 것이다. 모든 태스크에 암묵적으로 포함된다.

- **`core/src/types.ts` 의 `McpClient` · `ToolResult` 는 동결이다.** 건드리지 않는다.
- **다른 오너의 패키지를 수정하지 않는다.** 이 계획은 `packages/generate/**` 와 `docs/adr/`,
  `.changeset/` 만 쓴다. `runner`·`mock`·`cli`·`dashboard`·`record`·`core`·루트 `fixtures/` 는
  읽기 전용이다. 바꿔야 할 것 같으면 멈추고 `BLOCKED`.
- **의존 방향은 단방향이다.** `cli` → `runner`/`generate`/`record`/`mock` → `core`. `generate` 가
  `runner` 에서 가져오는 심볼은 `packages/generate/tests/dependency-boundary.test.ts` 의 승인
  목록 안이어야 하며 이 계획은 목록을 넓히지 않는다.
- **`@modelcontextprotocol/sdk` 는 1.x 고정.** 새 의존성 없음. 정규식 파서는 직접 쓴다.
- **커밋·푸시는 사람이 한다.** 서브에이전트는 git 명령을 실행하지 않는다.
- **유닛테스트는 인메모리와 `packages/generate/tests/fixtures/` 만 쓴다.** 실서버·`examples/`
  프로세스 기동은 통합 게이트(T6)에서 오케스트레이터만 한다.
- **결정론성.** 타임스탬프·랜덤·`Object.keys` 순서 의존 금지. 갈래·문자 선택은 전부 "선언 순서의
  첫 번째" 또는 "최소" 다. 같은 입력 2회 실행의 `baselineFingerprint` 가 같아야 한다.
- **실패 메시지가 곧 제품이다.** 경로·값·해결 수단이 문장에 있어야 한다(설계 §6).
- **기존 지원 툴의 바이트를 바꾸지 않는다.** `BASELINE_POLICY_VERSION` 은 그대로다.
- 검증 명령: `pnpm install` · `pnpm build --force` · `pnpm --filter @mcpeak/generate test` ·
  `pnpm test` · `pnpm typecheck --force` · `pnpm lint`.

## 1. 목표 / 비범위 / 완료 조건

**목표** (설계 §2): `additionalProperties`·`pattern`·로컬 `$ref`(`$defs`·`definitions`)·
`anyOf`/`oneOf` 를 읽고 그 뜻을 지키는 입력값을 결정론적으로 합성한다. 못 읽는 갈래·구문은
그 갈래·그 툴만 건너뛰고 원인 경로를 남긴다.

**비범위** (설계 §3): `allOf`·`not`·`if`·`patternProperties`·`propertyNames`, 배열 `type`, 튜플
`items`, 원격 `$ref`, `UNDECLARED_FIELD` 축, `runner`/`mock` 해석 확장, zod 예제 서버 E2E(#407),
정책 버전 인상, README 전면 개정(#404).

## 3. 공유 계약

설계 §5.5 의 `composition.ts` 시그니처와 병합 표, §5.2.1 의 정규식 부분집합 표, §6 의 문안 표가
전량이다. 이 계획은 복제하지 않는다. 구현자는 그것을 그대로 옮기고 아래만 덧붙인다.

- `SUPPORTED_SCHEMA_KEYS` 추가 순서(`format` 뒤): `additionalProperties`, `pattern`, `$ref`,
  `$defs`, `definitions`, `anyOf`, `oneOf`. T1 이 `additionalProperties`, T2 가 `pattern`, T3 가
  `$ref`·`$defs`·`definitions`, T4 가 `anyOf`·`oneOf` 를 넣는다. 순서는 최종 상태 기준이다.
- `root` 인자 시그니처(T3 에서 고정):

```ts
export function validateSchema(
  schema: unknown,
  path: string,
  active: Set<object> = new Set(),
  root: JsonSchema = schema as JsonSchema,
): asserts schema is JsonSchema;

export function synthesizeValue(
  schema: JsonSchema,
  path: string,
  root: JsonSchema = schema,
  active: Set<object> = new Set(),
): JsonValue;

function valueMatchesSchema(value: JsonValue, schema: JsonSchema, root: JsonSchema): boolean;
```

`root` 의 기본값이 자기 자신이라 기존 호출부(`render.ts:33`, `render.ts:43`, 테스트의
`synthesizeValue(schema, "p")`)는 그대로 컴파일된다. `active` 는 `$ref` 대상 객체만 담는다.

### Task T2 — `pattern`

모델: 상위. 사유: 정규식 부분집합의 경계와 최소 문자열·길이 채움 선택은 계획에 코드로 다
못 박히는 판단이고 결정론성이 걸린다. 문안(§6 1·2·3·12)도 여기서 만든다.

- `src/pattern.ts`(신규):

```ts
/** 컴파일된 검증기. "u" 먼저, 실패하면 플래그 없음. 둘 다 실패면 INVALID_SCHEMA_CONSTRAINT. */
export function compilePattern(pattern: unknown, path: string): RegExp;
/**
 * 설계 §5.2.1 부분집합으로 최소 문자열을 만들고 §5.2.2 로 minLength 를 채운다.
 * 부분집합 밖 구문·길이 불가는 UNSUPPORTED_SCHEMA. 만든 값은 compilePattern 결과로 재검증한다.
 */
export function synthesizePatternString(
  pattern: string,
  bounds: { readonly minLength: number | null; readonly maxLength: number | null },
  path: string,
): string;
```

  파서는 AST(리터럴·클래스·그룹·교대·수량자·앵커)를 만든 뒤 생성기가 걷는다. 수량자 노드는
  `min`·`max`(무한은 `null`)를 갖고, 길이 채움은 AST 를 왼쪽부터 다시 걸으며 `max > min` 인
  첫 수량자부터 채운다.
- `constraints.ts` `assertConstraints`: `pattern` 이 있으면 `compilePattern` 으로 검사(문자열
  아님·컴파일 실패 → 문안 3).
- `synthesize.ts`: `string` 분기를 설계 §5.2 의 4 단계로 바꾼다. `valueMatchesConstraints` 의
  문자열 검사에 `pattern` 테스트를 더한다(알려진 `format` 이 있어도 `pattern` 은 본다. 길이만
  건너뛴다). 생성기 값이 여기서 떨어지면 문안 12.
- `provenance.ts` `hasApplicableRangeKeyword`: `string` 의 키 목록에 `pattern` 추가(값이
  문자열일 때).
- `schema.ts`: 키 허용.

테스트 (전량):
