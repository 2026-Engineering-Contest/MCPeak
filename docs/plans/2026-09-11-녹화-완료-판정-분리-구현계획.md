# 녹화 완료 판정 분리 구현계획 (2026-09-11)

참조 문서: `docs/2026-09-11-녹화-완료-판정-분리-설계.md`(이하 "설계"),
`docs/2026-09-11-공개서버-직접조작-데모-실측-문제.md` §1, ADR-0052 · ADR-0053 · ADR-0057 ·
ADR-0066.

> **실행 방식:** 터미널 세션은 오케스트레이터이며 태스크마다 서브에이전트를 스폰해 구현시키고
> 사이사이 리뷰한다(테스트 통과 + 파일 소유권 준수 + 설계 §5 문안 일치). 직접 구현하지 않는다.
> 규약은 `.claude/conventions/plan.md` 와 `.claude/conventions/execution.md` 다.

기점 커밋: `8093660`

## 전역 제약

모든 태스크에 암묵적으로 포함된다.

- **`core/src/types.ts` 의 `McpClient` · `ToolResult` 는 동결이다.** 건드리지 않는다.
- **의존 방향은 단방향이다.** `dashboard` → `cli` → `runner`/`generate`/`record`/`mock` → `core`.
  역참조와 순환을 만들지 않는다. 이 계획은 새 의존을 하나도 더하지 않는다.
- **`packages/record/**` 는 읽기 전용이다.** 세션 저장소의 상태 계약("완료된 세션에 미완료
  interaction 이 없다")은 그대로 둔다. 바꿔야 할 것 같으면 멈추고 `BLOCKED` 로 보고한다.
- **`@modelcontextprotocol/sdk` 는 1.x 고정.** 새 의존성을 추가하지 않는다.
- **커밋·푸시는 사람이 한다.** 서브에이전트는 git 명령을 실행하지 않는다(worktree 진입은 예외이며
  1단계에 명시된 두 명령뿐이다).
- **유닛테스트는 인메모리와 `packages/cli/tests/fixtures/` 만 쓴다.** `examples/` 의 실제 서버
  프로세스는 띄우지 않는다. E2E 도 그 픽스처 서버와 `tmpdir` 안의 세션 파일만 쓴다.
- **결정론성.** 타임스탬프·랜덤·실행 순서에 의존하는 코드를 넣지 않는다. 새 단언은 전부 고정
  문자열과 카운터다.
- **실패 메시지가 곧 제품이다.** 설계 §5 의 문자열이 정본이다. 한 글자도 바꾸지 않는다.
- 검증 명령: `pnpm install` · `pnpm build --force` · `pnpm test` · `pnpm typecheck --force` ·
  `pnpm lint`.

## 1. 목표 / 비범위 / 완료 조건

**목표** (설계 §2): 녹화 세션의 종료 상태를 테스트 판정에서 떼어내고, 그 결과 달라지는 화면
문장을 사실에 맞춘다.

**비범위** (설계 §3): 세션에 테스트 판정 저장, `SESSION_ALREADY_EXISTS` 재녹화 흐름, 실측 문서의
나머지 절 전부, `record` 패키지의 상태 계약 변경.

**완료 조건과 대응 태스크**

| 설계 §2 완료 조건 | 태스크 |
|---|---|
| 1 실패한 실행의 세션이 `completed` | T1(규칙) · T2(E2E 증거) |
| 2 그 세션이 재생된다 | T2 |
| 3 예외로 끝난 실행은 `failed` | T1 |
| 4 미완료 interaction 진단이 보인다 | T1(문안) |

| 6 `REPLAY_SOURCE_INVALID` 와 대시보드 사유 | T1(CLI) · T3(대시보드) |
| 7 빌드·테스트·타입체크·린트 | T4 통합 게이트 |

## 3. 공유 계약

설계 §4.1 의 종료 상태 표와 §5 의 문안 표가 전량이다. 이 계획은 복제하지 않는다. 구현자는 그
문자열을 그대로 옮긴다.

`runCli` 이 바뀌는 자리는 `packages/cli/src/test-command.ts:2082` 한 줄이다.

```ts
// 기존
const summary = await wiring.finish(exitCode === 0 ? "completed" : "failed");
// 새로
const summary = await wiring.finish("completed");
```

그 위의 주석 두 줄("실행이 실패했으면 세션도 실패다 …")은 새 규칙을 설명하는 문장으로 갈아
넣는다. 설계 §1.3 과 §4.1 의 근거를 담고, ADR-0094 를 인용한다.

`catch (error)` 안의 `wiring.finish("failed")`(`:2075`)는 **그대로 둔다.** 설계 §4.1 표의
셋째 줄이 그것이다.

## 4. 의존성 그래프와 웨이브

```
Wave 1 (병렬 2 터미널)
  터미널 A: T1 → T2      (cli)
  터미널 B: T3           (dashboard + ADR)

Wave 2 (직렬, 오케스트레이터)
  T4 통합 게이트: A 머지 → B 머지 → 전량 검증
```

병렬 두 터미널은 쓰는 파일이 완전히 분리돼 있고, 공유 계약(설계 §5 문안)은 문서에 고정돼 있어
서로를 기다릴 이유가 없다.

## 8. T4 통합 게이트 (오케스트레이터 직접)

두 터미널의 보고를 받고, **보고서와 diff 와 테스트 출력을 직접 확인한 뒤에** 진행한다. "완료"
선언만으로는 통합하지 않는다.

1. 각 브랜치의 diff 가 §2 의 파일 소유권 표 안에만 있는지 확인한다. 벗어나면 통합하지 않는다.
2. 설계 §5 의 문자열과 실제 코드의 문자열을 한 글자씩 대조한다.
3. `fix/record-session-completion-cli` 를 먼저 머지하고, 그다음
   `fix/record-session-completion-dashboard` 를 머지한다. 순서가 있는 이유는 CLI 안내문이
   대시보드 문구의 근거이기 때문이다. 충돌은 없어야 한다(파일이 겹치지 않는다).
4. 통합 브랜치에서 아래를 **이 순서로** 돌린다.

   ```sh
   pnpm install
   pnpm build --force      # Cached: 0 cached 를 출력에서 확인한다
   pnpm test
   pnpm typecheck --force
   pnpm lint
   ```

   `pnpm build --force` 의 `Cached: 0 cached` 를 눈으로 확인한다. turbo 캐시가 이전 녹색을
   재생하면 통합 게이트가 아무것도 판정하지 못한다.
5. 실환경 확인 한 가지를 직렬로 한다. `packages/cli/dist/cli.mjs` 를 직접 실행해
   `examples/live-weather-server` 에 실패 케이스가 있는 명세를 `--record-session` 으로 녹화한 뒤,
   같은 명세를 `--session` 으로 재생해 `녹화가 완료되지 않은 세션입니다` 가 나오지 않는 것을
   확인한다. 세션 파일은 저장소 밖 임시 경로에 만든다. 이것이 실측 문서 §1 을 닫는 증거다.
6. 통합 SHA 를 `docs/task-integration-ledger.tsv` 에 기록하고 별도 문서 커밋으로 보존한다.

어느 단계라도 실패하면 후속 머지·푸시를 멈추고, 실패한 태스크와 SHA 와 검증 출력을 포함해
`BLOCKED` 로 보고한다.

## 9. 자체 검토

- 설계 §2 의 완료 조건 일곱이 전부 §1 의 표에서 태스크에 대응한다.
- 병렬 두 터미널의 쓰기 파일이 겹치지 않는다(§2). `.changeset/` 은 파일명이 다르고
  `docs/adr/README.md` 는 T3 만 쓴다.
- 공유 계약(설계 §5 문안, §4.1 표)은 계획서 밖의 문서 한 곳에만 있고 두 터미널이 같은 문서를
  읽는다.
- 상위 모델은 문안 갈래 분리와 완료 판정 경계가 걸린 T1 에만 붙였고 사유를 §5 에 적었다.
- 모든 테스트가 인메모리와 `packages/cli/tests/fixtures/` 만 쓴다. 실서버 확인은 T4 의 직렬
  단계 하나뿐이고 오케스트레이터가 직접 한다.
- 태스크마다 표적 검증과 전체 회귀 명령이 있고, T4 에 최종 리뷰 게이트가 있다.
- 판단이 갈리는 자리(종료 상태 표, 문안 전량, E2E 단언 전량)는 설계 문서에 전량으로 적혀 있다.
