## 1. 전역 제약

모든 태스크에 암묵적으로 포함된다.

- **`packages/dashboard/web/` 밖을 고치지 않는다.** `packages/dashboard/src`(서버) · 다른
  패키지 · 루트 설정은 읽기 전용이다. 고쳐야 할 것 같으면 멈추고 `BLOCKED` 로 보고한다.
- **`core/src/types.ts` 의 `McpClient` · `ToolResult` 는 동결이다.**
- **의존 방향은 단방향이다.** `dashboard` → `cli` → … → `core`. 이 계획은 새 의존을 하나도
  더하지 않는다. **web 안에서도 방향이 있다** — `components/` 는 `generate/` · `home/` ·
  `screens/` 를 참조하지 않는다. PR A 가 고치는 것이 정확히 그 역참조다.
- **새 의존성을 추가하지 않는다.** 새 npm 패키지 · 새 Tailwind 플러그인 전부 금지.
- **커밋·푸시·PR 은 오케스트레이터가 한다.** 구현 에이전트는 `git add` · `commit` · `push` ·
  `stash` · `worktree` 를 포함해 **git 쓰기 명령을 하나도 실행하지 않는다.** 조회(`git grep` ·
  `git diff` · `git log`)는 자유다.
- **결정론성.** 타임스탬프 · 랜덤 · 실행 순서에 의존하는 코드를 넣지 않는다. 새 단언은 전부
  고정 문자열이다.
- **기존 테스트의 단언을 고치지 않는 것이 통과 조건이다.** #456 이 세운 규칙을 이어받는다.
  불가피하게 고쳐야 하면 고치지 말고 그 출력을 그대로 보고한다. 예외는 §4 표에 미리 적힌
  자리(`button.test.tsx` 의 variant 목록과 제목 두 줄)뿐이다.
- **DOM 구조를 새로 감싸지 않는다.** `Button` 이 래퍼 없이 `<button>` 하나만 내는 규칙
  (`button.test.tsx:17`)을 새 컴포넌트에도 적용한다. `SegmentedControl` 은
  `<fieldset>` 하나와 그 직계 `<button>` 들만 낸다.

### 3-2. 옛 경로에 재수출 shim 을 남기지 않는다

남기지 않는다. 근거 셋:

1. import 9곳이 전부 같은 PR 안에서 바뀌므로 남길 대상이 없다.
2. `web/` 는 번들되는 화면 코드다. `packages/dashboard/package.json` 의 `files` 는
   `["dist"]` 이고 `exports` 는 서버 진입점만 낸다 — **패키지 밖에서 이 경로를 import 하는
   소비자가 없다.** `packages/dashboard/src` 도 `web/src` 를 참조하지 않는다(실측 0건).
3. shim 을 남기면 ADR-0093 이 없애려던 것("새 화면이 import 경로를 따라 또 `generate/` 를
   참조한다")이 그대로 남고, 두 경로 중 무엇이 옳은지를 사람의 기억이 지키게 된다.

완료 판정: `git grep -n 'generate/steps/fields'` 가 **0줄**.

### 3-3. Tailwind 유틸리티 충돌은 클래스 나열 순서로 못 이긴다

`className={`${INPUT_CLASS} border-accent-border`}` 같은 덧붙이기는 **통하지 않을 수 있다.**
같은 속성을 다투는 유틸리티(`border-line` 대 `border-accent-border`, `px-4` 대 `px-3`)의
승패는 생성된 CSS 의 소스 순서가 정하지 호출부의 문자열 순서가 정하지 않는다. 그래서

- 색이 다른 입력칸은 `INPUT_CLASS` 에 덧붙이지 않고 **별도 상수**(`INPUT_ON_ACCENT_CLASS`)로
  만든다. 두 상수는 같은 `INPUT_BASE` 에서 나오고, 다투는 유틸리티는 각자 한 번만 적는다.
- 패딩·글자 크기가 `Button` 의 `SIZES` 와 다투는 자리는 `Button` 으로 옮기지 않는다(§6-3).

`${INPUT_CLASS} font-mono` 처럼 **다투지 않는** 속성을 더하는 기존 방식은 그대로 둔다.

### 3-4. 포커스 링 문자열

```ts
/** 바깥으로 2px 띄운 링. 잘릴 걱정이 없는 자리의 기본값이다. */
export const FOCUS_RING =
  "focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-focus-ring";

/**
 * 안쪽으로 2px 들인 링. `overflow-hidden` 안에 든 요소용이다 — 바깥으로 띄우면 조상이
 * 잘라내 화면에서 사라진다. 세그먼트 컨트롤의 `<fieldset>` 이 그 경우다.
 */
export const FOCUS_RING_INSET =
  "focus-visible:outline-2 focus-visible:-outline-offset-2 focus-visible:outline-focus-ring";
```

`focus-visible:outline-focus-ring` 이라는 낱말이 두 상수에 모두 들어가야 한다 —
`button.test.tsx:95` 가 그 문자열을 본다.

## 6-1. 공유 계약 — `SegmentedControl` 타입 시그니처 먼저

```ts
import type { JSX } from "react";

export interface SegmentedOption<V extends string> {
  readonly value: V;
  readonly label: string;
  /** 이 선택지만 못 고르는 경우. 사유 문장은 세그먼트 밖에 호출부가 적는다. */
  readonly disabled?: boolean;
}

export interface SegmentedControlProps<V extends string> {
  readonly options: readonly SegmentedOption<V>[];
  readonly value: V;
  /** 전부 비활성. 개별 `option.disabled` 와 OR 로 합친다. */
  readonly disabled?: boolean;
  readonly onChange: (value: V) => void;
}

export function SegmentedControl<V extends string>(
  props: SegmentedControlProps<V>,
): JSX.Element;
```

**`disabled` 가 두 갈래인 이유는 실측이다.** `StepServer:84` 는 세그먼트 전체를 한 번에 끄고
(`props.disabled`), `StepRunOptions:112` 는 선택지마다 다르게 끈다
(`http || (mode !== "off" && props.options.determinism)`). 어느 한쪽만 두면 나머지 호출부가
자기 `map` 을 다시 적게 되어 컴포넌트가 헛돈다. **비활성 사유 문구는 전파하지 않는다** —
지금도 사유는 세그먼트 밖 `<p>`(`StepRunOptions:124-132`, `TestOptionsPanel` 의 `hint`)에
있고, 세그먼트 안으로 들이면 `TransportFields`·`StepServer` 에는 그릴 자리가 없다.

**DOM 은 지금 세 벌과 글자 하나 다르지 않다.**

```tsx
<fieldset className="inline-flex overflow-hidden rounded-md border border-line">
  {options.map((option) => (
    <button
      key={option.value}
      type="button"
      aria-pressed={value === option.value}
      disabled={(props.disabled ?? false) || (option.disabled ?? false)}
      className={`px-3 py-1.5 text-sm disabled:opacity-50 ${FOCUS_RING_INSET} ${
        value === option.value
          ? "bg-accent-soft font-semibold text-accent"
          : "text-ink-muted hover:bg-line-subtle"
      }`}
      onClick={() => props.onChange(option.value)}
    >
      {option.label}
    </button>
  ))}
</fieldset>
```

지금 셋과 달라지는 것은 둘뿐이고 둘 다 의도한 것이다.

1. **`TransportFields` 세그먼트가 `disabled:opacity-50` 을 얻는다.** 지금 그 한 벌에만 없다.
   `disabled:` 변형이라 비활성일 때만 적용되고, 그 세그먼트는 비활성이 되는 경로가 없다.
   렌더는 그대로다.
2. **세 벌 다 포커스 링을 얻는다.** 지금은 셋 다 브라우저 기본 아웃라인이다.

**`-outline-offset-2` 를 쓰는 이유(§0 마지막 줄).** `<fieldset>` 에 `overflow-hidden` 이 있고
버튼이 그 상자를 꽉 채운다. `outline-offset-2`(바깥 2px)를 쓰면 조상이 링을 네 면 다 잘라
**테스트는 초록인데 화면에는 아무것도 안 보인다.** 안쪽으로 들인다.

음수 접두 문법이 이 버전에서 실제로 도는지 확인했다 — 설치된 `tailwindcss@4.3.3` 의
`outline-offset` 유틸리티가 `supportsNegative: true` 로 선언돼 있다. 추측이 아니다.

## 6-2. 공유 계약 — `Button` 의 네 번째 variant

QuestionPanel 의 `border-accent-border` 버튼 셋을 `Button` 으로 옮긴다. **`secondary` 로는
안 된다** — #456 본문이 적은 대로 accent-soft 패널 위에서 `border-line` + `text-ink-muted` 는
대비가 죽는다. variant 를 하나 더한다.

```ts
export type ButtonVariant = "primary" | "secondary" | "ghost" | "on-accent";

const VARIANTS: Record<ButtonVariant, string> = {
  // …기존 셋 그대로…
  /** accent-soft 패널 위에 놓이는 갈래. 그 면 위에서 secondary 는 대비가 죽는다(#456). */
  "on-accent": "border border-accent-border bg-surface text-ink hover:border-accent",
};
```

`bg-surface` 가 문자열에 있어야 한다 — `question-panel.test.tsx:44 · 66` 이 본다.

**이름을 `on-accent` 로 고른 이유.** 기존 셋은 위계(주·보조·투명)를 말하는데 이것은 위계가
아니라 **놓이는 면**이 다른 갈래다. `surface` 라고만 하면 다른 흰 면 위 버튼도 여기를 쓰게
되어 원래 문제가 돌아온다.

**딸려 오는 시각 변화 둘.** 리뷰가 봐야 한다.

- 버튼 셋이 `font-medium` 을 얻는다(`Button` 의 `BASE`). #456 이 보조 버튼 전체에 대해
  이미 한 판단과 같다.
- 뒤로가기 버튼(`QuestionPanel:96`)의 글자색이 `text-ink-muted` → `text-ink` 가 된다.
  `className` 으로 되돌리면 §3-3 의 충돌에 걸리므로 되돌리지 않는다. 셋이 같은 갈래로
  보이는 쪽이 맞다고 본다. 이견이 있으면 `on-accent-quiet` 를 따로 두는 대신
  **variant 를 나누지 말고 이 PR 을 되돌리는 것**이 낫다.
- 모서리 반경이 `rounded`(4px) → `rounded-sm`(6px, #455 가 덮은 값)이 된다. 다른 버튼 전부와
  같아진다.

### `ThemeToggle` 을 `SegmentedControl` 로 흡수하지 않는다 — 근거와 되돌리는 법

| 바깥 요소 | `<fieldset>` | `<div role="group" aria-label="테마">` + `<span>` 스트립. `ThemeToggle.tsx:51` 의 biome-ignore 가 fieldset 을 피한 이유를 적어 두었다 |

| 눌린 쪽 | `bg-accent-soft font-semibold text-accent` | `bg-surface text-accent shadow-card` |
| 버튼 크기 | `px-3 py-1.5 text-sm` | `rounded-sm px-4 py-1 text-sm font-medium transition-colors …` |
| 곁들이 | 없음 | 해·달 아이콘이 그룹 안, 스트립 **밖**에 있다 |

되돌리는 법(오케스트레이터가 반대 결정을 내릴 경우): `SegmentedControlProps` 에

**그 경우 §13 의 ADR 이 필요하다.**

## 6-4. `TestOptionsPanel` 주의 — #464 구조를 유지한다

#464 는 `TestOptionsPanel.tsx:61-73` 을 이렇게 만들었고 그 구조가 계약이다.

```tsx
<h2 className="text-title font-semibold text-ink">
  <button type="button" aria-expanded={props.open}
          className="flex w-full items-center justify-between gap-3 px-3 py-2 text-left" …>
    <span>{props.open ? "▾" : "▸"} 테스트 옵션</span>
    <span className="text-caption font-normal text-ink-muted">…</span>
  </button>
</h2>
```

**이 버튼을 `Button` 으로 옮기지 않는다.** 이유 셋.

1. **`Button` 의 `BASE` 에 `font-medium` 이, `SIZES` 에 `text-sm` 이 있다.** 지금 이 버튼은
   Tailwind preflight 의 `button { font: inherit }` 으로 h2 의 17px·600 을 물려받는다.
   `Button` 으로 옮기면 그 둘이 상속을 덮어 **머리글이 14px·500 으로 조용히 내려앉는다.**
   테스트는 role·level 만 보므로 초록이다 — #464 가 computed 17px·600 으로 확인한 값이
   테스트 없이 무너지는 자리다.
2. **모양이 정반대다.** 이 버튼은 `flex w-full … justify-between text-left` 이고 `Button` 의
   `BASE` 는 `inline-flex … justify-center` 다. `className` 으로 덮으면 `inline-flex` 와
   `flex` 가 다투고 승패를 호출부가 정하지 못한다(§3-3).
3. **패딩도 다툰다.** 필요한 것은 `px-3 py-2` 인데 `size="md"` 는 `px-4 py-2`, `size="sm"` 은
   `px-3 py-1.5` 다. 어느 쪽도 맞지 않고 덧붙이기로는 이길 수 없다.

그러므로 **`FOCUS_RING` 세 유틸리티만 `className` 끝에 더한다.** `font-normal` 을 둔 요약
`<span>`(`:69`)과 그 위 주석(`:56-60`)은 한 글자도 건드리지 않는다.
`test-options-panel.test.tsx:111-112` 의 `heading.querySelector("button")` 이 계속 통과한다.

## 12. 시각 점검 — 키보드 Tab 과 computed `outline`

`pnpm --filter @mcpeak/dashboard build` 로 만든 dist 서버를 띄우고 **키보드 Tab 으로만**
옮겨 다니며 잰다. 마우스 클릭에는 `:focus-visible` 이 뜨지 않는다.

**400ms 기다린 뒤에 잰다.** Tailwind 4 의 `transition-colors` 는 `outline-color` 도 민다 —
포커스 직후에 재면 이전 색이 잡힌다(#456 에서 두 번 헛다리를 짚은 자리다). 설치된
`tailwindcss@4.3.3` 의 `transition-colors` 속성 목록이 실제로
`color, background-color, border-color, outline-color, text-decoration-color, fill, stroke, …`
임을 확인했다.

### 스니펫

브라우저 콘솔에 붙여 두고, Tab 으로 한 칸 옮길 때마다 `ring()` 을 부른다.

```js
// 라이트·다크 각각 한 바퀴 돈다. 다크는 사이드바 하단이 아니라 본문 오른쪽 위 Light/Dark 로 바꾼다.
globalThis.ring = async () => {
  const el = document.activeElement;
  await new Promise((r) => setTimeout(r, 400));       // transition-colors 가 정착할 때까지
  const s = getComputedStyle(el);
  const clip = el.closest(".overflow-hidden");
  const er = el.getBoundingClientRect();
  const cr = clip?.getBoundingClientRect();
  const offset = parseFloat(s.outlineOffset) || 0;
  return {
    이름: (el.getAttribute("aria-label") ?? el.textContent ?? "").trim().slice(0, 24),
    태그: el.tagName,
    outline: `${s.outlineStyle} ${s.outlineWidth} ${s.outlineColor}`,
    offset: s.outlineOffset,
    // 링이 조상의 overflow-hidden 밖으로 나가면 잘린다. 음수 offset 이면 늘 안전하다.
    잘림: cr === undefined ? false
      : er.top - offset < cr.top || er.left - offset < cr.left ||
        er.bottom + offset > cr.bottom || er.right + offset > cr.right,
  };
};
```

### 기대값

- `outline`: `solid 2px rgb(109, 40, 217)` (라이트, `--focus-ring: #6d28d9`)
- `outline`: `solid 2px rgb(167, 139, 250)` (다크, `--focus-ring: #a78bfa`)
- `offset`: 세그먼트 버튼만 `-2px`, 나머지 전부 `2px`
- `잘림`: **모든 행에서 `false`**

## 13. 거짓 신호 점검

이 계획에서 **초록인데 틀릴 수 있는** 자리 전부다.

1. **jsdom 은 CSS 를 읽지 않는다.** 클래스 문자열 단언은 "그 낱말이 `className` 에 있다" 만
   말한다. Tailwind 가 그 유틸리티를 실제로 내보냈는지, 다른 유틸리티에 졌는지, 조상이
   잘랐는지는 **전부 모른다.** §12 가 유일한 판정 수단이다. ADR-0093 「결과」의
   `@theme static` 함정과 같은 갈래다.
2. **포커스 링 잘림(§6-1).** `outline-offset-2` 를 쓰면 모든 테스트가 통과한 채 세그먼트의
   링만 화면에서 사라진다. §12 의 `잘림` 칸이 이것만 본다.
3. **Tailwind 유틸리티 충돌(§3-3).** `${INPUT_CLASS} border-accent-border` 같은 코드는
   컴파일되고 테스트도 통과하지만 테두리 색은 소스 순서가 이긴 쪽이 된다.
   `INPUT_ON_ACCENT_CLASS` 를 따로 둔 이유다.
4. **`TestOptionsPanel` 머리글 상속(§6-4).** `Button` 으로 옮기면 `text-sm font-medium` 이
   h2 상속을 덮어 17px·600 이 14px·500 으로 내려앉는데, 기존 테스트는 role·level 만 본다.
   §12 의 11번이 이것만 본다.
5. **Node 26 거짓 실패(§1).** 플래그 없이 돌린 8개 파일의 빨간 출력을 회귀로 보고하지 않는다.
   거꾸로, **플래그가 있으면 통과하는데 CI 에서 깨질 이유는 없다** — CI 는 Node 22 · 24 다.
6. **turbo 캐시.** `pnpm build --force` · `pnpm typecheck --force` 의 `Cached: 0 cached` 를
   눈으로 본다.
7. **수집 0개.** `vitest` 가 `include` 를 못 맞추면 "전부 통과" 로 초록이 뜬다.
   §11-4 의 파일 수 · 케이스 수를 센다.
8. **shim 이 남으면 "다 옮겼다" 가 거짓이다.** `git grep -n 'generate/steps/fields'` 가
   0줄이어야 한다. 0줄이 아닌데 테스트는 통과한다.
9. **`REPAIR_INPUT_CLASS` 가 복제였다는 사실은 테스트가 잡지 못했다.** 지금도 그 세 칸이
   비활성이 되는 경로가 없어, 되찾은 `disabled:opacity-50` 을 확인할 실행 경로가 없다.
   `field.test.tsx` 의 「두 입력칸 갈래가 같은 바탕을 쓴다」가 **대신 서는 유일한 그물**이다.
   이 케이스를 빼면 다음 복제도 같은 방식으로 새어 나간다.
10. **`getByText` 로 잡는 버튼(`question-panel.test.tsx:79 · 83 · 85 · 98`).** 텍스트가
    `<button>` 의 직계 자식이 아니게 되면 `getByText` 는 버튼이 아니라 안쪽 `<span>` 을 준다.
    그러면 `toHaveProperty("disabled", …)` 가 `undefined` 와 비교되어 **거짓 실패**가 나거나,
    클릭이 버블링으로 통해 **거짓 통과**가 난다. `Button` 은 children 을 감싸지 않는다.
11. **접근 가능한 이름.** `SegmentedControl` 이 `aria-label` 을 붙이면
    `theme-toggle.test.tsx:112-114` 와 같은 계약이 깨지고, 라벨을 `<span>` 으로 감싸면
    이름은 그대로라 테스트는 통과하지만 10번의 `getByText` 문제가 생긴다. 라벨을 그대로
    children 으로 낸다.

## 14. ADR

**새 ADR 은 원칙적으로 쓰지 않는다.** 이 두 PR 은 ADR-0093 「결정」의 PR 3 을 그대로
수행하는 것이고, 그 ADR 이 이미 선택지와 이유를 담고 있다. #464 도 같은 이유로 ADR 을
쓰지 않았다.

아래 셋 중 하나가 **계획과 다르게 결정되면** 그때는 한 페이지 ADR 이 필요하다.
"다르게 갈 수도 있었던" 판단이고, 다음 사람이 근거 없이 되돌릴 수 있는 자리다.

| 결정 | 계획의 기본값 | ADR 이 필요해지는 경우 |
|---|---|---|
| `ThemeToggle` 을 세그먼트로 흡수 | **흡수하지 않는다**(§6-3 대조표) | 흡수하기로 뒤집을 때. #463 본문이 반대 방향을 적어 두었으므로 근거가 문서에 남아야 한다 |
| QuestionPanel 갈래를 `Button` variant 로 | **`on-accent` 를 더한다**(§6-2) | variant 를 더하지 않고 raw `<button>` 으로 남기기로 할 때, 또는 variant 대신 `Card` 처럼 별도 컴포넌트로 갈 때 |
| `Card` 에 다형(`as`) | **들이지 않는다**(§0 비범위) | `RunView` 의 repair `<form>` 을 이번에 `Card` 로 옮기기로 할 때 |

**ADR 번호를 미리 잡지 마라.** 이 저장소는 같은 ADR 이 번호 충돌로 두 번 밀린 전례가 있다
(ADR-0093 의 「결과」 마지막 문단). 잡아야 할 때가 오면 그 시점에 아래로 확인한다.

```sh
git -c core.quotePath=false ls-tree --name-only origin/main docs/adr/
```

`-c core.quotePath=false` 를 빼면 git 이 한글 경로를 따옴표로 싸서 `grep '^docs/adr/'` 가 늘
빈 출력을 낸다(실측: 99개 중 9개만 보인다). 머지 직전에 그 번호가 여전히 비어 있는지 다시
확인한다.
