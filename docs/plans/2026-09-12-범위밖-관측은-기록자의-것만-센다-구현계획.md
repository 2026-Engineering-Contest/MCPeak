# 범위 밖 관측 정확도 구현계획 (2026-09-12)

참조 문서: `docs/2026-09-12-범위밖-관측은-기록자의-것만-센다-설계.md`(이하 "설계"),
ADR-0057 · ADR-0068 · ADR-0095, `docs/2026-09-11-npx-런처-녹화-누락-설계.md` §8.2.

> **실행 방식:** 터미널 세션은 오케스트레이터이며 태스크마다 실행 세션에 넘겨 구현시키고
> 사이사이 리뷰한다. 직접 구현하지 않는다. 규약은 `.claude/conventions/plan.md` 와
> `.claude/conventions/execution.md` 다.

기점 커밋: §6 에서 확정한다.

## 전역 제약

- **패키지 오너 제한은 이 계획에 적용하지 않는다.** 사용자가 2026-09-11 에 풀었고 2026-09-12 에
  다시 확인했다. 필요하면 어느 패키지든 고친다. 다만 **다른 패키지를 열기 전에 오케스트레이터에
  알린다.** 막기 위해서가 아니라 파일 소유권 표와 changeset 대상을 맞추고, 병렬 태스크와 겹치는지
  보기 위해서다. 지금 설계는 `record` 안에서 끝나므로, `cli` 를 건드릴 이유가 생겼다면 설계가
  무언가 놓쳤다는 뜻이다.
- **`core/src/types.ts` 의 `McpClient` · `ToolResult` 는 동결이다.** 이것은 오너 문제가 아니라
  5인 병렬 작업의 기준점이라 그렇다. 필요해 보이면 제안까지만 한다.
- **의존 방향은 단방향이다.** 이 계획은 새 의존을 하나도 더하지 않는다.
- **`@modelcontextprotocol/sdk` 는 1.x 고정.** 새 의존성을 추가하지 않는다. 설계가 쓰는
  `node:path` · `node:crypto` · `node:fs` 는 표준 모듈이다.
- **커밋·푸시는 사람이 한다.** 실행 세션은 git 명령을 실행하지 않는다.
- **네트워크를 타지 않는다.** 실제 `npx` 를 테스트에서 부르지 않는다. 인메모리 origin HTTP
  서버와 `tests/fixtures/` 만 쓴다.
- **결정론성.** 보고 파일명에 들어가는 난수는 세션에 저장되지 않으므로 무관하다. 단언 대상으로
  삼지 않는다.
- **`packages/*` 를 건드린 브랜치는 그 브랜치에서 changeset 을 새로 만든다**(ADR-0063).
- 검증: `pnpm install` · `pnpm build --force` · `pnpm test` · `pnpm typecheck --force` ·
  `pnpm lint`.

## 1. 목표 / 비범위 / 완료 조건

**목표** (설계 §2): 관측이 세는 것을 이 세션의 기록자가 낸 호출로 좁힌다. ADR-0068 의
"부재는 0이 아니라 못 셌음" 은 유지한다.

**비범위** (설계 §3): 녹화에서의 관측, 어댑터 범위 확대, `cli` 문안, ADR-0095 의 다른 갈래.

| 설계 §2 완료 조건 | 태스크 |
|---|---|
| 1 런처 트래픽이 안 섞인다 | T1(구현) · T2(증거) |
| 2 기록자의 범위 밖 호출은 그대로 센다 | T1 · T2 |
| 3 어댑터를 안 쓴 재생에서도 센다 | T1(폴백) · T2 |
| 4 훅이 못 뛰면 "못 셌음" | T1(§7.3) |
| 5 기존 동작 유지 | T1 · T2 회귀 |
| 6 빌드·테스트·타입체크·린트 | T3 통합 게이트 |

## 2. 파일 소유권

| 태스크 | 쓰는 파일 |
|---|---|
| T1 | `packages/record/src/external/child/out-of-scope-observer.mjs`, `.../out-of-scope-observer.d.mts`, `.../child/fetch-adapter.mjs`, `.../child/bootstrap.mjs`, `packages/record/src/external/coordinator.ts`, `packages/record/tests/out-of-scope-observer.test.ts`, `packages/record/tests/external/observer-aggregate.test.ts`(신규), `packages/record/tests/external/observer-env-contract.test.ts`(신규), `.changeset/observer-writer-only.md`(신규) |
| T2 | `packages/record/tests/external/launcher-chain-e2e.test.ts`, `packages/record/tests/fixtures/external/stdio-launcher.mjs`, `packages/record/tests/fixtures/external/fetch-mcp-server.mjs` |
| TA | `docs/adr/0096-*.md`(신규), `docs/adr/README.md` |
| T3 | `docs/task-integration-ledger.tsv` (오케스트레이터 직접) |

T1 과 T2 는 파일이 겹치지 않지만 **T2 가 T1 의 동작을 판정하므로 직렬**이다. 같은 worktree,
같은 브랜치에서 T1 → T2 순으로 돈다.

TA 는 코드에 의존하지 않아 T1 과 병렬이다.

**지금 설계는 한 패키지 안에서 끝난다.** 코드는 전부 `record` 다. 오너 제한 때문이 아니라
숫자가 맞아지면 `cli` 의 기존 문장이 그대로 참이 되기 때문이다(설계 §3). 범위가 넘어가야 할
근거가 나오면 이 표를 고치고 진행한다.

## 3. 공유 계약

설계 §5 가 전량이다. 계획서에 박는 것은 둘뿐이다.

**환경변수 이름.** `coordinator.ts` 와 `bootstrap.mjs` 두 자리가 같아야 한다.

```
MCPEAK_EXTERNAL_OBSERVER_DIR
```

어긋나면 관측이 조용히 꺼지고, 꺼진 관측은 `undefined`(못 셌음)로 보여 실패처럼 보이지
않는다. 그래서 §7.1 이 소스를 문자열로 읽어 단언한다.

**보고 파일의 모양.**

```json
{ "outOfScope": 3, "claimed": true }
```

`claimed` 가 없으면 `false` 로 본다. 자식이 쓴 값이라 형식을 믿지 않는다.

## 5. 모델 배분

| 태스크 | 모델 | 사유 |
|---|---|---|
| 오케스트레이터 | 상위 | 리뷰·머지 게이트 |
| T1 | 상위 | 집계 규칙의 폴백 갈래와 `claimed` 판정 시점이 판단이다. 둘 다 틀려도 대부분의 테스트는 통과한다. 지침 표의 예외(재생 결정론성, 목 서버·관측 프로토콜 준수)에 걸린다 |
| T2 | 상위 | 런처가 자기 `node:http` 호출을 내는 E2E 는 프로세스 종료 순서에 결과가 달린다 |
| TA | 표준 | 설계 문서에서 옮겨 적는 일이다 |

## 6. 기점

오케스트레이터가 설계 문서와 이 계획서를 커밋한 SHA 다. 실행 세션에 넘기는 프롬프트에
실제 값으로 적는다. 계획서·설계 문서가 untracked 면 새 worktree 에 딸려가지 않는다.

worktree 생성과 부트스트랩(`pnpm install`, `pnpm build`, 러너 실행 확인)은 **오케스트레이터가
먼저 끝내고** 실행 세션에 넘긴다. 실행 세션의 1단계는 생성이 아니라 확인이다.

## 7. T3 통합 게이트 (오케스트레이터 직접)

보고서와 diff 와 테스트 출력을 직접 확인한 뒤에 진행한다.

1. diff 가 §2 의 파일 소유권 표 안에만 있는지 확인한다.
2. 설계 §5 의 코드와 실제 코드를 대조한다. 특히 세 자리를 눈으로 본다.
   - `claimed` 를 `WRITER_CONFLICT` 가 **아닌** 모든 결과에서 세우는가 (성공만이 아니다)
   - 집계의 폴백이 "기록자 보고가 0개일 때" 인가 (파일이 0개일 때가 아니다)
   - 관측 설치가 어댑터 설치보다 **앞**인가
   셋 다 틀려도 대부분의 테스트는 통과한다. 그래서 사람이 본다.
3. `record` 브랜치를 머지하고, 그다음 ADR 브랜치를 머지한다.
4. 통합 브랜치에서 `pnpm install` → `pnpm build --force`(`Cached: 0 cached` 확인) →
   `pnpm test` → `pnpm typecheck --force` → `pnpm lint`.
5. **실환경 재확인을 직렬로 한다.** 이 계획의 진짜 판정이다. 저장소 밖 임시 디렉터리에서
   `packages/cli/dist/cli.mjs` 로 context7 을 재생한다.

   ```sh
   node <저장소>/packages/cli/dist/cli.mjs test <명세> \
     --command npx --arg -y --arg @upstash/context7-mcp \
     --session <녹화본>
   ```

   판정은 stderr 다. **`경고: 범위 밖 호출 ...` 이 나오지 않아야 한다.** 고치기 전에는 1건이
   나왔고 2회 반복해도 같았다(설계 §1.2). 런처 없이 띄운 대조군은 그때도 경고가 없었다.
   두 형태를 다시 돌려 **둘 다 경고가 없는지**를 본다.
6. 통합 SHA 를 `docs/task-integration-ledger.tsv` 에 기록하고 별도 문서 커밋으로 보존한다.
7. `docs/2026-09-11-공개서버-직접조작-데모-실측-문제.md` §2 의 "남은 갈래" 문단을 해소로
   갱신한다. ADR-0095 설계 문서 §8.2 에도 한 줄 남긴다.

어느 단계라도 실패하면 멈추고 `BLOCKED` 로 보고한다.

## 8. 자체 검토

- 설계 §2 의 완료 조건 여섯이 전부 §1 의 표에서 태스크에 대응한다.
- Wave 1 두 세션의 쓰기 파일이 겹치지 않는다. T1 은 `packages/record/` 와 `.changeset/`,
  TA 는 `docs/adr/` 다.
- 한 브랜치가 두 패키지를 건드리는 자리가 없다. 코드는 전부 `record` 다.
- 상위 모델은 판단이 걸린 T1 · T2 에만 붙였고 사유를 §5 에 적었다.
- 테스트가 인메모리와 `packages/record/tests/fixtures/` 만 쓴다. 실제 `npx` 는 §7 의 직렬
  단계 하나뿐이고 오케스트레이터가 직접 한다.
- 폴백 갈래의 부정확을 테스트가 정확한 값으로 고정하지 않는다(설계 §7.2 케이스 4). 고정하면
  나중에 고칠 때 테스트가 방해한다.
- `packages/*` 를 건드리는 브랜치에 changeset 이 있고, 안 건드리는 TA 에는 없다.
