### 사양

**1) 새 타입 두 개를 `valid-branches.ts` 에 둔다.**

```ts
/** 밟지 않은 정상 분기 한 건. render.ts 의 OutputContractSkip 과 같은 계열이다. */
export interface ValidBranchSkip {
  readonly tool: string;
  readonly field: string;
  /** 화면에 그대로 찍는 한 문장. 무엇을 안 밟았고 왜인지가 다 들어 있다. */
  readonly reason: string;
}

export interface ValidBranchResult {
  readonly cases: readonly GeneratedCase[];
  readonly skips: readonly ValidBranchSkip[];
}
```

**2) 공개 함수 하나를 낸다.**

```ts
export function buildValidBranchCases(options: {
  readonly tool: ToolDef;
  /** 기준 정상 입력. render.ts 의 synthesizeValue 결과를 그대로 받는다. */
  readonly happyInput: JsonObject;
  /** 케이스 id 접두사. render.ts 의 baseName 과 같은 값이다. */
  readonly baseName: string;
  /** 출력 계약이 지원되면 그 스키마. 아니면 null. 기준 정상 케이스와 같은 단언을 붙인다. */
  readonly responseSchema: ResponseSchema | null;
}): ValidBranchResult
```

**3) 대상 필드와 순서.**

`tool.inputSchema.properties` 의 키를 **UTF-16 코드 단위 오름차순**으로 정렬해 순회한다.
`properties` 의 선언 순서를 쓰지 않는다. 서버가 순서를 바꾸는 것만으로 케이스 배열이 흔들리면
결정론성이 깨진다. 정렬 비교는 `(a, b) => (a < b ? -1 : a > b ? 1 : 0)` 이다.
`localeCompare` 를 쓰지 않는다(로캘·ICU 데이터에 따라 결과가 달라진다).

한 필드 안에서는 `enum 두 번째 → enum 마지막 → boolean false → 선택 필드 있음` 순서다.

`required` 판정은 `tool.inputSchema.required` 배열에 그 이름이 있는지로 한다.

**4) 필드별 분기 규칙.** 위에서부터 판정하고, `skips` 에 넣은 경우 그 필드의 다른 분기는
만들지 않는다.

| # | 조건 | 결과 |
|---|---|---|
| 1 | 필드 스키마가 객체가 아님 | 아무것도 안 만들고 skip 도 안 넣는다 |
| 2 | `$ref` · `anyOf` · `oneOf` 중 하나라도 키로 있음 | skip: `anyOf/oneOf/$ref 가 선언돼 있어 갈래별 정상 입력을 만들지 않았습니다.` |
| 3 | `"const" in schema` | 아무것도 안 만든다. 분기가 없다 |
| 4 | required 가 아님 (선택 필드) | "선택 필드 있음" 케이스 하나. 추가로 그 필드가 `enum` 또는 `type === "boolean"` 이면 skip: `선택 필드라 '있음' 케이스만 만들고 값 분기는 만들지 않았습니다.` |
| 5 | `Array.isArray(schema.enum)` | §4.1 의 enum 규칙 |
| 6 | `schema.type === "boolean"` | §4.2 의 boolean 규칙 |
| 7 | `schema.type === "object"` 이고 `plainObject(schema.properties)` | skip: `중첩 객체 안의 분기는 아직 생성하지 않습니다.` |
| 8 | 그 밖 | 아무것도 안 만든다 |

**§4.1 enum 규칙.** `values = schema.enum` 이라 한다.

| `values.length` | 만드는 변형 |
|---|---|
| 0 또는 1 | 없음 |
| 2 | `values[1]` |
| 3 이상 | `values[1]` 과 `values[values.length - 1]`, 그리고 skip: `enum 값 ${values.length}개 중 3개만 실행했습니다. 첫 값·두 번째 값·마지막 값만 밟습니다.` |

`values.length === 3` 이면 세 값을 다 밟으므로 skip 을 넣지 않는다. 즉 skip 조건은
`values.length >= 4` 다. **3 과 4 를 헷갈리지 마라.** 다 밟았는데 "3개만 실행했습니다" 를
찍으면 화면이 거짓말을 한다.

| 변형 | id | name |
|---|---|---|
| `values[1]` | `${baseName}-branch-enum-${fieldSlug(field)}-2` | `${tool.name}가 '${field}' 의 다른 선언값에 정상 응답한다` |
| 마지막 | `${baseName}-branch-enum-${fieldSlug(field)}-last` | `${tool.name}가 '${field}' 의 마지막 선언값에 정상 응답한다` |

**§4.2 boolean 규칙.** `happyInput[field] === true` 일 때만 만든다.

| 변형 | id | name |
|---|---|---|
| `false` | `${baseName}-branch-false-${fieldSlug(field)}` | `${tool.name}가 '${field}' 가 false 인 입력에 정상 응답한다` |

**§4.3 선택 필드 규칙.**

값은 `synthesizeValue(fieldSchema, "properties.<field>", tool.inputSchema as JsonSchema)` 다.
루트를 넘겨야 `$ref` 가 풀린다.

| 변형 | id | name |
|---|---|---|
| 있음 | `${baseName}-branch-with-${fieldSlug(field)}` | `${tool.name}가 선택 필드 '${field}' 를 받아 정상 응답한다` |

`synthesizeValue` 가 `GenerateTestsError` 를 던지면 그 변형만 안 만들고 skip 에 넣는다.
`reason` 은 `선택 필드 값을 만들지 못했습니다: ${error.message}` 다. **`GenerateTestsError`
만 삼킨다.** 그 밖의 오류는 우리 결함이므로 `throw` 로 그대로 올린다. 전부 삼키면 우리
버그가 "분기 못 만듦" 으로 위장돼 조용히 유지된다.

**5) 값이 기준과 같으면 만들지 않는다.**

만든 변형 값이 `happyInput[field]` 와 같으면 케이스를 만들지 않고 skip 에 넣는다.
`reason` 은 `변형 값이 기준 정상 입력과 같아 케이스를 만들지 않았습니다.` 다.

비교는 `packages/generate/src/canonical.ts` 의 `canonicalJson` 으로 한다.

```ts
canonicalJson(variantValue) === canonicalJson(happyInput[field] ?? null)
```

`===` 를 쓰지 마라. enum 값이 배열이나 객체일 수 있다(JSON Schema 가 막지 않는다).

선택 필드의 "있음" 케이스는 이 검사를 하지 않는다. 기준에 그 키가 아예 없으므로 입력이 늘
다르다.

**6) 케이스 모양.** 전부 정상 케이스다.

```ts
{
  id, name,
  operation: { type: "callTool", tool: tool.name, input: { ...happyInput, [field]: value } },
  assertions: [
    { type: "isError", expected: false },
    ...(responseSchema === null ? [] : [{ type: "structuredContentMatchesSchema", schema: responseSchema }]),
  ],
}
```

`expected: false` 다. **`true` 가 아니다.** `GeneratedCase.assertions` 의 유니온이 이 실수를
컴파일러가 잡게 만들어 뒀으니, 타입 오류가 나면 값을 고쳐라. 타입을 넓히지 마라.

id 중복 회피는 `violation-cases.ts` 의 `uniqueId` 와 같은 규칙(`-2`, `-3` 접미사)으로 이
파일 안에 지역 `Set` 을 두고 한다. 접두사가 `branch-*` 라 다른 계열과 겹치지 않는다.

**7) `render.ts` 배선.**

`buildSuite` 가 `buildValidBranchCases` 를 부르고, `BuiltSuite` 에 `validBranchSkips` 를 싣는다.
`cases` 배열 순서는 다음과 같다.

```
기준 정상 → 상한 경계 정상(#387 이 넣은 것) → 정상 분기 → 위반
```

정상 계열을 앞에 모아 둔다. 실패 목록을 위에서부터 읽을 때 "정상이 되는 입력" 이 한 덩어리로
보여야 한다.

```ts
interface BuiltSuite {
  readonly suite: GeneratedSuiteSpec;
  readonly outputContractSkip?: OutputContractSkip;
  /** 비어 있으면 빈 배열이다. undefined 로 두지 않는다. 호출부가 ?? [] 를 안 써도 되게 한다. */
  readonly validBranchSkips: readonly ValidBranchSkip[];
}
```

`buildGeneratedCases` 의 반환에도 `validBranchSkips` 를 싣는다.

**8) `baseline.ts` 배선.** `outputContractSkips` 와 **정확히 같은 모양**으로 모은다.
그 코드를 보고 따라 해라. 48행·100행·110행·158행 부근이다.

```ts
readonly validBranchSkips: readonly ValidBranchSkip[];
```

순서는 툴 처리 순서를 그대로 따른다. 새로 정렬하지 않는다.

**9) `index.ts`.** `ValidBranchSkip` 타입과 `buildValidBranchCases` 를 내보낸다.

### 사양

`outputContractSkips` 가 흐르는 길을 **그대로 따라** `validBranchSkips` 를 잇는다. 새 길을
내지 마라. 1373행·1696행·2111행·2119행·2140행·2143행·2310행·2365행·2383행·2440행 부근에
`outputContractSkips` 가 있다. 그 자리마다 짝을 만든다.

`renderOutputContractSkips` 와 같은 계열로 `renderValidBranchSkips` 를 만든다. 커버리지 표
아래, 출력 계약 미검증 덩어리 다음에 찍는다.

머리말은 실제로 센 숫자로 만든다.

```
정상 분기: 툴 {툴수}개에서 {분기수}개 분기를 실행하지 않았습니다.
```

- `{분기수}` 는 `skips.length` 다
- `{툴수}` 는 `skips` 의 서로 다른 `tool` 값 개수다

이어서 한 줄씩 찍는다. 들여쓰기는 파일 안의 다른 목록과 같은 너비를 쓴다(직접 확인해라).

```
  {tool}.{field}  {reason}
```

`tool` 과 `field` 사이는 마침표, 그 뒤와 `reason` 사이는 공백 두 칸이다.

**`skips` 가 비어 있으면 머리말도 목록도 안 찍는다.** 빈 목록을 찍으면 화면만 길어지고
사용자가 읽을 것이 없다.

순서는 `skips` 배열 순서를 그대로 쓴다. `generate` 가 이미 결정론적으로 만들었다. 여기서
다시 정렬하면 두 곳이 갈린다.

### 테스트 (`packages/cli/tests/generate-command.test.ts`)

```
describe("정상 분기 미실행 목록을 찍는다")
  it("머리말에 툴 수와 분기 수를 센다")
    - skips 3건, 그중 tool 이 2종류
    - 출력에 "정상 분기: 툴 2개에서 3개 분기를 실행하지 않았습니다." 가 있다
  it("한 줄에 tool.field 와 사유를 찍는다")
    - { tool:"convert_units", field:"unit", reason:"enum 값 8개 중 3개만 실행했습니다. 첫 값·두 번째 값·마지막 값만 밟습니다." }
    - 출력에 "convert_units.unit" 과 그 reason 이 같은 줄에 있다
  it("skips 가 비면 머리말을 안 찍는다")
    - 출력에 "정상 분기:" 가 없다
  it("generate 가 준 순서를 그대로 쓴다")
    - skips 를 [b, a] 순서로 주면 출력에서도 b 가 a 보다 먼저다
  it("출력 계약 미검증 덩어리 다음에 온다")
    - 두 덩어리가 다 있을 때 출력 안 인덱스를 비교한다
```
