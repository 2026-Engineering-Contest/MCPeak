# repair 효과 벤치마크 구현 계획

> **에이전트 작업자용:** 필수 하위 스킬은 superpowers:subagent-driven-development(권장) 또는
> superpowers:executing-plans 다. 스텝은 체크박스(`- [ ]`)로 추적한다.

**목표:** 결함을 주입한 MCP 참조 서버를 ① 그대로, ② 코딩 에이전트 단순 수리, ③ mcpeak 진단을 곁들인
수리의 세 조건으로 공식 conformance 스위트로 채점하고, 발표용 보고서 한 장을 만든다.

**구조:** 저장소 최상위 `bench/repair-effect/` 에 워크스페이스 밖 독립 디렉터리를 둔다. 판정 로직
(시나리오 채점, 결함 주입, 수리 판정, 프롬프트, 집계)은 순수 함수로 두고 `node:test` 로 검증한다.
실제 서버·conformance·mcpeak·claude 를 부르는 명령 스크립트는 그 위에 얇게 얹는다. 실제 실행은
공유 포트와 외부 LLM 을 쓰므로 전부 직렬이다.

**기술 스택:** Node 24, TypeScript(tsx 로 실행, 타입체크 없음), `node:test`,
`@modelcontextprotocol/conformance@0.1.16`, `@modelcontextprotocol/sdk@1.30.0`, Claude Code CLI 2.1.280

**설계 문서:** `docs/plans/2026-09-23-repair-효과-벤치마크-설계.md` (이 계획은 설계 문서를 근거로 한다.
실행자는 둘 다 읽는다)

## 전역 제약

- `packages/`, `examples/`, `fixtures/`, 루트 설정(`package.json`·`pnpm-workspace.yaml`·`turbo.json`·`tsconfig.base.json`·`biome.json`·`vitest.config.ts`) 수정 금지
- 루트 `pnpm test`·`pnpm lint`·`pnpm typecheck` 결과가 이 작업 전후로 같아야 한다

- 설치는 `pnpm install --ignore-workspace` 로 `bench/repair-effect/` 안에서만 한다
- 참조 서버 원본: `modelcontextprotocol/conformance` 커밋 `1573ad5fc857d569ef405296e5d61de3ee6f921c` 의 `examples/servers/typescript/everything-server.ts`, SHA-256 `4502608417f4cde36e50689ba272e46159a14b40f8e64fbf429fbd3fe265bcc4`
- 수리 에이전트 모델 `claude-sonnet-5`, 조건당 변형당 5회. mcpeak generate 는 `--baseline-only`, repair 의 provider 는 `claude` / `claude-sonnet-5`

- 서브에이전트는 git 명령을 실행하지 않는다. diff 는 `diff -u` 로 만든다
- 산문(보고서, 주석)은 한국어, 대시 기호(—) 금지

## 리뷰 초점

테스트가 직접 다루지 않지만 사람이 실제로 밟기 쉬운 조건들이다. 각 줄의 대응은 괄호 안 태스크에 있다.

1. **원본 서버에서도 mcpeak 이 실패를 낸다.** `test_sampling`·`test_elicitation` 은 클라이언트 역호출이 필요한데 mcpeak 클라이언트는 지원하지 않는다. 이 소음이 번들 상한(기본 10건)을 채우면 진짜 결함이 진단에서 밀려난다. 원본 대조 실행으로 소음을 기록하고, 번들 실패 수가 10건 이상이면 보고서에 밝힌다. (Task 4)
2. **에이전트가 파일을 망가뜨려 서버가 안 뜬다.** 채점 단계에서 예외로 죽지 않고 `serverDown` 판정으로 기록돼야 한다. (Task 3 `judgeRepair` 의 null 입력 테스트, Task 6)
3. **80회 도중 중단.** 재실행하면 끝난 실행을 건너뛰고 이어서 돈다. 반쯤 쓴 실행 디렉터리는 `done.json` 이 없으므로 처음부터 다시 돈다. (Task 5)
4. **수리 에이전트 격리가 조용히 풀린다.** 사용자 훅(Stop 훅의 알림 요구)이나 플러그인이 끼어들면 ②③ 모두 오염된다. canary 가 도구 목록과 MCP 서버 목록을 확인하고, 어긋나면 본 실행을 막는다. (Task 5)
5. **conformance 결과 디렉터리 이름에 타임스탬프가 들어간다.** 경로를 이름 규칙으로 해석하지 않는다. 시나리오마다 빈 임시 cwd 에서 따로 돌리고, 그 안의 `checks.json` 을 전부 모은다. (Task 1 `runScenario`)

- [ ] **Step 6: scenario-score.ts 구현**

```ts
export type ScenarioOutcome = "pass" | "fail";
export type ScenarioTable = Readonly<Record<string, ScenarioOutcome>>;
export interface Check {
  readonly id: string;
  readonly status: string;
}

/**
 * conformance 0.1.16 번들에서 관찰된 상태값은 SUCCESS, FAILURE, WARNING, INFO 넷이다.
 * WARNING 은 SHOULD 위반이고 INFO 는 참고 기록이라 통과로 친다. 그 밖의 값은 모르는 값이므로
 * 통과로 세지 않는다. 모르는 값을 통과로 두면 채점기 버전이 바뀌었을 때 조용히 점수가 오른다.
 */
const PASSING_STATUSES = new Set(["SUCCESS", "WARNING", "INFO"]);

export function scoreChecks(checks: readonly Check[]): ScenarioOutcome {
  if (checks.length === 0) return "fail";
  return checks.every((check) => PASSING_STATUSES.has(check.status)) ? "pass" : "fail";
}

/** `conformance list` 출력에서 "Server scenarios" 절의 이름만 사전순으로 돌려준다. */
export function parseServerScenarios(listOutput: string): string[] {
  const names: string[] = [];
  let inServer = false;
  for (const line of listOutput.split("\n")) {
    if (line.startsWith("Server scenarios")) {
      inServer = true;
      continue;
    }
    if (line.startsWith("Client scenarios")) {
      inServer = false;
      continue;
    }
    const match = /^\s+-\s+(\S+)/.exec(line);
    if (inServer && match) names.push(match[1] as string);
  }
  return names.sort();
}

export function sortTable(table: Record<string, ScenarioOutcome>): ScenarioTable {
  return Object.fromEntries(Object.entries(table).sort(([a], [b]) => a.localeCompare(b)));
}
```

```ts
import type { ScenarioTable } from "./scenario-score.ts";

export type RepairVerdict = "success" | "targetStillFailing" | "regressed" | "serverDown";

/**
 * 수리 성공은 목표 시나리오 통과 **그리고** S 의 나머지가 하나도 깨지지 않은 것이다.
 * 회귀가 있으면 목표 통과 여부와 무관하게 regressed 다. 다른 곳을 망가뜨린 수리를
 * 성공으로 세면 "고쳤다"는 숫자가 부풀려진다. 표에 없는 시나리오는 실패로 센다.
 */
export function judgeRepair(input: {
  baselinePassing: readonly string[];
  target: string;
  table: ScenarioTable | null;
}): { verdict: RepairVerdict; regressed: string[]; passCount: number } {
  const { baselinePassing, target, table } = input;
  if (table === null) return { verdict: "serverDown", regressed: [], passCount: 0 };
  const passed = (s: string) => table[s] === "pass";
  const regressed = baselinePassing.filter((s) => s !== target && !passed(s)).sort();
  const passCount = baselinePassing.filter(passed).length;
  if (regressed.length > 0) return { verdict: "regressed", regressed, passCount };
  if (!passed(target)) return { verdict: "targetStillFailing", regressed, passCount };
  return { verdict: "success", regressed, passCount };
}
```

```ts
import { FAULTS, type FaultId } from "./faults.ts";
import type { RepairVerdict } from "./judge.ts";

export type Condition = "defect" | "plain" | "diagnosed";
export interface RunRecord {
  readonly faultId: FaultId;
  readonly condition: Condition;
  readonly attempt: number;
  readonly verdict: RepairVerdict;
  readonly passCount: number;
  readonly regressed: readonly string[];
  readonly inputTokens: number | null;
  readonly outputTokens: number | null;
  readonly durationMs: number | null;
}
export interface Row {
  readonly faultId: FaultId;
  readonly condition: Condition;
  readonly runs: number;
  readonly successes: number;
  readonly meanPassCount: number;
}
type Tally = { successes: number; runs: number };
const CONDITIONS: readonly Condition[] = ["defect", "plain", "diagnosed"];
const emptyTallies = (): Record<Condition, Tally> => ({
  defect: { successes: 0, runs: 0 },
  plain: { successes: 0, runs: 0 },
  diagnosed: { successes: 0, runs: 0 },
});

export function aggregate(records: readonly RunRecord[]) {
  const rows: Row[] = [];
  const tool = emptyTallies();
  const control = emptyTallies();
  for (const fault of FAULTS) {
    for (const condition of CONDITIONS) {
      const group = records.filter((r) => r.faultId === fault.id && r.condition === condition);
      if (group.length === 0) continue;
      const successes = group.filter((r) => r.verdict === "success").length;
      const meanPassCount = group.reduce((sum, r) => sum + r.passCount, 0) / group.length;
      rows.push({ faultId: fault.id, condition, runs: group.length, successes, meanPassCount });
      const bucket = fault.area === "tool" ? tool : control;
      bucket[condition].successes += successes;
      bucket[condition].runs += group.length;
    }
  }
  return { rows, tool, control };
}
```

- `lines` 를 `stream.jsonl` 에, 토큰은 `result.usage.input_tokens`·`result.usage.output_tokens` 에서 읽어(없으면 null) `done.json` 을 **마지막에** 쓴다. `done.json` 이 완료 표지이므로 반드시 다른 파일보다 뒤에 쓴다.
- 임시 디렉터리는 지운다.
- 진행을 `[12/80] F3 diagnosed #2 exit=0 7m12s` 형식으로 한 줄씩 찍는다.
