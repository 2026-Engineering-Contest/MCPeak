# 경쟁 도구 비교 개선 구현 계획 (2026-09-27)

- 설계: `docs/plans/2026-09-27-경쟁-도구-비교-개선-설계.md` (이하 "설계"). 문안·계약·테스트
  이름과 단언은 설계가 유일한 진실이다. 이 문서는 그것을 태스크로 나누고 순서를 정한다.
- 통합 대장: `docs/task-integration-ledger.tsv`. 태스크명은 `cmp-T1-runner-diagnostics` 식이다.
- 기점: 계획서 커밋 직후의 `main` HEAD. 각 worktree 는 오케스트레이터가 로컬 HEAD 기준으로
  만들고 부트스트랩까지 끝낸 뒤 넘긴다.

## 1. 실행 모델

- 오케스트레이터(이 계획을 도는 세션)는 코드를 쓰지 않는다. worktree 생성, 부트스트랩, 프롬프트
  전달, diff 리뷰, 검증 재실행, 머지, 대장 기록, 최종 E2E 를 맡는다.
- 구현은 같은 저장소의 idle 피어 세션이 한다. 세 태스크 모두 실패 메시지 문안이라
  `CLAUDE.local.md` 의 상위 모델 예외에 해당한다. 피어 세션의 모델은 오케스트레이터가 고를 수
  없으므로, 문안은 설계의 표를 글자 그대로 옮기게 하고 판단이 필요한 곳은 `BLOCKED` 로 올리게
  한다.

## 2. 태스크와 웨이브

| 웨이브 | 태스크 | 패키지 | 선행 | 설계 절 |

## 5. 실행 프롬프트

프롬프트는 오케스트레이터가 worktree 를 만들고 부트스트랩을 끝낸 뒤 `SendMessage` 로 보낸다.
worktree 생성은 오케스트레이터 몫이므로 프롬프트 1단계는 **진입과 기점 검증**만 한다.

공통으로 모든 프롬프트 본문에 들어가는 금지 문장(각 프롬프트에 실제로 풀어 쓴다):

- 허용 Files 밖 파일 수정 금지. 특히 다른 오너의 패키지, `packages/core/src/types.ts` 의
  `McpClient`·`ToolResult`, 루트 빌드 설정(`package.json`, `pnpm-workspace.yaml`, `turbo.json`,
  `tsconfig.base.json`), `fixtures/`. 맞지 않으면 고치지 말고 보고.
- `@modelcontextprotocol/sdk` 버전 변경 금지, 목록 밖 의존성 추가 금지.
- 의존 방향 단방향(`cli` → `runner` → `core`), 역참조·순환 금지.
- 커밋, 머지, 푸시, 백그라운드 실행, 하위 에이전트 스폰, 다른 작업자의 변경 되돌리기 금지.
- 유닛테스트는 인메모리와 `fixtures/` 만. `examples/` 서버 프로세스를 띄우지 않는다.
- 문안은 설계 표를 글자 그대로 옮긴다. 표가 코드와 안 맞아 판단이 필요하면 `BLOCKED`.

보낸 프롬프트 원문은 전송 시점에 이 절 아래에 덧붙여 남긴다.
