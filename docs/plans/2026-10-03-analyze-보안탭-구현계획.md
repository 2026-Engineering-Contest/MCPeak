## 1. 목표, 비범위, 완료 조건

### 1.1 목표

- Analyze 의 **보안** 탭이 "준비 중" 자리를 벗고 `mcpeak audit` 의 결과를 보인다.
- 판정은 CLI 와 **같은 함수가 한다**(ADR-0046). 대시보드는 `runAuditCommand` 를 `--json` 으로 돌려 stdout
  바이트를 메모리로 받는다. 규칙·정렬·종료 코드를 대시보드에서 다시 쓰지 않는다.
- 화면에 나오는 위치 문장("도구 'x' 의 description")과 격리 상태 문장("행위 관측 안 함: ...")은
  `@mcpeak/audit` 가 만든 글자다. 웹이 같은 문장을 손으로 복제하지 않는다.
- 점검은 run 으로 돈다. 격리 실행은 이미지를 처음 만들 때 수 분이 걸리므로 진행 문장을 기존
  run-registry 와 SSE 로 흘린다. 격리 없는 점검도 같은 길을 탄다(화면의 상태 기계가 하나다).
- 토큰 탭에서 고른 서버가 보안 탭으로 넘어와도 남는다(로드맵 §0 "서버 접속은 한 번").

### 1.2 비범위

- `--sandbox-session`·`--sandbox-replay`(녹화·재생)와 `--sandbox-mount`. 경로 인자가 셋 더 늘고 각각 경로
  가드가 필요하다. 화면은 격리 켜기, `--compare-host`, `--allow-host` 만 낸다. 마운트 범위는 CLI 의 기본
  규칙(대시보드 루트와 서버 인자에서 구한다)을 따른다.
- 지속 감시(매 세션 `--baseline` 자동 비교). 로드맵이 단계 3 이후로 둔 것이다.
- 격리 실행 자체의 한계를 고치는 것. PR #497 이 적은 것 둘이 화면에도 그대로 온다. 이 계획은 고치지
  않고 **화면이 말하게만** 한다(§5.7 의 격리 힌트, §1.5).
- `supply` 가족. 아직 구현이 없다.
- 점검 run 을 Runs 목록에 싣는 것(§3 결정).
- 발견을 화면에서 무시·승인 처리하는 것.

### 1.3 완료 조건 (전부 검증 가능해야 한다)

1. `examples/audit-target-server` 를 대상으로 `GET /api/analyze/security/<runId>` 의 `reportText` 가, 같은
   대상에 `runAuditCommand(["--json", ...])` 를 직접 돌린 stdout 과 **바이트 단위로 같다**. 따라서
   `report.findings` 의 순서도 같다(로드맵 완료 조건 "순서 포함").
2. 같은 요청으로 점검을 두 번 돌린 결과 응답 본문이 바이트 단위로 같다(결정론).
3. 응답의 `rendered` 가 `renderReport(report)` 와 글자 단위로 같고, 화면은 이것을 "CLI 리포트 원문" 구획에
   그대로 보인다.
4. 화면의 심각도별 목록은 심각, 주의, 낮음, 정보 순의 구획이고 구획 안의 순서는 `report.findings` 의
   순서다. `flow/` 발견은 결함 목록에 섞이지 않고 별도 구획에 나온다.
5. PATH 에 `docker` 가 없는 환경에서 격리를 켜고 점검하면 응답의 `sandboxLine` 이
   `행위 관측 안 함: Docker 를 찾을 수 없습니다. 서버는 격리 없이 이 머신에서 실행됐습니다. (설치: https://docs.docker.com/get-docker/)`
   이고 화면이 그 문장을 `role="alert"` 로 보인다(로드맵 완료 조건).
6. 기준 파일은 프로젝트 루트 아래 `.json` 경로에만 쓰이고, `updateBaseline` 은 기준 파일이 아닌 파일을
   덮어쓰지 않는다.
7. CLI 가 리포트 없이 끝나면(연결 실패, 사용법 오류) 화면에 CLI 의 stderr 문장이 **그대로** 보인다.
8. Docker 가 있는 러너에서 `examples/sandbox-target-server` 를 격리로 점검한 `{exitCode, counts, findings}`
   가 `examples/sandbox-target-server/server.sandbox.expected.json` 과 같고, SSE 로 진행 문장이 흐르며,
   끝난 뒤 `mcpeak.audit=1` 라벨의 컨테이너·네트워크·볼륨이 0 이다.
9. `pnpm test`, `pnpm build --force`, `pnpm typecheck --force`, `pnpm lint` 녹색. `Cached: 0 cached`.
10. `packages/dashboard/tests/dependency-boundary.test.ts` 가 `dashboard` 의 `@mcpeak/audit` 의존을 허용
    목록과 실제 import 양쪽에서 확인한다.

## 3. 결정 사항 (다르게 갈 수도 있었던 것)

| 항목 | 결정 | 대안과 버린 이유 |
|---|---|---|
| 실행 방식 | **run 으로 돈다.** `POST /api/analyze/security` 가 `{ runId }` 를 바로 돌려주고, 진행은 기존 `GET /api/runs/<id>/events`(SSE), 결과는 `GET /api/analyze/security/<id>` 로 받는다. 격리 없는 점검도 같은 길이다 | 토큰 탭처럼 동기 `POST`. 격리 이미지를 처음 만들 때 수 분 동안 화면이 멈춘 것처럼 보인다. 격리만 run 으로 가르면 화면이 상태 기계를 둘 가진다 |
| run 의 종류 | `RunSummary.flow` 를 `RunFlow = StartRunRequest["flow"] \| "audit"` 로 넓힌다. `StartRunRequest` 에는 넣지 않는다. `POST /api/runs` 로는 점검을 시작할 수 없다 | `StartRunRequest` 에 `audit` 을 넣는 것. 브라우저가 보낸 argv 가 `--baseline <경로>` 를 그대로 싣게 돼 경로 가드를 `wiring.ts` 안에서 다시 해야 하고, 결과를 맡길 자리가 `RunIo` 에 없다 |
| Runs 목록 | `GET /api/runs` 는 `flow === "audit"` 을 **싣지 않는다** | 싣는 것. `RunView` 는 터미널 출력이 주인공인 화면이라 점검 run 을 열면 진행 문장 몇 줄만 보이고 결과가 없다. 토큰 분석도 이력에 남지 않는다. 주소를 손으로 쳐서 연 경우만 대비해 제목과 집계 칸 조건만 맞춘다(§5.4) |
| 결과의 자리 | 라우트 모듈의 `WeakMap<RunHandle, SecuritySlot>`. run 과 수명이 같다 | `RunRegistry` 에 결과 필드를 더하는 것. 레지스트리가 flow 별 결과 타입을 알게 된다 |
| 리포트 바이트의 출처 | `runAuditCommand` 를 `--json` 으로 돌리고 `writeStdout` 을 **메모리 캡처**로 바꿔 끼운다 | 대시보드가 `audit()` 를 직접 부르고 `JSON.stringify(report, null, 2)` 를 다시 적는 것. 대상 해석·사전 점검·마운트 범위·정리 실패 처리가 두 곳이 된다 |
| 의존성 조립 | `@mcpeak/cli/commands` 가 `nodeAuditDependencies` 를 내보내고, 대시보드는 그것을 펼친 뒤 **다섯 자리만** 바꾼다(`readEnv`, `readFile`, `writeFile`, `writeStdout`·`writeStderr`, `sandbox.cwd`) | 토큰 탭처럼 항목 단위로 다시 적는 것. audit 의 의존성은 열다섯 개이고 Docker IO(`nodeDockerIo`)까지 있어, 다시 적으면 한쪽만 고쳐지는 날이 온다 |
| 위치·격리 문장 | `@mcpeak/audit` 가 `describeLocation`·`escapeInvisible` 을 내보내고 **서버가** 발견마다 `where`·`tool` 을 만들어 응답에 싣는다. 격리 상태 줄과 한계 문장은 `renderReport` 출력에서 줄 위치로 꺼낸다 | 웹이 `describeLocation` 과 숨은 문자 표를 복제하는 것. 숨은 문자 표가 어긋나면 `get<U+200B>time` 이 화면에서 `gettime` 으로 보인다. 웹이 `@mcpeak/audit` 를 값으로 import 하면 번들에 서버 코드가 섞인다 |
| 기준 파일 경로 | 요청의 `baselinePath`(루트 기준 상대경로) 한 필드로 받고 서버가 `resolveProjectPath` 로 가둔다. CLI 에는 **상대경로 그대로** 넘기고 `readFile`·`writeFile` 이 루트 기준으로 푼다 | 절대경로로 바꿔 넘기는 것. `surface/baseline-created` 의 문장과 근거에 절대경로가 실려 리포트가 머신마다 달라진다 |
| `updateBaseline` 가드 | 대상 파일이 있으면 `parseBaseline` 을 통과해야만 시작한다 | CLI 와 같이 그냥 쓰는 것. CLI 는 사용자가 터미널에서 경로를 직접 친 것이지만 화면은 한 번의 클릭이고, `package.json` 을 적으면 덮어쓴다 |
| 접속 상태 공유 | `TokensPanel` 안의 접속 상태를 `useAnalyzeTarget` 훅으로 옮기고 `AnalyzeView` 가 한 번 부른다. 두 탭은 같은 `AnalyzeView` 인스턴스라 탭을 오가도 남는다 | 보안 패널이 상태를 따로 갖는 것. 같은 서버를 탭마다 다시 골라야 한다 |

ADR 초안 한 건을 T2 가 쓴다: `docs/adr/0109-보안-탭의-점검은-run-으로-돌리고-화면-문장은-audit-가-만든다.md`.
위 표의 첫 네 줄과 "위치·격리 문장" 줄이 내용이다. 번호는 작성 시점의 다음 번호이고, 오케스트레이터가
머지 직전에 `ls docs/adr | tail -3` 으로 다시 확인한다(실행 규약 "머지 직전 재확인").

## 4. 공유 계약 (전량. 여러 태스크가 동시에 의존한다)

### 4.1 `@mcpeak/audit` 공개 면에 더하는 것 (T0)

`packages/audit/src/report.ts`: `function describeLocation` 앞에 `export` 를 붙인다. 본문과 주석은 그대로다.

`packages/audit/src/index.ts`: 두 줄을 바꾼다.

```ts
export { describeLocation, renderReport } from "./report.js";
export { DESC_RULES, escapeInvisible, runDescRules } from "./rules/description.js";
```

다른 export 는 건드리지 않는다. `types.ts` 는 건드리지 않는다.

### 4.2 `packages/cli/src/commands.ts` 에 더하는 것 (T1)

```ts
export {
  type AuditCommandDependencies,
  type AuditCommandInput,
  parseAuditCommand,
  runAuditCommand,
} from "./audit-command.js";
```

```ts
export { nodeAuditDependencies } from "./index.js";
```

첫 블록은 `auto-review-io` 블록 앞, 둘째 줄은 `generate-command` 블록과 `optimize-command` 블록 사이에 둔다
(모듈 경로 순). `pnpm lint` 가 다른 순서를 요구하면 그 순서를 따른다. `index.ts` 는 import 만으로는 아무것도
실행하지 않는다(진입점은 `cli.ts` 다). `index.ts` 가 `commands.ts` 를 import 하지 않으므로 순환이 없다.
함수 본문은 건드리지 않는다.

### 4.3 `packages/dashboard/src/api-types.ts` 에 더하는 것 (T2)

```ts
import type { AuditReport, ProbePolicy } from "@mcpeak/audit";

/**
 * run 의 종류. `audit` 는 보안 탭이 `POST /api/analyze/security` 로 시작하는 점검이다.
 * `POST /api/runs` 로는 시작할 수 없고 `GET /api/runs` 목록에도 실리지 않는다(ADR-0109).
 */
export type RunFlow = StartRunRequest["flow"] | "audit";
```

`RunSummary.flow` 의 타입을 `RunFlow` 로 바꾼다. 주석은 그대로 둔다.

```ts
/**
 * POST /api/analyze/security. 보안 점검을 run 으로 시작한다. 판정은 `mcpeak audit --json` 과 같은
 * 함수(`runAuditCommand`)가 한다(ADR-0046).
 *
 * `argv` 는 `AnalyzeTokensRequest.argv` 와 같은 배열이다. **대상 옵션과 그 값만** 싣는다. 점검 옵션은
 * 아래 필드로 보낸다. 서버가 경로를 가둔 뒤 CLI argv 로 조립한다.
 */
export interface AnalyzeSecurityRequest {
  readonly argv: readonly string[];
  readonly serverId?: string;
  /** 없으면 CLI 기본값이다(격리가 실제로 켜지면 `all`, 아니면 `readonly`. ADR-0107). */
  readonly probe?: ProbePolicy;
  /** 프로젝트 루트 기준 상대경로(`.json`). 없으면 도구 표면 비교를 건너뛴다. */
  readonly baselinePath?: string;
  readonly updateBaseline?: boolean;
  /** 있으면 `--sandbox` 다. */
  readonly sandbox?: {
    readonly compareHost: boolean;
    /** `--allow-host` 값. 준 순서 그대로다. */
    readonly allowHosts: readonly string[];
  };
}

/** 발견 하나의 표시용 글자. `report.findings` 와 같은 순서·같은 길이로 온다. */
export interface SecurityFindingView {
  /** `describeLocation(finding.location)`. CLI 리포트의 위치와 같은 글자다. */
  readonly where: string;
  /** 도구에 걸린 발견이면 `escapeInvisible(toolName)`, 아니면 null. 도구별 묶음의 제목이다. */
  readonly tool: string | null;
  /** 도구에 걸린 발견이면 그 `toolIndex`, 아니면 -1(CLI 정렬과 같은 값). */
  readonly toolIndex: number;
}

/** GET /api/analyze/security/<runId>. 시각·난수·runId 를 싣지 않는다. */
export interface AnalyzeSecurityResponse {
  /** `reportText` 를 `JSON.parse` 한 값. */
  readonly report: AuditReport;
  /** `mcpeak audit --json` 이 stdout 에 내는 바이트 그대로(2칸 들여쓰기, 끝 개행). */
  readonly reportText: string;
  /** `renderReport(report)`. CLI 의 사람용 리포트와 같은 함수가 만든다. */
  readonly rendered: string;
  readonly views: readonly SecurityFindingView[];
  /** `report.sandbox` 가 있으면 `rendered` 의 둘째 줄(격리 실행 줄 또는 "행위 관측 안 함" 줄), 없으면 null. */
  readonly sandboxLine: string | null;
  /** `rendered` 의 마지막 빈 줄 뒤의 줄들(이 점검의 한계). */
  readonly limits: readonly string[];
  /** CLI 종료 코드. 0 은 발견 없음, 2 는 발견 있음, 1 은 리포트를 낸 뒤 격리 자원 정리에 실패한 경우다. */
  readonly exitCode: number;
  /** 리포트를 낸 **뒤에** CLI 가 stderr 에 쓴 글자(정리 실패 문장). 끝 개행은 뗀다. 없으면 "". */
  readonly cleanupError: string;
}
```

`POST` 의 성공 응답은 기존 `StartRunResponse`(`{ runId }`)다. 실패는 기존 `ApiError` 다.

### 4.4 HTTP 면 (T2 가 만들고 T3·T4 가 쓴다)

| 메서드·경로 | 성공 | 실패 |
|---|---|---|
| `POST /api/analyze/security` | `200` `StartRunResponse` | `400 { error }`. 아래 표 |
| `GET /api/analyze/security/<runId>` | `200` `AnalyzeSecurityResponse` | `404`, `409`, `400`. 아래 표 |
| `GET /api/runs/<runId>/events` | 기존 SSE. stderr 이벤트가 진행 문장이다 | 기존 그대로 |
| `GET /api/runs` | 기존 목록에서 `flow === "audit"` 을 뺀 것 | 기존 그대로 |

`POST` 의 `400` 문장. 위에서부터 먼저 걸리는 것 하나만 낸다.

| 조건 | `error` |
|---|---|
| 본문이 JSON 이 아님 | `본문이 올바른 JSON이 아닙니다.` |
| 필드 형식이 틀림(§5.4 `isAnalyzeSecurityRequest`) | `요청 형식이 올바르지 않습니다.` |
| 모르는 `serverId` | `` `서버 후보를 찾을 수 없습니다: ${serverId}` `` |
| `argv` 에 대상 옵션과 그 값이 아닌 토큰 | `` `오류 [ANALYZE_USAGE]: argv 에는 대상 옵션(--command, --arg, --env, --url, --header-env)과 그 값만 실을 수 있습니다: '${token}'\n해결: 점검 옵션은 요청의 probe·baselinePath·updateBaseline·sandbox 필드로 보내세요.` `` |
| `baselinePath` 가 루트 밖 | `허용되지 않는 경로입니다.` (기존 문장) |
| `baselinePath` 가 `.json` 으로 끝나지 않음 | `기준 파일은 .json 확장자 파일만 쓸 수 있습니다.` |
| `updateBaseline` 인데 그 파일을 읽지 못함(ENOENT 제외) | `` `기준 파일을 읽지 못했습니다: ${baselinePath}` `` |
| `updateBaseline` 인데 그 파일이 기준 파일이 아님 | `` `기준 파일이 아닌 파일은 덮어쓰지 않습니다: ${baselinePath}\n→ 기준 파일 갱신은 이전에 mcpeak audit 가 만든 기준 파일만 바꿉니다. 다른 경로를 쓰세요.` `` |

그 밖의 사용법 오류(`updateBaseline` 만 있고 `baselinePath` 없음, `sandbox` 와 `--url` 병용, 호스트 이름이
아닌 `allowHosts`)는 서버가 미리 막지 않는다. CLI 가 자기 문장으로 거절하고 그 문장이 결과의 `error` 로 온다.
화면은 이 조합을 애초에 보내지 않는다(§5.5).

`GET /api/analyze/security/<runId>` 의 실패.

| 상태 | 조건 | `error` |
|---|---|---|
| `404` | run 이 없거나 점검 run 이 아님 | `그런 점검이 없습니다.\n→ 대시보드는 점검 결과를 메모리에만 둡니다. 서버를 다시 시작했다면 다시 점검하세요.` |
| `409` | 아직 끝나지 않음 | `점검이 아직 끝나지 않았습니다.` |
| `400` | CLI 가 리포트 없이 끝남 | CLI stderr 누적 그대로(끝 개행만 제거). 진행 문장이 앞에 있으면 그것도 함께다 |

### 5.2 `prepareSecurityRun` 본문 규칙 (판단이 있는 곳이라 전량)

```ts
const TARGET_VALUE_OPTIONS = new Set(["--command", "--arg", "--env", "--url", "--header-env"]);

export async function prepareSecurityRun(root, request, overrides = {}) {
  // 1. argv 는 (대상 옵션, 값) 쌍의 나열이어야 한다. 값은 `--` 로 시작해도 값이다(`--arg --port`).
  //    쌍이 아닌 토큰을 통과시키면 `--baseline`·`--json`·`--sandbox-mount` 가 가드 없이 CLI 에 닿는다.
  for (let index = 0; index < request.argv.length; index += 2) {
    const token = request.argv[index] as string;
    if (!TARGET_VALUE_OPTIONS.has(token) || index + 1 >= request.argv.length)
      return { ok: false, error: usage(token) };   // §4.4 의 ANALYZE_USAGE 문장
  }
  // 2. 기준 파일 경로를 가둔다.
  const baselinePath = request.baselinePath;
  if (baselinePath !== undefined) {
    const absolute = resolveProjectPath(root, baselinePath);
    if (absolute === null) return { ok: false, error: "허용되지 않는 경로입니다." };
    if (!baselinePath.endsWith(".json"))
      return { ok: false, error: "기준 파일은 .json 확장자 파일만 쓸 수 있습니다." };
    if (request.updateBaseline === true) {
      let text: string | undefined;
      try {
        text = await readFile(absolute, "utf8");
      } catch (error) {
        if (!isMissing(error))   // code === "ENOENT" 만 없는 파일로 본다
          return { ok: false, error: `기준 파일을 읽지 못했습니다: ${baselinePath}` };
      }
      if (text !== undefined) {
        const audit = await loaders.loadAudit();
        try {
          audit.parseBaseline(text);
        } catch {
          return { ok: false, error: /* §4.4 의 두 줄 문장 */ };
        }
      }
    }
  }
  // 3. 조립. 순서를 고정한다. 같은 요청이면 항상 같은 배열이다.
  const argv: string[] = [];
  if (request.probe !== undefined) argv.push("--probe", request.probe);
  if (baselinePath !== undefined) argv.push("--baseline", baselinePath);
  if (request.updateBaseline === true) argv.push("--update-baseline");
  if (request.sandbox !== undefined) {
    argv.push("--sandbox");
    if (request.sandbox.compareHost) argv.push("--compare-host");
    for (const host of request.sandbox.allowHosts) argv.push("--allow-host", host);
  }
  argv.push("--json", ...request.argv);
  return { ok: true, argv };
}
```

- `resolveProjectPath` 는 `./paths.js` 의 기존 함수다. 고치지 않는다.
- `loadAudit` 가 던지면 §5.3 의 `ANALYZE_RUNTIME_UNAVAILABLE` 문장을 `error` 로 돌려준다.
- `--baseline` 값은 **상대경로 그대로**다(§3).

### 5.3 `analyzeSecurity` 본문 규칙 (판단이 있는 곳이라 전량)

```ts
export async function analyzeSecurity(argv, io, context, overrides = {}) {
  const runner = overrides.runner ?? runAuditCommand;
  const loaders = { ...defaultLoaders, ...overrides.loaders };
  const fail = (error: string) => {
    io.writeStderr(`${error}\n`);
    return { exitCode: 1, outcome: { ok: false as const, error } };
  };

  let core; let audit;
  try {
    [core, audit] = await Promise.all([loaders.loadCore(), loaders.loadAudit()]);
  } catch {
    return fail(
      "오류 [ANALYZE_RUNTIME_UNAVAILABLE]: 점검에 필요한 @mcpeak/core·@mcpeak/audit 를 로드하지 못했습니다.\n해결: 의존성을 설치한 뒤 다시 실행하세요.",
    );
  }

  // CLI 의 조립을 그대로 쓰고 다섯 자리만 바꾼다.
  const base = nodeAuditDependencies(core, audit);
  let stdout = "";
  let stderrBefore = "";   // 리포트가 나오기 전의 stderr: 진행 문장과 실패 문장
  let stderrAfter = "";    // 리포트가 나온 뒤의 stderr: 격리 자원 정리 실패 문장
  const deps = {
    ...base,
    readEnv: (name: string) => overrides.candidateEnv?.[name] ?? process.env[name],
    // 기준 파일은 상대경로로 온다. 대시보드 루트 기준으로 푼다. 절대경로(격리의 선언 출처)는 그대로다.
    readFile: (path: string) => readFile(resolve(context.root, path), "utf8"),
    writeFile: (path: string, text: string) => writeFile(resolve(context.root, path), text, "utf8"),
    writeStdout: (text: string) => { stdout += text; },
    writeStderr: (text: string) => {
      if (stdout === "") stderrBefore += text; else stderrAfter += text;
      io.writeStderr(text);
    },
    // 서버 인자의 상대 경로와 마운트 범위는 대시보드 루트를 기준으로 푼다. process.cwd() 가 아니다.
    sandbox: { ...base.sandbox, cwd: context.root },
  };

  let exitCode: number;
  try {
    exitCode = await runner(argv, deps);
  } catch (error) {
    return fail(
      `오류 [ANALYZE_FAILED]: 점검이 예기치 않게 끝났습니다: ${firstLine(error)}\n해결: 같은 서버에 mcpeak audit 를 터미널에서 직접 돌려 같은 오류가 나는지 확인하세요.`,
    );
  }
  if (stdout === "") {
    return { exitCode, outcome: { ok: false, error: stderrBefore.replace(/\n+$/, "") } };
  }

  let report: AuditReport;
  try {
    report = JSON.parse(stdout) as AuditReport;
  } catch (error) {
    return fail(
      `오류 [ANALYZE_FAILED]: 점검 결과를 읽지 못했습니다: ${firstLine(error)}\n해결: 같은 서버에 mcpeak audit --json 을 터미널에서 직접 돌려 출력이 JSON 인지 확인하세요.`,
    );
  }
  const rendered = audit.renderReport(report);
  // renderReport 는 "\n" 으로 끝난다. 끝 개행을 떼고 줄로 나눈다.
  const lines = rendered.replace(/\n$/, "").split("\n");
  return {
    exitCode,
    outcome: {
      ok: true,
      body: {
        report,
        reportText: stdout,
        rendered,
        views: report.findings.map((finding) => ({
          where: audit.describeLocation(finding.location),
          tool: "toolName" in finding.location ? audit.escapeInvisible(finding.location.toolName) : null,
          toolIndex: "toolIndex" in finding.location ? finding.location.toolIndex : -1,
        })),
        // 첫 줄은 제목이고, sandbox 가 있으면 둘째 줄이 그 상태다(report.ts renderReport).
        sandboxLine: report.sandbox === undefined ? null : (lines[1] ?? null),
        limits: lines.slice(lines.lastIndexOf("") + 1),
        exitCode,
        cleanupError: stderrAfter.replace(/\n+$/, ""),
      },
    },
  };
}
```

- `sandboxLine` 과 `limits` 는 `renderReport` 의 줄 배치에 기댄다. 그 배치가 바뀌면 §7.3 의 두 테스트
  ("docker-missing 문장", "한계 두 줄")가 빨개진다. 실제 `renderReport` 를 쓰는 테스트라 조용히 어긋나지 않는다.
- `stderrBefore`·`stderrAfter` 의 구분은 `runAuditCommand` 가 정리 실패 때 "리포트를 먼저 내고 남은 자원을
  말한다" 는 순서(`audit-command.ts` 의 `cleanupFailureReport` 갈래)에 기댄다. §7.3 이 fake runner 로 이 순서를
  고정한다.
- 서버 프로세스의 `process.cwd()` 를 바꾸지 않는다. 동시에 도는 다른 run 이 깨진다.

### 5.4 `routes.ts`·`run-registry.ts` 배선과 웹의 타입 맞춤 (T2)

- `run-registry.ts`: `type Flow = StartRunRequest["flow"]` 를 `type Flow = RunFlow` 로 바꾼다. 그 밖은 그대로다.
- `RouterOptions` 에 둘을 더한다. 기본값은 `analyze-security.ts` 의 실제 함수다.
  ```ts
  readonly prepareSecurity?: typeof prepareSecurityRun;
  readonly analyzeSecurity?: typeof analyzeSecurity;
  ```
- 모듈 수준에 결과 자리를 둔다.
  ```ts
  interface SecuritySlot { outcome?: AnalyzeSecurityOutcome }
  const securitySlots = new WeakMap<RunHandle, SecuritySlot>();
  ```
- `POST /api/analyze/security` 분기를 `POST /api/analyze/source-edits` 분기 뒤, `POST /api/runs` 분기 앞에 둔다.
  `handleAnalyzeSecurity`:
  1. `readJsonBody` → undefined 면 `400`.
  2. `isAnalyzeSecurityRequest`: `argv` 가 문자열 배열, `serverId` 가 없거나 문자열, `probe` 가 없거나
     `"readonly" | "none" | "all"`, `baselinePath` 가 없거나 문자열, `updateBaseline` 이 없거나 boolean,
     `sandbox` 가 없거나 `{ compareHost: boolean, allowHosts: string[] }`. 아니면 `400`.
  3. `serverId` 가 있으면 `resolveCandidateEnv`. undefined 면 `400`.
  4. `const prepared = await prepareSecurity(root, body)`. `ok: false` 면 `400 { error }`.
  5. 시작한다.
     ```ts
     const slot: SecuritySlot = {};
     const handle = registry.start("audit", prepared.argv, async (io) => {
       const result = await analyze(prepared.argv, io, { root },
         candidateEnv === undefined ? undefined : { candidateEnv });
       slot.outcome = result.outcome;
       return result.exitCode;
     });
     securitySlots.set(handle, slot);
     sendJson(response, 200, { runId: handle.runId });
     ```
     `registry.start` 는 `execute` 를 다음 마이크로태스크로 미루므로 `set` 이 항상 먼저다.
- `GET /api/analyze/security/<runId>` 분기를 `GET /api/runs` 분기 앞에 둔다. `registry.get` 이 없거나
  `securitySlots` 에 없으면 `404`, `slot.outcome` 이 undefined 면 `409`, `ok` 면 `200 body`, 아니면
  `400 { error }`.
- `GET /api/runs`: `registry.list().filter((run) => run.flow !== "audit")`.
- 웹의 타입 맞춤(같은 패키지다. `RunSummary.flow` 를 넓히면 이 세 곳이 타입체크에 걸린다).
  - `web/src/components/FlowChip.tsx`: prop 타입을 `RunFlow` 로.
  - `web/src/run-target.ts`: `describeRun` 의 `flow` 매개변수 타입을 `RunFlow` 로. 본문은 그대로다
    (audit argv 의 첫 토큰은 옵션이라 `suite` 가 null 로 나온다).
  - `web/src/screens/RunView.tsx`: `FLOW_TITLES` 에 `audit: "보안 점검"`. `RunCounts` 를 그리는 조건의
    `flow !== "generate" && flow !== "repair"` 에 `&& flow !== "audit"` 를 더한다(점검은 요약 줄을 내지 않는다).

### 5.5 웹: 폼 → 요청 (`web/src/analyze/build-security-request.ts`, T3. 이 파일이 사양이고 테스트가 전량 단언한다)

```ts
import type { AnalyzeSecurityRequest } from "../../../src/api-types.js";
import type { Transport } from "../build-test-argv.js";

export type ProbeChoice = "auto" | "readonly" | "none" | "all";

export interface SecurityForm {
  readonly probe: ProbeChoice;
  readonly baselinePath: string;
  readonly updateBaseline: boolean;
  readonly sandbox: boolean;
  readonly compareHost: boolean;
  readonly allowHosts: readonly string[];
}

export const INITIAL_SECURITY_FORM: SecurityForm = {
  probe: "auto", baselinePath: "", updateBaseline: false,
  sandbox: false, compareHost: false, allowHosts: [],
};

/** CLI `audit-command.ts` 의 HOSTNAME 과 같은 식. 길이 상한 253 도 같다. */
const HOSTNAME = /^[a-z0-9]([a-z0-9-]*[a-z0-9])?(\.[a-z0-9]([a-z0-9-]*[a-z0-9])?)*$/i;

/** 위반 시 한국어 메시지로 throw. 버튼 비활성 판정과 제출이 같은 함수를 부른다. */
export function buildSecurityRequest(
  argv: readonly string[],
  serverId: string | undefined,
  transport: Transport,
  form: SecurityForm,
): AnalyzeSecurityRequest {
  const baselinePath = form.baselinePath.trim();
  if (baselinePath !== "" && !baselinePath.endsWith(".json"))
    throw new Error("기준 파일 경로는 .json 으로 끝나야 합니다.");
  // 원격 대상은 격리할 수 없다. 체크가 남아 있어도 싣지 않는다(buildAnalyzeArgv 가 http 에서 args 를 버리는 것과 같다).
  const sandbox = form.sandbox && transport === "stdio";
  if (sandbox) {
    for (const host of form.allowHosts) {
      if (host.length > 253 || !HOSTNAME.test(host))
        throw new Error(`허용 호스트는 호스트 이름이어야 합니다(예: api.example.com): '${host}'`);
    }
  }
  return {
    argv,
    ...(serverId === undefined ? {} : { serverId }),
    ...(form.probe === "auto" ? {} : { probe: form.probe }),
    ...(baselinePath === "" ? {} : { baselinePath }),
    // 경로가 없으면 갱신도 없다. CLI 가 거절하는 조합을 보내지 않는다.
    ...(baselinePath !== "" && form.updateBaseline ? { updateBaseline: true } : {}),
    ...(sandbox ? { sandbox: { compareHost: form.compareHost, allowHosts: [...form.allowHosts] } } : {}),
  };
}
```

### 5.6 웹: 발견 묶음 (`web/src/analyze/security-view.ts`, T3. 판단이 있는 곳이라 전량)

```ts
import type { Finding, Severity } from "@mcpeak/audit";   // 타입만. 값으로 import 하지 않는다.
import type {
  AnalyzeSecurityRequest, AnalyzeSecurityResponse, SecurityFindingView,
} from "../../../src/api-types.js";

export interface FindingRow {
  /** `report.findings` 안의 자리. React key 이자 순서의 근거다. */
  readonly index: number;
  readonly finding: Finding;
  readonly view: SecurityFindingView;
}

/** CLI `report.ts` 의 SEVERITY_ORDER·SEVERITY_LABEL 과 같은 값. */
export const SEVERITIES: readonly { readonly severity: Severity; readonly label: string }[] = [
  { severity: "high", label: "심각" },
  { severity: "medium", label: "주의" },
  { severity: "low", label: "낮음" },
  { severity: "info", label: "정보" },
];

/** flow 는 결함이 아니라 경고다. 한 목록에 섞지 않는다(검사 목록 보강 검토 §6). */
export function splitFindings(response: AnalyzeSecurityResponse): {
  readonly defects: readonly FindingRow[];
  readonly flows: readonly FindingRow[];
} {
  const rows = response.report.findings.map((finding, index) => ({
    index, finding, view: response.views[index] as SecurityFindingView,
  }));
  return {
    defects: rows.filter((row) => !row.finding.ruleId.startsWith("flow/")),
    flows: rows.filter((row) => row.finding.ruleId.startsWith("flow/")),
  };
}

/** 심각도 순의 구획. 빈 구획은 내지 않는다. 구획 안은 rows 의 순서 그대로다(다시 정렬하지 않는다). */
export function bySeverity(rows: readonly FindingRow[]) {
  return SEVERITIES.map(({ severity, label }) => ({
    severity, label, rows: rows.filter((row) => row.finding.severity === severity),
  })).filter((group) => group.rows.length > 0);
}

/** 도구 순의 구획. toolIndex 오름차순이고 -1(도구에 걸리지 않은 것)이 맨 앞이다. 구획 안은 rows 의 순서 그대로다. */
export function byTool(rows: readonly FindingRow[]) {
  const keys = [...new Set(rows.map((row) => row.view.toolIndex))].sort((a, b) => a - b);
  return keys.map((toolIndex) => {
    const group = rows.filter((row) => row.view.toolIndex === toolIndex);
    return {
      toolIndex,
      title: toolIndex === -1 ? "서버 전체 (실행 명령·프로토콜·도구 표면)" : `도구 '${group[0]?.view.tool ?? ""}'`,
      rows: group,
    };
  });
}

/** 기준 파일 상태 한 줄. 경로를 보내지 않았으면 null 이다(그때는 "검사하지 않은 것" 구획이 이유를 말한다). */
export function baselineStatus(
  request: AnalyzeSecurityRequest,
  response: AnalyzeSecurityResponse,
): string | null {
  const path = request.baselinePath;
  if (path === undefined) return null;
  const ids = response.report.findings.map((finding) => finding.ruleId);
  if (ids.includes("surface/baseline-created")) return `기준 파일을 새로 썼습니다: ${path}`;
  const changed = ids.filter((id) => id === "surface/changed").length;
  return changed === 0
    ? `기준 파일과 같습니다: ${path}`
    : `기준 파일과 다릅니다: ${path} (변경 ${changed}건)`;
}
```

## 6. 결정론 규칙

- 결과 응답에 시각·난수·runId 를 넣지 않는다. 같은 서버에 두 번 돌린 결과 본문은 바이트가 같아야 한다(§7.5).
  카나리 난수(`random`)는 출력에 실리지 않는다(`nodeAuditDependencies` 주석).
- `prepareSecurityRun` 의 argv 순서는 고정이다.
- 묶음 함수(§5.6)는 다시 정렬하지 않는다. `filter` 로만 나눈다.
- 화면에 타이머·폴링을 두지 않는다. 완료는 SSE 의 `done` 이벤트로만 안다.

### 7.5 `packages/dashboard/tests/analyze-security-e2e.test.ts` (T4, 새 파일. 직렬 e2e 갈래)

`analyze-e2e.test.ts` 와 같은 방식이다. 서버 둘을 띄운다.

- `plain`: `startDashboardServer({ port: 0, root: <mkdtemp> })`. 격리 없는 스펙이 쓴다.
- `inRepo`: `startDashboardServer({ port: 0, root: repoRoot })`. 격리 스펙 둘이 쓴다. CLI 의
  `audit-sandbox-e2e.test.ts` 가 저장소 루트를 cwd 로 돌리므로 마운트 범위와 경로가 같아진다. 이 서버로는
  기준 파일을 쓰지 않는다(저장소에 파일을 남기지 않는다).

도우미 `check(server, body)`: `POST /api/analyze/security` → `runId`, `/api/runs/<id>/events` 를 읽어 `done`
이벤트까지 모은다(`routes.test.ts` 의 `collectSseEvents` 방식이되 개수가 아니라 `done` 으로 끝낸다),
`GET /api/analyze/security/<id>` 의 `{ status, text, events }` 를 돌려준다.

도우미 `direct(argv)`: `runAuditCommand(["--json", ...argv], { ...nodeAuditDependencies(core, audit), writeStdout: 캡처, writeStderr: 캡처 })`
의 `{ code, stdout }`. `core`·`audit` 는 `@mcpeak/core`·`@mcpeak/audit`, 함수는 `@mcpeak/cli/commands` 에서 import 한다.

CI 에서 이 파일은 두 번 수집된다. `verify` 잡의 `pnpm test` 는 `MCPEAK_SKIP_DOCKER_E2E=1` 이라 Docker 스펙 둘을
건너뛰고 나머지를 돌린다. `e2e` 잡의 `Sandbox E2E (Docker)` 스텝은 지금 cli 의 파일 하나만 이름으로 돌리므로,
그 명령 끝에 이 파일을 더해야 Docker 스펙이 CI 에서 돈다(§8.1 T4, §11-6). 더하지 않으면 Docker 스펙은 어느
잡에서도 실행되지 않고 초록으로 남는다.

Docker 갈래의 skip 과 승격은 `packages/cli/tests/audit-sandbox-e2e.test.ts` 와 **같은 규칙·같은 변수**다
(`MCPEAK_SKIP_DOCKER_E2E=1` 이면 건너뛰고, `MCPEAK_REQUIRE_DOCKER_E2E=1` 이면 Docker 가 없을 때 실패한다.
`docker version` 의 종료 코드로 판정한다). 타임아웃은 격리 없는 스펙 `60_000`, Docker 스펙은 그 파일의
`E2E_TIMEOUT_MS` 와 같은 값.

## 11. 확인이 필요한 결정

1. **점검 run 을 Runs 목록에서 뺀다(§3).** 목록에 실어 "언제 무엇을 점검했는지" 를 남기는 쪽이 맞다고 보면
   `GET /api/runs` 의 filter 한 줄을 빼고, `RunView` 가 점검 run 을 열었을 때 보안 탭으로 보내는 링크를
   더하는 후속이 필요하다.
2. **녹화·재생과 마운트 범위 지정을 화면에서 뺐다(§1.2).** 로드맵 단계 2 의 녹화·재생 재실행은 CLI 로만 쓴다.
3. **화면은 같은 도구·같은 규칙의 발견을 접지 않는다(§5.7).** CLI 는 셋을 넘으면 "같은 도구에서 N곳 더" 로
   접는다. 화면은 스크롤이 있어 전부 보이는 쪽을 골랐다. 접힌 모양은 "CLI 리포트 원문" 에 있다.
4. **`updateBaseline` 가드는 CLI 에 없는 제한이다(§3).** CLI 는 사용자가 준 경로를 그대로 덮어쓴다. 같은
   제한을 CLI 에도 넣을지는 이 계획의 범위 밖이다.
5. **`describeLocation`·`escapeInvisible` 을 `@mcpeak/audit` 공개 면에 올린다(§4.1).** `audit` 는 5인 공동
   경로다. 공개 면이 둘 늘어나는 것에 이견이 있으면 대안은 리포트 JSON 에 표시용 글자를 싣는 것인데,
   그러면 `AUDIT_SCHEMA_VERSION` 과 기대 파일이 전부 움직인다.
6. **`ci.yml` 의 한 줄을 바꾼다(§7.5, T4).** `e2e` 잡의 Docker 스텝이 파일을 이름으로 돌려서, 넣지 않으면
   대시보드의 Docker 스펙이 CI 어디에서도 돌지 않는다. `ci.yml` 은 전원 리뷰 대상이다. 필수 체크 이름은
   바뀌지 않는다. 대가는 `e2e` 잡이 격리 점검을 한 번 더 도는 시간이다(이미지는 같은 러너에 이미 있다).
   **확정(2026-10-04, 사용자 결정): 바꾼다.** 버린 대안은 `ci.yml` 을 건드리지 않고 Docker 스펙을 로컬
   게이트에서만 보는 것이다. 그러면 머지 뒤의 회귀를 CI 가 초록으로 지나친다(검사 대상 0개의 초록).
7. **`npx -y` 제한을 화면 힌트로만 알린다(§1.5).** `.mcp.json` 후보가 `npx` 일 때 격리 체크박스를 아예
   막는 방법도 있다. 로컬에 설치된 패키지를 `npx` 로 띄우는 경우는 뜨므로 막지 않았다.
