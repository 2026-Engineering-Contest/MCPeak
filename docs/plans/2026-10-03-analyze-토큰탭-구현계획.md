# 대시보드 Analyze 토큰 탭 구현 계획 (로드맵 단계 3a, 2026-10-03)

## 문서 지위

`docs/2026-10-03-analyze-로드맵.md` 의 **단계 3a(토큰 탭)** 구현 계획이다. 로드맵 §3 이 "단계 3a 는 어느
단계와도 겹치지 않아 단계 1 과 병렬로 시작할 수 있다" 고 정한 그 자리다. 기준 커밋은 `main` 의 HEAD(작성
시점 `b318d63`)이고, 현재 진행 중인 `feat/audit-T7-cli` 와 파일이 겹치지 않는다(§1.4).

보안 탭(3b)은 이 계획의 범위가 아니다. 이 계획은 Analyze 메뉴의 **틀**(라우트, 접속 폼, 탭, 결과 목록)과
토큰 탭을 세우고, 보안 탭 자리는 "준비 중" 으로 둔다.

## 1. 목표, 비범위, 완료 조건

### 1.1 목표

- 대시보드 사이드바에 `Analyze` 메뉴를 더하고, 그 안에 **토큰** 탭과 **보안** 탭 자리를 둔다.
- 토큰 탭은 서버에 한 번 붙어 `tools/list` 를 읽고 `@mcpeak/optimize` 를 돌린 결과(원본·압축 크기, 변환별
  기여, 도구별 감소 목록)를 보여 준다.
- 숫자와 파일 바이트는 CLI `mcpeak optimize` 와 **같은 함수가 만든다**(ADR-0046 의 "판정 로직을 새로
  쓰지 않는다"). 대시보드는 `runOptimizeCommand` 를 그대로 부르고, `--out` 에 쓸 바이트를 디스크 대신
  메모리로 받는다.
- 오버레이 저장 버튼은 CLI `--out` 과 같은 파일 계약(2칸 들여쓰기 JSON, 끝 개행)으로 프로젝트 루트 아래에
  쓴다.

### 1.2 비범위

- 보안 탭의 내용(단계 3b). 탭 자리와 "준비 중" 안내만 둔다.
- 사용 빈도 기반 토큰 분석(ADR-0102 가 범위 밖으로 둔 것과 같음).
- 오버레이로 프록시를 대시보드에서 띄우는 것. 저장한 파일을 `mcpeak-optimize-proxy` 에 쓰는 안내 한
  줄만 보인다.
- 실행 이력(run-registry)에 분석을 남기는 것. 분석은 수 초 안에 끝나는 동기 요청으로 두고, SSE 와
  run 목록은 쓰지 않는다. 보안 탭의 샌드박스 실행(오래 걸림)이 run-registry 를 쓰는 것은 3b 의 일이다.

### 1.3 완료 조건 (전부 검증 가능해야 한다)

1. `examples/weather-server` 를 대상으로 `POST /api/analyze/tokens` 가 돌려준 `overlayText` 가, 같은
   대상에 `runOptimizeCommand` 를 직접 돌려 `writeFile` 로 받은 텍스트와 **바이트 단위로 같다**
   (`packages/dashboard/tests/analyze-e2e.test.ts`).
2. 같은 요청을 두 번 보낸 응답 본문이 바이트 단위로 같다(결정론).
3. 응답의 `report` 가 `renderReport(overlay)` 와 글자 단위로 같다. 화면은 이 문자열을 그대로 보이는
   구획을 갖는다. 그래서 "토큰 탭 숫자가 CLI 리포트와 같다" 는 로드맵 완료 조건이 구조로 보장된다.
4. 토큰 탭에서 저장한 오버레이 파일의 바이트가 `overlayText` 와 같고, `parseOverlay` 를 통과한다.
5. CLI 가 비정상 종료하면(연결 실패, 사용법 오류, 무손실 위반) 화면에 CLI 의 stderr 문장이 **그대로**
   보인다. 새 문장을 만들지 않는다.
6. `pnpm test`, `pnpm typecheck --force`, `pnpm lint`, `pnpm build --force` 녹색. `Cached: 0 cached`.
7. `packages/dashboard/tests/dependency-boundary.test.ts` 가 `dashboard` 의 `@mcpeak/optimize` 의존을
   허용 목록과 실제 import 양쪽에서 확인한다.

### 1.4 진행 중 작업과의 충돌 확인 (2026-10-03 조사)

| 진행 중 | 고치는 파일 | 이 계획과 겹침 |
|---|---|---|
| `feat/audit-T7-cli` (worktree `mcpeak-audit-T7`) | `packages/cli/src/{index.ts,help.ts,audit-command.ts}`, `packages/cli/package.json`, `packages/cli/tests/{index,audit-command,audit-e2e}.test.ts`, `examples/audit-target-server/`, `pnpm-lock.yaml` | **`pnpm-lock.yaml` 만.** 서로 다른 importer 구역(cli 와 dashboard)이라 자동 병합되고, 충돌 시 늦게 들어가는 쪽이 `pnpm install` 한 번으로 푼다 |

그래서 이 계획은 `packages/cli/src/index.ts` 를 건드리지 않는다. `nodeOptimizeDependencies` 가 거기
있지만 옮기지 않고, 대시보드가 의존성을 직접 조립한다(`wiring.ts` 가 test·generate 에 이미 그렇게 한다.
ADR-0091 이 아래 방향 직접 의존을 허용한다).

## 2. 실행 모델과 모델 배분

구현·테스트는 서브에이전트가 하고, 이 세션은 오케스트레이터(스폰·리뷰·머지 게이트)다. 한 태스크는 한
패키지만 건드린다(팀 `CLAUDE.md`).

| 태스크 | 모델 | 근거 |
|---|---|---|
| T1 `cli` 공개 면 re-export | 표준 | 네 줄 re-export 와 존재 단언 테스트. 판단이 없다 |
| T2 `dashboard` 서버(라우트·분석 실행기·공유 타입) | 표준 | 공유 계약(§4)과 실행기 본문(§5.2)이 전량 적혀 있다. 실패 문장은 CLI 것을 그대로 쓴다 |
| T3 `dashboard` 웹(메뉴·라우트·화면) | 표준 | 폼→argv 변환과 숫자 표기가 §5.4·§5.5 에 전량 있다 |
| T4 `dashboard` E2E(실제 예제 서버, 직렬) | 표준 | 단언이 §7.4 에 전량 있다 |

CLAUDE.local.md 의 상위 모델 예외(실패 문안 설계, 재생 결정론, 목 프로토콜, 패키지 경계 판단)는 이
계획에서 전부 **계획서가 코드로 못 박았다.** 경계 판단은 §1.4·§4.1 에서 끝났고, 실패 문안은 CLI 문장
재사용으로 정했다.

## 3. 결정 사항 (다르게 갈 수도 있었던 것)

| 항목 | 결정 | 대안과 버린 이유 |
|---|---|---|
| 분석 실행 방식 | **동기 `POST`.** 서버 프로세스 안에서 `runOptimizeCommand` 를 끝까지 돌리고 결과를 한 번에 돌려준다 | run-registry + SSE. 토큰 분석은 접속·`tools/list`·순수 변환뿐이라 수 초다. SSE 는 보안 탭 샌드박스(3b)에서 필요할 때 그 틀을 쓴다. 지금 넣으면 화면이 "실행 중" 상태 기계를 하나 더 가진다 |
| 오버레이 바이트의 출처 | `runOptimizeCommand` 의 `writeFile` 을 **메모리 캡처**로 바꿔 끼운다. 디스크에 쓰지 않는다 | 대시보드가 `optimize()` 를 직접 부르고 `JSON.stringify(overlay, null, 2)` 를 다시 적는 것. 직렬화 규칙(들여쓰기·끝 개행·`otherCapabilities` 필터)이 두 곳이 되고, 한쪽이 바뀌면 "CLI 와 같다" 가 조용히 깨진다 |
| 변환별 기여 숫자 | 화면은 `overlay.totals`·`tools[].bytes` 로 요약과 표를 그리고, **변환별 기여는 CLI 리포트 원문 구획**으로 보인다 | `measureContributions` 를 `@mcpeak/optimize` 공개 면에 올리는 것. `optimize` 패키지를 고쳐야 해서 태스크가 하나 늘고, 이 계획이 두 패키지에 걸친다. 필요해지면 별도 제안 |
| 저장 경로 | 프로젝트 루트 기준 상대경로를 `PUT /api/overlays/<path>` 로. 스위트·목 정의와 같은 저장 계약(`handlePutFile`) | 브라우저 다운로드. 바이트는 같지만 프록시 명령이 가리킬 파일이 프로젝트 밖(다운로드 폴더)에 생긴다 |
| 저장 충돌 | `baseMtimeMs: 0` 으로만 PUT 한다. 있는 파일은 `conflict` 로 거절되고 화면이 다른 경로를 권한다 | 덮어쓰기 확인. 분석 결과는 매번 다시 만들 수 있으니 기존 파일을 지우는 쪽이 사용자 책임으로 남는 편이 안전하다 |
| 실패 응답 상태 | CLI 가 0 이 아니면 전부 `400` 이고 본문 `error` 는 stderr 누적 그대로 | 연결 실패를 `502` 로 가르는 것. 화면은 상태 코드를 쓰지 않고 문장만 보이며, CLI 종료 코드도 사유를 가르지 않는다 |
| `api-types.ts` 의 오버레이 타입 | `import type { OptimizeOverlay } from "@mcpeak/optimize"` | `SessionEntry.status` 처럼 다시 적는 것. 오버레이는 필드가 스무 개가 넘어 복제하면 어긋난다. 타입 import 는 번들에 남지 않고, `dashboard` 가 `optimize` 를 어차피 런타임 의존한다 |

ADR 은 내지 않는다. 대시보드가 CLI 커맨드 함수를 재사용하는 결정은 ADR-0046 이고, 아래 방향 직접 의존은
ADR-0091 이다. 이 계획은 둘을 그대로 따른다.

### 4.1 `packages/cli/src/commands.ts` 에 더하는 것 (T1)

### 4.2 `packages/dashboard/src/api-types.ts` 에 더하는 것 (T2)

```ts
import type { OptimizeOverlay } from "@mcpeak/optimize";

/**
 * POST /api/analyze/tokens — 토큰 분석. 서버에 한 번 붙어 tools/list 를 읽고 `@mcpeak/optimize` 를
 * 돌린다. 판정은 `mcpeak optimize` 와 같은 함수(`runOptimizeCommand`)가 한다(ADR-0046).
 *
 * `argv` 는 optimize 의 **대상 옵션만** 싣는다(`--command`/`--arg`/`--env` 또는 `--url`/`--header-env`).
 * `--out`·`--json` 은 싣지 않는다. 오버레이를 어디에 쓸지는 화면의 저장 버튼이 따로 정한다.
 * `serverId` 는 `StartRunRequest` 와 같은 뜻이다. 값은 실리지 않는다(설계 §4.3).
 */
export interface AnalyzeTokensRequest {
  readonly argv: readonly string[];
  readonly serverId?: string;
}

export interface AnalyzeTokensResponse {
  readonly overlay: OptimizeOverlay;
  /**
   * CLI 가 `--out` 파일에 쓰는 바이트 그대로(2칸 들여쓰기, 끝 개행). 저장 버튼이 이것을
   * `PUT /api/overlays/<path>` 로 보낸다. `overlay` 는 이 문자열을 `JSON.parse` 한 값이다.
   */
  readonly overlayText: string;
  /** `mcpeak optimize` 가 stdout 에 내는 사람용 리포트 원문(`renderReport`). */
  readonly report: string;
}
```

실패는 기존 `ApiError`(`{ error: string }`)다. 새 타입을 만들지 않는다.

### 4.3 HTTP 면 (T2 가 만들고 T3·T4 가 쓴다)

| 메서드·경로 | 요청 | 성공 | 실패 |
|---|---|---|---|
| `POST /api/analyze/tokens` | `AnalyzeTokensRequest` | `200` `AnalyzeTokensResponse` | `400 { error }`. 본문이 JSON 이 아니면 `"본문이 올바른 JSON이 아닙니다."`, 형식이 틀리면 `"argv 형식이 올바르지 않습니다."`, 후보가 없으면 `` `서버 후보를 찾을 수 없습니다: ${serverId}` ``, CLI 가 0 이 아니면 **stderr 누적 그대로**(끝 개행만 제거) |
| `PUT /api/overlays/<상대경로>` | `PutFileRequest` | `200` `PutFileResponse` | `handlePutFile` 의 기존 문장. 확장자 문장만 `"오버레이는 .json 확장자 파일만 저장할 수 있습니다."`, 내용 검증 실패는 `parseOverlay(parsed, relative)` 가 던진 `OptimizeError.message` 그대로, JSON 파싱 실패는 `"본문 content가 올바른 JSON이 아닙니다."` |

## 5. 구현 사양

### 5.1 `packages/dashboard/src/server/analyze.ts` 공개 시그니처 (T2)

```ts
import type { runOptimizeCommand } from "@mcpeak/cli/commands";
import type { AnalyzeTokensResponse } from "../api-types.js";

export interface AnalyzeModuleLoaders {
  readonly loadCore: () => Promise<typeof import("@mcpeak/core")>;
  readonly loadOptimize: () => Promise<typeof import("@mcpeak/optimize")>;
}

export interface AnalyzeTokensOverrides {
  /** 기본값은 `@mcpeak/cli/commands` 의 `runOptimizeCommand`. 테스트가 fake 로 바꾼다. */
  readonly runner?: typeof runOptimizeCommand;
  readonly loaders?: Partial<AnalyzeModuleLoaders>;
  /** `routes.ts` 가 `resolveCandidateEnv` 로 만든 후보 env. `wiring.ts` 의 같은 필드와 같은 뜻. */
  readonly candidateEnv?: Readonly<Record<string, string>>;
}

export type AnalyzeTokensOutcome =
  | { readonly ok: true; readonly body: AnalyzeTokensResponse }
  | { readonly ok: false; readonly error: string };

export async function analyzeTokens(
  argv: readonly string[],
  overrides?: AnalyzeTokensOverrides,
): Promise<AnalyzeTokensOutcome>;
```

### 5.2 `analyzeTokens` 본문 규칙 (판단이 있는 곳이라 전량)

```ts
/** `parseOptimizeCommand` 가 `--out` 을 요구해 채우는 자리. 디스크에는 쓰지 않는다(`writeFile` 이 가로챈다). */
const OUT_PLACEHOLDER = "overlay.json";

export async function analyzeTokens(argv, overrides = {}) {
  // 1. 화면이 보낼 수 없는 옵션. 통과시키면 CLI 가 "`--out`은 한 번만" 이라는 엉뚱한 문장으로 거절한다.
  if (argv.some((token) => token === "--out" || token.startsWith("--out=") || token === "--json")) {
    return {
      ok: false,
      error:
        "오류 [ANALYZE_USAGE]: argv 에 `--out`·`--json` 을 실을 수 없습니다. 저장 위치는 화면의 저장 버튼이 정합니다.",
    };
  }
  // 2. 모듈 로드. wiring.ts 의 executeRepair 와 같은 꼴.
  let core; let optimize;
  try {
    [core, optimize] = await Promise.all([loaders.loadCore(), loaders.loadOptimize()]);
  } catch {
    return {
      ok: false,
      error:
        "오류 [ANALYZE_RUNTIME_UNAVAILABLE]: 분석에 필요한 @mcpeak/core·@mcpeak/optimize 를 로드하지 못했습니다.\n해결: 의존성을 설치한 뒤 다시 실행하세요.",
    };
  }
  // 3. 의존성 조립. cli 의 nodeOptimizeDependencies 와 항목 단위로 같고, 쓰기 세 자리만 메모리다.
  let overlayText: string | undefined;
  let stdout = "";
  let stderr = "";
  const deps: OptimizeCommandDependencies = {
    connectStdio: core.connectStdio,
    connectHttp: core.connectHttp,
    readEnv: (name) => overrides.candidateEnv?.[name] ?? process.env[name],
    optimize: optimize.optimize,
    renderReport: optimize.renderReport,
    generatorVersion: optimizeMetadata.version,   // import optimizeMetadata from "../../../optimize/package.json"
    writeFile: async (_path, text) => { overlayText = text; },
    writeStdout: (text) => { stdout += text; },
    writeStderr: (text) => { stderr += text; },
  };
  // 4. 실행. `--json` 없이 돌리므로 stdout 은 사람용 리포트다.
  const exitCode = await runner(["--out", OUT_PLACEHOLDER, ...argv], deps);
  if (exitCode !== 0 || overlayText === undefined) {
    return { ok: false, error: stderr.replace(/\n+$/, "") };
  }
  return {
    ok: true,
    body: { overlay: JSON.parse(overlayText) as OptimizeOverlay, overlayText, report: stdout },
  };
}
```

- `generatorVersion` 은 `packages/optimize/package.json` 의 `version` 이다. cli 가 `../../optimize/package.json`
  을 import 하는 것과 같은 방식이고, `tsconfig.base.json` 에 `resolveJsonModule` 이 켜져 있다. 이 값이
  CLI 와 다르면 `overlay.generator.version` 이 달라져 §1.3-1 이 깨진다.
- `readEnv` 는 `wiring.ts` 의 `createReadEnv` 와 같은 규칙(후보 env 가 `process.env` 를 이긴다)이다. 그
  함수는 export 되지 않으므로 여기 한 줄로 다시 적는다. `wiring.ts` 는 고치지 않는다.

### 5.4 웹: 폼 → argv (`web/src/analyze/build-analyze-argv.ts`, T3. 이 파일이 사양이고 테스트가 전량 단언한다)

```ts
import type { Transport } from "../build-test-argv.js";

export interface AnalyzeForm {
  /** 실행 파일 하나. 스크립트 경로는 `args` 선두다(`splitCommand` 계약). */
  readonly command: string;
  readonly args: readonly string[];
  /** 후보의 env 이름. 값은 오지 않는다(설계 §4.3). */
  readonly envNames: readonly string[];
  readonly transport: Transport;
  readonly url: string;
  readonly headerEnvs: readonly string[];
}

/** 위반 시 한국어 메시지로 throw. 버튼 비활성 판정과 제출이 같은 함수를 부른다(buildTestArgv 와 같은 규율). */
export function buildAnalyzeArgv(form: AnalyzeForm): readonly string[] {
  const http = form.transport === "http";
  if (!http && form.command === "") throw new Error("서버를 고르거나 실행 명령을 입력하세요.");
  if (http) {
    if (form.url.trim() === "") throw new Error("URL 을 입력하세요.");
    for (const entry of form.headerEnvs) {
      if (!isHeaderEnv(entry))
        throw new Error(`헤더 환경변수는 <헤더이름>=<환경변수이름> 형식이어야 합니다: '${entry}'`);
    }
    const argv: string[] = ["--url", form.url.trim()];
    for (const entry of form.headerEnvs) argv.push("--header-env", entry);
    return argv;   // `args`·`envNames` 는 싣지 않는다. CLI 가 `--url` 과의 병용을 거절한다.
  }
  const argv: string[] = ["--command", form.command];
  for (const arg of form.args) argv.push("--arg", arg);
  for (const name of form.envNames) argv.push("--env", name);
  return argv;
}
```

문장 세 개는 `buildTestArgv` 의 것과 글자 단위로 같다. 같은 폼이 다른 화면에서 다른 말을 하면 안 된다.

### 5.5 웹: 숫자 표기 (T3. CLI `report.ts` 와 같은 식이어야 한다)

```ts
/** `packages/optimize/src/report.ts` 와 같다. 소수 첫째 자리, 분모 0 이면 "0.0". */
export function percent(reduced: number, base: number): string {
  if (base === 0) return "0.0";
  return (Math.round((reduced / base) * 100 * 10) / 10).toFixed(1);
}
/** 토큰은 바이트÷4 근사(report.ts 와 같다). */
export function tokens(bytes: number): number { return Math.round(bytes / 4); }
```

`web/src/analyze/format.ts` 에 두고 테스트가 `percent(1, 3) === "33.3"`, `percent(0, 0) === "0.0"`,
`percent(-5, 100) === "-5.0"`, `tokens(10) === 3`, `tokens(2) === 1` 을 단언한다. 전체 감소율의
분자는 `totals.bytesBefore - totals.bytesAfterWithInstructions`, 분모는 `totals.bytesBefore` 다(리포트
2번째 크기 줄과 같은 식).

## 6. 결정론 규칙

- 응답 본문에 시각·난수·runId 를 넣지 않는다. 같은 서버에 두 번 보낸 응답은 바이트가 같아야 한다(§7.4).
- 도구별 표의 정렬은 안정 정렬(`Array.prototype.sort`)에 원본 인덱스를 2차 키로 쓴다.
- 화면 상태에 타이머를 두지 않는다. "분석 중" 은 요청 Promise 의 수명과 같다.
