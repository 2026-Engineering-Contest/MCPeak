# Analyze 토큰 탭: 두 단계 화면과 도구별 before/after (2026-10-03)

## 문서 지위

`docs/plans/2026-10-03-analyze-토큰탭-구현계획.md`(T1~T4 통합 완료) 의 후속이다. 사용자 피드백 두 가지를 반영한다.

1. 폼과 결과가 한 줄로 이어져 보기 불편하다. `분석 시작` 을 누르면 다음 단계로 넘어가 거기에 결과가 나와야 한다.
2. 도구 표 오른쪽에 `변경사항` 버튼을 두고, 누르면 그 도구의 before/after 를 보여야 한다.

태스크는 하나(U1)이고 `dashboard` 패키지만 고친다. 기존 완료 조건(overlayText·report 가 CLI 와 바이트 단위로 같음, 응답 결정론)은 그대로 유지한다.

## 1. 결정 사항

| 항목 | 결정 | 버린 대안과 이유 |
|---|---|---|
| before 의 출처 | `analyze.ts` 가 `deps.optimize` 를 감싸 `input.tools`(서버 tools/list 원본)를 받아 두고 응답 `sourceTools` 로 싣는다 | 오버레이에서 역산. `schema-key-removed` 는 지운 키의 값을 남기지 않아 원본을 복원할 수 없다. cli·optimize 를 고치는 것은 패키지가 둘로 늘어난다 |
| 단계 표시 | 기존 `Stepper` 를 `["서버 선택", "결과"]` 로 쓴다 | 새 탭이나 라우트. 결과는 요청 한 번의 산물이라 URL 로 다시 열 수 없다 |
| 비교 표시 | 표 행 아래 펼침(다시 누르면 접힘). 원본·압축 JSON 을 나란히, 그 아래 변경 목록 | 모달. 이 저장소에 대화상자 컴포넌트가 없고, 여러 도구를 열어 두고 비교하기 어렵다 |
| 비교 JSON 의 범위 | `{ name, description, inputSchema }`. 오버레이 바이트 계산(`bytes`)과 같은 세 필드 | `outputSchema` 포함. 게이트 A 가 원본과 같음을 보장하므로 비교할 것이 없다 |

ADR 은 내지 않는다. 응답 필드 하나 추가와 화면 배치다.

## 2. 공유 계약

### 2.1 `packages/dashboard/src/api-types.ts`

```ts
import type { ToolDef } from "@mcpeak/core";

export interface AnalyzeTokensResponse {
  readonly overlay: OptimizeOverlay;
  readonly overlayText: string;
  readonly report: string;
  /**
   * 서버 tools/list 원본. `runOptimizeCommand` 가 `optimize()` 에 넘긴 `input.tools` 그대로다.
   * 화면의 before/after 비교용이며 `overlay.tools` 와 같은 순서·같은 이름이다.
   */
  readonly sourceTools: readonly ToolDef[];
}
```

### 2.2 `packages/dashboard/src/server/analyze.ts`

`deps.optimize` 를 이렇게 바꾼다. 나머지는 그대로다.

```ts
let sourceTools: readonly ToolDef[] | undefined;
optimize: (input, version) => {
  sourceTools = input.tools;
  return optimize.optimize(input, version);
},
```

성공 응답에 `sourceTools: sourceTools ?? []` 를 더한다(`exitCode === 0` 이면 계약상 항상 채워진다. `[]` 는 방어).

## 3. 웹 사양

### 3.1 `web/src/analyze/tool-diff.ts` (새 파일. 테스트가 전량 단언한다)

```ts
import type { ToolDef } from "@mcpeak/core";
import type { AnalyzeTokensResponse } from "../../../src/api-types.js";

type ToolChange = AnalyzeTokensResponse["overlay"]["tools"][number]["changes"][number];

/** 비교에 보일 세 필드. 오버레이 바이트 계산과 같은 범위다. */
export interface ToolSide {
  readonly name: string;
  readonly description?: string;
  readonly inputSchema: unknown;
}

/** 2칸 들여쓰기 JSON. `description` 이 없으면 키를 싣지 않는다. 키 순서는 name, description, inputSchema. */
export function formatToolSide(tool: ToolSide): string;

/** 이름으로 원본을 찾는다. 없으면 undefined(화면은 "원본 정의를 찾지 못했습니다." 를 보인다). */
export function findSourceTool(sourceTools: readonly ToolDef[], name: string): ToolDef | undefined;

/** 변경 하나를 한국어 한 줄로. 아래 표의 문장을 글자 그대로 쓴다. */
export function describeChange(change: ToolChange): string;
```

`describeChange` 문장(`<path>` 등은 값 그대로, 따옴표 포함):

| kind | 문장 |
|---|---|
| `schema-key-removed` | `` `${path}` 에서 '${key}' 키를 지웠습니다. 검증 의미는 같습니다. `` |
| `description-cleaned` | `` `${path}` 설명을 정리했습니다: "${before}" → "${after}" `` |
| `description-removed` | `` `${path}` 설명을 지웠습니다(${REASON}): "${before}" `` |

`REASON`: `restates-name` → `이름을 되풀이함`, `empty` → `비어 있음`, `duplicate-of-tool-description` → `도구 설명과 같음`, `promoted` → `공통 파라미터로 서버 instructions 에 옮김`.

### 3.2 `TokensPanel.tsx`: 두 단계

- 맨 위에 `<Stepper steps={["서버 선택", "결과"]} current={result === null ? 0 : 1} />`.
- 단계 0: 지금의 접속 폼 Card 와 `분석 시작`, 실패 시 `<pre role="alert">`. `result` 가 있으면 그리지 않는다.
- 단계 1: `result !== null` 일 때만. 맨 위에 `Button` `← 서버 다시 고르기`(누르면 `setResult(null)`, 폼 상태는 유지). 그 아래 `<TokensResult result={result} />`.
- 분석 실패는 단계 0 에 머문다. 타이머 없음.

### 3.3 `TokensResult.tsx`: 변경사항 버튼과 펼침

- 표에 여섯째 열 `<th>` 를 더한다. 머리글은 시각적으로 숨긴 `비교`(`sr-only`).
- 각 행 마지막 칸: `changes.length > 0` 이면 `Button` `변경사항`, `aria-expanded`, `aria-controls="analyze-diff-<index>"`. 0 이면 비활성 `Button` `변경 없음`.
- 펼친 상태는 `ReadonlySet<string>`(도구 이름) 하나. 여러 도구를 동시에 펼칠 수 있다.
- 펼친 행 바로 아래 `<tr><td colSpan={6} id="analyze-diff-<index>">`:
  - 두 칸 그리드. 왼쪽 제목 `원본 (${before} 바이트)`, 오른쪽 `압축 (${after} 바이트)`. 각 아래 `<pre>` 에 `formatToolSide`.
  - 그 아래 `<ul aria-label="${name} 변경 목록">` 에 `describeChange` 한 줄씩.
  - 원본을 못 찾으면 왼쪽 `<pre>` 대신 `원본 정의를 찾지 못했습니다.`
- 표의 `key` 는 `tool.name` 대신 정렬 전 인덱스를 쓴다(이름 중복 시 React 경고 방지. T3 남은 위험).

## 4. 테스트

`packages/dashboard/tests/analyze.test.ts` 에 더한다.
- `sourceTools 는 optimize 에 들어간 input.tools 그대로다`: fake runner 가 `deps.optimize({ tools: T, instructions: "", otherCapabilities: [] }, "v")` 를 부르고 writeFile 후 0 → `body.sourceTools === T`(같은 참조).
- `sourceTools 를 받아도 overlayText·report 는 바뀌지 않는다`: 기존 writeFile·writeStdout 단언과 같은 값.

`packages/dashboard/tests/routes.test.ts`, `web/tests/analyze-view.test.tsx`: fake 응답에 `sourceTools` 를 더해 타입을 맞춘다(단언 추가 없음).

`packages/dashboard/tests/analyze-e2e.test.ts` 에 더한다.
- `sourceTools 이름 목록이 overlay.tools 이름 목록과 같다`.

`web/tests/tool-diff.test.ts` (새 파일).
- `formatToolSide` 가 `{ name: "a", inputSchema: { type: "object" } }` 에 `'{\n  "name": "a",\n  "inputSchema": {\n    "type": "object"\n  }\n}'`, description 이 있으면 name 다음에 온다.
- `describeChange` 세 kind 와 네 reason 각각 표의 문장.
- `findSourceTool` 이 이름으로 찾고, 없으면 undefined.

`web/tests/analyze-view.test.tsx` 에 더한다.
- `처음에는 서버 선택 단계다`: `aria-current="step"` 인 단계 이름이 `서버 선택`, 표(`도구별 감소`)가 없다.
- `성공하면 결과 단계로 넘어가 폼이 사라진다`: 단계 `결과`, `분석 시작` 버튼이 없다, 표가 있다.
- `실패하면 서버 선택 단계에 머문다`: 단계 `서버 선택`, alert 가 있다.
- `서버 다시 고르기를 누르면 폼으로 돌아온다`.
- `변경사항을 누르면 원본·압축 JSON 과 변경 목록이 보이고 다시 누르면 사라진다`: 도구 `a` 의 `aria-expanded` 가 true, 원본·압축 `<pre>` 텍스트가 `formatToolSide` 결과와 같다, 변경 목록에 `describeChange` 문장이 있다.
- `변경이 없는 도구는 변경 없음 버튼이 비활성이다`.
- 기존 테스트 중 결과와 폼이 동시에 보인다고 가정한 것은 새 흐름에 맞춰 고친다.
