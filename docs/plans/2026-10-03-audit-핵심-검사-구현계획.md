## 1. 목표, 비범위, 완료 조건

### 1.1 목표

`mcpeak audit <대상>` 이 MCP 서버에 **우리가 띄우고 우리가 끝내는** 연결로 붙어, 사용자 클라이언트
설정을 읽거나 쓰지 않고, 사용자 비밀을 넘기지 않고, 외부로 아무것도 보내지 않은 채 다음 여덟 가족의
검사를 돌려 발견 목록과 리포트를 낸다.

| 가족 | 보는 것 | 근거(검토 문서) |
|---|---|---|
| `desc` | 도구·프롬프트·리소스·instructions 의 **모든 문자열**에 담긴 모델 지시, 숨은 부차 행위, 섀도잉, 교차 출처, 민감 경로, 숨은 유니코드, ANSI, 인코딩 블록, 암묵 트리거 | §3.1 |
| `schema` | 비밀 요구 필드, 유출 통로 필드, 주석 불일치, 파괴 주석 누락, 과도하게 넓은 입력, 비표준 필드 | §4, §3.1 |
| `launch` | 서버 실행 명령줄의 인라인 코드, 파이프 투 셸, 버전 없는 패키지, 원격 코드 출처 | §3.2 |
| `protocol` | 평문 HTTP, 무인증 수락, Origin 검사 부재, OAuth 엔드포인트, 세션 ID 노출, 서버 발신 요청(sampling 등)과 그 안의 지시, 감사 중 목록 변경 | §3.5 |
| `surface` | 도구 표면 해시 기준 파일 생성·비교(러그풀) | §4 |
| `secret` | 가짜 토큰(카나리)을 env 로 심고 응답에서 찾기. 실제로 넘긴 값의 에코 | §4, E |
| `result` | 호출 응답·오류 본문에 담긴 지시·숨은 문자·과대 응답 | §3.6 |
| `flow` | 외부 입력 읽기 + 비공개 데이터 + 외부 쓰기의 조합 경고 | §3.4 |

판정은 정규식, 유니코드 코드포인트 표, 해시 비교, 고정 키워드 표만으로 한다. LLM 과 외부 API 는
쓰지 않는다. 같은 서버에 두 번 돌리면 리포트와 JSON 이 바이트 단위로 같다.

### 1.2 비범위

- Docker 격리와 행위 관측(파일 카나리, `connect()`·`execve()` 기록, 옵션 주입 페이로드). 단계 2.
- `supply` 가족의 비교·레지스트리 조회. 이 단계는 기준 파일에 패키지 이름·버전만 **기록**한다(§3.5).
- 소스 코드 정적 분석, LLM 판정, 클라이언트 설정 파일 자동 탐지, 대시보드 화면.
- 호출 인자의 "정상값" 생성. 이 단계의 호출(§3.7)은 타입별 자리값만 쓴다. `generate` 는 의존하지 않는다
  (둘 다 `core` 위의 형제).
- `core/src/types.ts` 의 `McpClient`·`ToolDef`·`ToolResult`. 건드리지 않는다. 주석·title 은 §5.3 의
  원시 도구 목록으로 읽는다.
- 한국어 설명문 전용 지시 문형. 규칙은 영어 문형이다. 한국어 서버는 유니코드·필드명·주석·해시 규칙만
  실질적으로 적용된다. 한국어 문형은 실측 뒤 별도 결정.

## 3. 검사 규칙 (판단이 있는 곳이므로 전량으로 적는다)

### 3.0 공통

- 발견(`Finding`, §5.1)은 `ruleId`, `severity`(`high`|`medium`|`low`|`info`), `location`(§3.0.1), `message`,
  `fix`, `evidence` 를 갖는다.
- **정렬**: 발견 목록은 `(location.toolIndex ?? -1, ruleId, location.path, evidence 첫 값)` 순으로 정렬한다.
  규칙 실행 순서에 의존하지 않는다(결정론).
- **중복 제거**: 같은 `ruleId`·`location.path`·`evidence[0]` 은 하나만 남긴다.
- **같은 규칙이 한 도구의 여러 위치에서 걸리면** 위치마다 발견 하나다. 리포트가 묶는다(§6).

#### 3.0.1 위치

```
{ kind: "tool", toolIndex, toolName, path }      path 예: "description", "inputSchema.properties.note.description", "annotations"
{ kind: "prompt", name, path }
{ kind: "resource", uri, path }
{ kind: "instructions", path: "" }
{ kind: "launch", path: "args[2]" }
{ kind: "protocol", path: "" }
{ kind: "surface", path: "" }
{ kind: "result", toolIndex, toolName, path }    path 예: "content[0].text", "structuredContent.items[1].title"
{ kind: "server", path: "" }                    flow 처럼 서버 전체에 대한 것
```

#### 3.0.2 문자열 수집기 (`collectStrings`)

`desc` 규칙이 보는 문자열의 전체 집합이다. 원시 도구 객체(§5.3 `listToolsRaw`)를 깊이 제한 없이
걷는다. SDK 가 도구 최상위의 비표준 키는 지우지만 `inputSchema`·`outputSchema` 안의 비표준 키와
`_meta` 는 남긴다는 사실을 전제한다(SDK 1.30 `ToolSchema`: `inputSchema` 는 `catchall(unknown)`).

| 대상 | 수집하는 문자열 | path 표기 |
|---|---|---|
| 도구 | `name`, `title`, `description`, `annotations.title`, `inputSchema`·`outputSchema` 안의 모든 문자열 값(키 이름 포함), `_meta` 안의 모든 문자열 값 | 점 경로. 배열은 `[i]`. 키 이름 자체는 `...properties.<key>` 에 `(key)` 접미 |
| 프롬프트 | `name`, `title`, `description`, `arguments[i].name`, `arguments[i].description` | 같음 |
| 리소스 | `name`, `title`, `description`, `uri`, `mimeType` | 같음 |
| instructions | 전체 | `""` |
| 응답(`result` 가족) | `content[i].text`, `structuredContent` 안의 모든 문자열, `isError` 응답의 모든 문자열 | 같음 |

문자열 값과 **키 이름** 둘 다 수집한다. CyberArk 가 파라미터 이름에서도 주입을 성공시켰다.

### 3.1 텍스트 정규화와 디코딩 (`normalizeText`, T1)

`desc`·`result` 규칙은 아래 단계 결과 **각각**에 대조한다. 어느 단계에서 걸려도 발견이고,
`evidence` 에 어느 단계였는지 적는다(`"raw"`, `"folded"`, `"base64"`, `"hex"`, `"rot13"`).

1. **raw**: 원문. 유니코드·ANSI 규칙(§3.2 의 `hidden-unicode`, `ansi-escape`)은 **raw 에서만** 본다.
   접은 뒤에 보면 지울 대상을 지운 뒤 보는 꼴이다.
2. **folded**: `String.prototype.normalize("NFKC")` → 제로폭·양방향 제어 문자 제거(§3.2 표) →
   혼동 문자 접기(아래 표) → `[_\-]+` 와 연속 공백을 공백 하나로 → 소문자.
3. **base64**: raw 에서 `/[A-Za-z0-9+/]{40,}={0,2}/g` 에 걸리는 토큰마다 디코딩. 디코딩 결과가
   UTF-8 로 유효하고 인쇄 가능 문자 비율이 0.9 이상이면 그 결과를 folded 와 같은 처리로 접어 대조.
4. **hex**: `/(?:[0-9a-f]{2}){20,}/gi` 토큰마다 같은 방식.
5. **rot13**: folded 전체를 ROT13 변환해 대조. 길이 조건 없음(변환이 싸다).

혼동 문자 접기 표(코드포인트 → ASCII). 이 표만 쓴다. 더 넓은 confusables 표는 의존성이 필요하다.

```
U+0430 а→a  U+0435 е→e  U+043E о→o  U+0440 р→p  U+0441 с→c  U+0443 у→y  U+0445 х→x
U+0456 і→i  U+0458 ј→j  U+04BB һ→h  U+0455 ѕ→s  U+0501 ԁ→d  U+051B ԛ→q  U+051D ԝ→w
U+03B1 α→a  U+03BF ο→o  U+03C1 ρ→p  U+03BD ν→v  U+0391 Α→A  U+0392 Β→B  U+0395 Ε→E
U+0397 Η→H  U+0399 Ι→I  U+039A Κ→K  U+039C Μ→M  U+039D Ν→N  U+039F Ο→O  U+03A1 Ρ→P
U+03A4 Τ→T  U+03A5 Υ→Y  U+03A7 Χ→X  U+0410 А→A  U+0412 В→B  U+0421 С→C  U+0415 Е→E
U+041D Н→H  U+041A К→K  U+041C М→M  U+041E О→O  U+0420 Р→P  U+0422 Т→T  U+0425 Х→X
U+FF01..U+FF5E (전각 ASCII) → 대응 ASCII (NFKC 가 처리)
```

### 3.2 `desc` 가족 (T1)

모든 규칙은 §3.0.2 가 모은 문자열 각각에 적용한다. 심각도는 괄호 안.

/\b(hide|conceal) (this|it|that|these instructions?) from (the )?user\b/
/\bsystem ?: ?you are\b/
/\byou are now (in )?(admin|developer|debug|god|unrestricted) mode\b/
/\bbefore (doing|you do) anything else\b/
/\bthis is (very )?(very )?important\b.*\b(read|send|include|call|use|run|execute)\b/
/<\s*(important|instructions?|system|secret|hidden|admin|override)\s*>/

**`desc/implicit-trigger` (medium)**. MCPTox P2·P3. 트리거와 행동 지정이 한 문장에 있을 때만.

```

행동:   /\b(call|invoke|use|run|execute|set|pass|include|append|add|send|forward|replace|override)\b/

```

/\breplace (the|all|any) (function|tool|method)s?\b/

/\b(this tool|this function) (must|should) (always )?be (called|used|invoked) (first|before|instead)\b/
```

**`desc/cross-origin` (info. 같은 문자열이 `desc/shadowing` 또는 `desc/implicit-trigger` 에도 걸리면 medium 으로 승격. 통합 중 결정: 정상 서버가 GitHub·Postgres 를 거론하는 일이 흔해 단독으로는 정보성)**. folded 문자열을 `/[^a-z0-9]+/` 로 토큰화해, 아래 목록 중 **자기 서버
이름(`serverInfo.name` 을 folded 한 것)에 포함되지 않는** 이름이 토큰으로 있으면 발견.

```
whatsapp, slack, discord, telegram, signal, gmail, outlook, github, gitlab, bitbucket, jira, confluence,
notion, linear, asana, trello, gdrive, "google drive", dropbox, onedrive, aws, gcp, azure, stripe, paypal,
supabase, postgres, mysql, mongodb, redis, kubernetes, docker, 1password, lastpass, bitwarden
```

"google drive" 는 두 토큰이 연속일 때. 제외: 그 이름이 `inputSchema` 의 `enum` 값이거나 리소스 `uri` 의
스킴일 때(`slack://` 같은 정당한 참조).

**`desc/sensitive-path` (info 단독, `desc/injection` 또는 `desc/covert-action` 과 같은 문자열에서 함께
걸리면 high 로 승격)**.

```
/~\/\.ssh\b/  /\bid_(rsa|ed25519|ecdsa)\b/  /\.env\b/  /\bmcp\.json\b/  /\.cursor\//  /\.claude\//
/\/etc\/(passwd|shadow)\b/  /\.aws\/credentials\b/  /\.npmrc\b/  /\.netrc\b/  /\.git-credentials\b/
```

**`desc/hidden-unicode` (high)**. raw 에서만. 코드포인트 표.

```
zero-width:  200B 200C 200D 2060 2061 2062 2063 2064 FEFF 180E 00AD
bidi:        202A 202B 202C 202D 202E 2066 2067 2068 2069 061C 200E 200F
tag:         E0000..E007F (유니코드 태그 문자. 보이지 않는 ASCII 복제)
confusable-space: 00A0 2000..200A 202F 205F 3000
variation:   FE00..FE0F E0100..E01EF
```

`confusable-space` 는 단독이면 info(복붙으로 흔히 들어온다), 다른 범주와 함께면 high.

**`desc/ansi-escape` (high)**. raw 에서 `/\x1b\[[0-9;?]*[ -\/]*[@-~]/` 또는 `/\x1b\][^\x07\x1b]*(\x07|\x1b\\)/`.

**`desc/encoded-blob` (medium)**. §3.1 의 base64·hex 토큰이 디코딩에 성공했고, 그 디코딩 결과가 다른
규칙에 걸리지 **않았을** 때. 걸렸으면 그 규칙 발견의 `evidence` 에 단계 이름이 남으므로 이 규칙은 내지
않는다(중복). 제외: 그 문자열이 `uri`, `mimeType`, `format` 이 `uri`·`byte` 인 속성의 `default`·`examples`.

**`desc/non-standard-field` (low)**. `inputSchema`·`outputSchema` 안에서 JSON Schema 2020-12 의 알려진
키워드 목록 밖의 키가 **문자열 값**이고 길이 40 이상이면. 알려진 키워드:

```
$schema $id $ref $defs $comment $anchor $dynamicRef $dynamicAnchor $vocabulary
type enum const default examples title description deprecated readOnly writeOnly
properties patternProperties additionalProperties unevaluatedProperties propertyNames required
minProperties maxProperties dependentRequired dependentSchemas
items prefixItems additionalItems unevaluatedItems contains minContains maxContains minItems maxItems uniqueItems
allOf anyOf oneOf not if then else
minimum maximum exclusiveMinimum exclusiveMaximum multipleOf
minLength maxLength pattern format contentEncoding contentMediaType contentSchema
definitions nullable discriminator
```

### 3.3 `schema` 가족 (T2)

원시 도구의 `inputSchema.properties` 최상위와 그 아래 중첩 `properties` 를 모두 본다.

**`schema/secret-field` (medium)**. 속성 이름(folded)이 다음에 **정확히** 일치.

```
password passwd pwd secret api_key apikey access_token auth_token bearer_token refresh_token
private_key ssh_key client_secret credentials credential token session_token aws_secret_access_key
```

제외: 그 도구 이름이 `/\b(auth|login|authenticate|connect|configure|set_?credentials?|rotate|token)\b/`
에 걸리면(인증이 본업인 도구). 제외해도 `info` 로 낮춰 남긴다.

**`schema/exfil-channel` (medium)**. 세 조건이 모두 참일 때만.

1. 속성 이름(folded)이 `note notes sidenote feedback details extra additional metadata debug context
   annotation reasoning remark remarks comment comments memo` 중 하나.
2. 타입이 `string` 이고 `enum`·`pattern`·`maxLength` 가 없다(자유 문자열).
3. 그 속성의 `description` 또는 도구 `description` 이 `/\b(always|must|should|be sure to|make sure to|remember to) (include|pass|provide|fill|populate|attach|add)\b/` 에 걸린다.

**`schema/annotation-mismatch` (high)**. `annotations.readOnlyHint === true` 이고 도구 `name`·`title`·
`description` 의 folded 문자열이 파괴 동사에 걸릴 때.

```
파괴 동사: /\b(delete|remove|destroy|wipe|erase|drop|truncate|purge|write|overwrite|modify|update|create|insert|mutate|change|reset|revoke|kill|terminate|send|post|publish|transfer|pay|commit|push|deploy)\b/
```

제외: 걸린 단어가 `/\b(list|get|read|fetch|show|describe|search|find|query|check)\b/` 와 **같은 단어 묶음**
(`list_deleted_items`, `get update history`)에 있는 경우. 구현: 이름을 `[_\- ]` 로 나눠 토큰 집합을 만들고,
읽기 동사 토큰이 하나라도 있으면 설명은 보지 않고 이름만 판정하되, 이름의 **첫 토큰**이 파괴 동사일 때만
발견.

**`schema/missing-destructive-hint` (low)**. `annotations` 가 있고 `readOnlyHint` 가 `true` 가 아니며,
이름의 첫 토큰이 `/^(delete|remove|destroy|wipe|erase|drop|truncate|purge|reset|revoke|kill|terminate)$/`
인데 `destructiveHint` 가 `undefined` 이거나 `false`. `annotations` 가 없는 서버에는 내지 않는다(그 서버는
주석을 전혀 안 쓰므로 누락이 아니라 미사용).

**`schema/over-broad` (medium)**. `inputSchema` 가 다음 중 하나.

- 최상위 `properties` 가 비어 있거나 없고 `additionalProperties` 가 `true` 또는 없음, **그리고** 도구
  이름·설명이 `/\b(shell|command|exec|execute|run|eval|script|sql|query|url|path|file)\b/` 에 걸린다.
- 어떤 속성이 `type: "string"` 이고 이름이 `/^(command|cmd|shell|script|sql|query|url|path|file_?path|filename)$/`
  인데 `pattern`·`enum`·`format` 이 전부 없다. (이것만으로는 info. 위 첫 조건과 겹치면 medium.)

**`schema/non-standard-field`** 은 `desc/non-standard-field` 와 같은 검사다. 하나만 둔다(`desc`).

### 3.4 `flow` 가족 (T2, 서버 단위, severity `low`)

도구를 세 역할로 분류한다. 이름·title·description 의 folded 토큰과 `annotations` 로 본다.

```
reads-untrusted:  토큰에 issue|issues|comment|comments|ticket|tickets|email|emails|mail|inbox|message|messages|
                  dm|web|webpage|page|url|fetch|browse|search|scrape|crawl|document|documents|doc|docs|file|files|
                  pull_request|pr|review|feed|rss 중 하나 AND (읽기 동사 토큰 list|get|read|fetch|search|find|query|
                  browse|open|load|download 중 하나 OR annotations.readOnlyHint === true)
reads-private:    토큰에 repo|repository|repositories|private|secret|secrets|credential|credentials|token|tokens|
                  database|db|table|record|records|row|rows|user|users|account|accounts|customer|customers|
                  message|messages|file|files|drive|vault|wallet|key|keys 중 하나 AND 읽기 동사 토큰 중 하나
writes-external:  토큰에 create|post|send|publish|comment|reply|open|submit|upload|share|invite|transfer|pay|
                  email|mail|tweet|push 중 하나 AND (annotations.openWorldHint === true OR
                  annotations.readOnlyHint !== true)
```

**`flow/toxic-combination`**: 세 집합이 모두 비어 있지 않으면 발견 하나. `evidence` 에 각 집합의 도구 이름
최대 3개. 같은 도구가 둘 이상의 집합에 들어가도 된다(GitHub 의 `get_issue` 는 untrusted 이고
`create_pull_request` 는 external).

리포트는 이 가족을 "결함" 이 아니라 "권한 조합 경고" 구획에 따로 둔다(§6). 종료 코드에 영향을 주지
않는다.

### 3.5 `launch`·`surface`·`secret` 가족 (T3)

**`launch`**: 대상이 stdio 일 때만. `command` 와 `args` 를 본다. `--url` 대상에는 적용하지 않는다.

| 규칙 | 심각도 | 조건 |
|---|---|---|
| `launch/inline-code` | high | `command` 의 basename 이 `node`·`bun`·`deno`·`python`·`python3`·`ruby`·`perl`·`php` 이고 args 에 `-e`·`--eval`·`-c`·`--input-type=module` 이 있음(`-r` 은 모듈 프리로드라 제외. 통합 중 결정). 또는 basename 이 `sh`·`bash`·`zsh`·`fish`·`cmd`·`cmd.exe`·`powershell`·`pwsh` 이고 args 에 `-c`·`/c`·`-Command`·`-EncodedCommand` 가 있음. 또는 어느 arg 에든 `` ` `` 나 `$(` 가 있음 |
| `launch/pipe-to-shell` | high | 어느 arg 에든 `/\b(curl|wget|iwr|Invoke-WebRequest)\b[^|]*\|\s*(sh|bash|zsh|python3?|node|pwsh|powershell)\b/` |
| `launch/unpinned-package` | medium | basename 이 `npx`·`pnpx`·`bunx` 이고 첫 비옵션 arg 가 `/@\d/` 에 걸리지 않음(스코프 패키지의 `@scope/name` 은 제외하고 `@scope/name@1.2.3` 만 핀으로 인정). 또는 basename 이 `uvx`·`pipx` 이고 첫 비옵션 arg 에 `==` 또는 `@` 가 없음 |
| `launch/remote-source` | high | 어느 arg 가 `/^(https?|git|git\+https?|ssh):\/\//` 에 걸리고 command basename 이 `npx`·`pnpx`·`bunx`·`uvx`·`pipx`·`pip`·`npm`·`git` |
| `launch/env-passthrough` | info | 사용자가 `--env NAME` 으로 실제 값을 넘긴 이름이 `/(TOKEN|SECRET|KEY|PASSWORD|PASSWD|CREDENTIAL|AUTH)/i` 에 걸림. 메시지는 "이 값은 서버에 그대로 전달됩니다. 응답에 나오는지 `secret/env-echo` 가 봅니다" |

**`surface`**: `--baseline <path>` 가 있을 때만 동작한다. 없으면 가족 전체를 건너뛰고 리포트에 "기준 파일
없음" 한 줄.

- 표면 정규화: 각 도구를 `{ name, title, description, inputSchema, outputSchema, annotations }` 로 추리고,
  `description`·`title` 은 연속 공백을 하나로 접고 앞뒤 공백 제거, `inputSchema`·`outputSchema`·`annotations`
  는 **키를 정렬한** compact JSON 으로 직렬화한다(여기서는 정렬한다. 비교 대상이 파일이고 서버가 키 순서를
  바꿔 보내는 것은 변경이 아니기 때문이다). 도구 목록은 `name` 으로 정렬.
- 해시: 각 도구 직렬화의 SHA-256 hex. 전체 해시는 정렬된 도구 해시를 `\n` 으로 이은 것의 SHA-256.
- 기준 파일 형식(§5.1 `AuditBaseline`): `schemaVersion: 1`, `server: { name, version }`, `tools: [{ name, hash }]`,
  `surfaceHash`, `launch?: { command, args, package?: { manager, name, version? } }`. `package` 는
  `launch/unpinned-package` 가 파싱한 값이다(단계 2 의 `supply` 가 비교한다. 이 단계는 기록만).
- `surface/baseline-created` (info): 파일이 없으면 쓰고 발견 하나.
- `surface/changed`: 파일이 있고 `surfaceHash` 가 다르면 도구 단위로 분류한다.
  - 도구 추가: `low`. 도구 삭제: `medium`.
  - 같은 이름의 해시 변경: 어느 필드가 바뀌었는지 다시 비교해 `annotations` 가 **완화**(`readOnlyHint`
    true→false 또는 사라짐, `destructiveHint` false→true, `openWorldHint` false→true)되었으면 `high`,
    `description`·`title` 변경은 `high`(러그풀의 전형), `inputSchema`·`outputSchema` 변경은 `medium`,
    그 외 주석 변경은 `low`.
  - 기준 파일은 **덮어쓰지 않는다**. `--update-baseline` 이 있을 때만 새로 쓴다.

**`secret`**: 연결 전에 결정한다.

- 카나리 이름 고정 목록(12개):
  `GITHUB_TOKEN OPENAI_API_KEY ANTHROPIC_API_KEY AWS_SECRET_ACCESS_KEY AWS_ACCESS_KEY_ID SLACK_TOKEN
  SLACK_BOT_TOKEN NOTION_TOKEN DATABASE_URL STRIPE_SECRET_KEY NPM_TOKEN GOOGLE_APPLICATION_CREDENTIALS`.
  사용자가 `--env` 로 넘긴 이름은 이 목록에서 뺀다(실제 값이 우선).
- 토큰 값: `MCPEAK_CANARY_` + 16자 소문자 hex(`crypto.randomBytes(8)`). 이름마다 다른 값.
  **리포트와 JSON 에는 값을 절대 쓰지 않는다**(결정론과 비밀 노출 둘 다의 이유). 위치와 이름만 쓴다.
- `secret/env-leak` (high): 카나리 값이 도구 목록·프롬프트·리소스 목록·instructions·호출 응답(§3.7)의 어느
  문자열에든 §3.1 의 raw·base64·hex·rot13 형으로 나타남.
- `secret/env-echo` (high): 사용자가 `--env` 로 넘긴 **실제 값**(길이 8 이상인 것만)이 같은 곳에 나타남.
  `evidence` 에는 값 대신 `<redacted:NAME>`.
- `secret/env-name-in-description` (info): 카나리·전달 이름이 도구 설명에 글자 그대로 있음.
  설정 안내로 흔하다. 정보성.

### 3.6 `protocol` 가족 (T4)

**stdio 대상에는 `protocol/server-request*`·`protocol/list-changed` 만 적용한다.** 나머지는 HTTP 대상 전용.

| 규칙 | 심각도 | 조건 |
|---|---|---|
| `protocol/plaintext` | medium | `--url` 이 `http://` 이고 호스트가 `localhost`·`127.0.0.1`·`::1` 이 아님. 로컬호스트면 info |
| `protocol/unauthenticated` | medium | 사용자가 `--header-env` 를 하나 이상 줬고, **헤더 없이** 같은 URL 로 `initialize` 를 POST 했을 때 HTTP 2xx 에 JSON-RPC `result` 가 옴. 헤더를 안 줬고 연결이 성립했으면 info("인증 없이 열려 있습니다. 로컬 전용이면 정상입니다") |
| `protocol/origin-check` | medium | 호스트가 로컬호스트일 때, `Origin: http://evil.invalid` 헤더를 붙인 `initialize` POST 가 2xx. SDK 2025-07 DNS 리바인딩 권고 |
| `protocol/oauth-endpoint` | high | `<origin>/.well-known/oauth-protected-resource` 또는 `/.well-known/oauth-authorization-server` 가 2xx JSON 이고, 그 안의 `authorization_endpoint`·`token_endpoint`·`authorization_servers[i]` 중 하나가 `https://` 로 시작하지 않거나 `/[\s;&|`$<>'"]/` 를 포함 |
| `protocol/session-in-url` | medium | 연결 중 관측된 리다이렉트 `Location` 또는 응답 본문 URL 에 `/[?&](session|sessionid|session_id|sid|token)=/i` |
| `protocol/server-request` | info | 감사 중 서버가 보낸 `sampling/createMessage`·`elicitation/create`·`roots/list` 요청 각 1건. 메서드와 횟수. 같은 메서드가 `server-request-injection` 에 걸리면 이 info 는 내지 않는다(픽스처 "정확히 하나" 조건. 통합 중 결정) |
| `protocol/server-request-injection` | high | 그 요청의 `params` 안 문자열(§3.0.2 수집)에 `desc/injection`·`desc/covert-action`·`desc/shadowing` 가 걸림 |
| `protocol/list-changed` | high | 감사 중 `notifications/tools/list_changed` 가 왔고, 다시 받은 목록의 표면 해시(§3.5)가 처음과 다름. 알림만 오고 같으면 info |

프로브 요청은 전부 `fetch`(Node 22 전역)로 보낸다. 새 의존성 없음. 타임아웃 5,000ms, 실패하면 그 규칙은
"확인 안 함" 으로 `info`(판정 불가를 조용히 통과로 만들지 않는다).

서버 발신 요청을 받으려면 클라이언트가 `sampling`·`elicitation`·`roots` 능력을 광고해야 한다. §5.3 의
`advertise` 옵션이 그것이다. `audit` 는 셋을 모두 켠다. 요청에는 **항상** JSON-RPC 오류(`MethodNotFound`,
-32601)로 답한다. 샘플링 요청에 실제 모델 응답을 주는 일은 없다.

### 3.7 호출 정책과 `result` 가족 (T6)

**어떤 도구를 부르는가(`--probe`)**. 사용자 환경을 바꿀 수 있는 호출이므로 기본은 좁다.

| 값 | 호출 대상 |
|---|---|
| `readonly` (기본) | `annotations.readOnlyHint === true` 인 도구만 |
| `none` | 호출 없음. `result`·`secret/env-leak` 의 응답 부분을 건너뛰고 리포트에 명시 |
| `all` | 모든 도구. 리포트 머리에 "상태를 바꾸는 도구도 호출했습니다" 경고. 단계 2 의 Docker 격리에서 기본값이 될 값 |

**인자 생성(`probeArguments`)**. `inputSchema` 의 `required` 속성만 채운다. 타입별 자리값:
`string` → `"mcpeak"`(단 `format` 이 `uri`·`url` 이면 `"https://example.invalid/mcpeak"`, `email` 이면
`"mcpeak@example.invalid"`, `date-time` 이면 `"2026-01-01T00:00:00Z"`, `enum` 이 있으면 첫 값), `integer`·
`number` → `minimum ?? 0`, `boolean` → `false`, `array` → `[]`(단 `minItems ≥ 1` 이면 `items` 로 하나),
`object` → 재귀. `anyOf`·`oneOf` 는 첫 갈래. 생성 불가(`$ref` 미해결 등)면 그 도구는 건너뛰고 리포트에
"인자를 만들 수 없어 호출하지 않음".

호출 결과는 `isError` 와 무관하게 전부 `result` 규칙에 넣는다. 오류 응답이 주입 통로다(ATPA).
호출 타임아웃 10,000ms. 타임아웃·예외는 `result/unavailable` (info, "호출이 끝나지 않았습니다") 로 **발견으로
남긴다**(fail closed).

| 규칙 | 심각도 | 조건 |
|---|---|---|
| `result/injection` | high | 응답 문자열(§3.0.2)에 `desc/injection`·`desc/covert-action`·`desc/shadowing` |
| `result/hidden-unicode` | medium | raw 응답 문자열에 §3.2 표의 zero-width·bidi·tag |
| `result/ansi-escape` | high | §3.2 의 ANSI 정규식 |
| `result/oversized` | medium | 응답 직렬화 바이트가 `maxMessageBytes`(core 기본 10MiB)의 절반 초과 |
| `result/unavailable` | info | 타임아웃 또는 전송 오류 |

### 3.8 종료 코드

| 상황 | 코드 |
|---|---|
| 사용법 오류, 연결 실패 | 1 |
| `high` 또는 `medium` 발견이 하나라도 있음(`flow` 제외) | 2 |
| 그 외 | 0 |

## 4. 결정론 규칙 (코드가 지켜야 할 것)

- 발견 정렬·중복 제거는 §3.0. 규칙 실행 순서에 의존하는 출력 금지.
- 카나리 값은 출력에 쓰지 않는다. `evidence` 에는 `"<canary:GITHUB_TOKEN>"` 같은 자리표.
- 시각·소요 시간·PID 를 출력에 쓰지 않는다.
- 프로브 결과가 네트워크 상태로 달라질 수 있는 규칙(`protocol/*` HTTP 프로브)은 "확인 안 함" 을 발견으로
  남겨 두 실행의 차이가 **보이게** 한다.
- JSON 출력은 키 순서를 §5.1 선언 순서로 고정하고 `JSON.stringify(value, null, 2)` 뒤 개행 하나.

## 6. 리포트와 실패 메시지 문안 (전량. 테스트가 글자 단위로 고정한다)

### 6.1 리포트 (`renderReport`)

```
mcpeak audit 결과
서버 <name> <version> · 도구 <N>개 · 프롬프트 <P>개 · 리소스 <R>개 · instructions <있음|없음>
호출 정책 <readonly|none|all> · 호출한 도구 <K>개<probe 가 all 이면: " (상태를 바꾸는 도구도 호출했습니다)">

판정: 심각 <h>건, 주의 <m>건, 낮음 <l>건, 정보 <i>건
```

그 뒤 심각도 **내림차순**, 같은 심각도 안에서는 §3.0 정렬 순으로 발견을 적는다. 발견 하나는 세 줄이다.

```
[<심각|주의|낮음|정보>] <ruleId> · <위치 한 줄>
  → <message>
  해결: <fix>
```

위치 한 줄: `tool` → `도구 '<name>' 의 <path>`; `prompt` → `프롬프트 '<name>' 의 <path>`; `resource` →
`리소스 <uri> 의 <path>`; `instructions` → `서버 instructions`; `launch` → `실행 명령 <path>`; `protocol` →
`프로토콜`; `surface` → `도구 표면`; `result` → `도구 '<name>' 호출 응답의 <path>`; `server` → `서버 전체`.
`path` 가 빈 문자열이면 " 의 <path>" 를 생략한다.

같은 `ruleId` 가 같은 도구에서 4곳 이상 걸리면 처음 3개만 적고 `  → 같은 도구에서 <n>곳 더` 한 줄.

`flow` 발견은 심각도 목록에 넣지 않고 별도 구획으로 **마지막에** 둔다.

```
권한 조합 경고 (결함이 아닙니다)
  → 이 서버는 외부 입력을 읽고(<a, b, c>), 비공개 데이터에 닿고(<d, e>), 밖으로 쓸 수 있습니다(<f>).
  → 외부 입력에 숨은 지시가 있으면 비공개 데이터가 밖으로 나갈 수 있습니다. GitHub MCP 2025-05 사고가 이 모양입니다.
  해결: 세 역할을 한 세션에서 함께 켜지 마세요. 외부 입력을 읽는 도구만 따로 붙이거나 쓰기 도구를 끄세요.
```

건너뛴 검사가 있으면 그 뒤에:

```
검사하지 않은 것
  - <family>: <reason>
```

`reason` 문장(고정):
- `surface`: `--baseline 을 주지 않아 도구 표면 변경을 비교하지 않았습니다.`
- `result`·`secret`(호출 부분): `--probe none 이라 도구를 호출하지 않았습니다.` 또는
  `readOnlyHint 가 true 인 도구가 없어 호출할 도구가 없었습니다. --probe all 은 상태를 바꿀 수 있습니다.`
- `protocol`: `stdio 대상이라 HTTP 프로토콜 검사는 해당 없습니다.`
- `launch`: `--url 대상이라 실행 명령 검사는 해당 없습니다.`

리포트 마지막은 항상 이 두 줄이다.

```
이 검사는 설명문의 문형과 프로토콜 표면만 봅니다. 바꿔 말한 지시와 서버 코드의 실제 행위는 보지 못합니다.
행위 관측(Docker 격리)은 mcpeak audit --sandbox 로 켭니다. (단계 2에서 제공)
```

### 6.2 규칙별 `message`·`fix` (T1~T6 가 그대로 쓴다. `<…>` 만 치환)

| ruleId | message | fix |
|---|---|---|
| `desc/injection` | 모델에게 내리는 지시가 있습니다: "<조각>" (<form> 형에서 발견) | 이 서버를 신뢰하지 않는다면 등록하지 마세요. 서버 작성자라면 설명에서 모델 지시를 빼세요. |

### 6.4 CLI 사용법

```
사용법: mcpeak audit (-- <executable> [args...] | --command <executable> [--arg <value> ...] [--env <NAME> ...] | --url <URL> [--header-env <헤더이름>=<환경변수이름> ...]) [--probe readonly|none|all] [--baseline <path>] [--update-baseline] [--json]

`--probe` 값이 셋 밖이면: `오류 [CLI_USAGE]: --probe 값은 readonly, none, all 중 하나입니다.`
`--update-baseline` 만 있고 `--baseline` 이 없으면: `오류 [CLI_USAGE]: --update-baseline 은 --baseline 과 함께 써야 합니다.`
대상 옵션 오류 문장은 `connect-target.ts` 의 것을 그대로 쓴다(`optimize` 와 같은 방식).
