# 대시보드 모드 분리와 사용자 사전 점검 구현 계획 (2026-10-04)

## 문서 지위

`docs/2026-10-03-analyze-로드맵.md` 의 단계 1·2·3 이 전부 끝난 뒤의 후속 계획이다. 기준 커밋은 `main` 의
HEAD(작성 시점 `805f413`, PR #499 의 머지 커밋)다. 로드맵 §0 은 "대시보드 메뉴는 `Analyze` 하나에 보안 탭과
토큰 탭" 으로 정했는데, 그 보안 탭은 서버 개발자가 자기 프로젝트의 서버를 점검하는 화면이다. MCP 서버를
쓰기만 하는 사람이 **등록 전에** 남의 서버를 점검하는 화면은 없다. 이 계획은 그 화면을 더하고, 대시보드를
개발자·사용자 두 모드로 나눈다.

사용자가 정한 것(2026-10-04 대화):

- 처음 켤 때 개발자·사용자를 **한 번만** 묻는다.
- 모드 전환은 사이드바 아래쪽 `Settings` 바로 위에 둔다.
- 사용자 모드의 메뉴는 당장 **사전 점검 하나**다. 구현 예정 메뉴는 넣지 않는다.
- 사용자용 판정 문장은 새로 만들지 않는다. 발견의 **기존 해결 문장**으로 구성한다.

## 완주 뒤에 바뀐 것 (2026-10-04)

이 계획은 완주됐다(`usermode-T1` `d666cf9`, `usermode-T2` `5d70da1`). 그 뒤 실제로 써 보고 아래를 고쳤다.
본문의 해당 대목은 처음 결정을 기록한 것이라 그대로 두었다. 지금의 동작은 이 절과 ADR-0111 이 기준이다.

- **"먼저 할 일" 카드와 "해결" 줄을 없앴다.** §1.3-8, §3 의 "판정 문장" 줄, §4.4 의 요약 카드 두 줄, §5.4,
  §5.5 의 요약 카드, §7.3 의 `fix-summary.test.ts`, §7.4 의 카드 테스트가 해당한다. `fix` 문장은 MCP 를 만든
  사람에게 하는 말이 섞여 있어 사용자가 무언가를 고쳐야 하는 것처럼 읽혔다. 사전 점검의 결과는 발견마다
  "왜 위험한가" 한 줄을 보인다. 문장은 `web/src/analyze/risk-text.ts` 가 규칙 id 마다 하나씩 갖고,
  `SecurityResult` 는 `audience="user"` 일 때 그 줄을 그리고 CLI 리포트 원문을 감춘다.
  `web/src/precheck/fix-summary.ts` 와 그 테스트는 지웠다.
- **선택 화면의 문장과 크기.** §4.4 의 선택 화면 제목은 `MCP를 어떻게 쓰시나요?` 이고 두 카드 설명은
  `MCP 서버` 대신 `MCP` 라고 쓴다(본문 표에 반영했다). 가운데 묶음을 키우고 두 카드 제목의 색을 달리했다.

## 1. 목표, 비범위, 완료 조건

### 1.1 목표

- 저장된 모드가 없는 브라우저가 빈 주소로 들어오면 모드 선택 화면(`#/welcome`)이 뜬다. 고른 뒤에는 다시
  묻지 않는다.
- 개발자 모드의 사이드바와 화면은 지금과 글자 단위로 같다. 주소도 그대로다(`#/home`, `#/runs`, ...).
- 사용자 모드의 사이드바는 `Check` 한 항목이고 그 화면이 사전 점검(`#/user/check`)이다.
- 두 모드 모두 사이드바 아래쪽에 모드 전환 링크가 `Settings` 바로 위에 있다.
- 사전 점검은 붙여 넣은 서버 설정(JSON 조각, 실행 명령 한 줄, URL)을 대상으로 기존
  `POST /api/analyze/security` 를 그대로 부른다. 서버 쪽 코드는 한 줄도 바꾸지 않는다.
- 사전 점검은 붙여 넣은 설정의 환경변수·헤더 **값을 어디에도 보내지 않는다.** 이름만 화면에 보인다.

### 1.2 비범위

- `packages/dashboard/src/` (서버 면) 변경. 요청·응답 계약은 그대로 쓴다.
- `@mcpeak/audit`·`@mcpeak/cli` 변경. 사용자용 판정 문장을 `audit` 에 더하는 일은 하지 않는다.
- Docker 가 없을 때 점검 시작을 **막는** 것. 지금 CLI 는 격리를 못 쓰면 서버를 호스트에서 띄우고 그 사실을
  리포트에 적는다. 시작 전에 막으려면 `cli` 나 서버 면에 Docker 감지를 더해야 한다. 이 계획은 시작 전
  안내 문장과 결과의 기존 경고 줄(`sandboxLine`)로만 알린다(§11-2).
- 실제 비밀값이 있어야 뜨는 서버의 점검. env 를 넘기지 않으므로 그런 서버는 연결 실패로 끝날 수 있고,
  화면은 CLI 의 실패 문장을 그대로 보인다(§11-1).
- 기준 파일 저장, 지속 감시, 호출 정책·허용 호스트 같은 점검 옵션. 그것은 개발자용 보안 탭에 있다.
- 클라이언트 설정 파일(Claude Desktop, Cursor 등) 자동 탐지. 로드맵 §4 의 비범위 그대로다.
- 사용자 모드의 그 밖의 메뉴.
- 모드에 따른 접근 제한. 모드는 보기 필터다. 주소를 직접 치면 반대 모드의 화면이 열린다.

### 1.3 완료 조건 (전부 검증 가능해야 한다)

1. `localStorage` 가 비어 있고 해시가 빈 상태로 `App` 을 그리면 해시가 `#/welcome` 이 되고 사이드바가
   없다. 저장값이 `developer` 면 `#/home`, `user` 면 `#/user/check` 로 간다.
2. `#/welcome` 의 두 링크는 `#/home` 과 `#/user/check` 를 가리킨다. 도착한 뒤 `localStorage` 의
   `mcpeak-mode` 가 각각 `developer`, `user` 다.
3. 개발자 모드 사이드바의 링크 글자는 순서대로 `Test, Runs, Generate, Replay, Mock, Repair, Analyze,
   Switch to User, Settings, Help & Docs` 다. 사용자 모드는 `Check, Switch to Developer, Settings,
   Help & Docs` 다.
4. `#/settings` 는 두 모드 공통이다. 저장된 모드의 사이드바로 그린다(저장값이 없으면 개발자).
5. 저장값이 없는 브라우저가 `#/runs/abc` 같은 개발자 주소로 바로 들어오면 선택 화면을 거치지 않고 그 화면이
   열린다(깊은 링크를 막지 않는다).
6. `parseServerInput` 이 §5.2 의 표대로 JSON 조각, 명령 한 줄, URL 을 풀고, 실패 문장이 §5.2 의 글자와 같다.
7. 사전 점검이 보내는 요청 본문에 `--env`, `--header-env`, `serverId`, `probe`, `baselinePath` 가 없다.
   격리 토글이 켜져 있고 대상이 stdio 면 `sandbox: { compareHost: false, allowHosts: [] }` 가 있다.
8. 결과 단계 맨 위의 "먼저 할 일" 카드는 심각·주의 발견의 `fix` 문장을 발견 순서대로, 같은 문장은 한 번만
   보인다. 그 아래는 개발자용 보안 탭과 같은 `SecurityResult` 다. 심각·주의 발견이 없으면 카드가 없다.
9. 같은 입력을 두 번 넣으면 `parseServerInput`·`buildPrecheckRequest`·`fixSummary` 의 출력이
   `JSON.stringify` 로 같다(결정론).
10. 기존 web 테스트가 §7.5 에 적은 수정 외에는 고치지 않고 녹색이다.
11. `pnpm test`, `pnpm build --force`, `pnpm typecheck --force`, `pnpm lint` 녹색. `Cached: 0 cached`.
12. 실제로 띄운 대시보드의 사전 점검에 `examples/audit-target-server` 를 붙여 넣어 점검한 발견 목록이
    같은 서버에 `mcpeak audit --json` 을 돌린 것과 순서까지 같다(최종 게이트, §8.3).

### 1.4 진행 중 작업과의 충돌 확인

## 3. 결정 사항 (다르게 갈 수도 있었던 것)

| 항목 | 결정 | 대안과 버린 이유 |
|---|---|---|
| 모드의 진실 | **해시가 먼저, 저장값이 다음.** 지금 화면의 모드는 `modeOfHash(hash) ?? 저장값 ?? "developer"` 다 | 저장값만 보는 것. 공유한 주소·새로 고침·뒤로 가기가 저장값에 따라 다른 화면을 연다 |
| 저장 시점 | **도착할 때 저장한다.** 받아들인 해시의 모드가 저장값과 다르면 저장한다. 저장값은 "마지막으로 머문 모드" 다 | 링크를 누를 때 저장하는 것. 이탈 확인(`leave-guard`)이 이동을 막으면 이동은 안 했는데 저장만 바뀐다 |
| 전환 수단 | 반대 모드의 첫 화면을 가리키는 **링크**(`<a href>`) | 버튼과 콜백. 이탈 확인이 `hashchange` 에 걸려 있어 링크면 그대로 탄다. 버튼이면 같은 확인을 다시 짜야 한다 |
| 개발자 주소 | 그대로 둔다(`#/home` 등). 사용자 쪽만 `#/user/` 접두사를 쓴다 | `#/dev/` 접두사. 기존 링크·저장된 주소·테스트 전부가 움직인다 |
| 선택 화면 | 저장값이 없고 **갈 곳이 없는 주소**(빈 해시, 모르는 해시)일 때만 뜬다 | 저장값이 없으면 항상 띄우는 것. 깊은 링크로 들어온 사람을 막는다 |
| 구현 안 된 메뉴 | 넣지 않는다 | 비활성으로 보이는 것. 사용자 결정 |
| 사전 점검의 서버 경로 | 기존 `POST /api/analyze/security` 를 그대로 쓴다 | 사용자용 경로를 새로 두는 것. 가드와 실행기가 둘이 된다 |
| env·헤더 값 | **보내지 않는다.** 이름만 화면에 보인다 | `--env <이름>` 으로 넘기는 것. 그러면 대시보드 프로세스의 같은 이름 환경변수 **실제 값**이 믿지 않는 서버에 간다(`audit-command.ts` 의 `forwardedEnv`). 가짜 값으로 바꿔 넘기려면 `cli`·`audit` 을 고쳐야 한다 |
| 격리 기본값 | 켜짐 | 꺼짐(개발자용 보안 탭의 기본값). 사전 점검의 대상은 믿지 않는 서버다 |
| 점검 옵션 | 격리 토글 하나만 낸다. 호출 정책은 CLI 기본값(격리 안 `all`, 아니면 `readonly`) | 보안 탭의 옵션을 전부 내는 것. 서버를 쓰기만 하는 사람은 뜻을 모른다 |
| 판정 문장 | 새로 쓰지 않는다. 결과 위에 심각·주의 발견의 `fix` 문장을 모아 보인다 | 대시보드가 "등록하지 마세요" 같은 결론을 만드는 것. ADR-0110 이 금지한다. 사용자 결정 |
| 결과 화면 | 요약 카드 아래에 기존 `SecurityResult` 를 그대로 쓴다 | 사용자용 결과 화면을 새로 쓰는 것. 같은 발견이 두 화면에서 다른 모양이 된다 |

## 4. 공유 계약 (전량. T2 가 T1 의 산출물에 의존한다)

### 4.1 `packages/dashboard/web/src/mode.ts` (T1, 새 파일. 글자 그대로)

```ts
/**
 * 대시보드의 모드(ADR-0111). 개발자는 서버를 만들고 테스트하는 사람, 사용자는 남의 서버를 등록 전에
 * 점검하는 사람이다. 모드는 보기 필터다. 접근을 막지 않는다.
 *
 * 지금 화면의 모드는 해시가 먼저 정하고, 해시가 말하지 않을 때만 저장값을 본다. 저장값은 "마지막으로
 * 머문 모드" 다. App 이 해시를 받아들일 때 쓴다.
 */
export type AppMode = "developer" | "user";

const STORAGE_KEY = "mcpeak-mode";

/** 모드를 고르는 화면. 저장값이 없고 갈 곳이 없는 주소일 때만 온다. */
export const WELCOME_HASH = "#/welcome";

/** 모드의 첫 화면. 전환 링크와 기본 리다이렉트가 같은 값을 쓴다. */
export const MODE_HOME: Readonly<Record<AppMode, string>> = {
  developer: "#/home",
  user: "#/user/check",
};

/** 개발자 모드의 화면들. `#/settings` 와 `#/welcome` 은 어느 모드의 것도 아니다. */
const DEVELOPER_SCREENS: ReadonlySet<string> = new Set([
  "home",
  "runs",
  "generate",
  "replay",
  "mock",
  "repair",
  "analyze",
]);

/** 해시가 속한 모드. 공통 화면, 선택 화면, 빈 해시, 모르는 해시는 null 이다. */
export function modeOfHash(hash: string): AppMode | null {
  const withoutHash = hash.startsWith("#") ? hash.slice(1) : hash;
  const first = withoutHash.split("/").find((segment) => segment.length > 0);
  if (first === undefined) return null;
  if (first === "user") return "user";
  return DEVELOPER_SCREENS.has(first) ? "developer" : null;
}

/** 저장된 모드. 없거나 알 수 없는 값이면 null(아직 고르지 않음). */
export function getStoredAppMode(storage: Pick<Storage, "getItem">): AppMode | null {
  const raw = storage.getItem(STORAGE_KEY);
  return raw === "developer" || raw === "user" ? raw : null;
}

/** 저장에 실패해도 던지지 않는다. 모드를 기억하지 못하는 것은 불편이고 화면이 죽는 것은 고장이다. */
export function saveAppMode(mode: AppMode, storage: Pick<Storage, "setItem">): void {
  try {
    storage.setItem(STORAGE_KEY, mode);
  } catch {
    // 기억하지 못하면 다음에 선택 화면이 다시 뜬다.
  }
}
```

### 5.2 붙여 넣은 입력 풀기 (T2, `web/src/precheck/parse-server-input.ts`. 이 파일이 사양이다. 글자 그대로)

```ts
/**
 * 붙여 넣은 글자 → 점검 대상(계획서 §5.2). 세 꼴을 받는다: mcpServers JSON 조각, 실행 명령 한 줄, URL.
 *
 * env 와 헤더는 **이름만** 남긴다. 값은 여기서 버려지고 요청에도 화면에도 실리지 않는다(ADR-0111).
 * 같은 글자를 넣으면 항상 같은 결과다. 엔진마다 다른 `JSON.parse` 오류 문장을 싣지 않는다.
 */

import type { Transport } from "../build-test-argv.js";

export interface PastedServer {
  /** mcpServers 의 키. 명령 한 줄이나 URL 로 왔으면 null. */
  readonly name: string | null;
  readonly transport: Transport;
  /** 실행 파일 하나. http 면 "". */
  readonly command: string;
  readonly args: readonly string[];
  /** 표시용. 요청에 싣지 않는다. */
  readonly envNames: readonly string[];
  /** http 면 주소, 아니면 "". */
  readonly url: string;
  /** 표시용. 요청에 싣지 않는다. */
  readonly headerNames: readonly string[];
}

export type ParsedInput =
  | { readonly ok: true; readonly servers: readonly PastedServer[] }
  | { readonly ok: false; readonly error: string };

const ENV_ASSIGNMENT = /^[A-Za-z_][A-Za-z0-9_]*=/;
const HTTP_URL = /^https?:\/\//i;

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value);
}

function fail(error: string): ParsedInput {
  return { ok: false, error };
}

/**
 * 공백으로 나누되 따옴표 안은 한 토큰이다. 역슬래시 이스케이프는 풀지 않는다. 줄 끝의 `\` 하나는 줄
 * 잇기라 버린다. 따옴표가 닫히지 않으면 null.
 */
function tokenize(line: string): readonly string[] | null {
  const tokens: string[] = [];
  let current = "";
  let started = false;
  let quote: '"' | "'" | null = null;
  for (const char of line) {
    if (quote !== null) {
      if (char === quote) quote = null;
      else current += char;
      continue;
    }
    if (char === '"' || char === "'") {
      quote = char;
      started = true;
      continue;
    }
    if (/\s/.test(char)) {
      if (started) tokens.push(current);
      current = "";
      started = false;
      continue;
    }
    current += char;
    started = true;
  }
  if (quote !== null) return null;
  if (started) tokens.push(current);
  return tokens.filter((token) => token !== "\\");
}

function entryOf(name: string | null, value: unknown): PastedServer | string {
  const label = name === null ? "설정" : `'${name}' 항목`;
  if (!isRecord(value)) return `${label}이 객체가 아닙니다.`;
  if (typeof value.command === "string" && value.command.trim() !== "") {
    const args = value.args ?? [];
    if (!Array.isArray(args) || !args.every((arg): arg is string => typeof arg === "string")) {
      return `${label}의 args 는 문자열 배열이어야 합니다.`;
    }
    return {
      name,
      transport: "stdio",
      command: value.command.trim(),
      args,
      envNames: isRecord(value.env) ? Object.keys(value.env) : [],
      url: "",
      headerNames: [],
    };
  }
  if (typeof value.url === "string" && HTTP_URL.test(value.url.trim())) {
    return {
      name,
      transport: "http",
      command: "",
      args: [],
      envNames: [],
      url: value.url.trim(),
      headerNames: isRecord(value.headers) ? Object.keys(value.headers) : [],
    };
  }
  return `${label}에 command 도 http(s) url 도 없습니다.`;
}

function fromJson(text: string): ParsedInput {
  let parsed: unknown;
  try {
    parsed = JSON.parse(text);
  } catch {
    return fail("JSON 으로 읽지 못했습니다. 중괄호와 따옴표, 쉼표를 확인하세요.");
  }
  if (!isRecord(parsed)) return fail("JSON 최상위가 객체가 아닙니다.");
  // 한 서버의 설정만 붙여 넣은 경우.
  if (typeof parsed.command === "string" || typeof parsed.url === "string") {
    const entry = entryOf(null, parsed);
    return typeof entry === "string" ? fail(entry) : { ok: true, servers: [entry] };
  }
  // `{"mcpServers": {...}}` 이거나, 그 안쪽 `{이름: {...}}` 만 붙여 넣은 경우.
  const map = isRecord(parsed.mcpServers) ? parsed.mcpServers : parsed;
  const servers: PastedServer[] = [];
  for (const [name, value] of Object.entries(map)) {
    const entry = entryOf(name, value);
    if (typeof entry === "string") return fail(entry);
    servers.push(entry);
  }
  if (servers.length === 0) return fail("설정에 서버가 없습니다.");
  return { ok: true, servers };
}

export function parseServerInput(text: string): ParsedInput {
  const trimmed = text.trim();
  if (trimmed === "") return fail("서버 설정이나 실행 명령을 붙여 넣으세요.");
  if (trimmed.startsWith("{")) return fromJson(trimmed);
  if (HTTP_URL.test(trimmed)) {
    if (/\s/.test(trimmed)) return fail("URL 에 공백이 있습니다. 주소 하나만 붙여 넣으세요.");
    return {
      ok: true,
      servers: [
        {
          name: null,
          transport: "http",
          command: "",
          args: [],
          envNames: [],
          url: trimmed,
          headerNames: [],
        },
      ],
    };
  }
  const tokens = tokenize(trimmed);
  if (tokens === null) return fail("따옴표가 닫히지 않았습니다.");
  // 명령 앞의 `KEY=value` 는 env 다. 이름만 남긴다.
  let index = 0;
  const envNames: string[] = [];
  while (index < tokens.length && ENV_ASSIGNMENT.test(tokens[index] as string)) {
    const token = tokens[index] as string;
    envNames.push(token.slice(0, token.indexOf("=")));
    index += 1;
  }
  const command = tokens[index];
  if (command === undefined) return fail("실행 명령이 없습니다. 환경변수 뒤에 명령을 적으세요.");
  return {
    ok: true,
    servers: [
      {
        name: null,
        transport: "stdio",
        command,
        args: tokens.slice(index + 1),
        envNames,
        url: "",
        headerNames: [],
      },
    ],
  };
}
```

입력과 결과의 대응(테스트가 전부 단언한다, §7.2):

| 입력 | 결과 |
|---|---|
| `{"mcpServers":{"a":{"command":"npx","args":["-y","pkg"],"env":{"KEY":"v"}}}}` | stdio 하나. `name: "a"`, `command: "npx"`, `args: ["-y","pkg"]`, `envNames: ["KEY"]` |
| `{"a":{"command":"node","args":["s.mjs"]},"b":{"url":"https://x.test/mcp","headers":{"Authorization":"t"}}}` | 둘. 적힌 순서. 둘째는 http, `headerNames: ["Authorization"]` |
| `{"command":"node","args":["s.mjs"]}` | stdio 하나. `name: null` |
| `npx -y @scope/pkg --flag "a b"` | stdio 하나. `command: "npx"`, `args: ["-y","@scope/pkg","--flag","a b"]` |
| `API_KEY=secret node server.mjs` | `envNames: ["API_KEY"]`, `command: "node"`, `args: ["server.mjs"]` |
| `https://x.test/mcp` | http 하나 |

### 5.3 요청 조립 (T2, `web/src/precheck/build-precheck-request.ts`. 글자 그대로)

```ts
/**
 * 붙여 넣은 서버 → `POST /api/analyze/security` 의 본문(계획서 §5.3). 대상 옵션은 보안 탭·토큰 탭과 같은
```

### 5.4 해결 요약 (T2, `web/src/precheck/fix-summary.ts`. 글자 그대로)

```ts
/**
 * 결과 맨 위 "먼저 할 일" 의 줄들(계획서 §5.4). 문장은 발견의 `fix` 그대로다. 대시보드가 결론 문장을
 * 만들지 않는다(ADR-0110, ADR-0111). 심각을 먼저, 그다음 주의. 각 안에서는 `report.findings` 의 순서다.
 * 같은 심각도의 같은 문장은 한 줄로 접고 건수를 센다. flow 는 결함이 아니라서 뺀다.
 */

// 타입만. 값으로 import 하면 번들에 서버 코드가 섞인다.
import type { Finding } from "@mcpeak/audit";

export interface FixLine {
  readonly severity: "high" | "medium";
  readonly fix: string;
  readonly count: number;
}

export function fixSummary(findings: readonly Finding[]): readonly FixLine[] {
  const lines: { severity: "high" | "medium"; fix: string; count: number }[] = [];
  for (const severity of ["high", "medium"] as const) {
    for (const finding of findings) {
      if (finding.severity !== severity || finding.ruleId.startsWith("flow/")) continue;
      const existing = lines.find((line) => line.severity === severity && line.fix === finding.fix);
      if (existing === undefined) lines.push({ severity, fix: finding.fix, count: 1 });
      else existing.count += 1;
    }
  }
  return lines;
}
```

### 5.5 사전 점검 화면 (T2, `web/src/screens/PreCheck.tsx`. 시그니처와 검증 가능한 사양)

상태 기계는 `SecurityPanel` 과 같다. 단계는 따로 상태를 두지 않고 구한다: 결과가 있으면 2, 도는 run 이
있으면 1, 아니면 0. 타이머와 폴링이 없다.

상태: `text: string`, `picked: number`(고른 서버의 자리), `sandbox: boolean`(초기값 `true`),
`runId`, `sent: AnalyzeSecurityRequest | null`, `result`, `error`, `starting`, `awaitedRun`(ref).

단계 0:

1. `Card` 안에 `<textarea id="precheck-input">` (`INPUT_CLASS`, `font-mono`, 여섯 줄)과 라벨·힌트(§4.4).
2. `parseServerInput(text)` 를 렌더마다 부른다. 실패면 시작 버튼이 비활성이고 버튼 아래에 그 문장을
   `text-xs text-ink-muted` 로 보인다(보안 탭의 사유 줄과 같은 모양).
3. 성공이고 서버가 둘 이상이면 `<select id="precheck-server">` 로 고르게 한다. 선택지 글자는 `name`
   (null 이면 대상 줄과 같은 글자)이다. `text` 가 바뀌면 `picked` 를 0 으로 되돌린다. `picked` 가 범위를
   벗어나면 0 번을 쓴다.
4. 성공이면 대상 줄, env 안내, 헤더 안내를 §4.4 의 글자로 보인다. 대상 줄은 `break-all font-mono text-xs`.
5. 격리 `Toggle`. http 대상이면 `checked={false}`, `disabled`, 힌트는 `REMOTE_SANDBOX_HINT`.
6. 시작 버튼을 누르면 `buildPrecheckRequest(server, sandbox)` 를 `POST /api/analyze/security` 로 보낸다.
   `buildAnalyzeArgv` 가 던지면 그 문장이 사유 줄에 온다. 400 이면 단계 0 에 머물고 서버의 `error` 를
   `ErrorAlert` 로 보인다. 최근 명령 목록(`recent-commands`)에는 쓰지 않는다.

단계 1: `← 서버 다시 붙여넣기` 버튼, 안내 문장, 대상 줄, `<SecurityProgress key={runId} ...>`. `onFinished` 는
`GET /api/analyze/security/<runId>` 를 한 번 읽고, `onMissing` 은 단계 0 으로 돌아가 문장을 보인다. 늦게
도착한 결과는 `awaitedRun` 으로 버린다(`SecurityPanel` 의 `loadResult`·`leaveRun` 과 같은 규칙).

단계 2: 두 버튼(`← 서버 다시 붙여넣기`, `다시 점검`), 시작 실패 문장, 요약 카드, `<SecurityResult
response={result} request={sent} />`.

요약 카드: `fixSummary(result.report.findings)` 가 비면 그리지 않는다. 아니면 `Card` 안에 `h2` `먼저 할 일`
과 `<ul>`. 줄마다 심각도 라벨 칩(`SEVERITIES` 의 라벨, `SEVERITY_TONE` 의 색, `data-severity` 속성)과 `fix`
글자, 2건 이상이면 건수 꼬리. `fix` 는 텍스트 노드로 넣는다. `dangerouslySetInnerHTML` 을 쓰지 않는다.

`← 서버 다시 붙여넣기` 는 `text`, `picked`, `sandbox` 를 남긴다.

## 6. 결정론 규칙

- `parseServerInput`, `buildPrecheckRequest`, `fixSummary` 는 순수 함수다. 시각, 난수, 저장소를 읽지 않는다.
- JSON 조각의 서버 순서는 적힌 순서다(`Object.entries`). 다시 정렬하지 않는다.
- 요약 줄의 순서는 심각도, 그다음 `report.findings` 의 순서다. 건수로 정렬하지 않는다.
- 모드 판정은 해시와 저장값만 본다. 접속 시각이나 방문 횟수를 보지 않는다.

전부 jsdom 과 `fetch`·`EventSource` 스텁만 쓴다. 실제 서버를 띄우지 않는다. 화면 테스트의 `beforeEach` 는
`window.localStorage.clear()` 를 부른다(저장된 모드가 테스트 사이에 새지 않게 한다).

### 7.2 `web/tests/parse-server-input.test.ts` (T2, 새 파일)

- §5.2 표의 여섯 줄 각각 한 테스트. 결과 전체를 `toEqual` 로 단언한다(필드 전부).
- `env 값은 결과 어디에도 없다`: 첫 줄 입력의 결과를 `JSON.stringify` 한 글자에 `"v"` 값 문자열
  (`":"v"`)이 없다. 다섯째 줄 입력의 결과에 `secret` 이 없다.
- `헤더 값은 결과 어디에도 없다`: 둘째 줄 입력의 결과에 `"t"` 값이 없다(`headerNames` 는 `["Authorization"]`).
- `mcpServers 안쪽만 붙여 넣어도 읽는다`: `{"a":{"command":"node"}}` → `name: "a"`, `args: []`.
- `따옴표 안의 공백은 나누지 않는다`: `node "my server.mjs" 'x y'` → `args: ["my server.mjs", "x y"]`.
- `줄 잇기 역슬래시를 버린다`: `"npx -y pkg \\\n  --port 3000"` → `args: ["-y","pkg","--port","3000"]`.
- `앞뒤 공백과 개행을 무시한다`: `"\n  node s.mjs \n"` → `command: "node"`, `args: ["s.mjs"]`.
- 실패 문장. 입력마다 한 테스트이고 각각 `toEqual({ ok: false, error: <글자> })`.
  - `""`, `"   "` → `서버 설정이나 실행 명령을 붙여 넣으세요.`
  - `{"mcpServers":` → `JSON 으로 읽지 못했습니다. 중괄호와 따옴표, 쉼표를 확인하세요.`
  - `{"mcpServers":{}}` → `설정에 서버가 없습니다.`
  - `{"a":{"args":["x"]}}` → `'a' 항목에 command 도 http(s) url 도 없습니다.`
  - `{"a":"node"}` → `'a' 항목이 객체가 아닙니다.`
  - `{"a":{"command":"node","args":"s.mjs"}}` → `'a' 항목의 args 는 문자열 배열이어야 합니다.`
  - `{"command":"","args":[]}` → `설정에 command 도 http(s) url 도 없습니다.`
  - `node "s.mjs` → `따옴표가 닫히지 않았습니다.`
  - `https://x.test/mcp extra` → `URL 에 공백이 있습니다. 주소 하나만 붙여 넣으세요.`
  - `API_KEY=1` → `실행 명령이 없습니다. 환경변수 뒤에 명령을 적으세요.`
- `url 이 http(s) 가 아니면 거절한다`: `{"a":{"url":"ftp://x"}}` → `'a' 항목에 command 도 http(s) url 도 없습니다.`
- `같은 입력은 같은 결과다`: 첫 줄 입력을 두 번 풀어 `JSON.stringify` 가 같다.

### 7.3 `web/tests/build-precheck-request.test.ts`, `fix-summary.test.ts` (T2, 새 파일)

`build-precheck-request.test.ts`:

- `stdio 대상에 격리를 켜면 sandbox 를 싣는다`: `{ argv: ["--command","npx","--arg","-y","--arg","pkg"],
  sandbox: { compareHost: false, allowHosts: [] } }` 와 `toEqual`.
- `격리를 끄면 argv 만 보낸다`: `toEqual({ argv: [...] })`. `"sandbox" in request` 가 false.
- `env 이름을 싣지 않는다`: `envNames: ["API_KEY"]` 인 서버의 요청 `argv` 에 `--env` 가 없다.
- `http 대상은 격리를 켜도 sandbox 를 싣지 않고 헤더도 싣지 않는다`: `toEqual({ argv: ["--url",
  "https://x.test/mcp"] })`.
- `serverId, probe, baselinePath 를 싣지 않는다`: `Object.keys(request)` 가 `["argv"]` 또는
  `["argv","sandbox"]` 다.

`fix-summary.test.ts` (발견은 테스트 안에서 손으로 만든다. `ruleId` 는 실제 규칙 id 꼴의 문자열이면 된다):

- `심각을 먼저, 그다음 주의를 낸다`: 주의 하나 뒤에 심각 하나인 목록 → 심각 줄이 먼저.
- `같은 심각도의 같은 문장은 한 줄로 접고 건수를 센다`: 같은 `fix` 의 심각 셋 → `count: 3` 한 줄.
- `심각도가 다르면 같은 문장도 따로 낸다`: 같은 `fix` 의 심각 하나, 주의 하나 → 두 줄.
- `낮음과 정보는 내지 않는다`: 낮음 하나, 정보 하나 → `[]`.
- `flow 발견은 내지 않는다`: `ruleId: "flow/..."`, `severity: "high"` → `[]`.
- `각 심각도 안에서는 발견 순서다`: 심각 A, 심각 B → A, B 순.
- `입력을 바꾸지 않는다`: `Object.freeze` 한 배열을 넘겨도 던지지 않는다.

  인증이 필요한 서버는 접속 실패로 끝날 수 있습니다.`
- `서버가 둘이면 고르게 하고 둘째를 고르면 대상 줄이 바뀐다`: `점검할 서버` select.

- `격리를 끄면 이 머신에서 실행된다고 말한다`: `격리를 끄면 서버가 이 머신에서 사용자 권한으로 실행됩니다.`
- `점검 시작이 env 없는 본문을 POST 한다`: fetch 의 `POST /api/analyze/security` 본문이 `{ argv:

- `점검 시작을 누르면 점검 단계로 넘어가고 입력이 사라진다`: 단계 표시가 `점검`, textarea 가 없다.
- `done 뒤 결과를 읽으면 결과 단계다`: `GET /api/analyze/security/<runId>` 가 한 번 불리고 `판정: ` 줄이 보인다.
- `심각·주의 발견이 있으면 먼저 할 일 카드가 해결 문장을 보인다`: 같은 `fix` 의 심각 둘, 다른 `fix` 의 주의
  하나인 응답 → `h2` `먼저 할 일`, 줄 둘, 첫 줄에 ` (발견 2건)`, 칩의 `data-severity` 가 `high`, `medium`.
- `심각·주의 발견이 없으면 먼저 할 일 카드가 없다`: 낮음 하나뿐인 응답 → `queryByRole("heading",
  { name: "먼저 할 일" })` 가 null.
- `격리를 쓰지 못했으면 그 문장을 alert 로 보인다`: `sandboxLine` 이 `행위 관측 안 함: ...` 인 응답 →
  `role="alert"` 에 그 글자(`SecurityResult` 가 그린다).
- `결과 요청이 400 이면 붙여넣기 단계로 돌아가 error 문장을 그대로 보인다`: 입력 글자가 남아 있다.
- `서버 다시 붙여넣기를 누르면 입력과 격리 선택이 남는다`.
- `다시 점검은 같은 본문을 다시 POST 한다`.
- `해결 문장을 HTML 로 해석하지 않는다`: `fix` 가 `<img src=x onerror=1>` 인 응답 → `document.querySelector("img")`
  가 null 이고 그 글자가 텍스트로 보인다.

## 11. 확인이 필요한 결정

1. **env 와 헤더를 넘기지 않는다(§3).** API 키가 있어야 뜨는 서버는 사전 점검이 연결 실패로 끝난다. 화면은
   CLI 의 실패 문장을 그대로 보인다. 가짜 값을 대신 넘겨 그런 서버도 띄우려면 `cli` 의 `--env` 처리와
   `audit` 의 카나리 계획을 고쳐야 하고, 둘 다 이 계획의 범위 밖이다. 후속 후보다.
2. **Docker 가 없어도 점검은 돈다(§1.2).** 격리 토글이 켜져 있어도 Docker 가 없으면 서버가 호스트에서 뜬다.
   시작 전 힌트와 결과의 경고 줄이 알린다. 사용자 모드에서는 "Docker 가 없으면 시작하지 않는다" 가 더
   안전한 기본값일 수 있다. 그러려면 서버 면에 Docker 감지 경로를 더하거나 CLI 에 격리 필수 옵션을 더해야
   한다. 후속 후보다.
3. **사이드바 라벨을 영어로 뒀다(§4.4).** 기존 메뉴가 전부 영어(`Test`, `Runs`, `Settings`)라 `Check`,
   `Switch to User`, `Switch to Developer` 로 맞췄다. 한국어가 낫다고 보면 §4.4 표의 세 줄과 §7.5 의 단언만
   바꾸면 된다.
4. **저장값은 마지막으로 머문 모드다(§3).** 사용자 모드인 사람이 개발자 주소 링크를 열면 그 뒤로는 개발자
   모드로 기억된다. 전환 링크를 눌렀을 때만 바뀌게 하려면 이탈 확인과의 순서를 따로 짜야 한다.
5. **로드맵 §0 의 "대시보드 메뉴" 결정을 고친다.** `Analyze` 의 두 탭은 개발자 모드에 그대로 있고, 사용자용
   점검은 모드를 나눠 따로 둔다. ADR-0111 이 기록한다.
6. **사용자 모드에 `Runs` 가 없다.** 사전 점검 run 은 지금도 Runs 목록에 실리지 않는다(ADR-0110). 지난
   점검 결과를 다시 볼 방법이 없다. 새로 고침하면 결과가 사라진다.

## 12. 자체 검토

- 요구사항 대응: 한 번만 묻기(T1 §5.1 의 리다이렉트 규칙과 §7.5), 전환을 `Settings` 위에(T1 §5.1
  Sidebar 2번과 §7.5 의 라벨 순서 단언), 사용자 메뉴는 사전 점검 하나(T1 §5.1 Sidebar 1번), 기존 해결
  문장으로 구성(T2 §5.4 와 §7.4), 개발자 화면 불변(§1.3-3·10, T1 게이트).

  글자로 적었다.
- 유닛테스트는 jsdom 과 스텁만 쓴다. 실제 서버와 Docker 는 최종 게이트(직렬, 오케스트레이터)에만 있다.
- 통합 게이트(§8.3)가 태스크마다 있고 대장 기록을 요구한다. 최종 게이트에 실환경 확인이 있다.

  쓴 것과 같다).
