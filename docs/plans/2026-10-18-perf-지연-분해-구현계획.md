## 0. 목표, 비범위, 완료 조건

**목표.** 설계 §1.1 의 일곱 항목을 그대로 쓴다. 요약하면 케이스별 응답·외부 대기·서버 안 시간·외부 요청 수 표,
본문 끝 종료 시각, 진단 두 규칙, 기준선 회귀 게이트(종료 코드 2), 실패 분리, 집계·판정·문장의 결정론, 비밀 미기록이다.

**비범위.** 설계 §1.2 전부. 더해서 팀 `CLAUDE.md`·`CONTRIBUTING.md` 의 scope·의존 방향 줄 갱신(Q5), analyze 설계 §9 에
성능 카드 한 줄 적기(Q1), record 오너와의 2단계 협의(Q2)는 이 계획의 태스크가 아니다.

## 1. 실행 모델

최대 셋이라, 실행 세션을 태스크마다 빈 컨텍스트로 새로 여는 편이 앞 태스크의 맥락에 덜 끌려가기 때문이다.

## 2. 태스크 공통 규칙

모든 실행 프롬프트에 그대로 들어가는 규칙이다. 여기 적는 것은 사람이 읽기 위한 것이고, 프롬프트는 각자 전문을 갖는다.

- **테스트 먼저.** 각 태스크는 자기 테스트 파일을 먼저 쓰고 실패를 확인한 뒤 구현한다.
- **표적 검증** 은 태스크 절의 명령. **회귀 검증** 은 worktree 루트에서
  `pnpm build --force && pnpm typecheck --force && pnpm lint && MCPEAK_SKIP_DOCKER_E2E=1 pnpm test` 이고, build·typecheck
  출력에 `Cached: 0 cached` 가 있어야 한다. 도커 격리 E2E 는 perf 와 무관해 건너뛴다(CI `verify` 와 같은 설정).
  skip 문장은 에이전트 환경에서 안 보이므로 통과 수와 skip 수로 판정한다.
- **병렬 웨이브의 E2E 흔들림.** W2 는 세 세션이 동시에 `pnpm test` 를 돌린다. e2e 갈래 스펙이 타이밍으로 실패하면
  그 파일만 단독으로 다시 돌려 결과 둘을 모두 보고한다. 단독 녹색이면 그 실패는 결함으로 보지 않는다.
- **커밋하지 않는다.** 실행 세션은 worktree 생성 외의 git 쓰기를 하지 않는다.
- **보고서** 는 `docs/reports/2026-10-19-perf-<태스크>.md` 하나이고 허용 Files 안이다. pwd, `git rev-parse HEAD`, BASE,
  실제 의존성 경로(`realpath node_modules`), 실행한 명령과 통과·실패 수, 임의로 판단한 것을 적는다.

```ts
/** 리포트·기준 파일·진단·오류 문장에 싣는 URL 모양. 스킴·userinfo·fragment 를 지우고 쿼리 값을 가린다. */
export function displayUrl(url: string): string {
  let parsed: URL;
  try {
    parsed = new URL(url);
  } catch {
    return "[URL]";
  }
  const names = [...parsed.searchParams.keys()];
  const query = names.length === 0 ? "" : `?${names.map((name) => `${name}=…`).join("&")}`;
  return `${parsed.host}${parsed.pathname}${query}`;
}
```

   `pnpm build --force && pnpm typecheck --force && pnpm lint && MCPEAK_SKIP_DOCKER_E2E=1 pnpm test` 를 돌려 `Cached: 0 cached` 를

   (YYYY-MM-DD)를 탭으로 이은 한 행으로 더하고, 사람이 별도 문서 커밋으로 남긴다(`docs(perf): perf-<태스크> 통합 기록`). 수정
   루프 뒤 다시 병합했으면 앞 행을 지우고 새 행을 넣는다. 같은 웨이브의 병렬 태스크는 하나씩 병합·기록한다.
8. **정리.** 6·7 이 통과한 뒤에만 한다. 그 worktree 안의 세션(실행 세션, 오케스트레이터 자신 포함)을 프로젝트 루트로 내보내고,
   그 worktree 의 `git status --short` 가 비었는지 본 뒤 사람이 `git worktree remove <그 worktree 절대 경로>`, `git worktree prune`,
   `git branch -d feat/perf-<태스크>` 를 실행한다.

    발행 권한이 새 패키지에도 적용되는지 릴리스 담당(@storyrago)이 확인한다.
