## 4. 계획서와 다르게 옮긴 곳과 이유

**본질적으로 다르게 처리한 곳은 없다.** 딱 하나, 실행 방식의 재량이 있었다.

- 9곳의 import 교체 후 `npx biome check --write <교체한 파일들>` 을 한 번 돌려 import 정렬을
  자동으로 맞췄다. `StepConfirm.tsx` · `StepMode.tsx` · `StepRunOptions.tsx` 세 파일에서 import
  줄 순서가 biome 기준으로 재배치됐다(가져오는 심볼과 최종 내용은 계획서 그대로, 줄 순서만
  이동). 계획서 §5-3 이 "biome 의 import 정렬이 줄 위치를 옮길 수 있다 — 정렬 결과를 그대로
  받는다"고 미리 적어 둔 바로 그 상황이라 손으로 정렬을 다시 맞추는 대신 도구가 낸 결과를
  받았다. `pnpm lint`(`biome check .`, 쓰기 없음)가 419개 파일에서 "No fixes applied"로 끝나
  최종 상태가 biome 기준과 일치함을 확인했다.
- 그 밖의 모든 산출물(`Field.tsx` 의 JSX·클래스 상수, `RunView.tsx` 의 `Field` 치환, `QuestionPanel.tsx`

  §5-3 이 적은 그대로 구현했다.

2. **되찾은 `disabled:opacity-50` 을 실제로 확인할 실행 경로가 없다(§13-9, §0 마지막 표 행).**

   방식의 복제가 다시 새어 나갈 수 있다.
3. **PR B 선행 조건.** `components/Field.tsx` 의 `INPUT_BASE` 안 포커스 링 리터럴은 PR B 가
   `focus-ring.ts` 의 `FOCUS_RING` 상수로 교체할 자리다(계획서 §5-1 마지막 문단). PR A 를 먼저
   확정한 뒤에 PR B 를 얹어야 한다(계획서 §7 웨이브 순서와 동일).
4. **시각 확인 셋(§12 표의 7·8·9·12·14·17·18·19행, `outline` 색·offset, `disabled:opacity-50`
   실제 렌더)은 이 태스크 범위 밖이다.** 오케스트레이터의 §11 통합 게이트·§12 시각 점검이

### 6-2. 화면을 못 띄운 행과 그 대신 잰 것

17(Run 상세 repair 폼) · 18(QuestionPanel 입력칸)은 **실패한 실행과 대기 중인 질문이 있어야**
뜨고, 19(Replay)는 **녹화본이 있어야** 뜬다. 이 환경에는 셋 다 없다. 그래서 세 자리가 쓰는
클래스 문자열을 **빌드된 실제 CSS 에 대고** 쟀다(살아 있는 페이지에 탐침 요소를 넣어
`getComputedStyle`). 이것이 §13-3 「Tailwind 유틸리티 충돌」과 §13-9 「되찾은
`disabled:opacity-50` 을 확인할 실행 경로가 없다」를 실제로 판정하는 유일한 수단이었다.

| 클래스 | 테두리(다크) | 테두리(라이트) | 포커스 링 | `disabled` opacity |
|---|---|---|---|---|
| `INPUT_CLASS` (행 17 repair) | `rgb(42, 42, 51)` = `--line` | `rgb(232, 232, 236)` | ✓ 2px · offset 2px | **0.5** |
| `${INPUT_CLASS} font-mono` (행 17 실제 형태) | 같음 | — | ✓ | — |
| `INPUT_ON_ACCENT_CLASS` (행 18 QuestionPanel) | `rgb(76, 53, 117)` = `--accent-border` | `rgb(221, 214, 254)` | ✓ 2px · offset 2px | **0.5** |

**두 가지가 확인됐다.**

1. **두 갈래가 실제로 다른 테두리 색으로 그려진다.** `INPUT_CLASS` 는 `--line`,
   `INPUT_ON_ACCENT_CLASS` 는 `--accent-border` 다. `${INPUT_CLASS} border-accent-border` 로
   덧붙였다면 승패를 생성된 CSS 의 소스 순서가 정했을 자리다(§3-3). 별도 상수로 가른 판단이
   맞았다는 것을 문자열이 아니라 렌더된 색으로 확인했다.
2. **되찾은 `disabled:opacity-50` 이 두 갈래 모두 `opacity: 0.5` 로 실린다.** §13-9 는 이것을
   확인할 실행 경로가 없어 `field.test.tsx` 의 문자열 단언이 유일한 그물이라고 적었는데,
   탐침으로 실제 렌더값까지 확인했다. 복제가 잃었던 것이 정말로 돌아왔다.

19(Replay 「서버 명령」 · 「스위트 경로」)는 `ReplayView` 가 같은 `INPUT_CLASS` 를 쓰고, 그
상수를 위 여섯 행에서 이미 화면으로 여덟 번 확인했다. 녹화본이 생기면 §12 를 다시 돌린다.
