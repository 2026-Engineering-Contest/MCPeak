### 5-6. jsdom 이 못 보는 것 — 빌드 CSS · 실제 브라우저로 확인

§13-1·13-2 가 「초록인데 틀릴 수 있다」고 적은 자리라, 클래스 문자열 단언에 기대지 않고
**빌드 산출물과 실행 중인 대시보드**에서 직접 쟀다.

**(가) 음수 offset 문법이 실제로 컴파일된다.** `dist/web/assets/index-*.css` 에 둘 다 있다.

```
focus-visible\:-outline-offset-2:focus-visible{outline-offset:calc(2px * -1)}
focus-visible\:outline-offset-2:focus-visible{outline-offset:2px}
focus-visible\:outline-focus-ring:focus-visible{outline-color:var(--focus-ring)}
focus-visible\:outline-2:focus-visible{outline-style:var(--tw-outline-style);outline-width:2px}
--focus-ring:var(--lightningcss-light,#6d28d9)var(--lightningcss-dark,#a78bfa);
```

`calc(2px * -1)` 로 나오므로 `outline-offset:-2px` 를 문자열로 찾으면 0건이다 — 이 값으로
판정하려는 사람이 헛다리를 짚지 않게 적어 둔다.

**(나) 실제 브라우저에서 링이 잘리지 않는다.** `localhost:7357` 의 대시보드(내 빌드가
서비스되는 것을 DOM 으로 확인)에서 **진짜 Tab 키**로 세그먼트에 들어가 §12 스니펫 논리대로 쟀다.
`el.focus()` 는 `:focus-visible` 을 띄우지 않아(`matchesFocusVisible: false`, `outline: none`)
키보드 Tab 으로 바꿔야 했다 — §12 의 경고가 실제로 그대로 재현됐다.

| 테마 | 요소 | `:focus-visible` | outline | offset | 잘림 |
|---|---|---|---|---|---|
| light | `stdio (위 서버 명령)` | true | `solid 2px rgb(109, 40, 217)` | `-2px` | **false** |
| light | `HTTP URL` | true | `solid 2px rgb(109, 40, 217)` | `-2px` | **false** |
| dark | `stdio (위 서버 명령)` | true | `solid 2px rgb(167, 139, 250)` | `-2px` | **false** |

§12 「기대값」의 라이트 `rgb(109, 40, 217)` · 다크 `rgb(167, 139, 250)` · 세그먼트만 `-2px` ·
잘림 false 와 전부 일치한다. (측정 중 테마를 다크로 바꿨다가 **light 로 되돌려 두었다.**)

**(다) 런타임 클래스 문자열.** `INPUT_CLASS`·세그먼트 버튼 클래스는 템플릿 리터럴이라 번들에서

```

px-3 py-1.5 text-sm disabled:opacity-50 ${f} ${e.value===t.value?`bg-accent-soft …
```

`d`=`FOCUS_RING`, `f`=`FOCUS_RING_INSET` 이고 삽입 위치가 §5-1·§6-1 의 고정 문자열과 같다.
`on-accent` 는 평문이라 그대로 보인다 — `border border-accent-border bg-surface text-ink hover:border-accent`.

**(라) 머리글 상속(§6-4 · §13-4).** `TestOptionsPanel` 은 `Button` 으로 옮기지 않았고 diff 가
`FOCUS_RING` import 1줄과 className 의 `${FOCUS_RING}` 뿐이다 — `text-sm`·`font-medium` 을
하나도 들이지 않았으므로 h2 의 17px·600 상속 경로가 그대로다. 다만 **computed 17px·600 을 눈으로
확인하지는 못했다**(Test 3단계까지 폼을 채워야 닿는 자리다). §12 점검표 11번에 남긴다.

## 6. 계획서와 다르게 한 곳

셋뿐이고 전부 기계적인 것이다.

1. **biome 포맷터 결과를 받았다**(§5-3). `SegmentedControl` 시그니처 3줄 → 1줄, QuestionPanel
   「아니오」 `Button` props 5줄 → 1줄. DOM·클래스 문자열·단언은 그대로다.
2. **`StepRunOptions` 의 `value` 에 캐스트를 넣었다.**
   `value={props.sessionMode as (typeof TEST_SESSION_MODES)[number]}`.
   `props.sessionMode` 는 `SessionMode`(`replay` 포함)인데 `options` 에서 추론되는 `V` 는
   `"off" | "record"` 라 타입이 좁아서다. **동작은 예전과 같다** — 예전 코드도
   `props.sessionMode === mode` 로 비교했고 `replay` 면 아무 칸도 눌리지 않았다. 캐스트 뒤에도
   `replay` 는 `options` 에 없어 전부 `aria-pressed="false"` 가 된다. 같은 캐스트가 이 파일
   `SESSION_HINTS` 조회(`:130` 부근)에 이미 쓰이고 있어 새 패턴도 아니다.
3. **`TransportFields` 의 `FOCUS_RING` import 를 T-B2 단계에서 함께 넣었다.** 같은 파일을
   T-B4 에서 또 열 일이라 한 번에 처리했다. 결과는 태스크를 나눠 했을 때와 같다.

`ThemeToggle` 흡수(§6-3 대조표) · `Card` 다형(§0 비범위) · variant 를 안 더하는 갈래 —
§14 가 ADR 이 필요해지는 세 경우로 꼽은 것 중 **하나도 뒤집지 않았다. 새 ADR 이 필요 없다.**

## 7. 남은 위험

1. **시각 점검이 아직 부분만 끝났다.** 내가 실측한 것은 §12 점검표의 4번(접속 방식 세그먼트)과
   라이트·다크 색·offset·잘림이다. **나머지 18행은 오케스트레이터 몫으로 남아 있고**, 그중
   특히 둘이 내 변경과 맞물린다.
   - **11번 — 접이식 머리글 17px·600.** 위 (라)의 근거는 구조적이고(폰트 유틸리티 0개 추가),
     computed 값으로는 못 봤다. `Button` 으로 옮기지 않았으니 내려앉을 이유가 없지만 §13-4 가
     「테스트는 role·level 만 본다」고 꼽은 자리다.
   - **18번 — QuestionPanel 버튼 셋.** `on-accent` 가 accent-soft 면 위에서 대비가 사는지는
     눈으로만 판정된다. §6-2 가 예고한 **시각 변화 셋이 실제로 일어난다**: `font-medium` 이
     붙고, 뒤로가기 글자색이 `text-ink-muted` → `text-ink` 가 되고, 모서리가 `rounded`(4px) →
     `rounded-sm`(6px) 이 된다. 계획서가 「되돌리지 않는다」고 정한 것이라 그대로 두었지만,
     이견이 생기면 §6-2 가 적은 대로 **variant 를 쪼개지 말고 이 PR 을 되돌리는 것**이 맞다.
2. **`TransportFields` 세그먼트가 `disabled:opacity-50` 을 새로 얻었다**(§6-1 의 의도한 변화 1).
   `disabled:` 변형이고 그 세그먼트는 비활성이 되는 경로가 없어 지금 렌더는 그대로다. 다만
   **그 경로가 없다는 것은 곧 되찾은 유틸리티를 확인할 실행 경로도 없다는 뜻**이라, PR A 의
   `disabled:opacity-50` 회복과 같은 종류의 「확인할 수 없는 복구」다. `segmented-control.test.tsx`
   의 disabled 두 케이스가 대신 서는 그물이다.
3. **`<button` 완료 판정값이 문서와 어긋난 채 남아 있다**(§5-5). 실측 10이 맞고 계획서의 8이
   틀렸다. 오케스트레이터가 이 숫자로 게이트를 돌리면 실패로 읽힌다. 계획서는 읽기 전용이라
   고치지 않았다.
4. **`git grep` 의 추적 파일 한정**(§5-4 각주). 커밋 전에 `--untracked` 없이 세면 신규 4파일이
   빠져 세그먼트 판정이 거짓으로 0줄이 된다. §13-8 이 경고한 「0줄인데 테스트는 통과」와 부호만
   반대인 거짓 신호다.
5. **Node 26 플래그.** `NODE_OPTIONS=--no-experimental-webstorage` 없이 돌린 8개 파일의 빨간
   출력은 회귀가 아니다(§1 · §13-5). CI 는 Node 22.18.0 · 24 라 해당하지 않는다.

### 8-4. 세그먼트 렌더가 그대로인가 (§12 「따로 확인할 값 셋」)

눌린 칸 `bg-accent-soft` `rgb(36, 26, 53)` · `text-accent` `rgb(139, 92, 246)` ·
`font-semibold` **600**, 안 눌린 칸 `text-ink-muted` `rgb(139, 139, 150)`.
복제 세 벌이 내던 값 그대로다 — **한 벌로 합치면서 렌더가 달라지지 않았다.**

### 8-5. 잘림 없음을 눈으로도 확인했다

계산(`잘림: false`)만이 아니라 좁은 뷰포트에서 렌더해 실제로 봤다. 포커스 링이
`<fieldset>` 의 `overflow-hidden` **안쪽**에 네 면 다 온전히 그려진다. `outline-offset-2`
(바깥)로 갔다면 테스트는 전부 초록인 채 화면에서만 사라졌을 자리다(§13-2).

빌드 CSS 에도 `focus-visible\:-outline-offset-2{outline-offset:calc(2px * -1)}` 가 실제로
나온다. 다만 `calc(2px * -1)` 로 나오므로 `outline-offset:-2px` 를 문자열로 찾으면 0건이다.
