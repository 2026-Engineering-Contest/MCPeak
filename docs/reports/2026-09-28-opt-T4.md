## 임의로 판단한 부분

1. **대상 파싱은 `parseTestCommand` 를 그대로 부른다.** `--out`·`--json` 을 먼저 떼고, test 전용 옵션
   (`--junit`·`--determinism`·`--session` 등)은 넘기기 전에 "지원하지 않는 optimize 옵션" 으로 거절한다.
   나머지를 첫 자리에 형식용 명세 경로를 붙여 넘기고, 사용 오류의 문장은 그대로, 해결 줄만 optimize 사용법으로
   바꾼다. `--arg` 값과 `--` 뒤는 해석하지 않는다. test 의 오류 클래스가 export 되지 않아 `failure` 모양으로 읽는다.
2. **서버 정보는 연결 함수를 감싸 잡는다.** `openConnection` 이 `CliConnection` 으로 좁혀 돌려주고 HTTP 는
   객체를 새로 만들어 `instructions`·`capabilityKeys` 가 빠진다. connect-target 을 고치지 않고, 주입하는
   `connectStdio`·`connectHttp` 를 감싸 반환값에서 잡았다.
3. **`generator.version` 은 `@mcpeak/optimize` 의 버전이다.** 그 패키지의 `exports` 가 `package.json` 을 열지
   않아 `index.ts` 가 `../../optimize/package.json` 을 상대 경로로 import 한다. 빌드가 값으로 싣고, 릴리스는
   `changeset version` 뒤에 빌드하므로 발행 시점의 두 버전이 맞는다. optimize 가 버전 상수를 export 하면 그쪽이 낫다.
4. **`--out` 파일이 있으면 덮어쓴다.** §7.3 이 "같은 명령으로 다시 만드세요" 라고 안내하므로 재실행이 기본
   흐름이다. generate 의 `--force` 같은 옵션은 두지 않았다.
5. **게이트 A 실패 시 파일을 쓰지 않는다.** `오류 [LOSSLESS_VIOLATION]: 오버레이를 쓰지 않았습니다.` 한 줄 뒤에
   §7.1 문장을 그대로 싣고 종료 코드 1.
6. 새 오류 코드 셋: `MCP_LIST_TOOLS_FAILED`, `OVERLAY_WRITE_FAILED`, `OPTIMIZE_RUNTIME_UNAVAILABLE`. 연결 실패는
   test 와 같은 `MCP_CONNECTION_FAILED/<core 코드>` 모양과 stderr 20줄·HTTP 진단 블록을 쓴다.
7. `otherCapabilities` 는 core 의 `capabilityKeys` 에서 §5.1 의 네 종류만 남긴다(`experimental` 등은 뺀다).
8. 프록시 오버레이 파싱의 이름표는 경로가 아니라 `"오버레이"` 다. §7.3 첫 줄이 이미 경로를 싣는다.
9. cli e2e 가 프록시를 띄울 때 optimize 의 `tests/fixtures/proxy-entry.mjs` 를 쓴다. CI verify 는 빌드 없이 돌아
   dist 가 없기 때문이다. 다른 패키지의 테스트 픽스처를 읽기 전용으로 참조한다.
10. `mcpeak help optimize` 머리줄은 기존 세 명령과 같은 형식(명령 이름, 대시 기호, 한 줄 설명)을 따랐다.
    CLI 출력 형식을 맞춘 것이고 문서 산문에는 대시를 쓰지 않았다.
