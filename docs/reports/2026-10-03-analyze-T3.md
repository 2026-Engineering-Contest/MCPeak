## 임의로 판단한 부분

1. **아이콘.** 세로 막대 셋(`M6 20V14`, `M12 20V4`, `M18 20V10`). 가운데가 가장 높고 오른쪽이 중간이라 막대그래프로 읽힌다. 바닥선은 넣지 않았다. 다른 아이콘이 선 2~3개의 단순한 모양이라 그 밀도에 맞췄다.
2. **표의 클래스.** `RunView` 목록 표를 따라 `Card className="overflow-hidden"` 안에 `w-full table-fixed text-left text-sm`, 본문 `divide-y divide-line-subtle`. `table-fixed` 는 긴 도구 이름이 숫자 열을 카드 밖으로 밀지 않게 하려는 것이고 이름 칸에 `truncate` 를 줬다. 머리 행은 `text-caption font-medium text-ink-muted`(RunCounts 의 `dt` 와 같은 결). 숫자 네 열은 `w-24`/`w-20` 고정폭, `text-right tabular-nums`. 이름은 `font-mono text-xs`(StepConfirm 의 값 칸과 같다).
3. **요약 세 칸.** `Card` 안 `<dl className="grid grid-cols-3 gap-4">`, `dt` 는 `text-caption font-medium text-ink-muted`, `dd` 는 `text-sm tabular-nums text-ink`. RunCounts 처럼 `text-display` 를 쓰지 않은 것은 값이 숫자 하나가 아니라 문장이라서다.
4. **탭 모양.** `SegmentedControl` 의 바깥 틀(`inline-flex overflow-hidden rounded-md border border-line`)과 칸 클래스(`px-3 py-1.5 text-sm`, 포커스는 `FOCUS_RING_INSET`)를 같이 따랐다. 계획서가 정한 것은 눌린 쪽 클래스뿐이다.
5. **"주의:" 두 줄.** 하나의 `<p className="whitespace-pre-line">` 안에 리포트의 두 줄을 `\n` 으로 이어 넣었다. 글자가 리포트와 같고 줄바꿈 위치도 같다. 색은 `--status-waiting-fg`(경고 성격. 실패색은 피했다).
6. **분석 실패 표시.** `<pre role="alert">` 에 `whitespace-pre-wrap`, 색 `--status-failed-fg`(Home 의 실패 문장과 같은 색). 저장 요청 실패(`ApiRequestError`)는 `<p role="alert" className="whitespace-pre-line text-sm text-ink">`(MockBuilder 의 저장 실패와 같은 모양). 성공·충돌 안내는 `<p role="status">`.
7. **저장 버튼 비활성.** 경로가 공백뿐이면 `오버레이 저장` 을 비활성으로 뒀다. 계획서에 없다. 빈 경로로 PUT 하면 서버의 경로 문장이 오지만 막을 수 있는 입력이라 막았다. 경로 자체는 trim 하지 않고 입력 그대로 보낸다(계획서 문장의 `${path}` 와 같게).
8. **새 분석 시작 시 이전 결과를 지운다.** `setResult(null)` 로 `TokensResult` 가 내려가 저장 경로·저장 문장도 초기화된다. 이전 결과의 오버레이를 새 분석 도중 저장하는 일을 막는다.
9. **`saveRecentCommand` 조건.** `transport === "stdio"` 이고 직접 입력 갈래이며 `target` 이 비지 않았을 때. Home 은 transport 를 안 보지만 계획서가 "직접 입력 stdio 갈래" 라고 적었으므로 그대로 했다.

## 계획서와 다른 점 (보고만 한다)

- **`StepRunServer` 에 `idPrefix` prop 이 없다.** 계획서 §5.6 은 `StepRunServer` 를 `idPrefix="analyze"` 로 쓰라고 했지만, `home/steps/StepRunServer.tsx` 는 내부에서 `TransportFields`·`StepServer` 에 `"home-run"` 을 박아 넘긴다. 이 파일은 수정 금지라 prop 없이 그대로 썼다. 화면이 한 번에 하나만 그려지므로 DOM id 충돌은 없다. 다른 화면과 id 를 가르려면 `StepRunServer` 에 선택적 `idPrefix?: string`(기본 `"home-run"`)을 더하는 변경이 필요하다. 그 파일 오너의 판단 사항이다.
- `buildAnalyzeArgv` 의 세 문장은 `build-test-argv.ts` 의 것과 글자 단위로 같아 조정할 필요가 없었다. `isHeaderEnv` 는 `header-env.ts` 의 것을 재사용했다.

## 남은 위험

- 실제 서버를 띄운 화면 확인은 하지 않았다(지시대로 jsdom·fetch 스텁만). 서버 응답 모양은 `api-types.ts` 타입과 T4 E2E 가 보증한다.
- `TokensResult` 의 표 행 key 를 도구 이름으로 썼다. MCP 서버가 같은 이름의 도구를 둘 내면 React key 경고가 난다(표시는 된다). optimize 가 이름 중복을 어떻게 다루는지는 확인하지 않았다.
