## 임의로 판단한 부분

- **서버 하나를 `beforeAll` 에서 띄워 다섯 테스트가 공유한다.** `dashboard-e2e.test.ts` 는 테스트마다
  서버를 띄우고 닫지만, §7.4 가 "임시 루트에 띄운다" 와 "afterAll 에서 지운다" 를 함께 요구하므로
  임시 루트와 서버의 수명을 파일 단위로 맞췄다. 테스트 사이에 공유하는 상태는 4번이 쓰는
  `weather.optimize.json` 하나뿐이고 다른 테스트는 그 파일을 읽지 않는다.
- **1번에서 직접 실행의 종료 코드도 단언한다.** §7.4 에는 없지만, 직접 실행이 실패하면
  `capturedText` 가 `undefined` 가 되어 "바이트가 다르다" 는 엉뚱한 실패로 보인다. 종료 코드 단언에
  stderr 를 메시지로 붙여 원인이 바로 보이게 했다.
- **200 단언에 응답 본문을 메시지로 붙였다.** 분석이 400 으로 떨어지면 CLI 의 stderr 문장이
  실패 출력에 그대로 찍힌다.
- **5번의 접두 검사는 `toMatch(/^오류 \[MCP_CONNECTION_FAILED/)` 로 했다.** `startsWith(...).toBe(true)` 는
  실패 시 `expected false to be true` 만 보여 주기 때문이다.
- `generatorVersion` 은 `import optimizeMetadata from "../../optimize/package.json"` 로 읽었다.
  `analyze.ts` 와 cli 가 쓰는 방식과 같다.
