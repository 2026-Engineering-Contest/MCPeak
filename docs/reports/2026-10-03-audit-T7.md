## audit 패키지에서 발견한 결함 (고치지 않음, 보고)

1. **`desc/injection` 첫 문형이 "ignore the previous instructions" 를 못 잡는다.** `rules/description.ts` 의 `/\bignore (all |any )?(previous|prior|…) (instructions?|…)\b/` 가 관사 "the" 를 허용하지 않는다(계획서 §3.2 문형 그대로). MCPTox 에서 이 문장이 든 418건 중 3건만 걸렸다. 그중 292건은 원문이 "instructionsand" 처럼 공백이 빠져 끝의 `\b` 에도 막힌다. 가장 흔한 주입 문장이라 우선순위가 높다. `(the )?` 와 끝 경계 완화가 필요해 보인다(benign 픽스처 재확인 필요).
2. **`desc/shadowing` 이 따옴표로 다른 도구를 가리키는 문형을 못 잡는다.** "when using the 'get-autocomplete' tool, you MUST …"(210건), "before using the 'read_file' tool …"(60건)이 0건이다. 첫 문형은 "tool is available" 꼴만, 다섯째 문형은 관사 뒤에 바로 tools 가 오는 꼴만 본다.
3. **`renderReport` 가 위치 줄의 도구 이름을 원문 그대로 쓴다.** 표적 서버의 `get\u200Btime` 이 리포트 위치 줄에 U+200B 를 그대로 담아, 사람 눈에는 `gettime` 으로 보인다(위 검증 출력의 `get\u200Btime` 은 보고서에서 보이게 이스케이프한 것이다). hidden-unicode 발견의 위치 줄이 정작 그 문자를 숨긴다. `evidenceFragment`/`escapeInvisible` 을 이름에도 쓰는 것이 맞아 보인다. 같은 자리에 ESC 같은 제어 문자도 그대로 실리는데, CLI 쪽은 줄마다 `escapeTerminalText` 를 씌워 막았다(아래 임의 판단 5). 보이지 않는 문자는 CLI 가 고칠 자리가 아니다.

## 임의로 판단한 부분

1. **lockfile 에 importer 두 개.** 지시는 "cli importer 줄만" 이었지만, `examples/audit-target-server` 가 새 워크스페이스 패키지라 그 importer(SDK `catalog:`)도 lockfile 에 들어갔다. 빼면 CI 의 `--frozen-lockfile` 이 실패한다. T0 의 audit 패키지 때와 같은 이유다.
2. **mock 예제 E2E 는 소스 진입점으로 띄운다.** `examples/mock-server/server.mjs` 는 `@mcpeak/mock` 의 dist 를 import 하는데 CI verify 잡은 빌드 없이 `pnpm test` 를 돌린다. 그래서 mock 패키지가 자기 E2E 에 쓰는 `packages/mock/tests/fixtures/stdio-entry.mjs`(+ `--import register-ts-resolve.mjs`)로 **같은 정의 파일** `weather.mock.json` 을 띄운다. 빌드된 dist 로 `server.mjs` 를 직접 돌린 결과도 발견 0, 종료 코드 0 으로 같았다.
3. **기대 파일 형식**은 `{ exitCode, counts, findings }`. 실제 `--json` 출력에서 만들고, 여섯 발견의 message·fix 를 §6.2 와 한 줄씩 대조했다. U+200B 는 파일에 `\u200B` JSON 이스케이프로 적었다(같은 값으로 파싱됨을 확인).
4. **`delete_all` 에 `destructiveHint: true`** 도 붙였다. 없으면 `schema/missing-destructive-hint`(low)가 일곱째로 걸려 "여섯 규칙" 사양과 어긋난다. 도구는 실제로 아무것도 지우지 않는다(readonly 정책이 부르기 때문).
5. **리포트 줄마다 `escapeTerminalText`**. 서버가 정한 글자(도구 이름 등)에 ESC 가 있으면 리포트를 읽는 터미널이 조작된다. 줄바꿈은 구조라 남긴다. `--json` 은 JSON 이스케이프가 있어 그대로 둔다. AuditError 블록도 같은 처리를 한다.
6. **`--env`·`--header-env` 사전 점검.** 감사 안에서 빈 환경변수가 걸리면 "서버에 붙지 못했습니다" 로 바뀌어 원인이 사용자 환경이라는 사실이 사라진다. 그래서 연결하지 않는 연결 함수를 넣은 `openConnection` 으로 먼저 돌려 connect-target 문장을 그대로 `CLI_USAGE` 로 낸다.
7. **실패 문장 두 개를 새로 만들었다.** 연결 뒤 실패: `오류 [AUDIT_FAILED]: 서버에 붙은 뒤 점검 도중 실패했습니다: <대상>` + `→ <원인 첫 줄>` + `해결: <core hint 또는 "mcpeak test 로 같은 서버가 tools/list 에 답하는지 먼저 확인하세요.">`, 그리고 서버 진단 블록. 기준 파일 쓰기 실패: `오류 [BASELINE_WRITE_FAILED]: 기준 파일을 쓰지 못했습니다 (<code>). 경로: <path>` + `해결: --baseline 경로의 디렉터리가 있는지와 쓰기 권한을 확인하세요.`(optimize 의 오버레이 쓰기 실패와 같은 모양).
8. **CONNECT_FAILED 뒤 서버 진단 블록.** AuditError 는 원인 첫 줄만 싣는다. CLI 의 연결 래퍼가 원래 오류를 잡아 두었다가 §6.3 블록 뒤에 `test`·`optimize` 와 같은 stderr 꼬리(또는 HTTP 엔드포인트 진단)를 붙인다. §6.3 블록 자체는 글자 그대로다.
9. `AuditCommandDependencies` 의 `connectHttp`·`readEnv` 는 필수로 두었다(§7 목록 그대로. optimize 는 선택).
10. `commandDiscovery` 에 audit 를 더했다(지시에 있음). 이 문구를 import 하는 다른 명령의 안내에도 audit 가 보인다.
11. `commandHelp("audit")` 첫 줄의 구분 기호는 기존 `commandHelp` 화면 문구(test·optimize 등)와 같은 모양으로 맞췄다. 문서 산문(ADR·README·RESULTS·보고서)에는 대시를 쓰지 않았다.
12. **MCPTox 측정 판정**: 탐지는 medium 이상(종료 코드 기준과 같음), 언급은 info 포함. 사례 1,312건 중 635건의 줄바꿈이 글자 그대로의 `\n` 이고, 일부에 `Arguments:` 목록이 붙어 있어 정규화했다(형식을 못 읽은 사례 0). 측정 스크립트는 빌드된 `packages/audit/dist` 를 읽는다.
13. ADR 번호 0104·0105 는 main 이력에서 한 번 쓰였다가 되돌려진 번호다(d1ac3d9). 색인 README 의 "빈 번호는 재사용" 규칙에 따랐다.

- 위 결함 1·2 를 고치면 `RESULTS.md` 의 값이 크게 바뀐다. 그 전의 36.1% 를 CI 하한으로 쓰면 안 된다.
