## 1) schema/over-broad

새 판정: 최상위 `properties` 가 비었거나 없고, 다음 중 하나일 때만 첫 조건(medium)을 적용한다.

- `additionalProperties === true`
- `properties` 키가 아예 없고 `additionalProperties` 도 없음

`properties: {}` 에 `additionalProperties` 가 true 가 아니면 인자 없는 도구로 보고 넘긴다.
`run_shell` 픽스처(`schema-over-broad.json`)는 `inputSchema: { "type": "object" }` 로 이미 (a) 꼴이라
그대로 두었고 medium 테스트도 그대로 녹색이다.

추가 테스트:
- `properties 가 빈 객체 {} 면 인자 없는 도구로 보고 잡지 않는다` (`list_trash`). 수정 전 `schema.ts` 로
  돌려 실패(1 failed)를, 수정 뒤 통과를 확인했다.
- `properties 가 {} 여도 additionalProperties 가 true 면 medium 으로 잡는다`.

## 2) 지시 판정 통합

두 구현의 차이는 하나였다. protocol.ts 판은 반환 조각에 `evidenceFragment` 를 이미 적용하고,
result.ts 판은 원문 조각을 돌려준 뒤 호출 지점에서 `evidenceFragment` 를 적용했다. 그래서 result.ts 의
호출 지점에서는 `evidenceFragment` 를 다시 부르지 않고 받은 조각을 그대로 쓴다. 이중 적용이 없으므로
출력은 같다. 패턴 목록(`COVERT_ACTION_PATTERNS` 뒤 `SHADOWING_PATTERNS`), 형 순서, raw 대소문자 무시,
가장 앞 일치 선택은 두 판이 같았다.

result.ts 는 이제 protocol.ts 를 import 한다. 같은 패키지 안이고 역방향 import(protocol → result)는
없어 순환은 없다.

## 임의로 판단한 부분

1. **(a)·(b) 의 읽기.** 지시를 글자 그대로 읽으면 "properties 키가 없으면 첫 조건 적용" 이라
   `{ type: "object", additionalProperties: false }` 도 medium 이 된다. 기존 테스트
   "additionalProperties 가 false 면 잡지 않는다" 와 §3.3 의 "true 또는 없음" 에 어긋나므로, 원래 조건에서
   "`properties: {}` 이고 additionalProperties 가 true 가 아님" 만 빼는 쪽으로 읽었다. 즉 (a) 는
   additionalProperties 도 없을 때다.
2. **list_trash 테스트의 설명문.** 지시의 예시 "Lists files in the trash" 는 수정 전 코드로도 잡히지 않는다.
   키워드는 `file` 인데 토큰은 `files` 라 `\bfile\b` 에 걸리지 않기 때문이다. 이 문장으로는 수정을 증명할 수
   없어 테스트 설명을 "Lists every file in the trash." 로 바꿨다.
