## 게이트웨이가 시작할 때 받는 env·인자 전문 (T1 과의 접점)

오케스트레이터의 접점 통지 그대로 맞췄다.

- 실행: `node /opt/mcpeak/gateway/server.mjs`. 인자는 읽지 않는다.
- `MCPEAK_GATEWAY_TOKEN`: 베어러 토큰. 필수. 비어 있으면 시작을 거절한다. 읽은 직후 `process.env` 에서 지우고, openssl 자식에게는 `PATH` 만 넘긴다.
- `MCPEAK_GATEWAY_INTERNAL_SUBNET`: internal 네트워크의 IPv4 CIDR(예: `172.24.0.0/16`). 필수. `os.networkInterfaces()` 에서 이 서브넷에 든 IPv4 를 찾아 `A` 응답 주소로 쓴다. 인터페이스 이름 순서에 기대지 않는다. 든 주소가 없으면 시작을 거절한다.
- `MCPEAK_GATEWAY_MODE`: `live` | `record` | `replay`. 없으면 `live`. 그 밖의 값이면 시작을 거절한다.
- 듣는 곳: `0.0.0.0` 의 UDP 53, TCP 80, TCP 443, TCP 7000(제어). 포트를 바꾸는 env 는 없다.
- 쓰는 곳: `os.tmpdir()`(컨테이너에서는 `/tmp`) 아래 `mcpeak-gateway-ca-*` 디렉터리 하나. CA 키, CA 인증서, 잎 인증서용 키가 여기 있다. 그 밖에는 아무것도 쓰지 않는다.
- 시작 거절은 stderr 에 `→ 게이트웨이를 시작할 수 없습니다: <이유>` 한 줄을 내고 종료 코드 1 이다. T1 의 `start-failed` detail 재료로 쓸 수 있다.
- `SIGTERM`·`SIGINT` 를 받으면 닫고 0 으로 끝난다.

모드별 동작:

- `live`: 전달만 한다. 녹화를 쌓지 않는다. `GET /session` 은 `entries` 가 빈 세션이다.
- `record`: 전달하고 상류 응답을 쌓는다.
- `replay`: 시작부터 재생이다. `POST /session` 을 받기 전에는 빈 세션이라 모든 요청이 `replay-miss`(504)다.
- 어느 모드로 시작했든 `POST /session` 이 성공하면 재생으로 넘어간다(§3.7 표 그대로).

## 제어 포트의 경로·요청·응답 형식 전문 (T1 과의 접점)

- 모든 요청에 헤더 `Authorization: Bearer <토큰>` 이 **정확히 이 꼴**로 있어야 한다. `Bearer` 의 대소문자와 공백 한 칸까지 본다. 비교는 양쪽을 sha256 한 뒤 `crypto.timingSafeEqual` 이다.
- 없거나 틀리면 경로와 메서드가 무엇이든(없는 경로 포함) `401`, 헤더 `www-authenticate: Bearer`, 본문 `{"error":"Authorization: Bearer <토큰> 이 없거나 틀립니다."}` 다. 본문을 읽기 전에 판정하고 상태를 바꾸지 않는다.
- 응답은 전부 `content-type: application/json; charset=utf-8`, `cache-control: no-store` 다.
- 경로의 `?` 뒤는 버린다.

## 80·443 쪽 동작 요약 (규칙 작성자가 알아야 할 것)

- 기록의 `port` 는 받은 소켓의 실제 포트가 아니라 스킴의 자리다(`http` 80, `https` 443). `Host` 에 붙은 포트는 버린다.
- 게이트웨이가 스스로 만든 응답의 상태 코드: `Host` 가 IP 면 502(`blocked`), `Host` 가 이름 문법에 안 맞거나 없으면 400(`blocked`), 이름이 내부 주소로 풀리면 502(`blocked`), SNI 와 `Host` 가 다르면 421, `CONNECT`·업그레이드는 501, 이름 풀이 실패와 상류 접속 실패는 502(`live`), 재생에서 키가 없으면 504 와 본문 `mcpeak: 녹화에 없는 요청입니다`(`replay-miss`).
- 재생 분기는 `forward.mjs` 의 `handle` 에서 이름 풀이와 소켓 열기보다 앞에 있다. 재생에서는 `lookup` 도 `dial` 도 불리지 않는다. 루프백 스펙이 상류의 TCP 접속 수와 `lookup` 호출 목록으로 단언한다.

## 이 태스크에서 검증하지 못한 것

- **컨테이너 안에서의 실행 전체.** Docker 를 쓰지 않았다. 이미지의 Node 22 와 bookworm openssl 3.0 에서의 동작, 루트 FS 읽기 전용에서 `/tmp` 만으로 뜨는지, `--cap-drop ALL --cap-add NET_BIND_SERVICE` 로 53·80·443 에 붙는지는 T6 의 Docker E2E 몫이다.
- **TLS 종단은 커밋된 테스트가 없다.** 대신 이 머신의 OpenSSL 3.0.18 과 Node 24.14.1 로 손으로 확인했다(스크립트는 스크래치패드에만 있다). 결과: 게이트웨이 CA 를 믿는 클라이언트가 443 으로 200 을 받는다, 잎 인증서가 `openssl verify -verify_hostname` 을 통과한다, SNI 와 `Host` 가 다르면 421, CA 를 안 믿는 클라이언트는 `tlsRejections` 에 남는다, 문법에 안 맞는 SNI(`bad_name…`)는 악수가 끊기고 `tlsRejections` 에 남지 않는다, ALPN 에 `h2` 를 함께 내밀어도 `http/1.1` 로 정해진다, `a;id`·`$(id)`·`../x`·대문자·IP 는 서명기가 거절한다.
- **https 상류로의 전달**(시스템 CA 검증, 실패 시 502). 루프백 스펙의 상류가 HTTP 뿐이다. 코드 경로는 `https.request` 에 `servername` 을 준 것 하나다.
- **실제 리졸버와의 궁합.** DNS 응답은 바이트 단위로 단언했지만 glibc·musl·c-ares 가 실제로 받아들이는지는 컨테이너에서만 확인된다.
- 기본 `lookup`(`dns.lookup`)은 테스트에서 주입으로 바뀌어 있어 실행되지 않았다.

## 임의로 판단한 부분

1. **허용 목록에 없는 내장 모듈을 썼다.** `node:dns/promises`(상류 이름 풀이), `node:zlib`(요청 본문 풀기), `node:os`, `node:path`, `node:util`, `node:fs/promises`. 전부 Node 내장이고 새 의존성은 없다. 이름 풀이와 압축 풀기는 §3.7 이 요구하는데 계획서 목록에 해당 모듈이 빠져 있었다.
2. **`live` 모드는 녹화를 쌓지 않는다.** `npx` 가 받는 패키지까지 메모리에 쌓이는 것을 `record` 에서만 감수한다.
3. **게이트웨이가 스스로 답한 요청(421, 501)의 `served`.** 네 값 중 맞는 것이 없다. 재생이 아니면 `live`, 재생이면 `replay-hit` 으로 적는다. `blocked` 로 적으면 T3 의 `network/internal-destination` 이 틀린 문장으로 나고, `replay-miss` 로 적으면 재생에서만 발견이 하나 더 생긴다. 이렇게 하면 녹화와 재생의 관측이 `served` 만 다르다는 불변식이 유지된다. 세션 파일에는 넣지 않는다.
4. **이름이 내부 주소로 풀려 막힌 요청은 재생에서 `replay-miss` 가 된다.** 재생은 이름을 풀지 않으므로 내부 주소인지 알 수 없고, 막힌 요청은 녹화에 없다. 그래서 녹화 실행의 `network/internal-destination` 이 재생 실행에서는 `network/replay-miss` 로 바뀐다. `Host` 가 IP 인 경우는 이름 풀이가 필요 없어 재생에서도 `blocked` 다. 세션 형식(§3.7)을 넓히지 않고는 고칠 수 없어 그대로 두었다. **결정이 필요하다.**
5. **상류 접속 실패(502)는 녹화에 넣지 않는다.** 상류 응답이 아니기 때문이다. 재생에서는 `replay-miss` 가 된다.
6. **매칭 키의 `bodySha256` 은 `content-encoding` 을 푼 본문 전체(자르기 전)를 가린 것의 해시다.** 압축된 채로 해시하면 카나리가 든 gzip 본문은 실행마다 달라져 재생이 맞지 않는다.
7. **비밀 가리기는 한 번 훑어 바꾼다.** 차례로 바꾸면 먼저 끼운 자리표 안의 글자가 다음 값에 다시 걸린다. 긴 값부터 맞추고, 같은 값에 자리표가 둘이면 자리표의 문자열 순으로 첫째를 쓴다(입력 순서에 기대지 않는다). 빈 값은 가리지 않는다.
8. **재생 응답의 `content-length` 는 실제 본문 길이로 다시 쓴다**(HEAD, 204, 304 제외). 자리표를 값으로 되돌리면 길이가 달라질 수 있다. 그 밖의 헤더는 녹화 그대로다.
9. **압축된 응답 본문은 가리지 않는다.** UTF-8 로 풀리는 것만 가린다는 §3.7 을 따랐다. 상류가 카나리를 gzip 응답에 되돌려 실으면 압축된 꼴로 세션 파일에 남는다. 평문으로는 남지 않는다.
10. **내부 주소 표에 `0.0.0.0/8`, `::`, IPv4 를 감싼 IPv6(`::ffff:a.b.c.d`)를 더했다.** 리눅스에서 `0.0.0.0` 접속은 자기 자신에게 닿고, 감싼 주소는 표를 비켜 가는 길이다. 주소로 읽히지 않는 값도 내부로 본다. §3.4 의 표보다 넓지만 접속하지 않는 쪽으로만 넓다. T3·T4 의 규칙이 쓰는 표와 다르다는 점은 알려 둔다.
11. **`Host` 가 없거나 이름 문법에 안 맞으면 400 이고 `blocked` 로 적는다.** §3.7 은 IP 인 경우(502)만 정했다.
12. **DNS**: 응답에 `AA` 와 `RA` 를 세운다. 질문이 하나가 아니거나 opcode 가 0 이 아니거나 QR 이 선 패킷은 버린다. 줄 주소를 모르면 `A` 에 SERVFAIL 이다(진입점에서는 주소를 못 찾으면 아예 시작하지 않으므로 실제로는 나지 않는다). 질의의 EDNS OPT 는 무시하고 응답에 싣지 않는다.
13. **인증서**: CA 와 잎 모두 P-256, 유효 2일. 잎 키는 하나를 같이 쓰고 이름마다 서명만 새로 한다. 이름은 SAN 에만 싣는다(CN 은 64자 제한). 이름은 명령 인자에만 들어가고 파일 이름으로는 쓰지 않는다(인증서를 stdout 으로 받는다). `openssl req -x509 -CA` 는 OpenSSL 3.0 이상이 필요하다.
14. **요청 본문을 다 받은 뒤에 전달한다.** 매칭 키가 본문 해시를 요구하고 재생은 응답 전에 키가 있어야 한다. 응답은 받는 대로 흘려보낸다.
15. **`GET /session` 은 재생 중이면 받은 세션을 그대로 돌려준다.** 빈 녹화를 내주면 실수로 사용자 파일을 비울 수 있다.
16. 기록은 본문을 다 읽고 `served` 가 정해진 시점에 목록에 들어간다. `phase` 는 헤더를 받은 시점의 값이다.

## 남은 위험

- **`POST /phase` 의 500ms 단언이 시간에 기댄다.** 하한 480ms, 상한 1500ms, "바로" 의 상한 400ms 로 넉넉히 잡았고 전체 스위트 안에서 포함해 세 번 녹색이었다. CI 러너가 심하게 밀리면 상한에 걸릴 수 있다. `*-e2e.test.ts` 라 직렬 갈래에서 돈다.
- **`tlsRejections` 의 오탐.** Node 클라이언트는 인증서를 거절할 때 경보 없이 끊어서 서버에는 `ECONNRESET` 으로만 보인다. 그래서 "인증서를 내준 뒤 악수가 완료되지 않은 접속" 을 전부 거부로 센다. 클라이언트가 악수 도중에 다른 이유로 끊어도 남는다. 발견은 info(`network/pinned-certificate`)와 목적지 발견이라 영향은 작다.
- **요청 본문과 `record` 의 응답 본문에 크기 상한이 없다.** 서버가 아주 큰 본문을 보내면 게이트웨이가 메모리 부족으로 죽을 수 있다. 그때는 T1 의 `gaps`(source gateway)로 드러나고 조용한 "발견 0" 은 되지 않는다. 컨테이너에 `--memory` 를 줄지는 T1 의 몫이다.
- **상류 요청에 제한 시간이 없다.** 상류가 응답하지 않으면 클라이언트가 끊을 때까지 열려 있다. 호출 제한 10초와 `destroy` 가 정리한다.
- **target 컨테이너에서 제어 포트(7000)에 TCP 로 닿을 수 있다.** 같은 internal 네트워크에 있기 때문이다. 토큰이 없으면 401 뿐이고 토큰은 target 에 넘어가지 않는다. 서버가 7000 에 접속하면 strace 의 `connect` 기록에 `<gateway>:7000` 으로 남는다(잡음 표는 53·80·443 만 뺀다).
- **계획서와 달라진 전제.** 재생에서도 게이트웨이가 bridge 에 붙는다(오케스트레이터 통지). "재생에서는 상류에 접속하지 않는다" 는 이제 네트워크 구성이 아니라 `forward.mjs` 의 분기 순서와 그 테스트가 지킨다. 계획서 §3.0·§3.7 의 "재생이면 붙이지 않음" 문장은 고치지 않았다(허용 Files 밖이다).
- 이 머신에서 진입점을 직접 띄우면 7000 이 이미 쓰이고 있어(`EADDRINUSE`) 시작이 거절된다. 컨테이너에서는 해당 없다. 시작 실패 경로에서 CA 임시 디렉터리가 지워지는 것은 확인했다.
