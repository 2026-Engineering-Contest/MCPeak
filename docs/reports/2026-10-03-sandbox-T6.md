```
  - surface: --baseline 을 주지 않아 도구 표면 변경을 비교하지 않았습니다.
  - behavior: 격리가 켜지지 않아 행위를 관측하지 않았습니다.
  - network: 격리가 켜지지 않아 행위를 관측하지 않았습니다.

이 검사는 설명문의 문형과 프로토콜 표면만 봅니다. 바꿔 말한 지시와 서버 코드의 실제 행위는 보지 못합니다.
행위 관측(Docker 격리)은 mcpeak audit --sandbox 로 켭니다.
```

## audit 패키지에서 발견한 것 (고치지 않았다)

1. **프로세스가 신호로 죽으면 격리 자원이 남는다.** `audit()` 의 정리는 `try`/`catch` 경로에만 있고 SIGINT·
   SIGTERM·SIGPIPE 에는 없다. 재현: 위 `| head -3` 명령, 또는 격리 실행 도중 Ctrl-C. 컨테이너 둘, 네트워크,
   볼륨, 임시 디렉터리가 남고 게이트웨이는 계속 떠 있다. 핸들이 `audit()` 안에 있어 CLI 에서 고칠 수 없다
   (`AuditDependencies` 에 중단 신호를 받는 자리가 없다). 사용자가 Ctrl-C 를 누르는 것은 흔한 일이라
   `packages/audit/README.md` 에 직접 치우는 명령을 적어 두었다. 후속 태스크 후보다.
2. **이미지가 있는데 "격리 이미지를 처음 만듭니다" 가 한 번 나왔다.** 이 세션의 첫 격리 실행에서
   `mcpeak-audit-sandbox:d81c6167c691` 이 이미 있었는데도 그 줄이 찍혔다. 실행은 4.6초에 끝났고 이미지의 생성
   시각은 그대로였다(빌드는 캐시로 끝났다). `docker image inspect` 가 한 번 실패한 것으로 보이는데 원인은
   확인하지 못했고, 뒤의 수십 번 실행에서는 재현되지 않았다. E2E 의 진행 줄 단언은 이 한 줄을 빼고 비교한다.
3. **Docker 가 없는 `--sandbox` 실행의 꼬리 문장.** 리포트 마지막 줄이 "행위 관측(Docker 격리)은 mcpeak audit
   --sandbox 로 켭니다." 다(직접 실행 3). 사용자는 이미 `--sandbox` 를 주었다. 둘째 줄이 사유를 말하므로 틀린
   것은 아니지만 어색하다. `report.ts` 의 `FOOTER` 다.
4. **서버가 목록 뒤에 죽은 실행의 종료 코드가 0 이다.** `--crash-after-list` 실행은 `result/unavailable` info
   여섯과 `skipped` 의 "서버 연결이 끊겨 남은 호출 n개를 보내지 않았습니다" 만 내고 0 으로 끝난다. 계획이
   정한 동작과 어긋나는지는 확인하지 못했다. 관측만 적는다.
5. **`SandboxCleanupError` 의 `name` 이 `AuditError` 가 아니다.** CLI 의 기존 `isAuditError`(이름으로 판정)에
   걸리지 않는다. CLI 쪽에서 코드(`SANDBOX_CLEANUP_FAILED`)와 `report` 필드로 알아보게 했다. 결함은 아니고
   다른 호출자가 같은 함정을 밟을 수 있어 적는다.

## 임의로 판단한 부분

1. **`AuditCommandDependencies.sandbox` 로 격리 배선을 묶었다.** §7 은 "`nodeAuditDependencies` 가 `--sandbox`
   일 때만 백엔드를 넣는다" 고 했다. `nodeAuditDependencies` 는 argv 를 모르므로 백엔드를 값이 아니라 생성
   함수(`createBackend(progress)`)로 넣었고 `runAuditCommand` 가 `--sandbox` 일 때만 부른다. 효과는 같다
   (`--sandbox` 없는 실행은 Docker 를 찾지도 부르지도 않는다. 스펙이 단언한다). 같은 묶음에 `stat`, `cwd`,
   `home` 이 있다. 이 필드는 필수라 `AuditCommandDependencies` 를 직접 만드는 호출자는 채워야 한다(지금은
   `index.ts` 와 테스트뿐이다).
2. **`AuditCommandInput.sandbox` 에 `probe` 를 넣지 않았다.** §7 대로 `probeExplicit` 만 두고
   `SandboxOptions.probe` 는 실행할 때 정한다. "--sandbox 만 주면 … sandbox.probe 는 all" 스펙은 `audit` 를
   가짜로 바꿔 실제로 넘어간 옵션을 본다.
3. **`readDeclarationTexts` 와 `resolveMountRoot` 의 인자 꼴.** 계획의 `(mountRoot, serverArgs)` 로는 상대 경로를
   풀 수 없어 `cwd` 와 주입 fs 를 함께 받는 객체로 했다.
4. **`--sandbox-mount` 가 파일이면 "경로가 없습니다" 문장을 낸다.** 디렉터리가 아닌 경로에 대한 문장이 §6.3 에
   없다. 문장에는 사용자가 쓴 글자 그대로 싣는다. 서버 인자 문장도 같다.
5. **실행한 자리가 마운트 범위 밖이면 서버의 작업 디렉터리는 마운트 범위다.** `SandboxOptions.cwd` 는 범위
   안이어야 한다. 이 경우 상대 경로 인자는 범위 밖으로 풀려 이미 거절되므로 남는 것은 절대 경로 인자뿐이다.
6. **경로 판정은 글자로만 한다.** 심볼릭 링크를 풀지 않는다. 범위 안의 링크가 밖을 가리키면 컨테이너에서는
   깨진 링크다.
7. **`--allow-host` 검증.** `sandbox/declared.ts` 와 같은 호스트 이름 문법(대소문자 무시, 253자 이하)을 쓴다.
   URL, 경로, 포트가 붙은 값은 거절한다. 점으로 이은 숫자(IPv4 꼴)는 문법에 맞아 통과한다. 값은 고치지 않고
   넘긴다(소문자화는 `extractDeclaredHosts` 가 한다).
8. **격리 옵션 없이 준 옵션이 여럿이면 고정 순서로 첫 것을 말한다**(session, replay, allow-host,
   compare-host, mount). 쓴 순서에 기대지 않는다.
9. **사용법 오류의 꼴은 기존 audit 것 그대로다.** `오류 [CLI_USAGE]: <문장>` 뒤에 `해결: <사용법>` 줄이 붙는다.
10. **진행 문장에 `escapeTerminalText` 를 한 번 더 건다.** audit 가 이미 표기로 바꿔 주므로 평소에는 글자가
    같다.
11. **`nodeDockerIo` 의 시간 초과는 거절한다.** 문장은 `docker <하위 명령> 이 n초 안에 끝나지 않았습니다` 다.
    백엔드가 이 첫 줄을 사유로 쓴다. `maxBuffer` 는 256MiB. `sandboxDir` 는 처음 쓸 때 찾는다.
12. **`auditSandboxDir` 의 탐색.** `import.meta.resolve("@mcpeak/audit")` 의 자리에서 위로 올라가며
    `sandbox/Dockerfile` 을 찾고, 풀지 못하면 저장소 안의 자리(`../../audit/src` 기준)를 쓴다. CI 의 e2e 잡은
    빌드 없이 돌아 `dist` 가 없다. Node 는 없는 파일이어도 경로를 돌려주는 것을 확인했다. CJS 산출물
    (`index.cjs`)에서 `import.meta.resolve` 가 어떻게 되는지는 실행해 보지 않았다(남은 위험 3).
13. **E2E 의 env 허용 목록에 `PWD` 를 더했다.** 계획의 목록(카나리, HOME, PATH, CA 다섯, 이미지 기본 env)에
    없던 이름이다. `docker run … node -p` 는 `PWD` 를 내고 `--entrypoint node` 로 돌리면 내지 않는 것을 확인했다.
    이미지의 진입 셸(`docker-entrypoint.sh`)이 넣는 값이고 호스트에서 온 것이 아니다. 단언을 출력에 맞춘 유일한
    곳이라 따로 적는다. 이미지 기본 env 는 `HOSTNAME`, `NODE_VERSION`, `YARN_VERSION`, `PWD` 로 못 박았다.
14. **E2E 는 실행을 나눠 쓴다.** 취약 예제의 compare-host 실행 하나를 네 스펙이, live-weather 의 녹화 실행을
    세 스펙이 본다(다섯 서버 스펙의 live-weather 는 `--sandbox-session` 을 준 실행이다). 스펙을 하나만 골라
    돌려도 필요한 실행은 그 자리에서 돈다. 전체가 57초다.
15. **`get_forecast` 의 `isError` 는 백엔드를 직접 띄워 본다.** 호출 응답은 리포트에 실리지 않는다. 인자는
    `{ city: "Seoul" }` 이고 응답 값은 보지 않는다. open-meteo 가 죽으면 이 스펙은 실패한다.
16. **"`/.dockerenv` 분기로 달라진 설명이 근거로 실려 있다"** 는 `evidence` 가 `["ping", "description"]` 인
    것으로 단언했다. 설명 글 자체는 발견에 실리지 않는다.
17. **`MCPEAK_SKIP_DOCKER_E2E=1` 과 `MCPEAK_REQUIRE_DOCKER_E2E=1` 을 함께 주면 실패한다**(둘 중 하나만 주라는
    문장). skip 문장은 두 가지다. 변수로 건너뛰면 `MCPEAK_SKIP_DOCKER_E2E=1 이라 Docker E2E 를 건너뜁니다.`,
    Docker 가 없으면 `Docker 가 없어 건너뜁니다`.
18. **예외로 끝나는 감사**는 디렉터리를 `--baseline` 으로 준 것이다(EISDIR). 격리를 띄운 뒤에 읽으므로 예외
    경로의 정리를 지난다(진행 문장이 찍히는 것으로 확인).
19. **`packages/audit/README.md` 에 "점검 도중 프로세스를 강제로 끝내면 남는다" 와 직접 치우는 명령을 적었다.**
    계획이 요구한 내용은 아니지만 한계를 숨기지 않는 쪽을 택했다.
20. **help 의 `--sandbox-replay` 설명**은 지시대로 "이 세션 파일로만 답합니다. 상류에 접속하지 않습니다." 까지만
    쓰고, `--compare-host` 는 "이 머신에서 격리 없이 서버를 한 번 더 띄워 … 서버의 시작 코드는 이 머신에서
    실행됩니다" 라고 썼다. 스펙이 두 문장과 `bridge` 가 없음을 단언한다.

## 남은 위험

1. **Linux x86_64 에서 처음 도는 것은 CI 다.** 이 E2E 는 macOS arm64 Docker Desktop 에서만 돌았다. §9.4 가
   이미 적은 둘(홈 파일 `0600` 의 가독성, x86_64 전용 시스템 콜 이름)에 더해, 러너의 uid(1001)와 컨테이너의
   uid(1000)가 달라 마운트한 임시 디렉터리와 저장소를 읽지 못할 가능성이 있다. `nodeDockerIo` 는 임시
   디렉터리를 0755, 파일을 주어진 mode 로 만든다.
2. **CI e2e 잡이 길어지고 외부 API 에 더 기댄다.** 첫 실행은 이미지 빌드(apt)가 든다. live-weather 스펙은
   open-meteo·usgs·frankfurter 가 응답해야 통과한다. `ci.yml` 변경은 전원 리뷰 대상이다(§10 의 13).
3. **CJS 산출물의 `auditSandboxDir`.** `index.cjs` 를 `require` 해서 `--sandbox` 를 돌리는 경로는 시험하지
   않았다. 배포 진입점은 `cli.mjs` 라 사용자 경로는 아니다.
4. **npm 으로 설치한 배포본에서는 돌려 보지 않았다.** 저장소 안에서 빌드한 CLI 만 확인했다. `@mcpeak/audit`
   의 `files` 에 `sandbox` 가 있어 실릴 것으로 보지만 실물 확인은 없다.
5. **신호로 죽으면 잔존이 남는다**(결함 1). 수동 정리 명령만 문서에 있다.
6. **러너 출력의 거짓 신호.** vitest 4.1 은 에이전트 환경(`CLAUDECODE`, `AI_AGENT`)에서 통과한 파일의 콘솔
   출력을 감춘다. 그래서 에이전트 세션에서 `MCPEAK_SKIP_DOCKER_E2E=1 pnpm test` 를 돌리면 skip 문장이 보이지
   않는다. 사람 터미널과 CI 에서는 보인다(`env -u CLAUDECODE -u AI_AGENT` 로 확인). skip 판정은 문장이 아니라
   통과 수와 skip 수로 한다.
7. **`--compare-host` 는 서버를 호스트에서 띄운다.** E2E 와 직접 실행 1 이 취약 예제를 이 머신에서 한 번
   띄웠다(목록만 받았고 도구는 부르지 않았다. 그 서버는 시작할 때 아무것도 하지 않는다).
