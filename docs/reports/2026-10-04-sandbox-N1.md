### 줄인 방법

원문 9,322줄을 아래 스크립트로 134줄(20KB)로 줄였다. **남긴 줄은 한 글자도 고치지 않았고 순서도 그대로다.**
원문 sha256 앞 16자: `a4f7e50a411909ff`.

```python
"""trace 원문에서 줄을 골라 남긴다. 남긴 줄은 한 글자도 고치지 않고 순서도 그대로다.

남기는 것:
  - execve, connect, unlinkat 줄과 신호 줄 전부
  - 쓰기 플래그가 있는 openat 과 renameat 은 자리(아래 bucket)마다 앞에서부터 LIMIT 개
버리는 것: 읽기 전용 openat 전부, 한도를 넘은 쓰기 openat·renameat, AF_UNSPEC connect(11줄).
갈라진 호출(<unfinished ...> / <... resumed>)은 앞 반쪽을 남기면 같은 PID 의 짝도 남기고, 버리면 짝도 버린다.
"""
import re, sys

LIMIT = {"open:/home/node/.npm/_cacache": 25, "open:/home/node/.npm/_npx": 25, "open:/tmp": 6,
         "rename:/home/node/.npm/_cacache": 12, "rename:/tmp": 4}
WRITE = re.compile(r"O_WRONLY|O_RDWR|O_CREAT|O_TRUNC|O_APPEND")
seen = {}
pending = {}  # pid -> 앞 반쪽을 남겼는가

def bucket(kind, body):
    path = re.search(r'"(/[^"]*)"', body).group(1)
    for prefix in ("/home/node/.npm/_cacache", "/home/node/.npm/_npx", "/tmp"):
        if path.startswith(prefix + "/"):
            return f"{kind}:{prefix}"
    return None  # 그 밖의 자리는 한도 없이 전부 남긴다

def keep(body):
    call = body.split("(", 1)[0]
    # 해석기(trace.ts)가 아직 모르는 줄이다. trace-*.txt 전부에서 unparsed 가 0 이라는 기존 계약을 지키려고 뺀다.
    if call == "connect" and "{sa_family=AF_UNSPEC," in body:
        return False
    if call in ("execve", "connect", "unlinkat") or body.startswith("--- "):
        return True
    if call == "openat" and not WRITE.search(body):
        return False
    kind = "open" if call == "openat" else "rename"
    key = bucket(kind, body)
    if key is None:
        return True
    seen[key] = seen.get(key, 0) + 1
    return seen[key] <= LIMIT[key]

out = []
for line in sys.stdin.read().split("\n"):
    if line == "":
        continue
    pid, body = re.match(r"^(\d+)\s+(.*)$", line).groups()
    if re.match(r"^<\.\.\. [a-z_0-9]+ resumed>", body):
        if pending.pop(pid, False):
            out.append(line)
        continue
    kept = keep(body)
    if body.endswith("<unfinished ...>"):
        pending[pid] = kept
    if kept:
        out.append(line)
sys.stdout.write("\n".join(out) + "\n")
sys.stderr.write(f"{seen}\n")
```

한도에 걸려 버린 수: `_cacache` 쓰기 열기 448 중 25 남김, `_npx` 3,852 중 25, `/tmp` 548 중 6, `_cacache`
옮기기 223 중 12, `/tmp` 옮기기 548 중 4. exec 18줄, unlinkat 9줄, `_logs`·`_update-notifier` 쓰기는 전부 남겼다.

`AF_UNSPEC` connect 11줄은 뺐다. `trace.ts` 의 해석기가 이 줄을 몰라 unparsed 로 세고,
`trace-parse.test.ts` 에 "trace-*.txt 전부에서 unparsed 가 0" 이라는 기존 계약이 있다. 두 파일 다 내 Files 밖이다.
처음에는 그 줄을 남기고 스펙에서 "unparsed 는 AF_UNSPEC 줄 수와 같다" 로 단언했다가 그 계약에 걸려 뺐다.

## 임의로 판단한 부분

1. **허용 Files 밖 새 파일 둘을 만들었다.** `behavior-noise-npm-cache.json` 과 `.counter.json` 이다.

   패키지의 새 파일이라 만들었다. 사건의 경로는 채집한 기록에 실제로 나온 것이다. 받아들이지 않으면 두 파일을
   지우고 그 스펙에 예외를 두는 수밖에 없는데, 그쪽이 더 나쁘다고 봤다.
2. 자리 파일 이름을 `.npm/.mcpeak-mount`(빈 내용, 0644)로 정했다. 기존 단언 "홈 쓰기는 전부 0644" 에 맞췄다.
3. 판정은 `command` 를 `[\\/]` 로 자른 마지막 조각의 **정확 일치**다. `npx-wrapper` 는 열지 않는다. Windows 의
   `npx.cmd` 도 열지 않는다. 이것은 기존 `backend.commands`(`node`·`npx`·`npm`) 판정과 같은 수준이라 넓히지 않았다.
4. 스펙을 지시보다 몇 개 더 썼다: 인자에 `npx` 가 있어도 열지 않는다, npx 여도 `--read-only`·`--cap-drop ALL`·
   `no-new-privileges`·`:ro` 마운트 셋은 그대로다, node 면 자리 파일을 쓰지 않는다.
5. 채집 때 작업 디렉터리는 빈 디렉터리를 `/workspace:ro` 로 붙였다(기존 `trace-npx-start.txt` 와 같은 자리).
6. ADR 의 결과에 지시받은 한계 둘 말고 둘을 더 적었다(start 단계에서 서버 자신의 캐시 쓰기를 가르지 못한다,
   실행마다 새로 받아 느리다).
7. 실물 진단을 위해 빌드 산출물을 한 번 고쳐 돌린 것(위 "실물 확인" 2번). 소스와 추적 파일은 건드리지 않았다.

   advertise })` 가 `connectTimeoutMs` 를 넘기지 않아 `core` 기본값 10초가 걸린다. 게이트웨이 없이 strace 아래
   `npx` 가 `initialize` 에 답하기까지 8.8초였고, 게이트웨이를 거치면 넘는다. 60초를 주면 통과한다(위 실물 확인).
   제안: 격리 대상에 한해 `connectTimeoutMs` 를 `core` 상한인 60_000 으로 넘긴다. `cli` 오너의 결정이라 제안만 한다.
   이것 없이는 changeset 의 "고친다" 가 사용자 눈에는 참이 아니다.
2. `trace.ts` 가 `connect(…, {sa_family=AF_UNSPEC, …})` 를 해석하지 못한다. 실물에서는 나오지 않았지만, 이름이
   주소 여러 개로 풀리는 경로(게이트웨이를 거치지 않는 조회)가 생기면 "N줄을 해석하지 못했습니다" 가 뜬다.
   해석기에서 신호 줄처럼 넘기는 것이 맞아 보인다. 내 Files 밖이라 고치지 않았다.
3. start 단계에는 서버의 시작 코드도 돈다. 서버가 시작하면서 `~/.npm` 에 쓴 것은 실행기의 것과 함께 빠진다
   (ADR 한계 3). 사건에 PID 가 없어 지금 구조로는 가를 수 없다.
4. 512MB 또는 컨테이너 메모리 1GB 를 넘는 패키지는 받지 못한다. 그때의 실패 문장은 여전히 "서버에 붙지
   못했습니다" 이고 원인(ENOSPC)은 stderr 꼬리에만 있다.
5. `registry.npmjs.org` 접속이 리포트에 `network/declared-destination`(info) 로 220회 실린다. 실행기의 접속이지
   서버의 접속이 아닌데 구분되지 않는다. 잡음은 아니고 info 라 두었다.
6. `npm` 을 명령으로 준 경우(`npm exec`, `npm start`)는 단위 스펙으로만 봤고 실물로는 `npx` 만 돌렸다.
