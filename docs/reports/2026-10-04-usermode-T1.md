## 임의로 판단한 부분

1. **아이콘 모양.** `Check` 는 방패 외곽선 안에 체크 표시(path 둘)다. 전환 링크는 위쪽 화살표가 왼쪽을, 아래쪽
   화살표가 오른쪽을 가리키는 두 줄(path 넷)이다. 둘 다 `ICON_PROPS` 를 쓰고 기존 아이콘과 같은 biome 무시
   주석을 달았다.
2. **선택 화면의 배치와 클래스.** `section` 은 `mx-auto flex h-full max-w-[720px] flex-col justify-center
   space-y-8 text-center` 로 세로 가운데에 둔다. 두 카드는 `grid gap-4 sm:grid-cols-2` 로 나란히 놓고 좁으면
   쌓인다. 카드는 `<a className="group block rounded-lg text-left + FOCUS_RING">` 안에 `Card` 컴포넌트를 넣었다
   (`h-full space-y-2 p-6 group-hover:border-accent`). 카드 제목은 `h2`(`text-title font-semibold`), 설명은
   `p`(`text-body text-ink-muted`), 꼬리는 `text-caption text-ink-muted` 다. `h1` 은 `PageHeader` 와 같은
   `text-display font-semibold tracking-tight text-ink` 다. 폭 720px, 카드 제목을 `h2` 로 둔 것, 호버 테두리
   색은 계획서에 없는 선택이다.
3. **사이드바 내부 구조.** 모드별 주 메뉴를 `MAIN_ITEMS: Record<AppMode, NavItem[]>`, 전환 링크의 대상과 글자를
   `SWITCH_TO: Record<AppMode, ...>` 표로 뒀다. 조건문 대신 표를 쓴 것은 내 선택이다. `Check` 의 `hash` 는
   리터럴 대신 `MODE_HOME.user` 를 썼다(값은 `#/user/check` 로 같다).
4. **`PRECHECK_DESCRIPTION` 의 자리.** `PreCheck.tsx` 안의 모듈 상수로 뒀고 내보내지 않았다. T2 가 같은 파일을
   채우므로 그대로 쓸 수 있다.
5. **저장 효과의 의존성.** 계획서는 "받아들인 해시가 바뀔 때마다" 라고 적었다. 효과의 의존성은
   `[route.screen, hashMode, storedMode]` 다. 해시가 바뀌어도 이 셋이 같으면 쓸 것이 없어서 결과는 같다.
   리다이렉트 효과에는 `redirectTarget` 을 의존성에 더했다.
6. **테스트의 모양.** §7.1 의 해시 목록과 §7.5 의 "전환 링크", "`#/welcome` 과 `#/settings`" 는 `it.each` 로
   펼쳤다. 그래서 테스트 이름 뒤에 해시가 붙는다. "선택 화면의 두 링크" 테스트에는 §4.4 의 접근 이름(제목과
   설명을 이은 글자)과 꼬리 문장 단언을 더했다. "`#/user/unknown`" 테스트에는 저장값이 `developer` 일 때
   `#/home` 으로 가는 경우와, 어느 경우에도 저장값이 바뀌지 않는다는 단언을 더했다.
7. **`#/runs/abc` 테스트의 스텁.** 실행 화면은 run 을 구독하는데 jsdom 에 `EventSource` 가 없다. 이 테스트 한
   곳에서만 아무 일도 하지 않는 `EventSource` 와, `/api/runs/abc` 에 끝난 run 요약
   (`status: "done"`)으로 답하는 fetch 를 세웠다. 화면 코드는 고치지 않았다.
8. **App.tsx 머리 주석.** 계획서가 말한 두 줄과 `security` 글자 수정 외에, `#/home` 줄을 "개발자 모드의 기본
   리다이렉트 대상" 으로 고치고 모드 판정을 설명하는 두 줄을 더했다.
9. **ADR 의 범위.** 계획서 §3 표의 다섯 줄(모드의 진실, 저장 시점, 선택 화면, env·헤더 값, 판정 문장)을
   선택지 표에 넣었다. 전환 수단(링크)과 개발자 주소를 그대로 두는 것은 그 다섯 줄의 이유로 필요해서 결정과
   이유 항목에 한 줄씩 적었다.

## 고치지 않고 보고하는 것

- **`SettingsView.tsx` 의 `Test 로 돌아가기` 링크는 `#/home` 고정이다.** 사용자 모드에서 설정 화면을 열고 그
  링크를 누르면 개발자 모드의 첫 화면으로 가고, 도착 시 저장 규칙에 따라 저장값이 `developer` 로 바뀐다. 이
  파일은 허용 Files 밖이라 손대지 않았다. 계획서 §11-4 가 받아들인 동작("개발자 주소 링크를 열면 그 뒤로는
  개발자 모드로 기억된다")의 한 예이지만, 화면 안의 링크가 모드를 바꾸는 유일한 자리다.
- **`EnterWorktree` 는 실패했다.** 세션의 작업 디렉터리가 이미 이 worktree 여서 도구가 경로를 worktree 안에서
  다시 찾았다. 모든 명령은 위 pwd 에서 실행했다. 프로젝트 루트의 파일은 건드리지 않았다.

## 남은 위험

- 선택 화면과 사용자 모드 사이드바를 **실제 브라우저에서 보지 않았다.** jsdom 은 배치와 색을 그리지 않는다.
  세로 가운데 정렬, 카드 호버 테두리, 아이콘 모양은 최종 게이트에서 눈으로 확인해야 한다.
- 저장값 상태는 App 이 마운트될 때 한 번 읽는다. 다른 탭에서 모드를 바꿔도 이 탭의 저장값 상태는 다음 도착
  때까지 그대로다. 해시가 모드를 말하는 화면에서는 영향이 없고, `#/settings` 에서만 사이드바가 이전 모드로
  보일 수 있다.
- `themeStorage()` 는 부를 때마다 probe 키를 한 번 쓰고 지운다. 마운트 때 한 번, 모드가 바뀔 때 한 번 부른다.
