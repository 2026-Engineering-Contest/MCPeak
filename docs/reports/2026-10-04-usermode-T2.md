## 임의로 판단한 부분

1. **요약 카드의 클래스.** `Card` 에 `space-y-3 p-4`(아래 `SecurityResult` 의 판정 카드와 같은 여백)를 줬다.
   제목은 `h2`, `text-title font-semibold text-ink`(보안 탭의 "점검 옵션" 제목과 같다). 줄은
   `<li className="flex items-start gap-2">` 안에 칩과 문장 두 `span` 이다. 칩은 `SecurityResult` 의 발견 배지와
   같은 `inline-block rounded-full px-2 py-0.5 text-xs font-semibold` 에 `shrink-0` 을 더했다(문장이 길어도 칩이
   눌리지 않게). 문장은 `min-w-0 break-words text-sm text-ink` 다. `SecurityResult.tsx` 의 `BADGE_CLASS` 는
   내보내지 않는 상수이고 그 파일은 수정 금지라, 같은 문자열을 `PreCheck.tsx` 에 다시 적었다. 중복 한 줄이
   생겼다.
2. **select 의 클래스.** `INPUT_CLASS` 그대로다(`Field.tsx` 주석이 `<input>` 과 `<select>` 가 함께 쓴다고 적었다).
   `Field` 로 감싸 라벨 `점검할 서버` 를 달았다. 선택지의 값은 자리 번호다.
3. **요약 카드의 자리.** 결과 단계에서 버튼 줄, 시작 실패 문장, 요약 카드, `SecurityResult` 순이다. §5.5 가 적은
   순서 그대로다.
4. **점검 단계의 대상 줄.** 붙여넣기 단계는 고른 서버에서 직접 만든다(`[command, ...args].join(" ")` 또는 url).
   점검 단계는 보안 탭과 같이 보낸 요청에서 읽는다(`describeRun("audit", sent.argv).server`). 두 글자는 같다.
   "다시 점검" 으로 온 경우에도 실제로 도는 대상을 보이려는 선택이다. `run-target.ts` 는 고치지 않고 import 만
   했다.
5. **대상 줄과 안내 줄의 묶음.** 대상 줄(`break-all font-mono text-xs text-ink`), env 안내, 헤더 안내를
   `space-y-1` 인 `div` 하나에 넣어 select 와 격리 토글 사이에 뒀다. 안내 줄은 버튼 아래 사유 줄과 같은
   `text-xs text-ink-muted` 다. 계획서는 대상 줄의 클래스만 정했고 안내 줄의 클래스는 내 선택이다.
6. **입력을 읽지 못했을 때의 격리 토글.** 대상이 없어도 토글을 보이고 켜고 끌 수 있다. 힌트는 켜짐·꺼짐 문장
   이다. §7.4 첫 테스트(빈 입력에서 토글이 checked)가 이 모양을 요구한다.
7. **도달하지 않는 갈래의 문장.** `requestResult` 에 `parsed.ok` 인데 서버가 없는 갈래가 타입 좁히기 때문에
   남아 있다. `parseServerInput` 은 성공이면 서버를 하나 이상 내므로 실행되지 않는다. 새 문장을 만들지 않고
   §5.2 의 `설정에 서버가 없습니다.` 를 그대로 썼다.
8. **선택지의 key.** 자리 번호를 key 로 쓰고 biome 무시 주석을 달았다. 이름 없는 서버는 글자가 겹칠 수 있어
   값만으로 유일하지 않다(`SecurityResult` 의 같은 주석과 같은 이유).
9. **§7.4 에 덧붙인 테스트(8건).** 읽지 못하는 입력의 사유 줄, 입력을 바꾸면 고른 서버가 첫째로 돌아가는 것,
   격리를 끄고 시작하면 `argv` 만 보내는 것, 헤더가 있는 원격 설정이 주소만 보내는 것, 시작 요청 400, 없는
   run(`onMissing`), 결과 단계에서 돌아가기, 늦게 도착한 결과를 버리는 것이다. §5.5 에 적혀 있지만 §7.4 목록에
   이름이 없던 동작들이다.
10. **비밀값 단언을 강하게 했다.** §7.4 는 값 `v` 가 입력 칸 밖에 없다고 단언하라고 했는데, 한 글자라 화면의
    다른 글자(`mcpServers` 의 `v`)와 구분되지 않는다. 표 첫 줄로는 `KEY=` 와 `"v"` 가 없다는 것을 보고, 같은
    테스트에서 눈에 띄는 값(`s3cr3t-value`)을 넣은 설정과 명령 한 줄로 한 번 더 본다. 헤더 테스트도 같은 값을
    쓴다. 입력 칸을 뺀 화면 글자는 `document.body` 를 복제해 `textarea` 를 지운 뒤 읽는다.
11. **최근 명령 목록.** "점검 시작이 env 없는 본문을 POST 한다" 테스트가 시작 뒤 `localStorage.length` 가 0
    임을 단언한다. 이 화면은 브라우저 저장소에 아무것도 쓰지 않는다.
12. **changeset 문안.** T1 의 changeset 과 같은 말투로 한 문단을 썼다.

## 남은 위험

- **실환경을 보지 않았다.** jsdom 과 스텁만 썼다. 실제 대시보드에서 `examples/audit-target-server` 를 붙여 넣어
  CLI 와 발견 순서가 같은지, 격리를 켠 점검 뒤 라벨 자원이 0 인지는 계획서 §8.3 의 최종 게이트 몫이다.
- **`SecurityProgress` 의 진행 설명 문장.** 재사용한 패널이 "도는 동안 대시보드를 끄면 격리 자원이
  남습니다(치우는 법: packages/audit/README.md)" 를 그대로 보인다. 개발자용 문장이 사용자 모드에 나온다.
  `SecurityPanel.tsx` 본문은 수정 금지라 그대로 뒀다.
- **`명령 한 줄` 의 역슬래시.** §5.2 가 정한 대로 역슬래시 이스케이프를 풀지 않는다. Windows 경로
  (`C:\tools\server.exe`)는 그대로 지나가지만 `my\ server.mjs` 같은 셸 이스케이프는 두 토큰으로 나뉜다.
- **JSON 안의 `KEY=value` 꼴 command.** `{"command":"API_KEY=x node"}` 처럼 command 한 칸에 셸 줄을 통째로 적은
  설정은 나누지 않고 그대로 실행 파일 이름으로 보낸다. §5.2 의 사양 그대로이고 그 글자가 대상 줄에 보인다.
  이 경우 env 값이 대상 줄과 요청 `argv` 에 실린다. JSON 의 `env` 칸과 명령 한 줄 앞의 `KEY=value` 만 값을
  버린다. 계획서가 다루지 않은 입력이라 고치지 않고 적어 둔다.
- 계획서 §11 의 1, 2, 6 번(비밀값이 필요한 서버는 연결 실패, Docker 가 없어도 점검이 돈다, 새로 고침하면 결과가
  사라진다)은 그대로 남아 있다.
