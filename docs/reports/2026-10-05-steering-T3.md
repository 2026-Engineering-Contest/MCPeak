## 임의로 판단한 부분

- **린트 녹색은 이 폴더를 검사한 결과가 아니다.** 계획서 §5 는 "이 폴더의 `.mjs` 도 검사 대상이다" 라고
  적었지만, `biome.json` 의 오버라이드가 `docs/benchmark/**` 의 linter·formatter·assist 를 전부 꺼 두었다.
  `pnpm exec biome check docs/benchmark/mcp-audit-recall` 은 "Checked 0 files" 와 "paths were provided but
  ignored" 를 낸다. 그래서 코드를 다듬을 일이 없었고, 두 파일은 계획서의 코드와 한 글자도 다르지 않다.
  `biome.json` 은 허용 Files 밖이라 건드리지 않았다.
- **README 의 변형 설명은 표로 적었다.** 계획서는 "`variants.mjs` 의 이름과 한 줄 설명" 만 요구했다. 여덟
  가지를 나란히 견주기 쉽도록 표를 골랐다. 설명 문장은 `variants.mjs` 의 주석을 풀어 쓴 것이다.
- **정상 정의 줄의 설명은 "판정" 절에 넣었다.** 계획서는 어느 절에 넣을지 정하지 않았다. 기존 "아직 재지
  않은 것" 절에 있던 정밀도 기준 문장(정상 서버 20개에서 발견 0)도 그 옆으로 옮겼다.
- **RESULTS.md 새 절에 측정 방식이 바뀌었다는 줄을 하나 더했다.** 계획서가 나열한 항목에는 없다. 원본
  탐지가 73.9% 에서 99.1% 로 뛴 것이 규칙 추가만이 아니라 서버 단위 판정으로 바뀐 것과 함께 읽혀야 해서
  넣었다. 수치는 출력 그대로이고 손으로 고친 것은 없다.
- **`measure.mjs` 의 실행 권한 비트는 건드리지 않았다.** 기존 모드를 그대로 두었다.

## 남은 위험

- `variants.mjs` 의 `nameSource` 는 `packages/audit/src/rules/steering.ts` 의 것을 옮겨 적은 사본이다. 규칙
  쪽이 바뀌면 변형의 이름 대조가 조용히 어긋난다. 지금은 §8 수치 일치가 두 사본이 같다는 근거다.
- 변형은 기계적 치환이라 회피의 하한만 보여 준다. 가장 낮은 행이 63.2% 인데, 사람이나 LLM 이 통째로 다시
  쓴 설명에서는 더 낮을 수 있다.
- 통합 게이트의 측정은 `pnpm build --force` 뒤에 다시 돌려야 한다. 이번 측정은 부트스트랩 때의 `dist` 를 읽었다.
