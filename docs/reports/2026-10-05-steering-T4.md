## 임의로 판단한 부분

1. **배경의 표.** 계획서는 "설계 §2 의 첫 표에서"라고만 했다. 그 표의 여덟 줄 중 "지금 문형 규칙" 열만
   옮겼다. 배경은 결정 이전의 상태를 말하는 자리라, 새 규칙의 수치는 결과 절과 README 에 맡겼다. 수치는
   설계 표 그대로다.
2. **이유의 넷째 항목.** 계획서의 골자는 셋(결정론, 음수 가중치 금지, high 없음)이다. 발견 문장에 근거와
   신호를 싣는 까닭을 한 항목 더했다. 설계 §3.3 의 첫 문장에서 옮긴 것이고 새 주장은 아니다. 셋째 항목의
   "주의는 오탐 1%, 낮음은 5%"도 설계 §3.1 에서 옮겼다.
3. **결과 절의 낱말 두 곳.** 설계 §5 는 "표의 수치", "표의 70.8%" 라고 하는데 ADR 에는 그 표가 없다.
   "실측 수치", "실측의 70.8%" 로 바꿨다. 나머지 일곱 항목의 문장과 수치는 설계와 같다.
4. **결정 절에 `runSteeringRules` 를 따로 둔 까닭 한 줄**(설계 §3.4)을 넣었다. 계획서 골자에는 없지만
   "다르게 갈 수도 있었던" 판단이라 기록 대상으로 봤다.
5. **길이.** 표 세 개와 발견 문장 예시 때문에 0112 보다 길다. 선택지 표 여섯 줄과 결과 일곱 항목을
   "그대로 옮긴다"는 지시를 한 페이지 제한보다 앞세웠다.

## 남은 위험

- README 가 수치의 출처로 `docs/benchmark/mcp-audit-recall/RESULTS.md` 를 가리킨다. 그 파일을 새 수치로
  고치는 것은 T3 다. T3 가 병합되기 전에는 README 의 수치가 가리키는 문서에 없다.
- README 의 "전체의 10% 쯤"과 "실측 1.3%"는 설계 §5 의 값(10.7%, 검증용 1.3%)을 계획서 문안 그대로 쓴
  것이다. 통합 게이트의 `measure.mjs` 로는 다시 확인되지 않는다.
- ADR 번호는 브랜치에서 매겼다. 병합 전에 main 에 다른 0114 가 생기면 번호를 다시 매겨야 한다.
