## 기대값 손계산

`tokensResponse()` 는 `analyze-view.test.tsx` 의 `analyzeResponse()` 를 복사했다(`OVERLAY_TEXT`·`SOURCE_A` 는 값으로 펼쳤다).

- 기본 픽스처: reduced = 1000 − 760 = 240. `percent(240, 1000)` = round(24.0 × 10) / 10 = `"24.0"`. 판정
  `"24.0% 줄일 수 있음"`, 큰 숫자 `"−24.0%"`. `tokens(1000)` = 250, `tokens(760)` = 190 이라 `"~250 → ~190 토큰"`.
  칩은 `source.toolCount` 2, `promotedParameters` 2.
- 기본 픽스처의 1위: a 의 감소 200, b 의 감소 40 이라 a. `percent(200, 600)` = 33.33… 이 반올림돼 `"33.3"`,
  즉 `"가장 큰 감소: a −33.3%"`.
- 감소 0: totals 1000→1000, 도구 a 600→600. reduced 0 이라 `"줄일 것 없음"`·`"0%"`, 1위의 감소가 0 이라 `"줄어든 도구 없음"`.
- 동률: a·b 가 둘 다 50 감소, c 는 10. 비교가 같으면 원본 순서라 a. `percent(50, 100)` = `"50.0"`.
- 막대: 200→50 이면 ratio = 50 / 200 = 0.25. before 0 이면 빈 배열이고 reduced 0 이라 `"줄일 것 없음"`.
- 보안 막대: high 1, medium 3 이면 defects 4, ratio 1/4 = 0.25, 3/4 = 0.75. low·info 칸은 0 이라 빠진다.
- 보안 큰 숫자: 기본 counts(high 1) 는 defects 1 이라 `"1"`, `server.toolCount` 2 라 `"건 발견 · 도구 2개 점검"`.
- 흐름 경고: counts 가 전부 0 이고 findings 가 `flow/` 하나면 defects 0, flows 1. 앞 두 조건이 거짓이라 `"흐름 경고만"`.
- 기준 파일: findings 가 `surface/changed` 둘이라 `baselineStatus` 가 `"기준 파일과 다릅니다: b.json (변경 2건)"`.

## 임의로 판단한 부분

1. **요약 함수의 타입 표기.** 설계 §6.1·§6.2 의 코드는 매개변수와 지역 변수에 타입을 적지 않았다. 그대로 두면
   막대·칩 배열 리터럴의 `tone` 이 `string` 으로 넓어져 `PillarSummary` 에 들어가지 않는다. 그래서 보안 막대를
   `const segments: readonly PillarBarSegment[] = [...]` 로 먼저 적고 `defects === 0 ? [] : segments.filter(...)` 로
   걸렀고, 칩에 `readonly PillarChip[]` 를 붙였다. 매개변수 타입은 §5.2 의 시그니처를 따랐다. 분기·식·문장은
   설계와 같다. `defects === 0` 일 때 `segments` 의 ratio 가 NaN 이 되지만 그 경우 쓰지 않는다.
2. **포매터 적용.** 중첩 삼항, 긴 문자열, `foot` 의 `??`, `AnalyzeView` 의 패널 분기는 biome 포매터가 줄을 나눈
   모양이다. 내용은 바뀌지 않았다. 테스트 파일도 같은 이유로 §2.5 의 한 줄짜리 호출을 여러 줄로 나눴고 단언은 그대로다.
3. **함수 머리 주석.** `securitySummary`·`tokensSummary` 에 한 줄짜리 머리 주석을 더했다(설계 절 번호와 읽는 값).
4. **`firstLine` 구현.** 첫 `\n` 앞까지 자르고 그 안의 `\r` 을 모두 지운다(`replaceAll`). 계획 §2.2 의 주석 문장대로다.
5. **`app.test.ts` 새 테스트의 단언.** "#/analyze/tokens" 는 토큰 탭 `aria-selected="true"` 와 보안 탭 `"false"` 를
   함께 본다. "#/analyze/performance" 는 토큰 탭 선택과 `location.hash === "#/analyze/performance"` 를 본다.
6. **`tokensResponse()` 복사.** 원본의 `OVERLAY_TEXT`·`SOURCE_A` 상수는 값으로 펼쳐 넣었다. 요약 함수는 둘 다 읽지 않는다.
7. **`AnalyzeView` 의 머리 주석**(`#/analyze/<tab>`·탭 설명)은 그대로 두었다. 허용 범위가 props·TABS·비교뿐이고
   화면이 아직 탭이라 틀린 문장도 아니다. T3 이 화면을 바꿀 때 고칠 대상이다.

## 남은 위험

- `AnalyzeView` 머리 주석과 `TokensPanel` 등 다른 파일 주석에 "탭" 어휘가 남아 있다. T3 몫이다.
- `as AuditReport` 캐스트는 `exitCode: number` 를 `0 | 2` 로 좁혀 넣는다. typecheck 는 통과했지만 audit 의
  `AuditReport` 필드가 늘면 테스트 helper 가 조용히 그 필드를 비운 채 남는다. 요약 함수가 읽지 않는 한 영향은 없다.
