## 구현 요약

**`preload.mjs`.** `MCPEAK_PERF_TRACE_DIR` 이 없으면 아무것도 하지 않고, 있어도 지우지 않는다. 로드 직후 `hello`
한 줄. `seq` 는 네 경로가 공유하는 프로세스 안 카운터. 시각은 전부 `performance.timeOrigin + performance.now()`.
쓰기는 `appendFileSync`. 관측 코드의 예외는 전부 잡아 버리고, 원래 fetch 가 던진 오류만 `end` 줄을 쓴 뒤 다시
던진다.

- fetch: `new Request(input, init)` 로 메서드·URL·헤더를 읽고 원래 fetch 에 그 Request 를 넘긴다. 원래 fetch 는
  `als.run(seq, ...)` 안에서 부른다. 응답이 오면 `clone()` 복제본을 `getReader()` 로 끝까지 읽는 작업을 **기다리지
  않고** 걸고 원본은 즉시 돌려준다. 복제본 읽기가 끝난 시각이 `tEnd`, `bodyEnd: true`. 본문이 `null` 이면
  `tEnd = tHeaders`, `responseBody: ""`. 상한 262,144 바이트를 넘기면 잘라 담고 `responseBodyTruncated: true`.
- `node:http`: `http.client.request.start` 에서 `start`, `http.client.response.finish` 에서 `tHeaders`·`status`·
  `location` 을 기억하고 **`response.once("end")`·`once("close")` 만** 건다. `data` 리스너·`resume()`·
  `setEncoding()` 은 어디에도 없다. `http.client.request.error` 는 `bodyEnd: false` 와 `error`.
- HTTP/2: `http2.client.stream.created`·`close`. 헤더·본문은 담지 않는다.
- undici: `undici:request:create` 에서 `start` 와 `als.getStore()` 의 `parentFetch`, `trailers` 가 `tEnd`,
  `error` 는 `bodyEnd: false`.

**`childEnvironment`.** `NODE_OPTIONS` 는 기존 값이 비어 있지 않으면 `${existing} --import=${url}`, 아니면
`--import=${url}`. `url` 은 `new URL("./child/preload.mjs", import.meta.url).href`. 키는 두 개.

**`readTrace`.** `readdir` 뒤 `.jsonl` 만 기본 `sort()` 순으로, 줄은 `\n` 으로 나누고 빈 줄은 세지 않는다.
`JSON.parse` 실패·객체 아님·`kind` 미지는 `skippedLines` 에 세고 건너뛴다. 그 밖의 필드는 검증하지 않는다.

## 임의로 판단한 부분

설계·계획이 비워 둔 자리를 아래처럼 채웠다. 다르게 갈 수 있는 것들이므로 검토 대상이다.

1. **`node:http` 의 URL 에 host 헤더를 쓴다.** 설계 §4.3 은 `${protocol}//${host}${path}` 라고만 적었다. `request.host`
   는 호스트 이름만이라 비기본 포트가 사라지므로, `request.getHeader("host")`(포트 포함)를 먼저 쓰고 없으면
   `request.host` 로 간다. preload-e2e 의 `start.url === origin + "/slow"` 단언이 이것을 본다.
2. **undici 의 `tHeaders`·`status` 를 `undici:request:headers` 에서 함께 적는다.** 설계는 `trailers`·`error` 만
   말하지만 타입이 허용하는 필드이고, 본문을 끝까지 안 읽어 `trailers` 가 안 오는 직접 undici 요청에 §5.1 의
   `tHeaders` 폴백이 생긴다. `parentFetch` 가 있는 줄은 §5.2 가 지우므로 fetch 경로에는 영향이 없다.
3. **fetch 의 `requestBodyUnknown` 은 본문이 실제로 있을 때만.** 설계 공통 규칙은 "GET·HEAD 가 아닌데 본문을 못
   보면" 이다. `request.body === null` 인 POST 는 볼 본문이 없으므로 적지 않는다. 문자열 본문이 상한을 넘기면 잘라
   담고 `requestBodyUnknown: true` 를 함께 적는다(§4.5). undici·http2·node:http 는 본문을 볼 수 없어 설계대로 메서드만으로
   정한다.
4. **`new Request(input, init)` 이 던지면 관측 없이 원래 fetch 에 그대로 맡긴다.** 같은 입력에 원래 fetch 도 같은
   이유로 던지므로 서버가 보는 오류는 같다. 관측 코드의 예외를 서버로 새지 않게 하는 규칙의 적용이다.
5. **복제본 처리 중 예외가 나면 `tEnd = tHeaders`, `bodyEnd: false` 로 끝 줄을 닫고 원본을 돌려준다.** 복제본
   읽기 자체가 던지면 설계 §4.3 5항대로 `bodyEnd: false` 와 `error` 를 적는다. 호출자에게는 원본이 이미 갔으므로
   던질 곳이 없다.
6. **`MCPEAK_PERF_TRACE_DIR` 이 빈 문자열이면 없는 것으로 본다.** 빈 경로에 `join` 하면 작업 디렉터리에 파일을
   쓰게 된다.
7. **중복 설치 가드 `Symbol.for("mcpeak.perf.preload")`.** ESM 캐시로 같은 URL 은 한 번만 로드되지만 record 와
   같은 방식으로 한 번 더 막았다.
8. **`readTrace` 의 빈 줄 판정은 `trim() === ""`.** 공백만 있는 줄과 `\r` 끝 줄을 빈 줄로 본다(세지 않는다).
9. **`end` 줄에 `bytes` 를 싣는다.** fetch 경로에서 실제 받은 바이트 수. 타입에 있는 선택 필드다.
10. **`requestHeaders` 는 고른 것이 하나도 없으면 키를 아예 두지 않는다.** 빈 객체 대신 필드 부재.
11. **테스트의 추가 케이스.** 설계 §10.1 의 항목 밖에 `child-env.test.ts` 에 "키가 둘뿐" 한 건, `trace.test.ts` 에
    "빈 줄·비객체·kind 미지", "jsonl 없음", "그 밖 필드 보존" 세 건을 더했다. 계획 §4.3 의 `200.jsonl`·`100.jsonl`·
    `notes.txt` 와 순서 단언은 첫 케이스에 있다.

## 남은 위험

- **Node 22 미확인.** 이 머신은 v24.14.1 이다. `http.client.request.error`·`http.client.response.finish` 와 fetch 안
  undici 의 ALS 귀속은 Node 24 에서만 확인했다. 설계 §2.2 대로 CI 의 `verify` 잡(22.18.0, E4)이 preload-e2e 를
  돌려 판정한다. undici start 가 0줄이면 두 번째 케이스는 통과하도록 돼 있고, 귀속이 깨져 `parentFetch` 가 빠지면
  그 케이스가 빨강이 된다.
- **HTTP/2 경로는 E2E 가 덮지 않는다**(설계의 알려진 한계). 구독 코드만 있고 실행 확인은 없다.
- **본문을 안 읽는 서버의 메모리.** 복제본 읽기가 원본 가지를 tee 버퍼에 남긴다. 설계 §4.3 3항이 받아들인 비용이다.
- 커밋·병합·푸시는 하지 않았다. `git status --short` 의 7개 항목이 이 태스크의 전부다.
