## 구현 요약

- `parsePerfCommand`: 첫 `--` 앞 토큰에서 `--url`·`--header-env`(`=` 형식 포함)를 가장 먼저 찾는다. 이어서
  perf 옵션(`--repeat`, `--interval-ms`, `--tool`, `--baseline`, `--update-baseline`, `--threshold-pct`, `--threshold-ms`, `--json`)을
  `optimize` 와 같은 규칙(값 누락, 중복, `=` 형식, 값 자리의 `--` 거절)으로 읽는다. test 전용 옵션은 `지원하지 않는 perf 옵션 '{이름}'입니다.`.
  첫 위치 인자를 명세 경로로 두고 나머지 대상 토큰과 함께 `parseTestCommand` 에 넘긴다.
- `runPerfCommand`: 명세(확장자, 읽기, UTF-8, JSON, 검증) → plan → 기준 파일(비교일 때만, 측정 전) → 추적 디렉터리 →
  `childEnvironment` → 연결(`now` 전후) → `tools/list`(`now` 전후) → 진행 문장 → `measure` → 연결 닫기 → 진행 문장 →
  `readTrace` → `analyze` → 기준선 쓰기 또는 비교 → stdout. 추적 디렉터리는 `finally` 에서 지운다.
- `help.ts`: `PERF_USAGE`, `PERF_USAGE_HINT`, 명령 목록의 perf 줄(audit 뒤), `commandDiscovery` 에 perf, `commandHelp("perf")`.
- `index.ts`: `COMMANDS`·`HELP_TOPICS` 에 perf, `nodePerfDependencies(core, runner, perf)`, perf 분기 동적 import 와
  `PERF_RUNTIME_UNAVAILABLE` 문장, `generatorVersion` 은 `../../perf/package.json` 의 `version`.

## 임의로 판단한 부분

1. **숫자 옵션 문장**: 설계가 문안을 정하지 않아 `` `{옵션}` 는 {min} 이상 {max} 이하의 정수여야 합니다. 받은 값: '{값}' `` 으로 했다.
   값 누락·중복·값을 받지 않는 플래그는 `optimize` 의 문장 모양(`` `--out` 옵션 값이 필요합니다. ``, `` `--json`은 한 번만 사용할 수 있습니다. ``)을 따랐다.
   정수 판정은 `/^\d+$/` 이다. `+5`, `5.0`, `1e2` 는 거절한다.
2. **원격 옵션 탐색 범위**: 설계 문장 그대로 첫 `--` 앞의 **모든 토큰**을 본다. 그래서 `--arg --url` 처럼 서버 인자 자리에 온 `--url`
   도 거절된다. `--` 형식으로 넘기면 피할 수 있다.
3. **위치 인자**: 첫 위치 인자가 명세 경로이고, 옵션 뒤에 와도 된다(`--repeat 2 s.json -- node`). 남는 위치 인자는 `parseTestCommand`
   에 넘겨 test 와 같은 문장으로 거절되게 했다.
4. **검사 순서**: 파싱 → 명세 → 측정 케이스 없음 → 기준 파일 → 추적 디렉터리. 설계는 기준 파일을 측정 전에 보라고만 한다.
5. **기준 파일 읽기 오류 중 ENOENT 가 아닌 것**(EACCES 등): `PERF_BASELINE_INVALID` 문장에 사유로 errno 를 넣는다. 설계 §8.5 는 없음과
   형식 오류만 정했다.
6. **기준 파일 쓰기 실패**: 리포트를 stdout 에 먼저 내고 `오류 [PERF_BASELINE_WRITE_FAILED]: 기준 파일을 쓰지 못했습니다 ({errno}). 경로: {path}`
   와 해결 줄, 종료 코드 1. 설계에 없는 코드다. `optimize` 의 `OVERLAY_WRITE_FAILED` 모양을 따랐다.
7. **`--update-baseline` 순서**: 파일을 먼저 쓰고 리포트를 낸다. 쓰기가 실패해도 잰 결과는 버리지 않는다.
8. **콜드 스타트 반올림**: `connectMs`·`listToolsMs` 를 `Math.round` 한다. 렌더러가 머리 줄에 값을 그대로 찍어 소수 밀리초가 나오기 때문이다.
9. **`makeTempDir` 인자**: `perf-command.ts` 가 `join(tmpdir(), "mcpeak-perf-")` 를 넘기고 `nodePerfDependencies` 는 `mkdtemp(prefix)` 다.
10. **`sleep`**: 이미 abort 된 signal 이면 타이머를 걸지 않고, abort 되면 `clearTimeout` 만 하며 resolve 하지 않는다(설계 §8.2 주석 허용 범위).
11. **도움말 본문**: §8.4 표에 더해 측정 대상, 원격 옵션을 받지 않는 이유, 간격 0 의 뜻, 종료 코드를 적었다. `--env` 설명은 기존
    `ENV_FORWARD_OPTION` 을 쓰고 `REMOTE_TARGET_OPTIONS` 는 넣지 않았다. 머리 줄은 다른 명령과 같은 `perf — …` 형식이다. 이 대시는
    산문이 아니라 기존 도움말 머리 형식을 맞춘 것이다.
12. **테스트의 임시 파일**: 동등성 테스트 둘(명세 오류, 연결 실패)은 진입점 `run` 을 실제 의존성으로 부르므로 `mkdtemp` 임시
    디렉터리에 명세 파일을 쓴다. `index.test.ts` 의 기존 관례와 같다. 연결 실패 테스트는 없는 실행 파일 경로로 spawn 을 시도하지만
    프로세스는 뜨지 않는다. 설계 §10.2 가 이 항목을 유닛(`perf-command.test.ts`)에 두었다.

## 남은 위험

- 명세 오류·연결 실패 문장은 `test-command.ts`·`optimize-command.ts` 의 복사본이다. 그쪽 문장이 바뀌면 동등성 테스트가 빨개진다.
  의도된 감지 장치지만, 그 파일 오너가 바꿀 때 perf 쪽도 함께 고쳐야 한다는 뜻이다.
- `commandDiscovery` 와 전체 도움말 명령 목록이 바뀌었다. 이 문자열을 리터럴로 단언하는 다른 테스트는 저장소에 없었다(전체 테스트 녹색).
  문서 사이트(`website/…/cli.md`)의 명령 목록 갱신은 T8 범위다.
