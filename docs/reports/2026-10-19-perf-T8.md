## 임의로 판단한 것

1. **ADR 작성자 `@seodduu`.** 오너는 전원 공동(E1)이지만 작성자 칸은 한 사람이라 이 저장소의 git 사용자로 적었다.
   담당은 계획서대로 `perf`.
2. **ADR 참조에 ADR-0013·0095·0097·0100 을 넣었다.** 설계 §3.2·§4.1·§4.2 가 근거로 대는 ADR 이다.
3. **ADR 이유의 (b) 에 "HTTPS 를 보려면 인증서를 바꿔야 해 측정이 서버 동작을 바꾼다" 를 더했다.** 설계 §12 는 "서버
   안 시간을 못 가른다" 만 적었다. 덧붙인 문장은 설계 §1.1 7항·§4.1 의 "관측만 하고 바꾸지 않는다" 와 같은 방향이다.
4. **ADR 결과에 "record 와 perf 프리로드를 한 자식에 싣지 않는다" 와 2단계 남은 일을 넣었다.** 설계 §4.1·§13 Q2 그대로다.
5. **perf README 의 "설치" 절은 `npm install -g @mcpeak/cli` 하나다.** `@mcpeak/cli` 가 `@mcpeak/perf` 를 의존성으로
   갖고(`packages/cli/package.json`) perf 에는 별도 실행 파일이 없기 때문이다. audit README 에는 설치 절이 없어
   optimize·루트 README 의 문장을 따랐다.
6. **perf README 에 "라이브러리로 쓰기" 절을 두지 않았다.** 계획서 §9.2 가 정한 절(언어 전환, 설치, 사용, 옵션, 종료
   코드, 한계)만 썼다. 비밀 미기록·결정론 문단은 설계 §1.1 6·7항이라 한계 절 뒤에 붙였다.
7. **영문 README 의 리포트 예시는 한국어 그대로 두고 진단 세 줄의 번역을 인용 블록으로 붙였다.** 리포트가 한국어로만
   나오기 때문이다. 루트 `README.en.md` 가 실패 예시에 같은 방식을 쓴다. 한국어 README 에는 그 인용이 없다.
8. **README 의 종료 코드 1 설명에 E9(관측 없이 `--baseline`)를 넣었다.** 계획서 E9·§8.2 기준이다.
9. **website perf 절의 사용법 줄은 `<서버 지정>` 대신 두 형태를 풀어 썼다.** perf 는 세 가지 방법 중 둘만 받아서,
   17행 문장을 고치지 않는 대신 사용법 줄과 본문 문장이 그 차이를 말하게 했다.
10. **루트 README 명령 표의 perf 예시 명령은 `mcpeak perf suite.json -- node ./server.js`.** 다른 행의 예시 꼴을 따랐다.
