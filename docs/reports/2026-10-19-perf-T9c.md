## 수동 신호 확인

`pnpm build` 뒤 dist CLI 를 격리한 `TMPDIR`(scratchpad 아래 빈 디렉터리)로 띄워, 같은 머신의 다른 worktree 가 만드는 임시
디렉터리와 섞이지 않게 했다.

```
TMPDIR=<빈 디렉터리> node packages/cli/dist/cli.mjs perf examples/weather-server/server.suite.json --repeat 100 --interval-ms 50 -- node examples/weather-server/server.mjs &
# 2초 뒤 kill -INT (또는 -TERM)
```

| 신호 | 측정 중 추적 디렉터리 | 종료 코드 | 끝난 뒤 `mcpeak-perf-*` | 남은 weather-server | stderr |

## 임의로 판단한 부분

- 주입점 이름을 `removeDirSync`·`onSignal`·`killSelf` 로 정했다. 지시의 "removeDir" 는 동기 삭제 요구와 함께 읽어, 기존
  비동기 `removeDir` 은 정상 경로에 두고 신호 경로에만 동기 함수를 따로 두었다.
- `onSignal` 의 처리기는 Promise 를 돌려주는 모양이다. 실제 리스너는 그 Promise 를 버리고(`void`), 테스트는 기다려 순서를 단언한다.
- 신호 경로의 연결 닫기는 정상 경로와 같은 `closeQuietly` 를 쓴다(close 실패면 forceClose). 두 번째 신호는 닫기를 건너뛴다.
  닫기가 멈추는 서버에서 사용자가 Ctrl-C 를 한 번 더 눌러 빠져나올 수 있게 하려는 것이다. 지시에 없는 규칙이다.
- `--update-baseline`+`--tool` 거절은 `parsePerfCommand` 안에서 한다. 명세를 읽기 전이라 연결도 측정도 하지 않는다.
- 기준 좁히기는 `caseId` 로만 한다. 지시대로이고, 도구 이름으로 좁히지 않는다.
