# `generate --out` 선검사와 덮어쓰기 설계 (2026-08-15)

- 선행 작업: R4(저장 경로의 no-clobber 보장), 승인 전 시험 실행 게이트, 입력값 교정
- 대상 패키지: `cli` 전부
- 새 ADR: 없다. 판단이 갈리는 곳은 `--force` 를 둘 것인가 하나뿐이고, 그 근거는 이 문서 §4 에
  적는다. R4 가 정한 no-clobber 원칙 자체는 안 바꾼다.

## 1. 배경

`ohmymcp generate` 는 출력 파일이 이미 있으면 저장하지 않고 `GENERATE_OUTPUT_EXISTS` 로 끊는다.
`rename` 이 대상을 말없이 덮어쓴다는 것을 실측으로 확인하고 `link` 로 바꾼 R4 의 결론이다
(`docs/reports/task-r4.md`). 남의 파일을 날리느니 저장을 안 하는 쪽이 옳다.

그런데 실제로 돌려 보니 두 가지가 드러났다.

**첫째, 덮어쓸 방법이 아예 없다.** `--force` 같은 옵션이 없어서 사용자는 CLI 밖에서 손으로 파일을
옮기거나 지워야 한다. 그런데 **재생성이 이 도구의 대표 사용 흐름이다.** 서버에 툴을 하나 추가하고
지난달에 만든 명세를 갱신하려면 같은 경로로 다시 돌리는 것이 자연스러운데, 그 길이 항상 막힌다.
CI 나 스크립트에 `--out` 이 고정돼 있으면 두 번째 실행부터 전부 실패한다. 안전장치의 취지는
옳지만 사용자가 의도를 밝힐 수단이 없다.

**둘째, 알려주는 시점이 늦다.** `--out` 은 인자 파싱 때 이미 안다. 그런데 검사는 저장 확인에
`y` 를 누른 다음에야 돈다. 그 사이 후보 검토, provider 승인, 실서버 시험 실행, 입력값 교정,
케이스 분류가 전부 지나간다. `--provider` 를 태웠으면 AI 호출이 이미 두 번 나갔고, 사용자는 교정
값을 손으로 쳤다. 알 수 있었던 사실을 늦게 말한 것이다.

저장 실패가 검토 메뉴로 돌아가므로(`generate-command.ts` 의 `save` 분기 `continue`) 세션이 죽지는
않는다. 다만 다시 `save` 를 고르면 시험 실행이 처음부터 다시 돈다.

## 2. 목표 / 비범위 / 완료 조건

**목표**

- 출력 경로 충돌을 **서버와 provider 를 건드리기 전에** 알린다.
- 사용자가 덮어쓰기 의도를 CLI 안에서 밝힐 수 있게 한다.

**비범위**

- R4 의 no-clobber 보장 변경. `link` 의 `EEXIST` 검사는 그대로 둔다.
- `rename` 도입. 덮어쓸 수 있는 primitive 를 두지 않는다는 원칙을 유지한다.
- 백업 파일 자동 생성. 사용자가 지우라고 한 것을 우리가 몰래 남기지 않는다.
- 기존 파일과 새 명세를 합치는 병합. 별개 기능이다.

**완료 조건**

1. `--out` 이 이미 있고 `--force` 가 없으면 **서버에 연결하기 전에** 사용 오류로 끊는다.
2. `--force` 가 있으면 기존 파일을 지우고 저장한다.
3. `--force` 없이 저장 단계까지 간 경우의 동작은 지금과 같다(경합 대비).
4. `generate --help` 와 `dist-cli-e2e.mjs` 에 `--force` 가 나온다.
5. 프로젝트 루트에서 `pnpm test`, `pnpm typecheck --force`, `pnpm lint`,
   `pnpm build && pnpm --filter ohmymcp test:e2e` 가 통과한다.

## 3. 옵션

| 옵션 | 값 | 규칙 |
|---|---|---|
| `--force` | 없음 | 한 번만. `flagNames` 에 더한다 |

`--baseline-only` 와 함께 쓸 수 있다. 그 경로도 같은 파일에 저장한다.

## 4. 검사 자리 세 곳

검사는 셋이 되고 셋 다 필요하다. 역할이 다르다.

| 자리 | 시점 | 역할 | `--force` 일 때 |
|---|---|---|---|
| 선검사 (신설) | 인자 파싱 직후, 서버 연결 전 | 비용을 치르기 전에 끊는다 | 건너뛴다 |
| `exists` 선검사 (기존) | 저장 시작 직전 | 빨리 알려준다 | 건너뛴다 |
| `link` 의 `EEXIST` (기존) | 커밋 순간 | **no-clobber 보장** | 아래 §5 |

기존 주석이 "선검사는 편의이고 보장은 `link` 에 있다" 고 적어 둔 구분을 그대로 유지한다. 새
선검사도 편의 쪽이다.

## 5. `--force` 의 저장 경로

`rename` 을 쓰지 않는다. 임시 파일을 만들고 검증하는 지금 순서를 그대로 두고, `link` 직전에
기존 파일을 `unlink` 한다. `unlink` 는 이미 `GenerateCommandDependencies` 에 있다.

```
openTemp → write → sync → close → readFile → validate
  → (--force 면) unlink(outPath)   // 없으면 ENOENT 를 삼킨다
  → link(temporary, outPath)
```

`unlink` 와 `link` 사이에 다른 프로세스가 같은 경로를 만들면 `link` 가 `EEXIST` 로 실패하고 지금과
같은 오류가 난다. 그 창을 없애려고 `rename` 으로 바꾸지 마라. 덮어쓸 수 있는 primitive 를 두지
않는다는 것이 R4 의 결론이고, `--force` 는 "이 경로를 내가 지운다" 는 뜻이지 "무엇이든 덮어쓴다"
는 뜻이 아니다.

`unlink` 가 `ENOENT` 로 실패하면 무시한다. 선검사와 저장 사이에 사용자가 파일을 치운 경우이고,
결과가 원하는 상태와 같다. 다른 오류는 §6 의 세 번째 문안으로 끊는다. `--out` 이 디렉터리면
`unlink` 가 `EISDIR` 또는 `EPERM` 을 내는데, 그 사실이 화면에 안 드러나면 사용자는 무엇을
확인해야 할지 모른다.

## 6. 화면 (전량)

**선검사에서 끊을 때.** 아직 아무것도 안 했다는 것이 문장에 드러나야 한다.

```
오류 [GENERATE_OUTPUT_EXISTS]: 출력 파일이 이미 있어 시작하지 않았습니다. 경로: <path>
해결: 다른 `--out` 경로를 지정하거나, 기존 파일을 덮어쓰려면 `--force` 를 붙이세요.
```

**저장 단계에서 끊을 때.** 기존 문안에 `--force` 만 더한다.

```
오류 [GENERATE_OUTPUT_EXISTS]: 출력 파일이 이미 있어 저장하지 않았습니다. 경로: <path>
해결: 다른 `--out` 경로를 지정하거나, 기존 파일을 덮어쓰려면 `--force` 를 붙이세요.
```

두 문장의 차이는 `시작하지 않았습니다` 와 `저장하지 않았습니다` 뿐이다. 사용자가 무엇을 잃었는지가
거기서 갈린다. 코드는 같아야 한다. 종료 코드도 기존 저장 실패와 같다.

**선검사가 경로를 확인하지 못할 때.** `exists` 가 던지는 경우다. 편의 검사가 명령 전체를
거절로 끝내면 호출자가 보는 것이 종료 코드가 아니라 예외가 된다.

```
오류 [GENERATE_OUTPUT_CHECK_FAILED]: 출력 경로를 확인하지 못해 시작하지 않았습니다. 경로: <path> (<code>)
해결: 그 경로와 상위 디렉터리의 권한을 확인하세요. 다른 `--out` 경로를 지정해도 됩니다.
```

**`--force` 인데 기존 파일을 못 지울 때.** `unlink` 가 `ENOENT` 말고 다른 오류를 낸 경우다.

```
오류 [GENERATE_OUTPUT_REPLACE_FAILED]: 기존 출력 파일을 지우지 못해 저장하지 않았습니다. 경로: <path> (<code>)
해결: 그 경로가 디렉터리이거나 쓰기 권한이 없는지 확인하세요. 다른 `--out` 경로를 지정해도 됩니다.
```

`<code>` 는 `EISDIR`·`EPERM`·`EACCES` 처럼 시스템이 준 값을 그대로 적는다. 우리가 원인을 단정하지
않는 이유는 `--out` 이 디렉터리인지 권한 문제인지 여기서 구분할 수단이 없기 때문이다. `stat` 을
주입하지 않는다. 사용자가 확인할 수 있는 두 가지를 문장에 적어 두는 것으로 충분하고, 그것이
`GENERATE_FAILED` 만 남기는 지금보다 낫다.

**도움말.** `GENERATE_USAGE` 의 옵션 목록 끝에 `[--force]` 를 더하고 설명 블록에 아래를 더한다.

```
  --force               `--out` 경로에 파일이 있으면 지우고 새로 씁니다. 기본은 저장을
                        멈추는 것입니다
```

## 7. 결정론성

선검사는 파일 존재 여부만 본다. 시각·순서에 의존하지 않는다. `--force` 가 지우는 대상은 사용자가
`--out` 으로 지정한 경로 하나뿐이고 다른 경로를 만들거나 지우지 않는다.

## 8. 알려진 위험

- **`--force` 는 되돌릴 수 없다.** 확인 프롬프트를 두지 않는다. 플래그를 붙이는 행위가 곧 의도
  표명이고, 비대화형 사용(CI)에서 프롬프트가 걸리면 쓸모가 없다.
- **선검사와 저장 사이에 파일이 생길 수 있다.** `--force` 없이 그 창에 걸리면 저장 단계 문안이
  나온다. 의도한 동작이다.
- **`packages/cli/tests/generate-command.test.ts` 는 PR #102 가 같은 시각에 고치고 있다.**
  머지 순서는 PR #102 가 먼저다.
